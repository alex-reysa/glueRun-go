## Objective

Deliver the single-slice `contract` layer of executable DAG node `context-packet-contract` (stage `S4-context-packets`, area `packets`, layer `contract`, kind `contract`): define the OPTIONAL, additive context-packet block for task markdown and ship a tolerant parser plus the planner-prompt request for it. This is a design/contract slice — the operator reviews the diff before integration. It adds a new pure helper in `engine/ctx-packet.sh` that is present-but-uncalled by every existing engine path (so with the ctx-loader block sourcing it the engine stays byte-identical to current behavior), an additive request in the two planner-prompt files, and a strict-test-first fixture parser test. No `GLUERUN_*` behavior flip and no existing-schema change: the `GLUERUN_CTX_PACKET` knob and the per-run assumption ledger belong to the downstream `assumption-ledger` node and are OUT OF SCOPE here, as is `artifact-secret-scan`.

Grammar (per the stage-4 file section for `context-packet-contract`): the packet is an OPTIONAL `## Context packet` block in the task markdown carrying up to four subsections — `Decisions`, `Assumptions`, `Rejected alternatives`, `Inspected symbols`. Each assumption entry follows `- [open|validated|violated] <claim> — <basis>`. The block and every subsection are optional and parsed tolerantly: a task with no block, or with only some subsections, stays valid forever, so every existing TEMPLATE-based task keeps parsing.

`engine/ctx-packet.sh` defines `gluerun_ctx_packet_json <task-file>`: it reads the given task markdown (STRICTLY READ-ONLY — it never creates, modifies, or deletes the task file or any repo file) and prints normalized JSON on stdout. A task with a well-formed packet yields a stable object `{ "schema": "gluerun.orchestration.ctx-packet.v0", "decisions": [...], "assumptions": [ {"status":..., "claim":..., "basis":...}, ... ], "rejectedAlternatives": [...], "inspectedSymbols": [...] }` with sorted keys and deterministic ordering; a task with NO `## Context packet` block prints exactly `{}`; a block present but malformed (e.g. an assumption entry that does not match `[open|validated|violated] <claim> — <basis>`) fails closed to `{}` and appends exactly one `ctx.packet_malformed` warning event via `gluerun_append_event` (its only side effect — the task file itself is untouched). The two planner-prompt files gain an additive, capped, concrete request for the block: decisions with their why, rejected alternatives with their why-not, assumptions the implementer must not silently violate expressed in the assumption grammar, and the standing rule "never restate what the repo can answer — no symbol inventories, only symbols whose ROLE in the plan is non-obvious." The request is OPTIONAL for planners; absent packets remain valid.

## Acceptance Criteria

Behavior-level and checked by `tests/test-ctx-packet.sh` (strict_test_first: the new test is RED before `engine/ctx-packet.sh` exists, GREEN after; `bash tests/run.sh` and `tests/test-engine-clean.sh` stay green). The test sources `engine/lib.sh` (which auto-sources `engine/ctx-packet.sh` via the ctx-loader block), asserts `gluerun_ctx_packet_json` is defined, and drives it over fixtures written to a temp dir:

- Present/full: a fixture task carrying a `## Context packet` block with all four subsections parses to the normalized object — `schema` const `gluerun.orchestration.ctx-packet.v0`, `decisions`/`rejectedAlternatives`/`inspectedSymbols` as the listed strings, and `assumptions` as `{status, claim, basis}` triples whose `status` is one of `open|validated|violated` — with deterministic key ordering across repeated runs on identical input.
- Absent block: a fixture task with no `## Context packet` block (e.g. a copy of `docs/orchestration/tasks/TEMPLATE.md`) parses to exactly `{}`, proving existing TEMPLATE-based tasks are unaffected.
- Partial: a fixture with only `Decisions` and `Assumptions` present parses successfully with just those populated and the omitted subsections absent/empty — absent subsections are valid, not an error.
- Malformed fail-closed: a fixture whose `## Context packet` block contains an assumption entry not matching `- [open|validated|violated] <claim> — <basis>` yields exactly `{}` on stdout AND appends exactly one `ctx.packet_malformed` warning event to a temp `GLUERUN_EVENTS_FILE`; no partial packet is emitted.
- Read-only: the fixture task file's content hash is byte-identical before and after each parse (the parser's only side effect is the malformed-case warning event, which lands in the events file, never in the task file or any other repo file).
- Planner-prompt request: both `templates/prompts/l1-planner.md` and `docs/orchestration/prompts/l1-planner.md` contain the additive context-packet request — the `Context packet` subsection names, the assumption grammar `[open|validated|violated] <claim> — <basis>`, and the "never restate what the repo can answer" rule — asserted by grepping both files (positive presence assertion only; no absence-of-future-work grep, per planner-contract rule 9).
- Additive/flag discipline: no `GLUERUN_*` knob is introduced, no existing schema is modified, and `gluerun_ctx_packet_json` is invoked by NO existing engine/CLI/driver path this slice (present-but-uncalled), so `bash tests/run.sh` is byte-identical to current behavior apart from the added `tests/test-ctx-packet.sh` and the additive prompt request.
- Engine cleanliness: `tests/test-engine-clean.sh` stays green — no project-specific symbols enter `engine/`.
