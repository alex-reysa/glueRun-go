## Objective

Final core strict-test-first slice of the executable DAG node `rehydrate-path` (stage `S5-routing`, layer `engine_runtime`). The spine emits `rehydrate` on refused-resume lineage steps (TASK-0054) and the packet manifest is now recorded in the `context.strategy_selected` event (TASK-0056). The one remaining requiredCompletion behavior is INJECTION: on a `rehydrate` decision the otherwise-fresh implementer run must receive the assembled, capped, quarantine-aware rehydration packet as a prompt section. `engine/l1-drive.sh:453` already carries a marker that this packet-injection hook is the deferred later slice.

Add that hook to `engine/l1-drive.sh`: when `worker_strategy == "rehydrate"` at the implementer (`implement`) attempt-open, assemble the packet by delegating into the integrated pure bricks — `singular_ctx_rehydrate_packet` over `singular_ctx_rehydrate_sources "$run_dir"` — and append it to the already-rendered `$active_prompt` (`$run_dir/l2-active-prompt.md`) under a provenance header, mirroring the `assumptions_inject_fix` injection (`engine/l1-drive.sh` ~963) and the fix-hints append (~402). The run stays FRESH: on a `rehydrate` decision `worker_resume_id` is empty, so no `--resume-session` is passed — it is a fresh session with injected durable context.

Properties, node `rehydrate-path`, layer `engine_runtime`:

- Deterministic + capped + quarantine-aware come for free from the integrated bricks: each section is capped at `SINGULAR_CONTEXT_SECTION_MAX_CHARS`, and quarantined artifacts are excluded because the assembler composes `singular_ctx_artifact_exclude`.
- Gated implicitly by the `rehydrate` strategy, which the spine emits only under `SINGULAR_REHYDRATE=1` (default 0). With the flag unset, `worker_strategy` is never `rehydrate`, the hook never fires, and `$active_prompt` is byte-identical to current behavior.
- The injected section is headed as injected durable context from a refused-resume lineage — reference only, NOT authoritative — because rehydrated content is tainted / model-authored, not host-verified. This preserves the advocate/skeptic line: a rehydrated (tainted) session must never pass its injected content off as authoritative evidence.
- The reviewer / `final-audit` path is independence-pinned (`fresh tainted`), so `rehydrate` is unreachable there and no independence-required prompt receives injected context.

This is a minimal call-site hook delegating into the integrated `ctx-*.sh` bricks; no resolver/assembler/quarantine logic is inlined into the driver.

## Context packet

Decisions:

- Inject in an `engine/l1-drive.sh` call-site hook that delegates into the integrated pure bricks (`singular_ctx_rehydrate_sources` → `singular_ctx_rehydrate_packet`) and appends to `$active_prompt` at attempt-open, mirroring `assumptions_inject_fix` (`engine/l1-drive.sh` ~963) and the fix-hints append (~402). No new `ctx-*.sh` render leaf: the packet is already section-rendered by TASK-0051, so only a provenance header is added inline, exactly as the fix-hints precedent does. Basis: planner-contract rule 2 (minimal driver hooks) and the existing inline-append precedent.
- Gate the injection implicitly by `worker_strategy == "rehydrate"` — which the spine emits only under `SINGULAR_REHYDRATE=1` — rather than adding a second knob; the stage file specifies the behavior is behind `SINGULAR_REHYDRATE`. Basis: stage-5-routing.md and the `engine/ctx-route.sh` spine.
- Head the injected section as reference-only / non-authoritative durable context: rehydrated content is tainted / model-authored, so the framing keeps the advocate/skeptic line intact — a tainted session cannot present injected content as authoritative. Basis: planner-contract rule 8 (evidence invariance) and `engine/ctx-route-taint.sh`.

Assumptions:

- [validated] `$active_prompt` (`$run_dir/l2-active-prompt.md`) is the implementer's rendered prompt, assembled at attempt-open and appended to for injected sections (`engine/l1-drive.sh` ~378/402/411; `assumptions_inject_fix` ~963).
- [validated] On a `rehydrate` decision `worker_resume_id` stays empty, so the worker runs fresh with no `--resume-session` — a fresh session plus injected context (`engine/l1-drive.sh` resume branch).
- [validated] `singular_ctx_rehydrate_packet` over `singular_ctx_rehydrate_sources "$run_dir"` yields the deterministic, capped, quarantine-excluded packet (TASK-0051 / TASK-0053).
- [open] The injection must fire once per `rehydrate` attempt-open, not per infra-retry (`try` > 0 reuse `$active_prompt`); place it where `active_prompt` is freshly assembled, as the fix-hints and assumptions injections do.

Rejected alternatives:

- A new pure `ctx-rehydrate-prompt.sh` render leaf wrapping the packet — rejected: the packet is already section-rendered by `singular_ctx_rehydrate_packet`; only a provenance header is added, which the fix-hints precedent appends inline, so a wrapper leaf would be make-work.
- Adding a second feature flag for the injection — rejected: the `rehydrate` strategy is already gated by `SINGULAR_REHYDRATE`; a second knob contradicts the stage file and complicates OFF-parity.
- Injecting on infra retries as well — rejected: `$active_prompt` already carries the packet after attempt-open; re-appending would duplicate the section.
- Injecting the packet on the reviewer / `final-audit` path — rejected: that step is independence-pinned (`rehydrate` unreachable); injecting tainted context there would violate evidence invariance.
