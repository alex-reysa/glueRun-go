## Objective

Advance executable DAG node `planner-resume-gates` (stage `S1-planner-persistence`, area `session`, layer `engine_runtime`) by landing the sanctioned `engine/generate-tasks.sh` consult hook — the last remaining slice of this node. The ordered fail-closed decider `singular_planner_resume_decide` (TASK-0009) and the finalize↔decide TEMPLATE-sha alignment (TASK-0010) are integrated, but no engine path yet invokes the decider: `generate-tasks.sh` already offers `--session-meta` to the planner runner under `SINGULAR_PLANNER_SESSION=1` (TASK-0008) yet never consults the resume decision, never emits `context.strategy_selected`, never passes `--resume-session`, and has no resume-refused fallback. This slice wires that consult hook at the single sanctioned `generate-tasks.sh` site, mirroring the integrated task-role worker path in `engine/l1-drive.sh`.

When `SINGULAR_PLANNER_SESSION=1`, before invoking the planner runner, consult the decider: `singular_planner_resume_decide "$planner_session_meta" "$active_node" "$(basename "$codex_runner")" "$SINGULAR_ROOT" "$planner_head_sha"`, where the lineage head is the current target-branch head already computed as `planner_head_sha` (the same anchor the finalize hook records). Parse the decider's single line: on `resume <sessionId>` add `--resume-session <sessionId>` to the planner runner args and acquire the canonical planner session-lease (`singular_planner_resume_lease_path "$active_node"`) before the run; on `fresh <reason>` invoke without `--resume-session`. Either way emit exactly one `context.strategy_selected` event carrying `role: "planner"`, `node`, `runId`, `strategy` (`resume` or `fresh`) and `reason` (the exact gate reason returned by the decider), plus `sessionId` on resume — so `ctx-metrics.sh` sees planner routing and every gate reason is event-visible. If the runner returns rc 86 (resume-refused) after a resume attempt, emit `context.resume_failed`, drop `--resume-session`, and re-run the planner fresh within the SAME run (a pure optimization miss; the planning outcome is unchanged), mirroring the worker rc-86 fallback in `l1-drive.sh`. Release the lease after the run returns — including on the rc-86 fresh fallback and on runner error.

Feature-flag discipline is preserved: with `SINGULAR_PLANNER_SESSION` unset or `0` the hook consults nothing, adds no `--resume-session`, emits no strategy event, and acquires no lease, so `bash tests/run.sh` is byte-identical to current behavior with the knob off. Evidence invariance and the advocate/skeptic line hold: the hook trusts the decider's fail-closed verdict verbatim — it never upgrades a `fresh <reason>` (or any decide error) into a resume, so a non-`planner` role yields `fresh role-mismatch` and a fresh run and a task/advocate/skeptic session is never resumed as the planner. Schemas stay additive: `context.strategy_selected` reuses the existing event shape with `role: "planner"`. The change to the scarce driver file `engine/generate-tasks.sh` is a minimal call-site hook that delegates the decision to the already-integrated `singular_planner_resume_decide` (no decision logic duplicated in the driver).
