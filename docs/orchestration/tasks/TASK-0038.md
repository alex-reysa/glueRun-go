## Objective

Advance the executable DAG node `assumption-ledger` (layer `engine_runtime`, stage
`S4-context-packets`) with the stage's "carried across attempts like the findings
ledger" deliverable. The seed (`gluerun_ctx_assumptions_seed`), the host-derived
transition (`gluerun_ctx_assumptions_transition`), and the fix/audit prompt render
(`gluerun_ctx_assumptions_fix_section` / `_audit_section`) are integrated. This slice
ships the pure per-attempt carry: a new `engine/ctx-assumptions-carry.sh` with a
helper `gluerun_ctx_assumptions_carry <prior-ledger-json> <seed-ledger-json>` that
merges the prior attempt's ledger into the current attempt's fresh seed so a
host-observed `violated` status carries forward across retries — like an open finding
that persists until addressed — while the current seed stays the structural authority
(the task packet is the per-run source of truth and is unchanged between attempts).

The helper is a pure string→string transform over its two JSON arguments: it reads no
files, consults no flag, and emits no events. Like the sibling ctx-assumptions files,
it is auto-sourced by the ctx loader block yet called by no default
engine/CLI/driver path, so behavior under `GLUERUN_CTX_PACKET=0` stays byte-identical.
This slice does NOT touch driver files, does NOT compose the per-run assembler, does
NOT record the capsule, does NOT inject into any prompt, and does NOT add or consult
the flag — those are later slices for this node.

## Context packet

### Decisions

- Structural authority is the current seed (the task packet is the per-run source of truth), so carry keys on the seed's ids and overlays only the prior run-time status — this anchors the ledger to the stable packet and never resurrects entries no longer present.
- Only the host-derived `violated` status is sticky across attempts (mirroring how an open finding carries until resolved); model-asserted or `validated` statuses are not carried as authority, preserving the host/model boundary the transition established.
- Carry emits the plain ledger shape (no `claims`) — model-asserted claims are per-attempt, non-authoritative reasoning and are deliberately not accumulated across attempts.

### Assumptions

- [validated] between attempts the task packet is unchanged, so the seed ledger's ids, claims, and bases are stable and carry only needs to overlay the prior status by id — the seed is a pure function of the task file (engine/ctx-assumptions.sh).
- [open] the composed per-run assembler (seed→carry→transition→render), the flag-gated driver hook, and the per-attempt capsule recording of statuses are LATER slices for `assumption-ledger`; this slice must not touch driver files, must not add or consult `GLUERUN_CTX_PACKET`, and must not inject into any prompt — stage-4 node wire-in bullets.

### Rejected alternatives

- Making the PRIOR ledger the structural authority (carrying its ids forward) — would resurrect entries no longer in the packet and drift from the per-run seed; the current seed stays authoritative for structure.
- Carrying `validated` or model-asserted statuses as sticky — violates the host/model boundary; only the host-derived `violated` carries, mirroring how open (not resolved) findings carry across attempts.

### Inspected symbols

- `gluerun_ctx_assumptions_transition` — sets the host-derived `violated` status that carry treats as sticky; carry consumes a prior-attempt ledger that already ran through this transition.
