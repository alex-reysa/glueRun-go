## Objective

Final wiring brick of the executable DAG node `plan-revision-loop` (stage `S3-plan-revision`, area `plancritic`, layer `engine_runtime`, kind `runtime`). Every engine-side piece is integrated: the bound decider (TASK-0019), the structured-findings revision prompt assembler (TASK-0020), the per-finding disposition classifier + `plan.revised` events (TASK-0021), the revision-round resume/fresh strategy + rc-86 fresh-fallback recorder (TASK-0022), and the composed bounded revise -> (resume|fresh) -> re-critique -> approve/park loop orchestrator `gluerun_plan_revise_loop` with its full-walk `tests/test-ctx-plan-revision.sh` (TASK-0023). The one thing still missing is the sanctioned call-site that actually runs that orchestrator inside the per-node planner driver.

This brick adds the single minimal, default-OFF call-site hook in `engine/l1-plan-node.sh` — the driver-file this node owns per the planner contract (plan-revision-loop chains behind planner-session-meta for the generate-tasks.sh / l1-plan-node.sh files). The hook fires only in the existing staging-success branch and only under `GLUERUN_PLAN_CRITIQUE=1`, delegating entirely to the integrated orchestrator; it adds no revision logic of its own. It is byte-identical to today when the flag is off, mirroring the feature-flag discipline of the integrated hooks (generate-tasks.sh planner-session hook, l1-drive.sh paired-audit hook). No new `engine/ctx-*.sh` is introduced and `engine/lib.sh` is untouched.

## Acceptance Criteria

- The hook fires ONLY after the staged planner has produced `*.candidate.md` (the existing success branch) AND `GLUERUN_PLAN_CRITIQUE=1`; it invokes the integrated orchestrator `gluerun_plan_revise_loop <node> <run_id> <stage_dir>` and routes its single terminal outcome: `import` keeps today's behavior (candidates left staged, node lease left active, print `planned:<node>`, exit 0, so L0 remains the sole importer); `park <reason>` (budget exhausted with a still-non-approve verdict, or an explicit park) sets the node lease failed via `gluerun_l1_lease_set_status <node> failed` and exits plan-failed (non-zero) so unapproved candidates never reach L0 import, mirroring the integrated critique-import gate reject disposition (TASK-0016).
- Default-OFF / feature-flag discipline: with `GLUERUN_PLAN_CRITIQUE` unset or not equal to 1 (default 0), the hook is inert — `gluerun_plan_revise_loop` is never invoked, no revision events are emitted, and `engine/l1-plan-node.sh` is behaviorally byte-identical to today (staged candidates left active, `planned:<node>`, exit 0). The hook is the minimum call-site lines that delegate into the ctx orchestrator.
- Scarce-hook discipline / evidence invariance: the change to `engine/l1-plan-node.sh` is the single minimal call-site for the `plan-revision-loop` node; it introduces no revision behavior beyond delegating to the orchestrator, never promotes candidates to the global tasks dir (L0 stays the sole importer), never weakens a resume or import gate, keeps the critic read-only / fresh-by-default, and never makes the fresh implementation auditor bypassable. Events stay on the per-node `GLUERUN_EVENTS_FILE` the driver already exports.
- Strict-test-first: `tests/test-l1-plan-node-revise-hook.sh` is authored red first (asserting the routing and the OFF byte-identity before the hook exists) and green after, hermetic with a STUB planner via `GLUERUN_L1_PLANNER` and a stubbed orchestrator/critic so no real runner is called; the full suite `bash tests/run.sh` is green. Cases covered: flag OFF -> orchestrator never invoked and the driver output / exit code / lease status identical to the pre-hook staging-success path; flag ON + orchestrator returns `import` -> `planned:<node>`, exit 0, lease active; flag ON + orchestrator returns `park` -> lease set failed, plan-failed printed, non-zero exit, candidates not imported.
- Gate candidate: with this hook integrated, the executable DAG node `plan-revision-loop` (layer `engine_runtime`) is wired end-to-end — a staged plan is critiqued and, on a revise verdict, the node planner is resumed (with the fresh fallback recorded) for up to `GLUERUN_PLAN_REVISE_MAX` (default 1) bounded rounds with per-finding accepted/rejected-observation dispositions evented, approve routing to import and budget-exhaustion parking — with the full-walk `test-ctx-plan-revision.sh` (TASK-0023) and this driver-level hook test green, satisfying the node requiredCompletion and the stage-file exit gate.
