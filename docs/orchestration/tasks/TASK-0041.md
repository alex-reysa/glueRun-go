## Objective

Ship the detection surface of the executable DAG node `artifact-secret-scan`
(layer `engine_runtime`): give the credential accident-guard an `--artifacts`
mode that applies commit-grade secret hygiene to durable context artifacts.

Add a new `engine/ctx-artifact-scan.sh` that enumerates, for a run's state
directory, the durable context-artifact classes produced by already-integrated
nodes — implementer/reviewer capsules (`implementer-capsule.json`,
`reviewer-capsule.json`), planner/implementer/reviewer session-meta
(`session-implementer.json`, `session-reviewer.json`, and the planner
session-meta), the context packet (`packet.json`), critique records, and
paired-audit records (`paired-audit.json`, `paired-audit-raw.json`) — and scans
each for the same high-confidence secret patterns the commit-grade scanner
already uses, reporting every hit with its artifact file path and pattern label.

Wire a small `--artifacts` dispatch into `engine/secret-scan.sh` (the single
sanctioned hook site this node owns) that delegates to the new function.

This slice is detection/reporting only. Quarantine (rename `.quarantined` plus
the `ctx.artifact_secret` event) and exclusion from prompt assembly /
rehydration are separate downstream slices of `artifact-secret-scan` and are OUT
OF SCOPE here, because each consumes this slice's detection output and so is not
a mutually-independent fold. The scan must be byte-safe: it only reads and
reports; it must not rename, delete, or mutate any artifact in this slice.

## Acceptance Criteria

- `tests/test-ctx-artifact-scan.sh` is red before implementation and green after
  (strict_test_first): the red log is the new test failing before the
  `--artifacts` mode exists.
- Running the `--artifacts` mode over a run-state directory detects a seeded
  fake secret (e.g. an `sbp_...` token, an AWS access key id, a private-key
  block, or a JWT) planted in any of the covered artifact classes — capsule,
  session-meta, context packet, critique record, and paired-audit record — and
  reports each hit with the offending artifact path and the pattern label.
- Clean artifacts yield a clean result (no false hit); an artifact class with no
  files present is skipped without error.
- Artifact scanning reuses the same secret patterns as the commit-grade path —
  no separate or weaker pattern set for artifacts.
- Existing `engine/secret-scan.sh` modes (staged / range / working) are
  byte-identical: invoking the scanner without `--artifacts` behaves exactly as
  before this task.
- Additive / default-OFF: no existing default flow invokes `--artifacts`; the
  finalize-site hook and its documented `GLUERUN_*` knob, together with
  quarantine and prompt-assembly exclusion, land in later slices of
  `artifact-secret-scan`.
- Advocate/skeptic line and evidence invariance preserved: detection is
  read-only and changes no task outcome.
- `bash tests/run.sh` passes, including `tests/test-engine-clean.sh` (no
  project-specific symbols in `engine/`).

## Context packet

Decisions:
- Detection-first decomposition: this slice ships `--artifacts`
  detection/reporting only. Quarantine, prompt-assembly/rehydration exclusion,
  and the finalize-site hook are separate downstream slices — each depends on
  detection output, so none is a mutually-independent same-node fold. Why: keeps
  the first brick strict-test-first and independently verifiable.
- New logic lives in `engine/ctx-artifact-scan.sh`; `engine/secret-scan.sh`
  receives only the minimal `--artifacts` dispatch. Why: new-file convention
  (planner-contract rule 1); `secret-scan.sh` is a scarce driver/hook file this
  node owns solely for the `--artifacts` extension.

Assumptions:
- [validated] `engine/secret-scan.sh` is the real script path that the stage
  file and contract refer to as `secret-scan.sh` — basis: the repo contains only
  `engine/secret-scan.sh`.
- [open] the commit-grade secret patterns must be a single shared source, not
  copied into a second (possibly weaker) list for artifacts — basis: contract
  rule "never restate what the repo can answer" and the requiredCompletion
  parity between commit and artifact hygiene.
- [open] `--artifacts` is byte-safe in this slice: read and report only, with no
  rename/delete/mutation of any artifact — basis: quarantine is a later slice.

Rejected alternatives:
- Put the scan logic directly in `secret-scan.sh` — why not: violates the
  new-file convention; the driver file may take only the small dispatch hook.
- Fold quarantine into this slice — why not: quarantine consumes detection
  output (not mutually independent), and it would force the first test to assert
  two behaviors, blurring the red-then-green boundary.
