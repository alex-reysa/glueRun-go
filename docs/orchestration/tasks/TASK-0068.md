## Objective

Close a genuine in-scope coverage gap in the CORE `requiredCompletion` of the executable DAG node `rehydrate-path` (stage `S5-routing`, layer `engine_runtime`): the durable-artifact class `decision-record` — the stage file's enumerated "relevant decision records" — is plumbed through the assembler but never actually fed to the packet or the manifest by any driver, so it is silently absent from every real rehydrate run. This is NOT the optional authored-knowledge track (that is functionally complete); it is the core "rehydration packets from durable artifacts" behavior.

Evidence of the gap: the TASK-0051 assembler ranks a `decision-record` source class (`engine/ctx-rehydrate.sh` rank 6) and the TASK-0053 resolver deliberately does NOT resolve it — it documents that the repo-level decision record lives OUTSIDE `run_dir` and must be supplied by the caller as an `extra-id=path` spec (`engine/ctx-rehydrate-sources.sh`). But BOTH rehydrate call sites in `engine/l1-drive.sh` supply NO extras: the packet-injection hook `rehydrate_inject_packet` calls `gluerun_ctx_rehydrate_sources "$run_dir"` (l1-drive.sh:429) and the strategy-event record calls `gluerun_ctx_rehydrate_event_data implementer "$task_id" "$run_id" "$n" "$worker_strategy_reason" "$run_dir"` (l1-drive.sh:539) — neither passes a `decision-record` extra. So the enumerated class never reaches the injected packet or the recorded manifest, exactly the premature-complete coverage gap the operator decision log warns about.

This task bundles the two dependent same-node slices into ONE task (they are small and chained, and the wire-in flips the leaf's would-be present-but-uncalled state, so per the operator's TASK-0067 amend-scope lesson the leaf is wired-in from birth and never left as a standalone invariant for a later task to flip):

1. New pure leaf `engine/ctx-rehydrate-decision-source.sh` defining `gluerun_ctx_rehydrate_decision_source [base_dir]`: read-only, deterministic, existence-gated. It prints the single class-tagged extra spec `decision-record=<base_dir>/docs/orchestration/decisions.md` when that durable orchestration decision log exists under `base_dir` (default `${GLUERUN_ROOT:-.}`), and prints nothing otherwise. It writes/renames/deletes nothing, appends no events, and never exits non-zero. It performs NO quarantine filtering (the assembler already composes `gluerun_ctx_artifact_exclude`, preserving a single quarantine authority) and confers NO independence (`rehydrate` stays tainted).

2. Wire that spec into BOTH rehydrate sites in `engine/l1-drive.sh`, passing the IDENTICAL spec (each site computes it via the same pure leaf `gluerun_ctx_rehydrate_decision_source "$GLUERUN_ROOT"`, so they agree by construction): the packet-injection hook appends it to the args of `gluerun_ctx_rehydrate_sources "$run_dir"` so the decision record is rendered into `$active_prompt`, and the strategy-event record appends it as a trailing `extra-id=path` to `gluerun_ctx_rehydrate_event_data` so the SAME decision record (id + content hash) is recorded in the manifest. Both changes are minimal delegating call-site edits; no resolution/rendering/relevance logic is inlined into the driver.

OFF-parity and taint are preserved: both sites fire only when `worker_strategy == rehydrate` (behind `GLUERUN_REHYDRATE=1`; the routing spine never yields `rehydrate` otherwise), so with the flag unset `$active_prompt` and the event data are byte-identical; the packet remains headed reference-only / NOT authoritative; and the section cap (`GLUERUN_CONTEXT_SECTION_MAX_CHARS`) already bounds the injected decision-record body (node `rehydrate-path`, layer `engine_runtime`). This slice does not declare the node complete; completion and gate promotion are operator authority.

- Packet injection: with `GLUERUN_CTX_ROUTING=1`, `GLUERUN_REHYDRATE=1`, a refused-resume lineage step that upgrades to `rehydrate`, and a durable decision log present under `GLUERUN_ROOT`, the injected durable-context section in `$active_prompt` includes the decision-record source body (bounded by `GLUERUN_CONTEXT_SECTION_MAX_CHARS`).
- Manifest recording: for the same `rehydrate` run, the `context.strategy_selected` event data manifest `sources` includes an entry with id `decision-record` and its content sha256.
- Injected<->recorded consistency: the `decision-record` source injected into the packet and the `decision-record` entry recorded in the manifest resolve to the SAME path and content hash, because both sites pass the identical spec from `gluerun_ctx_rehydrate_decision_source "$GLUERUN_ROOT"`.
- Quarantine authority preserved: when the durable decision log has a `.quarantined` sibling (or is itself a `*.quarantined` path), it is excluded from BOTH the injected packet and the recorded manifest, because the extra flows through the assembler's existing `gluerun_ctx_artifact_exclude` composition — the leaf performs no quarantine filtering of its own.
- Determinism: identical `run_dir` bytes, decision-log bytes, and `GLUERUN_ROOT` yield byte-identical injected packet and event data.
- OFF-parity (rehydrate flag): with `GLUERUN_REHYDRATE` unset, no `rehydrate` run occurs; `$active_prompt` and the recorded event data are byte-identical to the durable-only behavior (the decision-record extra is never introduced).
- Minimal delegation: each l1-drive site computes the spec via `gluerun_ctx_rehydrate_decision_source` and passes it expanded to the integrated sources resolver / event builder; no path, relevance, rendering, or hashing logic is inlined into `engine/l1-drive.sh`.
- Gate candidate: with this integrated, every durable-artifact class the stage file enumerates for `rehydrate-path` (task context packet, implementer/reviewer capsules, findings + assumption ledgers, critique records, AND relevant decision records) is resolved into both the injected packet and the recorded manifest — closing the last core durable-source coverage gap. This contributes to a `rehydrate-path` gate candidate but does not declare the node complete.

## Context packet

Decisions:

- Close the gap by supplying the `decision-record=<path>` extra at BOTH l1-drive rehydrate sites (the injection hook and the strategy-event record), because the assembler ranks `decision-record` (rank 6) and the resolver delegates it to the caller as an extra, yet no caller supplies it — so the enumerated class is silently absent from every real rehydrate packet and manifest. Basis: `engine/ctx-rehydrate.sh:104`, `engine/ctx-rehydrate-sources.sh:31-32`, `engine/l1-drive.sh:429` and `:539` (both pass no extras).
- Both sites pass the IDENTICAL spec via the same pure `gluerun_ctx_rehydrate_decision_source "$GLUERUN_ROOT"`, so the injected<->recorded consistency invariant holds by construction (the same invariant the authored track's TASK-0063/0065 established). Basis: consistency invariant.
- Resolve the durable orchestration decision log `docs/orchestration/decisions.md` under `GLUERUN_ROOT` as the "relevant decision records" source, with the assembler's per-section cap bounding it — it is the only durable file that IS the decision log, and the task context packet's own `Decisions:` subsection is already carried by the `task-packet` source (rank 0), so this class is the distinct repo-level decision record. Basis: `engine/ctx-rehydrate.sh` rank slots; repo layout.
- Bundle the leaf and its two-site wire-in into ONE task rather than leaf-then-wire-in across two, so the leaf is wired-in from birth and never leaves a standalone present-but-uncalled invariant for a later task to flip — directly applying the operator's TASK-0067 amend-scope lesson. Basis: `docs/orchestration/decisions.md` 2026-07-12 amend-scope entry, lesson (b), and the CHAINED-SLICE bundling rule.

Assumptions:

- [validated] `gluerun_ctx_rehydrate_packet` / `gluerun_ctx_rehydrate_manifest` accept `decision-record=<path>` specs, rank them (rank 6), and apply both the section cap and the quarantine exclusion via `gluerun_ctx_artifact_exclude` — basis: `engine/ctx-rehydrate.sh:66-73,104`.
- [validated] `gluerun_ctx_rehydrate_sources <run_dir> [extra…]` appends caller extras verbatim, and `gluerun_ctx_rehydrate_event_data <…> <run_dir> [extra…]` forwards its trailing extras into that resolver — basis: `engine/ctx-rehydrate-sources.sh:75-79`, `engine/ctx-rehydrate-event.sh:57`.
- [validated] Both rehydrate sites are in `engine/l1-drive.sh` and fire only when `worker_strategy == rehydrate` (behind `GLUERUN_REHYDRATE`) — basis: `engine/l1-drive.sh:428-429` and `:531-540`.
- [validated] `docs/orchestration/decisions.md` exists under `GLUERUN_ROOT` as the durable decision log, and `GLUERUN_ROOT` is in scope in `engine/l1-drive.sh` — basis: repo listing; `engine/l1-drive.sh` GLUERUN_ROOT usage.
- [open] "relevant decision records" is satisfied by the whole durable decision log bounded by the existing section cap; finer per-task or per-node relevance narrowing is a DELIBERATE non-goal for this slice — the gap being closed is the total absence of the class, not its granularity. The implementer must NOT gold-plate a relevance filter here.

Rejected alternatives:

- Inlining the decision-record path resolution directly into `engine/l1-drive.sh` — rejected: path/existence resolution is logic that belongs in a pure, unit-testable `ctx-*.sh` leaf per planner-contract rule 2; every other rehydrate source concern is already a pure leaf.
- Splitting the leaf and the wire-in into two separate tasks (leaf-then-wire-in) — rejected: it re-creates the standalone present-but-uncalled temporal invariant that TASK-0067 tripped on and forced an operator amend-scope; bundling wires the leaf from birth, which is the CHAINED-SLICE rule's intent for small dependent same-node slices.
- Wiring only the injection site or only the event site — rejected: it desyncs the injected packet from the recorded manifest, breaking the consistency invariant; both must carry the identical `decision-record` spec.
- Building a per-task relevance filter over `decisions.md` now — rejected: no clean task-keyed relevance signal exists in the dated ops log, it would add real complexity, and it risks the over-decomposition the operator decision log explicitly flags for this node; the section cap is the sanctioned bound.
