## Objective

Advance executable DAG node `metrics-extract` (stage `S0-baseline`, layer `harness`, kind `harness`) to its exit gate by shipping its second and final slice: the sanctioned `cli/singular metrics` subcommand that delegates read-only into the already-integrated `engine/ctx-metrics.sh` extractor (`singular_ctx_metrics_json`). TASK-0002 shipped the extractor; this slice wires the node-owned `cli/singular` hook so `singular metrics --json` emits the extractor's documented per-task and aggregate JSON.

Per the planner contract, `cli/singular` is a scarce driver-file hook and node `metrics-extract` is the node that owns it (dag.v0.json: “Read-only metrics extractor; owns the cli/singular hook.”). This slice adds only a small call-site `metrics)` dispatch case plus its usage line; it delegates entirely into the integrated `singular_ctx_metrics_json` function and introduces no new metric logic. The subcommand is a new, read-only, additive surface: every pre-existing `singular` invocation dispatches exactly as before, so behavior for all other commands is byte-identical.

The subcommand must be runnable over fixture inputs — a fixture runs dir (`runs/<runId>/attempts/index.json`) and a fixture events file — without reading or writing any real `.singular-state`, so the strict-first test can pin its bytes.

## Acceptance Criteria

- Strict test-first: `tests/test-ctx-metrics-cli.sh` is authored and fails (red) before the `metrics` subcommand exists (`singular metrics` resolves as an unknown command), then passes (green) after the hook is added.
- Delegation, not reimplementation: `singular metrics --json` emits exactly the JSON produced by the integrated `singular_ctx_metrics_json` extractor over the same fixture runs dir and events file — byte-identical stdout, `schema` value `singular.orchestration.ctx-metrics.v0`, sorted keys, trailing newline — and the subcommand adds no metric computation of its own.
- Fixture-scoped and read-only: the test points the subcommand at a temp fixture runs dir and events file and asserts the fixture inputs are byte-unchanged after the run; no real `.singular-state` run artifact, index, or event is read or written.
- Empty/missing inputs fail safe: `singular metrics --json` against an absent or empty runs dir and/or events file emits a well-formed metrics object with zeroed counts and exits 0, never an error or crash (mirroring the extractor's fail-safe contract).
- Additive/byte-identical dispatch: the `metrics)` case is purely additive; every other `singular` subcommand and the unknown-command and `help`/usage paths for non-metrics input dispatch identically to before, and `metrics` is listed in `usage()`.
- No knob, no schema churn: the new subcommand is read-only measurement and needs no `SINGULAR_*` feature flag; this task adds or modifies no file under `schemas/` and touches neither `engine/lib.sh` nor `engine/ctx-metrics.sh`.
- Gate candidate: `bash tests/run.sh` is green including the new `tests/test-ctx-metrics-cli.sh` and the existing `tests/test-ctx-metrics.sh`, and `tests/test-engine-clean.sh` stays green (no project-specific symbols added to `engine/`). Together with the integrated extractor this satisfies node `metrics-extract`'s exit gate — `singular metrics --json` produces stable, documented fields from fixtures — and this task proposes that gate candidate but declares neither the node nor the area complete.
