## Objective

Advance the `experiment-run` executable DAG node (layer `evaluation`) with its operator-facing CLI surface. The full raw-metrics engine suite is integrated — `singular_ctx_experiment_summary_json` (TASK-0083 umbrella bundle: escape-rate/cost/bias + strategy + attempts), `singular_ctx_experiment_delta_json` (TASK-0089 treatment-vs-control arm delta), and `singular_ctx_experiment_pipeline_md` (TASK-0087 corpus-to-report-tables markdown) — but there is NO `singular` command to invoke them; an operator must source engine internals. This task adds that command, mirroring the integrated `singular graph` / `SINGULAR_CTX_GRAPH` hook (TASK-0088) EXACTLY: a flag-gated dispatch arm plus flag-gated help line plus a `cmd_` function that sources the suite in ctx-loader order and forwards to the integrated entry points, reached ONLY when `SINGULAR_CTX_EXPERIMENT=1`. It is a small call-site hook that DELEGATES; it adds no metric logic in `cli/singular`. It does NOT run the paired-audited A/B experiment, author `docs/context-build-plan/experiment-report.md`, or record per-knob default decisions in `docs/orchestration/decisions.md` — all OPERATOR authority (kind: evaluation). It neither declares nor gates node completion.

Implement the following small, ordered call-site edits in `cli/singular`, plus a new test:

1. `cmd_experiment_report()`: resolve the engine home, verify `engine/ctx-experiment-summary.sh` exists (else a clear error), source the `engine/ctx-experiment-*.sh` modules in the SAME sorted order the ctx-loader uses (so no definition is shadowed), resolve sensible runs/events/metrics defaults from `SINGULAR_RUNS_DIR` / `SINGULAR_EVENTS_FILE` / the experiment metrics-file env, then dispatch sub-subcommands forwarding to the integrated functions: `summary` to `singular_ctx_experiment_summary_json`, `delta` to `singular_ctx_experiment_delta_json`, `tables` to `singular_ctx_experiment_pipeline_md`, each threading optional positional corpus args; an unknown sub-subcommand is a clear usage error. Structurally mirrors `cmd_graph`.

2. Flag-gated help line: the `experiment-report` usage line appears in `singular help` ONLY when `SINGULAR_CTX_EXPERIMENT=1`, exactly as the graph line is gated on `SINGULAR_CTX_GRAPH`.

3. Dispatch arm: route `experiment-report` to `cmd_experiment_report` ONLY when `SINGULAR_CTX_EXPERIMENT=1`; otherwise it is an unknown command exactly as before the hook existed (OFF-parity), mirroring the graph dispatch arm.

## Context packet

### Decisions

- Mirror the integrated TASK-0088 `singular graph` / `SINGULAR_CTX_GRAPH` hook exactly (flag-gated dispatch arm + flag-gated help line + a `cmd_` function that sources the suite in ctx-loader order and forwards), so the experiment CLI surface is symmetric, default-OFF, and byte-identical when the flag is unset.
- Delegate only: the CLI forwards to the integrated `summary_json` / `delta_json` / `pipeline_md` entry points and adds NO metric logic in `cli/singular`, keeping every measurement single-sourced in `engine/`.

### Rejected alternatives

- Deferring the CLI hook to `polish-release` — rejected: polish-release DOCUMENTS the CLI; the owning node builds its hook, exactly as metrics-extract built `singular metrics` (TASK-0003) and graph-projector built `singular graph` (TASK-0088).
- Adding a new `engine/ctx-*.sh` entry instead of a CLI hook — rejected: the engine entry points already exist and are integrated; the only missing surface is the operator-facing command, which lives in `cli/singular`.

### Assumptions

- [validated] `singular_ctx_experiment_summary_json`, `singular_ctx_experiment_delta_json`, and `singular_ctx_experiment_pipeline_md` are integrated and each accept positional corpus args with env fallbacks — basis: the public entry points of engine/ctx-experiment-summary.sh, engine/ctx-experiment-delta.sh, engine/ctx-experiment-pipeline.sh.
- [validated] `cli/singular` already exposes the flag-gated subcommand pattern to mirror: `cmd_graph` sources engine/ctx-graph*.sh in sorted order and the `graph` dispatch arm and help line are gated on `SINGULAR_CTX_GRAPH` — basis: cli/singular cmd_graph, its dispatch arm, and the gated help line.
- [open] The engine-home resolution and ctx-loader-order sourcing used by `cmd_graph` is the pattern to reuse for sourcing engine/ctx-experiment-*.sh; the hook must not re-source in a different order that could shadow definitions — basis: cmd_graph sources the sibling suite in sorted order.
