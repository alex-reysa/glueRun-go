## Objective

Advance the explicitly-OPTIONAL authored-knowledge manifest ingestion of the executable DAG node `rehydrate-path` (stage `S5-routing`, layer `engine_runtime`) by supplying the one `load-when` trigger dimension the track designed for but left inert: the run's executable DAG node.

TASK-0064's pure builder `gluerun_ctx_rehydrate_authored_triggers <role> <step> [node] [task]` accepts an optional `[node]` slot, but its two live consumers wired in by TASK-0065 — the injection at `engine/l1-drive.sh:469` and the manifest-record at `engine/ctx-rehydrate-event.sh:89` — both pass only `implementer implement "$task_id"`, omitting the node dimension because a run's DAG node is not readily in scope at either site (TASK-0065 explicitly deferred it). Consequently any authored entry whose `load-when` targets a node/stage (e.g. `["rehydrate-path"]`) can never become eligible, and the builder's `[node]` parameter is dead.

This slice is the first, PURE half of closing that gap, following the track's leaf-then-wire-in rhythm: a new read-only `engine/ctx-rehydrate-authored-node.sh` defining `gluerun_ctx_rehydrate_authored_node <task_id> [worktree]`, which deterministically resolves the executable DAG node that owns `<task_id>` from the durable task->node association in the control-state event log (the same durable convention TASK-0032's locator reads), printing the node id when present and unambiguous and printing nothing (fail-safe) when the association is absent or ambiguous. Like every prior leaf in this track it DEFINES a new function only and is present-but-uncalled by every engine/CLI/driver path, so with it sourced by the lib.sh `ctx-*.sh` loader block the engine stays byte-identical (`test-engine-clean.sh` green).

The later consumer — a separate follow-up wire-in that threads this resolver's output into the `[node]` slot of `gluerun_ctx_rehydrate_authored_triggers` at BOTH call sites — is OUT OF SCOPE here, because that wire-in touches existing driver files under the full-suite gate and adds an event-builder parameter, and the planner chained-slice rule routes such a risky driver change to its own task. This slice is NOT part of the `rehydrate-path` node's requiredCompletion (TASK-0051-0057, already integrated) and does NOT gate the node; completion and gate promotion are operator authority and are not claimed here (node `rehydrate-path`, layer `engine_runtime`).

## Acceptance Criteria

- `tests/test-ctx-rehydrate-authored-node.sh` is written FIRST and fails (red) before `engine/ctx-rehydrate-authored-node.sh` defines the function, then passes (green) after; `bash tests/test-ctx-rehydrate-authored-node.sh && bash tests/test-engine-clean.sh` is green.
- Resolution: given a fixture control-state event log (`GLUERUN_EVENTS_FILE`) in which `<task_id>` is associated with exactly one distinct non-empty node (events carrying `data.taskId` + `data.node`), `gluerun_ctx_rehydrate_authored_node <task_id>` prints exactly that node id and nothing else, rc 0.
- Fail-safe on ambiguity: when the log associates `<task_id>` with two or more distinct non-empty nodes, the function prints nothing (empty output) and returns rc 0 — never a fabricated or arbitrarily first-matched node.
- Fail-safe on absence: when no event associates `<task_id>` with any node (or the log is missing/empty), the function prints nothing and returns rc 0, so an empty node token contributes nothing to a later trigger set (consistent with TASK-0064's rule that absent optional arguments contribute nothing).
- Determinism: identical event-log bytes and task id yield byte-identical output across invocations.
- Pure and READ-ONLY: the function reads the event log only; it writes, renames, and deletes nothing, appends no events, and never exits non-zero on well-formed or malformed input (fail-soft — malformed event lines are skipped, not fatal).
- Present-but-uncalled / OFF-parity: no existing engine/CLI/driver path calls the new function; with the file sourced by the lib.sh `ctx-*.sh` loader block the engine is byte-identical to prior behavior and `bash tests/test-engine-clean.sh` is green.
- Scope discipline: the two trigger call sites (`engine/l1-drive.sh`, `engine/ctx-rehydrate-event.sh`) and the builder (`engine/ctx-rehydrate-authored-triggers.sh`) are NOT modified in this task; threading this resolver into the `[node]` slot is the separate follow-up wire-in, so this leaf by itself changes no injected packet and no recorded manifest.
- The file header contract names the executable DAG node `rehydrate-path` and layer `engine_runtime`, and states that node-scoped authored `load-when` matching becomes functional only once the follow-up wire-in lands.
- Gate candidate: with this resolver present, the run's node token exists as a pure, fixture-tested primitive for the follow-up wire-in that will make node-scoped authored `load-when` matching live; this refines the OPTIONAL authored-knowledge feature and does not gate the node.

## Context packet

Decisions:

- Ship the node resolver as its OWN pure new-file leaf and DEFER the driver wire-in, rather than folding both into one task — the wire-in touches two existing driver files (`engine/l1-drive.sh`, `engine/ctx-rehydrate-event.sh`) under the full-suite gate and must add an event-builder parameter, which the planner chained-slice rule says must land alone; every dimension of this track (selector, eligible, packet, config, triggers) has been a separate pure leaf first. Basis: planner-contract minimal-driver-hook rule + chained-slice carve-out.
- Resolve the node from the durable task->node association in the control-state event log (the mechanism TASK-0032's `gluerun_ctx_critic_recheck_locate_node` already proves works), not by re-parsing `dag.v0.json` or the task file — the event-log association is the durable, host-recorded source of truth for which executable node owns a task. Basis: TASK-0032 locator convention.
- Fail SAFE to empty on any ambiguity or absence, never a fabricated or first-match node — an empty `[node]` token contributes nothing to TASK-0064's trigger set (backward compatible), whereas a wrong node token could inject an unintended authored entry. Basis: authored-knowledge conservatism + TASK-0064 empty-arg semantics.

Assumptions:

- [validated] `gluerun_ctx_rehydrate_authored_triggers` accepts an optional `[node]` in position 3 and emits nothing for an empty node, so an empty resolver result is a no-op at the future call sites — basis: `engine/ctx-rehydrate-authored-triggers.sh` source.
- [validated] The durable task->node association is recorded in the control-state event log with `data.taskId` + `data.node` and is readable read-only via `GLUERUN_EVENTS_FILE` — basis: TASK-0032 `ctx-critic-recheck-locate.sh` header contract.
- [validated] Both trigger call sites currently pass `implementer implement "$task_id"` and omit the node dimension — basis: `engine/l1-drive.sh:469`, `engine/ctx-rehydrate-event.sh:89`.
- [open] The token authored `load-when` entries target for the node dimension is the executable DAG node id (e.g. `rehydrate-path`) rather than the stage or area id — the implementer must keep the resolver emitting the DAG node id so it matches the builder's `[node]` slot, and the follow-up wire-in plus its fixture manifests must agree on this token.

Rejected alternatives:

- Reusing `gluerun_ctx_critic_recheck_locate_node` directly at the future call sites instead of a rehydrate-path-owned resolver — rejected: it couples `rehydrate-path` to plancritic's `critic-carryover` file; no slice in this track reuses another node's ctx function, and a dedicated leaf keeps the dependency inside the node's own namespace (the shared thing is the event-log convention, not the function symbol).
- Folding the wire-in into this task (threading node at both driver sites now) — rejected: it touches existing driver files under the full-suite gate and adds an event-builder param, which the chained-slice rule routes to a separate task; keeping this leaf pure preserves the cheap own-test gate.
- Resolving the node by re-parsing `dag.v0.json` or the task-file header — rejected: the event-log task->node association is the durable host-recorded source of truth and the already-proven convention (TASK-0032); re-deriving risks disagreeing with what the host actually recorded.
