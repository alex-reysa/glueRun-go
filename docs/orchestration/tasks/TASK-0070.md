Depends on: []

## Objective

Harden the "manifest recorded in strategy events" clause of the executable DAG node `rehydrate-path` (stage `S5-routing`, layer `engine_runtime`) `requiredCompletion` by giving its two emitted manifest contracts the backing additive JSON Schemas the repo convention requires. The rehydrate path records manifests into the `context.strategy_selected` event under two versioned contract ids — `gluerun.orchestration.ctx-rehydrate-manifest.v0` (the core durable-source manifest: `{schema, sources:[{id, sha256}...]}`, with the optional additive `authored` key merged in by TASK-0063) and `gluerun.orchestration.ctx-rehydrate-authored-manifest.v0` (the config-gated authored-knowledge manifest, each entry carrying `class:"authored-knowledge"` / `authoritative:false`) — yet NEITHER has a file under `schemas/orchestration/`, while every other versioned contract in that directory (audit-verdict, dag, decider-verdict, gate-result, l1-lease, lock, state-packet, task-batch) does. The contracts are therefore emitted-but-unspecified and unvalidated: nothing pins their shape, and the Stage 6 graph and Stage 7 eval consumers that will read these manifests have no schema to bind to.

The core `requiredCompletion` behavior and the composed end-to-end guard are already integrated (TASK-0051-0069); this slice adds contract artifacts only and changes NO engine behavior (the engine stays byte-identical; `test-engine-clean.sh` green). It bundles three small, related deliverables in order:

1. `schemas/orchestration/ctx-rehydrate-manifest.v0.schema.json` — an additive JSON Schema (draft 2020-12, matching the sibling schema style) describing the CORE manifest exactly as `gluerun_ctx_rehydrate_manifest` / `gluerun_ctx_rehydrate_event_data` emit it: a `schema` const, a `sources` array of `{id, sha256}` objects, and the OPTIONAL additive `authored` object — written so a payload WITHOUT `authored` (durable-only) and one WITH it both validate (additive, backward-compatible).
2. `schemas/orchestration/ctx-rehydrate-authored-manifest.v0.schema.json` — an additive JSON Schema describing the authored-knowledge manifest exactly as the integrated config-gated authored manifest function emits it, pinning per-entry `id`, `sha256`, `class` (const `authored-knowledge`) and `authoritative` (const `false`) so the schema can never certify an authored entry as authoritative.
3. `tests/test-ctx-rehydrate-manifest-schema.sh` — a strict-test-first conformance guard that drives the actual emitters over fixtures and asserts the emitted bytes conform to the two schemas, and that the schemas are additive.

The schemas must be faithful to the REAL emitted bytes (the test enforces this by validating live emitter output, not a hand-written sample), so the implementer reads the emitters (`engine/ctx-rehydrate.sh`, `engine/ctx-rehydrate-event.sh`, and the authored manifest composer) before authoring the schema shapes. This slice does not declare the node complete; completion and gate promotion are operator authority.

## Acceptance Criteria

- `tests/test-ctx-rehydrate-manifest-schema.sh` is written FIRST and fails (red) before the two schema files exist (the schema files are absent, so validation cannot resolve them), then passes (green) after they are authored; `bash tests/test-ctx-rehydrate-manifest-schema.sh && bash tests/test-engine-clean.sh` is green.
- Core-manifest conformance: the exact bytes emitted by `gluerun_ctx_rehydrate_manifest` over a representative fixture source set (multiple `id`/`sha256` sources in the assembler's fixed order) validate against `schemas/orchestration/ctx-rehydrate-manifest.v0.schema.json`, and its `schema` const equals `gluerun.orchestration.ctx-rehydrate-manifest.v0`.
- Empty-source robustness: the well-formed empty-source manifest (`sources: []`) also validates against the core schema.
- Additive `authored` key: a core-manifest payload carrying the optional merged `authored` object (the TASK-0063 shape) validates, AND a payload WITHOUT it also validates — proving the schema is additive and backward-compatible.
- Authored-manifest conformance: the exact bytes emitted by the integrated config-gated authored-knowledge manifest function over a fixture `contextManifest` validate against `schemas/orchestration/ctx-rehydrate-authored-manifest.v0.schema.json`, its `schema` const equals `gluerun.orchestration.ctx-rehydrate-authored-manifest.v0`, and the schema pins every entry's `class` to the const `authored-knowledge` and `authoritative` to the const `false` (a mutated fixture entry with `authoritative: true` is REJECTED by the schema).
- Faithful-to-emitter: the conformance assertions validate LIVE emitter output (not a hand-authored sample), so a schema that diverges from what the engine actually emits fails the test.
- No behavior change / OFF-parity: only schema files and a test are added; no engine/CLI/driver file is modified, so `bash tests/test-engine-clean.sh` is green and all feature flags remain byte-identical when off.
- Additive-schema discipline: both schema files are new and additive (they describe already-emitted data and constrain no emitter), honoring the planner contract's additive-schema rule.
- Gate candidate: with the two rehydrate manifest contracts schematized and guarded against their live emitters, the `manifest recorded in strategy events` clause of the `rehydrate-path` `requiredCompletion` is backed by a validated additive contract that downstream Stage 6 / Stage 7 consumers can bind to. Proposed toward the node's gate candidate; this task does not declare the node or area complete.

## Context packet

Decisions:

- Schematize BOTH manifest contracts (core and authored) plus one conformance test in a single task, because they are small, related, mutually independent artifacts within the slice budget and share one test harness; splitting them would pay per-task overhead the operator decision log already flags for this node. Basis: folding rule; over-decomposition lesson.
- Enforce fidelity by validating LIVE emitter output rather than a hand-authored fixture, so the schema cannot silently diverge from `engine/ctx-rehydrate*.sh`. Basis: the schemas exist to pin the real contract, not a paraphrase.
- Keep the schemas additive (optional `authored` key, forward-compatible) so existing durable-only payloads and future enriched payloads both validate — the same additive discipline every emitter on this path already follows. Basis: planner-contract additive-schema rule; TASK-0063 merged `authored` key.

Assumptions:

- [validated] The rehydrate path emits exactly two versioned manifest schema ids — `gluerun.orchestration.ctx-rehydrate-manifest.v0` and `gluerun.orchestration.ctx-rehydrate-authored-manifest.v0` — and neither has a file under `schemas/orchestration/` — basis: grep of `engine/ctx-rehydrate*.sh` schema strings vs `schemas/orchestration/` listing.
- [validated] The core manifest shape is `{schema, sources:[{id, sha256}...]}` with an optional additive `authored` object merged in — basis: `engine/ctx-rehydrate-event.sh` and `engine/ctx-rehydrate.sh`.
- [validated] Authored manifest entries carry `class:"authored-knowledge"` and `authoritative:false` and must never be certifiable as authoritative — basis: `engine/ctx-rehydrate-authored-packet.sh`.
- [open] A JSON-schema validation mechanism is available to the test (the repo's existing schema-validation path, or `python3` with `jsonschema`, or a `python3`-driven structural check over the schema's `required`/`type`/`const`); the implementer must use whichever the repo already relies on rather than adding a new heavyweight dependency, and must NOT modify any engine file to do so.

Rejected alternatives:

- Refusing to plan / declaring the node complete — rejected: completion and gate promotion are operator authority, and the gate-race lesson warns against a premature `behaviorally complete` refusal while a concrete in-scope gap (here, two emitted-but-unschematized `...v0` contracts) is still on the table.
- Another authored-knowledge or driver micro-slice — rejected: that track and the durable-source coverage are complete, and a schema-contract artifact is a distinct deliverable class, not more manifest-chain leaf-chasing.
- Extending secret-scan coverage to the injected decision log — rejected: `docs/orchestration/decisions.md` is human-authored repo content outside the model-authored-artifact scan threat model, and any such change is owned by the `artifact-secret-scan` node, not `rehydrate-path`.
- Modifying the emitters to reference or enforce the schema at runtime — rejected: it would change engine behavior and break OFF-parity byte-identity; the contract is pinned by a test-time conformance guard, keeping the schemas purely additive.
