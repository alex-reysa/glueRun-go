## Objective

Advance the executable DAG node `critique-import-gate` (stage `S2-plan-critique`, area `plancritic`, layer `engine_runtime`, kind runtime) toward its required completion — L0 import honors critique verdicts behind `GLUERUN_PLAN_CRITIQUE` (default 0 = observe-only), ON enforces approve/revise/park and fails closed on missing record — by adding a new, present-but-uncalled `engine/ctx-critique-import.sh` that provides the pure critique-import gate DECISION the L0 importer will consult.

The already-integrated driver `engine/ctx-plan-critic.sh` (TASK-0013) persists the critique as `plan-critique.json` next to a node's staged candidates and records the `plan.critiqued` / `ctx.plan_critique_infra` events. This brick reads that persisted record together with the `GLUERUN_PLAN_CRITIQUE` knob and returns the import disposition, without touching the import path itself. The `reconcile.sh` / L0 import call-site hook that CONSUMES this decision — emitting `origin.l1_import_rejected` with reason `plan-critique`, handling the node lease as planning-failed so the frontier can be re-planned, and keeping the OFF path byte-identical — is the follow-up slice for this same `critique-import-gate` node and is out of scope here.

The file defines NEW functions only and is invoked by NO existing engine path, so with it present-but-uncalled the engine is byte-identical to prior behavior (mirroring `engine/ctx-plan-critic.sh` and `engine/ctx-paired-audit.sh`). It never owns `engine/lib.sh` and adds no driver-file hook, honoring the new-file (`engine/ctx-*.sh`) convention and the scarce-driver-hook rule.

Decision semantics, gated on `GLUERUN_PLAN_CRITIQUE` (default 0):

- OFF (unset or `0`): observe-only — the decision is always `import` regardless of the recorded verdict or a missing record, so wiring it OFF leaves the import path byte-identical to today; the critique may still be recorded but its verdict is not enforced.
- ON (`=1`): enforce the persisted verdict — `approve` imports; `revise` or `park` reject (disposition reason `plan-critique`), candidates NOT imported; a missing, unreadable, or schema-invalid critique record, or a verdict outside `approve|revise|park`, fails CLOSED to reject, never imports.

Pure and read-only (evidence invariance): the function reads only the persisted critique record and the knob; it appends NO events, spawns no runner, and mutates nothing — the disposition event and lease handling belong to the follow-up wiring slice. The gate is an added enforcement layer over the skeptic read-only critique and never weakens, resumes into, or bypasses the un-bypassable implementation auditor.
