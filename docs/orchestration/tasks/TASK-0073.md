## Objective

Harden the executable DAG node `graph-contract` (stage `S6-graph`, layer `contract`, single-slice) so its `requiredCompletion` clause — `schema validates fixtures; ... suite green` — stays durable as the stage advances. The integrated contract deliverable `tests/test-context-graph-schema.sh` carries a temporal negative-assertion guard that directly violates planner-contract rule 9 (`No temporal negative assertions in tests`) and that both TASK-0071's and TASK-0072's context packets explicitly declared forbidden, yet it shipped anyway.

The offending block is the `pure-projection guard` (the three lines under the `pure-projection guard` comment, ~lines 303-305): it computes `wired` via `grep -rl` for `context-graph.v0.schema.json` under `engine/` and `cli/` and `fail`s unless that grep is empty. This is a classic absence / present-but-uncalled assertion: it is true only until the next node legitimately lands. The DAG has `graph-projector` (`dependsOn: graph-contract`) shipping `engine/ctx-graph.sh`, whose whole job is to read this schema — the instant it references `context-graph.v0.schema.json` this guard turns the FULL SUITE red at integrate. That is precisely the failure mode rule 9 cites (`have twice broken integration`).

This is a CONTRACT-hardening slice on the node's own single owned test file only: no schema change (taxonomy already complete and green), no fixtures change, no mapping-doc change, no projector, no CLI, no engine wiring, no feature flag. It removes the forbidden guard and pins the pure-projection intent positively instead.

One cohesive slice, strict-test-first, in implementation order:

1.
