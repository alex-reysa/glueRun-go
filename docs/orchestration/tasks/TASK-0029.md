## Objective

Advance the executable DAG node `critic-carryover` (stage `S3-plan-revision`, area `plancritic`, layer `engine_runtime`, kind `runtime`) with its next smallest strict-test-first brick: the fail-closed RESUME AUTHORITY that decides whether the post-acceptance recheck may RESUME the persisted plan-critic session read-only over the accepted diff, enforcing the skeptic role gate (this session may never be resumed as planner/implementer), plus the record-only strategy provenance emitter.

The integrated slices establish the two ends of the recheck: TASK-0027 (`engine/ctx-critic-recheck.sh`) decides WHETHER an accepted task is sampled behind default-OFF `GLUERUN_CRITIC_RECHECK_PCT`; TASK-0028 (`engine/ctx-critic-recheck-classify.sh`) classifies the resumed critic's self-report into per-finding `addressed | survives | obsolete` and emits `ctx.critic_recheck`. What is still missing — and named as the OUT OF SCOPE follow-up in both files' headers — is the authority that SAFELY RESUMES the plan-critic session for that recheck. This brick supplies it as the post-acceptance-recheck sibling of the integrated in-loop re-critique decider `gluerun_plan_recritic_resume_decide` (TASK-0025), exactly as the codebase already carries parallel resume deciders for the planner (TASK-0009) and the critic re-critique (TASK-0025). It is a DIFFERENT engagement — the ACCEPTED diff (not revised candidates), gated by `GLUERUN_CRITIC_RECHECK_PCT` (not `GLUERUN_PLAN_RECRITIC_RESUME`), destined for the `l1-drive.sh` post-acceptance hook (not the in-loop `l1-plan-node.sh` revision loop) — so it advances the stage rather than duplicating TASK-0025.

Add a new `engine/ctx-critic-recheck-resume.sh`, auto-sourced by the existing ctx-loader glob in `lib.sh` (the `engine/ctx-*.sh` convention — this task does NOT own or edit `lib.sh`). It defines NEW functions only; NO existing engine path invokes them, so with the file present-but-uncalled the engine is byte-identical to prior behavior (mirroring TASK-0025 / TASK-0027 / TASK-0028). It resolves the SAME persisted plan-critic session-meta the plan-critic driver finalizes (role `plan-critic`, under the runtime state dir), adds no driver-file hook, invokes no runner, writes no state other than the one provenance event the recorder appends, and never owns `engine/lib.sh`.

Public entry points:

- `gluerun_ctx_critic_recheck_resume_decide <critic_session_meta> <node> <runner_basename> <worktree> <lineage_head>` — prints EXACTLY one line `resume <sessionId>` or `fresh <reason>`, never exits non-zero. Ordered fail-closed gates, the FIRST failing gate naming the reason: (1) `disabled` — `GLUERUN_CRITIC_RECHECK_PCT` unset / `0` / non-numeric (feature default 0 = OFF); (2) `no-session` — meta missing/unparseable; (3) `no-session-id` — empty provider or sessionId; (4) `role-mismatch` — meta role is not exactly `plan-critic` (the SKEPTIC role gate: a planner/implementer-role session may NEVER be resumed for a recheck); (5) `node-mismatch` — meta.node != target node; (6) `head-rewritten` — meta.headShaAtCreate is NOT an ancestor of the accepted-diff lineage head; (7) `runner-changed` — runner basename differs; (8) `prompt-template-changed` — meta.promptSha256 != sha256 of the critic base-prompt TEMPLATE; (9) `expired` — age > `GLUERUN_SESSION_MAX_AGE_SEC` or missing createdAt; (10) `worktree-moved` — meta.cwd != worktree; (11) `leased` — a LIVE plan-critic session-lease is held. Only when EVERY gate passes does it print `resume <sessionId>`. Any ambiguity (missing/unparseable meta, indeterminate ancestry, empty field, a lease whose holder cannot be proven dead) resolves to `fresh <reason>`, NEVER to resume. Pure decision — appends no event, mutates nothing.
- `gluerun_ctx_critic_recheck_record_strategy <node> <run_id> <task_id> <strategy> <reason> [session_id]` — records ONLY: emits EXACTLY ONE role=`plan-critic` `context.strategy_selected` event through `gluerun_append_event` carrying `node`, `runId`, `taskId` (the accepted task being rechecked), `strategy` (`resume` or `fresh`), the exact `reason`, and `sessionId` on resume — so a recheck that re-enters the same critic session is observable to `ctx-metrics.sh`. No lease change, no runner, no outcome mutation.

The decider resolves the critic prompt TEMPLATE path and the per-node plan-critic session-lease path via small pure helpers (override `GLUERUN_PLAN_CRITIC_TEMPLATE`; default under the runtime orch/state dirs). To keep the S2 contract gate (`tests/test-plan-critique-schema.sh`) and `tests/test-engine-clean.sh` green, the `plan-critic.md` prompt filename MUST be assembled from parts (never written as a contiguous literal), mirroring `engine/ctx-plan-recritic-resume.sh`.

Advocate/skeptic line + evidence invariance: these functions decide and record ONLY. Every gate fails closed; routing never weakens a gate to make a fresh-required decision resumable, never lets a resumed (tainted) critic session satisfy an independence-required step, never makes the fresh implementation auditor bypassable, and never changes any accept/reject outcome. The whole recheck stays default-OFF behind `GLUERUN_CRITIC_RECHECK_PCT`. The read-only critic-resume RUNNER that consults this decider + the sampling gate (TASK-0027) and feeds the classifier/recorder (TASK-0028), and the `l1-drive.sh` post-acceptance hook, are the sanctioned follow-up slices of `critic-carryover` and are OUT OF SCOPE here.

## Acceptance Criteria

- `engine/ctx-critic-recheck-resume.sh` is auto-sourced by the ctx-loader glob in `lib.sh` and defines NEW functions only; no existing engine path calls them, so the engine is byte-identical to prior behavior when the file is present-but-uncalled (advances node `critic-carryover`, layer `engine_runtime`).
