## Objective

Advance the executable DAG node `assumption-ledger` (layer `engine_runtime`, stage
`S4-context-packets`) with the pure attempt-open assembler that ties the integrated
pieces into one call the later flag-gated driver hook consumes — the composition step
behind the `requiredCompletion` headline "flows into fix and audit prompts". The seed
(`gluerun_ctx_assumptions_seed`), carry (`gluerun_ctx_assumptions_carry`), and fix/audit
render (`gluerun_ctx_assumptions_fix_section` / `_audit_section`) are all integrated.
This slice ships a new `engine/ctx-assumptions-assemble.sh` with a helper
`gluerun_ctx_assumptions_assemble <task-file> <prior-ledger-json>` that computes the
current attempt's input ledger as carry(prior, seed(task-file)) and renders both
prompt sections from it, returning a single envelope JSON carrying the `ledger`, the
`fixSection`, and the `auditSection`.

The assembler is the attempt-OPEN path: at attempt open there are no current-attempt
findings yet — the prior ledger already encodes the previous attempt's host-derived
transitions — so it composes seed, carry, and render but NOT the transition (the
already-integrated `gluerun_ctx_assumptions_transition` is applied at attempt-close by
the later driver hook). It is read-only on the task file; its only possible side
effect is the underlying packet parser's single `ctx.packet_malformed` warning,
inherited via the seed and never re-emitted. Like its siblings the file is
auto-sourced by the ctx loader block yet called by no default engine/CLI/driver path,
so behavior under `GLUERUN_CTX_PACKET=0` stays byte-identical. This slice does NOT
touch driver files, does NOT inject into any prompt, does NOT record the capsule, and
does NOT add or consult the flag — those are the later driver-hook slice.

## Context packet

### Decisions

- The assembler is the attempt-OPEN composition (seed→carry→render): at attempt open there are no current-attempt findings yet — the prior ledger already encodes the previous attempt's host-derived transitions — so it needs seed, carry, and render but not transition.
- The envelope carries `ledger` alongside the rendered sections so the later driver hook has one call producing both what to inject (the sections) and what to record in the capsule (the per-attempt ledger).
- The envelope emits its schema const inline (no separate `schemas/` file), matching how the seed/transition/render ledger consts are shipped — keeps the slice to two files.

### Assumptions

- [validated] the attempt-close fold is the already-integrated `gluerun_ctx_assumptions_transition`, invoked by the later driver hook after the auditor runs to update the ledger that carries to the next attempt; this slice composes only the attempt-open path — engine/ctx-assumptions-transition.sh.
- [open] the flag-gated driver hook that injects `fixSection`/`auditSection` into the real implementer/auditor prompts and records the `ledger` in the implementer capsule is the LATER slice for `assumption-ledger`; this slice must not touch driver files, must not add or consult `GLUERUN_CTX_PACKET`, and must not inject into any prompt — stage-4 node wire-in bullets.

### Rejected alternatives

- Applying `gluerun_ctx_assumptions_transition` inside the assembler — at attempt open there are no current-attempt findings, so folding transition in here would be a no-op or conflate the open and close lifecycle points; transition stays at attempt-close.
- A separate capsule-fragment producer brick — the per-attempt ledger IS the status record the capsule needs, so the envelope's `ledger` covers it without an extra artifact.

### Inspected symbols

- `gluerun_ctx_assumptions_carry` — the sticky-violation merge the assembler applies over the fresh seed to build the current attempt's input ledger; its prior-ledger argument is what the driver hook persists between attempts.
