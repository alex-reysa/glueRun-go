## Objective

Advance the executable DAG node `subgraph-rehydrate` (stage `S6-graph`, layer
`engine_runtime`) with its first, smallest strict-test-first brick: a NEW pure,
read-only, deterministic SUBGRAPH SELECTION reader in
`engine/ctx-rehydrate-subgraph.sh`. Given a graph dir and a task node id, it
walks the provenance lineage of that task node — its plan version, surviving
critique findings, open assumptions, contradiction flags — and emits the
DETERMINISTIC, ORDERED set of SELECTED node records, with (1) rejected
observations excluded and (2) contradiction-flagged nodes surfaced first. This
replaces flat per-artifact concatenation with rule-based lineage selection; no
relevance scoring (v0 rule).

This slice SELECTS only. It composes the integrated graph read API
(`gluerun_graph_query_lineage` and `gluerun_graph_query_open_contradictions` in
`engine/ctx-graph-query.sh`) over the materialized corpus
(`<graphDir>/nodes.jsonl` + `edges.jsonl`). Because a raw lineage walk follows
the provenance taxonomy that INCLUDES `rejects_observation`, the selector must
post-filter nodes reached only through a `rejects_observation` edge so rejected
observations never enter the selection. Contradiction targets from
`gluerun_graph_query_open_contradictions` (open `contradicts`/`invalidates`
edges with no superseding resolution) are emitted FIRST, then the remaining
selected lineage nodes in a deterministic order.

It does NOT resolve selected nodes to durable artifact paths, assemble the
packet, touch section caps, or record any manifest — the assembler that maps the
selection onto `gluerun_ctx_rehydrate_packet`/`_manifest` (caps and manifest
UNCHANGED) and the A/B arm wire-in are separate later slices for this node.

Feature-flag discipline: the file DEFINES new functions only and no existing
engine/CLI/driver path invokes it, so the engine is byte-identical with it
sourced (OFF-parity; the graph flag `GLUERUN_CTX_GRAPH` and the rehydrate arm
knobs gate the later wire-in, not this pure reader).

Evidence invariance / advocate-skeptic line: selection is a pure read — it never
writes, never mutates taint, confers NO independence on a resumed/rehydrated
session, and records nothing as `authoritative`. It only chooses and orders
existing records.

## Acceptance Criteria

- Over a hand-authored fixture corpus (`nodes.jsonl` + `edges.jsonl` conforming
  to `schemas/context-graph.v0.schema.json`) with a deep
  task -> attempt -> plan-version -> critique -> finding lineage, selecting from
  the task node emits exactly the lineage-reachable selected node records —
  byte-identical across repeated runs and independent of on-disk record order
  (deterministic, rule-based; no relevance scoring).
- A finding/observation reached only through a `rejects_observation` edge (a
  rejected observation) is EXCLUDED from the selection.
- Nodes flagged by an open contradiction (targets of `contradicts`/
  `invalidates` edges not resolved by any `supersedes` edge, per
  `gluerun_graph_query_open_contradictions`) are surfaced FIRST in the emitted
  order, ahead of the remaining selected lineage nodes.
- Section caps and the rehydration manifest are UNCHANGED: this slice emits only
  the selection and neither truncates bodies nor writes a manifest (those remain
  the province of the integrated `engine/ctx-rehydrate.sh`).
- With no graph corpus present (missing/empty `nodes.jsonl`/`edges.jsonl`) the
  selector yields a well-formed EMPTY selection and exits zero (fail-safe).
- OFF-parity: with the new file sourced but uncalled, the engine is
  byte-identical to prior behavior.
- `tests/test-ctx-rehydrate-subgraph.sh` is red before implementation and green
  after; `tests/test-engine-clean.sh` stays green (no project-specific symbols
  in `engine/`).

## Context packet

Decisions:
- New file `engine/ctx-rehydrate-subgraph.sh`, not an edit to
  `engine/ctx-rehydrate.sh` — why: new-file convention (planner-contract rule
  1), and editing the pre-existing assembler would force the full-suite gate and
  couple the selection core to the flat renderer; this stays a scoped-gate leaf.
- Emit selected node records/ids only, not resolved artifact paths or a packet —
  why: artifact-source resolution + packet/manifest assembly is a separate
  chained slice, and "caps and manifests unchanged" is satisfied by not touching
  them here.
- Ordering is rule-based: contradictions first, then deterministic lineage order
  — why: stage-6 forbids relevance scoring in v0.

Assumptions:
- [validated] `gluerun_graph_query_lineage` is an undirected provenance walk
  whose taxonomy includes `rejects_observation` — basis: the PROVENANCE set in
  `engine/ctx-graph-query.sh`; hence rejected observations are reachable and MUST
  be post-filtered by this selector, not by the walk.
- [validated] open contradictions are `contradicts`/`invalidates` edges whose
  `to` node is not superseded — basis:
  `gluerun_graph_query_open_contradictions`.
- [open] the fixture corpus is authored by hand as canonical `nodes.jsonl` +
  `edges.jsonl` using only existing context-graph.v0 node/edge types — basis:
  the integrated graph-query tests already build such fixtures; the worker must
  not invent new node or edge types.

Rejected alternatives:
- Inlining selection into `engine/ctx-rehydrate.sh` — why-not: full-suite gate,
  scope coupling, violates the new-file convention.
- Scoring/ranking the subgraph by relevance — why-not: stage-6 pins v0 selection
  to deterministic lineage + open-status rules only.

Inspected symbols:
- `gluerun_graph_query_lineage` — role: supplies the reachable lineage node set,
  but INCLUDES rejects_observation edges, so the selector owns the rejected-
  observation exclusion.
- `gluerun_ctx_rehydrate_packet` RANK order (`engine/ctx-rehydrate.sh`) — role:
  the fixed source-class emission order the LATER assembler slice must preserve;
  noted only so this selection layer's contradictions-first order composes with
  it later, NOT to widen this slice.
