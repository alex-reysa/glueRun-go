## Objective

Advance the `experiment-run` executable DAG node (layer `evaluation`) with the composed end-to-end requiredCompletion guard for the raw-metrics measurement half, plus the single explicit-corpus operator entry it pins. The full per-family aggregator + summary-merge + markdown-render suite is integrated: TASK-0077 `engine/ctx-experiment-report.sh` (escape-rate/cost/bias), TASK-0079 `engine/ctx-experiment-strategy.sh` (resume/rehydrate hit rates + gate-refusal reason mix), TASK-0081 `engine/ctx-experiment-attempts.sh` (attempts-to-accept + findings-per-attempt), TASK-0083 `engine/ctx-experiment-summary.sh` (`gluerun_ctx_experiment_summary_json` umbrella merge), and TASK-0085 `engine/ctx-experiment-render.sh` (`gluerun_ctx_experiment_render_md` tables). Each is unit-tested, but NO test walks a live runs/events corpus through the whole pipeline to the rendered report tables, and there is no single entry that takes explicit corpus paths (render_md accepts a pre-built bundle source or env defaults, not positional runs/events args). This task closes both gaps. It does NOT run the A/B experiment, author `docs/context-build-plan/experiment-report.md`, or record per-knob default decisions in `docs/orchestration/decisions.md` — all OPERATOR authority (kind: evaluation). It neither declares nor gates node completion.

The new entry lands in one NEW `engine/ctx-experiment-pipeline.sh`, auto-sourced by the ctx-loader block and defining a new function only. No existing engine path invokes it, so the engine is byte-identical with the file present (OFF-parity intrinsic, mirroring the sibling `engine/ctx-experiment-*.sh` idiom). It does NOT edit the five sibling `ctx-experiment-*.sh` files, `engine/ctx-metrics.sh`, or any other pre-existing file. It DELEGATES only — building the bundle via `gluerun_ctx_experiment_summary_json` and rendering via `gluerun_ctx_experiment_render_md`; it computes no metric, reclassifies nothing, and creates, moves, or mutates nothing (it threads the bundle to the renderer through the renderer's in-memory bundle-source input, writing no temp file).

Implement two chained slices in order:

1. Explicit-corpus pipeline entry `gluerun_ctx_experiment_pipeline_md [runs_dir] [events_file] [metrics_file]` in `engine/ctx-experiment-pipeline.sh`: thread the explicit corpus args through `gluerun_ctx_experiment_summary_json` to obtain the bundle, then render it through `gluerun_ctx_experiment_render_md` (fed the in-memory bundle, no file written), emitting the full report-metrics markdown to stdout. Read-only; fail-safe zeroed tables on an empty corpus; deterministic.

2. End-to-end requiredCompletion guard `tests/test-ctx-experiment-pipeline.sh`: construct a synthetic runs/events corpus exercising BOTH arms across all metric families — `ctx.arm_assigned` for A and B, `ctx.paired_audit` with and without disagreements, `ctx.critic_recheck` dispositions, `context.strategy_selected` (resume/rehydrate/fresh) plus `context.resume_failed`, and attempts indexes carrying per-attempt `findings` — then drive `gluerun_ctx_experiment_pipeline_md` over it and assert the whole walk in one guard.

## Acceptance Criteria

- `tests/test-ctx-experiment-pipeline.sh` is red before implementation (the new `gluerun_ctx_experiment_pipeline_md` does not yet exist) and green after; the gate command is green.
- Given the synthetic both-arm corpus, `gluerun_ctx_experiment_pipeline_md` with explicit `runs_dir`/`events_file` args emits a deterministic markdown fragment whose tables carry the expected per-arm escape-rate, cost, attempts-to-accept, findings-per-attempt, bias, and resume/rehydrate hit-rate + gate-refusal reason-mix values for arms A and B — the full raw-events-to-report-tables walk validated in one guard.
- The emitted markdown is byte-identical to feeding the same corpus through `gluerun_ctx_experiment_summary_json` and `gluerun_ctx_experiment_render_md` directly (delegation is loss-preserving; no recomputation), and byte-identical across repeated runs on the same corpus (determinism).
- Evidence invariance / advocate-skeptic line: the guard asserts that a context-aware `ctx.critic_recheck` disposition of `addressed` never removes a fresh `ctx.paired_audit` escape flag from the rendered escape counts.
- An empty corpus (no runs, empty events) yields well-formed zeroed tables and a zero exit (fail-safe), never an error or partial output.
- Strictly read-only: the guard asserts the walk creates, moves, or mutates no run artifact, index, event, lease, or task file, writes no `docs/context-build-plan/experiment-report.md`, and edits none of the sibling `ctx-experiment-*.sh` files or `engine/ctx-metrics.sh`. No test contains a temporal negative / present-but-uncalled assertion (planner-contract rule 9); read-only and OFF-parity guarantees are pinned behaviorally over the corpus, not by absence greps.
- `tests/test-engine-clean.sh` stays green (no project-specific symbols in `engine/`; the entry is generic over the corpus and bundle shape).
- Gate candidate (does not itself complete the node): this guard is the green end-to-end evidence that the escape-rate, cost, and bias measurements plus the secondary and strategy metrics render correctly from a paired-audited both-arm corpus — the raw-metrics artifacts `experiment-run`'s exit gate requires `experiment-report.md` to reference; node completion still requires the operator to run the paired-audited A/B experiment across both arms and record per-knob default decisions in `docs/orchestration/decisions.md`.

## Context packet

### Decisions

- Add an explicit-corpus entry `gluerun_ctx_experiment_pipeline_md [runs_dir] [events_file] [metrics_file]` rather than relying on `gluerun_ctx_experiment_render_md`'s env-default delegation, so the operator (and the guard) can drive the pipeline over a chosen corpus with positional args — matching the explicit-args signature every sibling composer already uses — without mutating environment or writing an intermediate bundle file.
- Thread the bundle to the renderer in memory (through its documented bundle-source input) rather than via a temp file, preserving the strict read-only contract shared by the whole `ctx-experiment-*` suite.

### Rejected alternatives

- A test-only guard with no new entry — rejected: it would be green on arrival (nothing to drive red-then-green), violating strict-test-first; pinning the walk to a genuinely new single entry gives a real red log and a stable operator surface.
- A `gluerun experiment-report` CLI subcommand — rejected here: it would own `cli/gluerun` (a pre-existing driver file, forcing the full-suite gate) and CLI coverage belongs to the `polish-release` node, not `experiment-run`.

### Assumptions

- [validated] `gluerun_ctx_experiment_summary_json [runs_dir] [events_file] [metrics_file]` builds the umbrella bundle and `gluerun_ctx_experiment_render_md` renders a bundle (delegating to the summary composer when given no source) — basis: engine/ctx-experiment-summary.sh and engine/ctx-experiment-render.sh public entry points.
- [open] The renderer's in-memory bundle-source convention (stdin `-` versus a passed argument) is whatever TASK-0085 shipped; the entry feeds the bundle through that documented input without writing a file — basis: engine/ctx-experiment-render.sh entry signature.
