## Objective

Advance the executable DAG node `assumption-ledger` (layer `engine_runtime`, stage
`S4-context-packets`) with its foundational brick: a new, pure, read-only
`engine/ctx-assumptions.sh` that seeds a per-run assumption ledger from a task's
context packet. This is the data-structure slice the later wire-in slices (fix/audit
prompt injection behind `GLUERUN_CTX_PACKET`, per-attempt carry, host-derived status
transitions) build on. It ships a helper `gluerun_ctx_assumptions_seed <task-file>`
that composes the already-integrated `gluerun_ctx_packet_json` parser and emits a
normalized ledger JSON. Like `engine/ctx-packet.sh`, the file is auto-sourced by the
ctx loader block yet called by no default engine/CLI/driver path, so behavior under
`GLUERUN_CTX_PACKET=0` stays byte-identical. This slice does NOT touch driver files,
does NOT inject anything into prompts, and does NOT add the flag — those are later
slices for this node.

Each seeded assumption gets a stable, deterministic id (`A1`, `A2`, … over the
packet's declared order) so a later host-derived transition — an auditor finding that
references an assumption's id — has a fixed anchor. The seed preserves each
assumption's declared `status` (open/validated/violated), `claim`, and `basis`.

## Acceptance Criteria

- `bash tests/test-ctx-assumptions.sh` passes and `bash tests/test-engine-clean.sh` stays green (the task's gate command).
- `gluerun_ctx_assumptions_seed <task-file>` reads the task STRICTLY READ-ONLY (composing the integrated `gluerun_ctx_packet_json`) and prints a normalized per-run assumption ledger JSON whose `schema` const is `gluerun.orchestration.ctx-assumptions.v0` and whose `assumptions` is an array.
- For a task whose context packet declares assumptions, each ledger entry carries a stable positional id (`A1`, `A2`, … in the packet's declared order) and preserves that assumption's `status` (one of open|validated|violated), `claim`, and `basis`; the id is the anchor later host-derived transitions reference.
- A task with no `## Context packet` block, an empty packet (`{}`), or a packet with zero assumptions seeds a stable empty ledger `{"schema":"gluerun.orchestration.ctx-assumptions.v0","assumptions":[]}`.
- Deterministic: identical input yields byte-identical stdout across repeated runs; assumption order and ids are a pure function of the packet's declared order.
- Read-only and side-effect-free on well-formed input: the task file is byte-identical before and after seeding, and seeding a well-formed packet appends no events. A malformed packet fails closed through the underlying parser (empty ledger; the parser's single `ctx.packet_malformed` warning is the parser's, not re-emitted by the seed).
- OFF byte-identical: `engine/ctx-assumptions.sh` is auto-sourced by the ctx loader block (lib.sh) yet invoked by no default engine/CLI/driver path, so runs under `GLUERUN_CTX_PACKET=0` are unchanged. Proposed node-gate candidate (NOT declared here): full suite green plus a stub retry run showing the ledger flowing into fix and audit prompts remains for the later wire-in slices named in the stage file.

## Context packet

### Decisions

- Seed assigns stable positional ids `A1..An` over the packet's deterministic declared order — gives host-derived transitions (auditor finding → assumption id) a fixed anchor without needing a content hash.
- Seed preserves each assumption's DECLARED status rather than forcing `open` — the ledger is a starting state; later host-derived transitions move `open`→`violated`, while pre-declared validated/violated are legitimate seeds.
- `gluerun_ctx_assumptions_seed <task-file>` composes the integrated `gluerun_ctx_packet_json` instead of re-parsing markdown — one parser, one assumption grammar, one malformed path.

### Assumptions

- [validated] the ctx loader sources every `engine/ctx-*.sh` once and function bodies bind at call time, so `ctx-assumptions.sh` sorting BEFORE `ctx-packet.sh` is harmless provided the seed invokes the parser only at call time, never at file-source time — lib.sh ctx loader loop.
- [open] prompt injection, per-attempt carry, and the auditor-finding→assumption-id transition are LATER slices for `assumption-ledger`; this slice must not touch driver files, must not add `GLUERUN_CTX_PACKET`, and must not inject into any prompt — stage-4 node wire-in bullets.

### Rejected alternatives

- Content-hash assumption ids — stable across reorderings but unreadable, and unnecessary since a task file's packet order is fixed; positional ids are deterministic and human-legible.
- Shipping a `schemas/` JSON-schema file for the ledger in this slice — deferred; the ledger emits its schema const inline exactly as `engine/ctx-packet.sh` does, keeping the slice to two files.

### Inspected symbols

- `gluerun_ctx_packet_json` — the integrated tolerant packet parser the seed composes; returns normalized JSON or `{}`, and its malformed path already emits the single `ctx.packet_malformed` warning the seed inherits rather than duplicates.
