## Objective

Expose the integrated `graph-projector` (layer `engine_runtime`) engine functions as the user-facing `singular graph rebuild/sync/query` subcommand, behind `SINGULAR_CTX_GRAPH` (default 0) — the last `requiredCompletion` piece. This is the single sanctioned `cli/singular` driver-hook for this node (the stage file: the cli hook chains behind metrics-extract for that file); it touches an existing driver file, so it carries the full-suite gate and lands alone. Implement one minimal call-site hook that mirrors the integrated `cmd_metrics` delegation pattern:

- Add a `cmd_graph` delegator to `cli/singular` that sub-dispatches `rebuild [stateDir] [graphDir]` to `singular_graph_rebuild`, `sync [stateDir] [graphDir]` to `singular_graph_sync`, and `query <neighbors|lineage|open-contradictions> [args]` to the corresponding integrated `singular_graph_query_*` reader, resolving sensible stateDir/graphDir defaults and adding NO projection logic of its own.
- Add one `graph` arm to the existing command-dispatch block so `singular graph ...` reaches `cmd_graph`.
- Gate the entire subcommand behind `SINGULAR_CTX_GRAPH`: when it is unset or `0`, `singular graph ...` refuses exactly as an unknown command did before this hook, and the help/usage output is unchanged (byte-identical OFF-parity). Any `graph` usage/help line appears only when the flag is enabled.

The hook only delegates into the integrated `engine/ctx-graph*.sh` functions (auto-sourced by the ctx-loader block). This task advances `graph-projector` toward its `requiredCompletion` by making rebuild/sync/query invocable behind the flag; it proposes the full `requiredCompletion` behavior (rebuild/sync/query behind SINGULAR_CTX_GRAPH, idempotent + deterministic, rebuild equals sync, loss-free) as a gate candidate but does not declare the node complete.

## Context packet

### Decisions
- OFF-parity is preserved by gating the whole `graph` subcommand AND its help/usage line behind `SINGULAR_CTX_GRAPH`: with the flag off, typing `singular graph` hits the same unknown-command refusal as before, so `cli/singular` stays byte-identical.
- The hook is a thin delegator mirroring `cmd_metrics`: it resolves stateDir/graphDir defaults and calls the integrated `singular_graph_rebuild`/`singular_graph_sync`/`singular_graph_query_*`, keeping the driver-file footprint to a minimal call site per the planner contract's driver-hook scarcity rule.

### Assumptions
- [validated] `singular_graph_rebuild`, `singular_graph_sync`, and the `singular_graph_query_*` readers are integrated and auto-sourced via the ctx-loader block — basis: TASK-0082/0084/0086 integrated.
- [validated] `cli/singular` dispatches subcommands via a cmd-dispatch case block with per-command `cmd_*` functions and a static usage list — basis: the integrated `cmd_metrics` hook and dispatch arm.
- [open] the CLI can resolve a default state dir (e.g. `.singular-state`) to pass as the rebuild/sync stateDir — basis: the real `.singular-state` tree the engine already reads.

### Rejected alternatives
- Adding a static `graph` usage line unconditionally — rejected: it would change `singular --help` output when the flag is off, breaking OFF byte-identity; the line shows only when `SINGULAR_CTX_GRAPH` is enabled.
- Splitting rebuild/sync/query into three separate cli hooks — rejected: they share one `cmd_graph` dispatch in the same existing driver file; three tasks would each re-own `cli/singular` and pay three full-suite gates for one call site.

### Inspected symbols
- `cmd_metrics` + the command-dispatch case block (`cli/singular`): the exact pattern the graph hook mirrors — a `cmd_graph` delegator plus one `graph` dispatch arm — which is why this is a minimal call-site hook, not new logic.
