## Objective

Of the `audit-infra` emitter sites in `engine/l1-drive.sh`, the evidence-manifest and binding
sites sit OUTSIDE every inner retry loop: one transient failure of `evidence-manifest.sh`
(pre-audit build, audit refresh, or post-verdict final refresh) or of the
`gate-report bind-head`/copy step immediately terminalizes the run as `escalate-infra` — even
when the worker exited 0, the gate is green, and (for the final-refresh site) the auditor has
already produced a parseable verdict. This is the audited "double success still parks as
infrastructure" defect, and it needs no new machinery: the auditor loop directly above these
sites already demonstrates the bounded-retry pattern.

The sprint's first self-hosted audit then exposed a second deterministic failure at the same
boundary: Codex reported 283,064 cumulative input tokens, including 244,736 cached replay
tokens, and the 100,000-token evidence canary counted the cached replay as new audit input.
The auditor had completed successfully with only 38,328 uncached input tokens, but the final
manifest refresh still erased that success into `audit-infra`. This task owns the permanent
fix because retrying the same deterministic accounting cannot remedy it.

The second self-hosted wave exposed a third deterministic defect in the same acceptance
boundary. The controller's last manifest refresh runs while root `packet.json` still has
`status: needs-review`; only later does acceptance rewrite the root packet and copy it into the
inbox. The durable manifest therefore names `packet.json` but binds the archived pre-accept
bytes, not the authoritative accepted root/inbox bytes. This reproduced on every inspected
native acceptance. Acceptance stamping, the post-stamp refresh, binding verification, and inbox
publication must be one fail-closed transaction.

Required changes:

1. Wrap each of the existing four evidence-manifest/binding emitter sites plus the new
   post-acceptance-stamp manifest/binding site in a bounded retry:
   `SINGULAR_EVIDENCE_INFRA_MAX` (default 2) attempts of the failed host step only — never the
   worker, never the gate, never the auditor. Reuse the existing per-step log files so each
   retry's output is preserved (per-try suffixes, following the `audit-verify.sh` convention).
2. Only on exhaustion does the site emit its failure. The post-verdict final-refresh site must
   then emit a class that cannot erase a successful audit: after a parsed auditor verdict
   exists, exhaustion routes to `escalate-parked` (human judges the completed work) with the
   verdict artifact referenced — not `escalate-infra`, which asserts "the work is fine, the
   environment is not" while discarding a finished verdict.
3. Pre-verdict sites (manifest build, bind-head) keep `audit-infra` on exhaustion — that
   classification is correct there.
4. Make evidence-manifest canary charging provider-correct while preserving raw provider
   accounting:
   - keep `providerUsage.inputTokens` and `providerUsage.cachedInputTokens` byte-for-byte raw;
   - for Codex auditor/reviewer runner results only, charge
     `inputTokens - cachedInputTokens` when both are coherent non-negative integers and
     `cachedInputTokens <= inputTokens`;
   - if the Codex cache counter is absent or malformed, fail closed by charging raw
     `inputTokens`; every other provider continues to charge raw `inputTokens`;
   - sum charged tokens across auditor tries exactly as today, and keep the bound inclusive
     (`charged >= canary` fails).
5. When `SINGULAR_CTX_ARTIFACT_SCAN` is enabled, run a packet-only read-only secret-scan
   preflight before the acceptance stamp. Reuse the existing scanner/patterns without
   duplicating them and without renaming the canonical root. A hit or scanner error enters the
   common acceptance-finalization failure path: the root remains `needs-review`, its current
   manifest binding stays resolvable, task and lease block/park, and no inbox packet appears.
   This preflight is quiet/redacted: durable logs, events, and failure records may contain only
   stage, return code, packet path/size/SHA, and pattern label—never a matched line or packet
   bytes. The existing post-accept quarantine ordering remains unchanged for non-packet
   artifacts.
6. Before publishing an accepted packet, atomically stamp the root packet accepted, rebuild the
   manifest from those bytes, and verify that its single `packet.json` reference matches the
   root by path, size, and SHA-256; the eventual inbox copy must be byte-identical too. The
   archived attempt packet remains immutable at its pre-accept status. Only after this
   transaction succeeds may the lease/task become accepted or the inbox entry appear.
7. Treat packet preflight, stamp, post-stamp refresh, and binding verification as an explicit
   `accept-finalizing` phase. Any write/fsync/rename failure, retry exhaustion, verifier
   mismatch, or catchable interruption blocks/parks the task and lease with stage- and
   SHA-bound failure evidence and no inbox packet. The EXIT trap must never leave the lease
   `running`, emit misleading auto-heal guidance, or claim acceptance after a partial
   transaction. If failure occurs after the atomic stamp, preserve that accepted root byte-for-
   byte as inert forensic evidence rather than attempting a non-atomic packet+manifest rollback.
   The failure record must make the distinction machine-readable with
   `publicationState: "blocked-before-inbox"`, `rootPacketRole: "evidence-only"`, and
   `publishable: false`. Publishable acceptance requires the bound root+manifest, accepted task
   and lease, and byte-identical inbox copy together.
8. Apply the same transaction to deterministic recovery. `engine/accept-existing-packet.sh` and
   L1 auto-heal must not stamp controls or enqueue a recovered packet until packet-only secret
   preflight and exact accepted root/manifest/inbox binding succeed. Prefer one shared finalizer
   used by native and recovered acceptance rather than two almost-equivalent publishers. A
   recovered secret-bearing, missing, tampered, or mismatched packet blocks with no inbox/import;
   a valid recovered packet publishes exactly once with byte-identical bound evidence. Until
   this permanent path ships, operator-overlay reruns explicitly set
   `SINGULAR_AUTO_ACCEPT_EXISTING=0`.

## Acceptance Criteria

- RED first against the exact unmodified target, before any production edit: a stub making
  `evidence-manifest.sh` fail exactly once then succeed shows the current transient-failure
  terminalization at every existing site; separate behavioral fixtures reproduce FR-050's
  pre-accept packet binding, FR-052's accepted secret-bearing inbox remaining importable after
  root quarantine, and a catchable finalization interruption leaving incomplete controls. Each
  RED must fail on the behavior later corrected—not a missing helper, structural precondition,
  or TODO sentinel.
- GREEN: a single transient manifest/binding failure at any of the five sites is retried and
  the attempt proceeds; the retry count and per-try step logs are on disk.
- With a parsed auditor verdict present and the final refresh failing beyond the bound, the run
  terminalizes `escalate-parked` and the verdict artifact is still referenced from the failure
  context; the lease retryCount is unchanged.
- Worker, gate, and auditor are never re-run by these retries (spawn-recording stubs prove it).
- Existing evidence-remedy tests from TASK-0112 pass unchanged.
- Evidence-manifest tests pin all canary cases: the reproduced Codex usage
  `283064 input / 244736 cached` charges 38,328 and passes a 100,000 bound; a Codex result at
  the exact charged bound fails; malformed/missing cached counters fail closed to raw input;
  and non-Codex providers continue to fail on raw input even when they expose a cache field.
- The manifest retains the original raw aggregate provider usage so cost/accounting telemetry
  is not rewritten to the charged value.
- A successful acceptance has byte-identical accepted root and inbox packets, and the final
  manifest's sole `packet.json` entry resolves to those exact bytes/size/SHA; the archived
  attempt packet remains byte-identical and pre-accept.
- With artifact scanning enabled, a clean packet follows that successful path. A packet secret
  hit or scanner error exits through `accepted-packet-secret-scan`: root remains `needs-review`
  and manifest-bound; no current-run inbox/temp/imported packet exists; dry and actuated
  reconcile import zero current-run packets; and task/lease are blocked with SHA-bound failure
  evidence. The injected secret token is absent from every current-run log, event, failure
  record, inbox, and imported tree except the explicitly allowlisted canonical forensic root
  packet and immutable attempt archive; diagnostics never reproduce matched packet bytes.
- A clean packet accompanied by a secret-bearing non-packet artifact is not overcaptured by the
  preflight: acceptance completes with bound root/manifest/inbox, then the unchanged post-accept
  full hook quarantines only the non-packet artifact with its established event ordering.
- Exact-base deterministic-recovery REDs reproduce `accept-existing-packet.sh` stamping an
  accepted root/task/lease before an accepted-root manifest refresh and L1 auto-heal enqueuing it
  without packet-only secret preflight. GREEN: valid existing-packet recovery reuses the same
  secret/binding finalizer and publishes exactly once; secret-bearing, missing, tampered, or
  mismatched recovery evidence blocks, creates no inbox/current-run import, and dry/actuated
  reconcile imports zero.
- Deterministic injections for acceptance-stamp failure, post-stamp manifest failure, manifest
  verifier mismatch, and a catchable interruption at each finalization stage all produce no
  inbox entry, a blocked/parked task and lease, a terminal stage-specific failure record, and no
  stranded running controls or published-acceptance ambiguity. Pre-stamp failure retains a
  `needs-review` root; post-stamp failure retains an accepted but explicitly non-publishable,
  evidence-only root. Dry and actuated reconcile import zero packets in both cases, and a
  subsequent supported recovery can start normally.
