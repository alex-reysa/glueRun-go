## Objective

Advance the `experiment-run` executable DAG node (layer `evaluation`) by rendering the report's HEADLINE sections that the existing renderer omits. TASK-0085 `engine/ctx-experiment-render.sh` renders the summary bundle's per-arm ABSOLUTE tables (escape/cost/bias, strategy, attempts), but the treatment-vs-control DELTA (TASK-0089 `singular_ctx_experiment_delta_json` — the actual experiment finding: did the treatment reduce escape rate, at what cost) and the arm-integrity AUDIT (TASK-0097 `singular_ctx_experiment_armaudit_json` — whether each arm actually ran its intended knob-state, i.e. experiment validity) are not rendered as markdown anywhere. This task renders both, completing the report presentation. It emits markdown to STDOUT ONLY; it never writes `docs/context-build-plan/experiment-report.md` (an operator-owned concept), never runs the paired-audited A/B experiment, and never records per-knob default decisions in `docs/orchestration/decisions.md` — all OPERATOR authority (kind: evaluation). It neither declares nor gates node completion.

All logic lands in one NEW `engine/ctx-experiment-render-delta.sh`, auto-sourced by the ctx-loader block and defining new functions only. No existing engine path invokes them, so the engine is byte-identical with the file present (OFF-parity intrinsic, mirroring the sibling `engine/ctx-experiment-*.sh` idiom). It does NOT edit `engine/ctx-experiment-render.sh`, `cli/singular`, or any other pre-existing file. It formats the already-computed delta and audit artifacts verbatim (no recomputation) and reads or writes nothing else.

Implement three chained slices in order, all inside `engine/ctx-experiment-render-delta.sh`:

1. Treatment-effect table renderer: from the delta artifact (`singular_ctx_experiment_delta_json`), render a deterministic markdown table of each headline metric's B-minus-A delta and neutral direction — the treatment-effect summary.

2. Arm-integrity table renderer: from the audit artifact (`singular_ctx_experiment_armaudit_json`), render a per-arm consistency table carrying recorded, unrecorded, consistent, and inconsistent counts plus the flagged inconsistent runIds.

3. Composed public entry `singular_ctx_experiment_render_result_md [runs_dir] [events_file] [metrics_file]`: obtain both artifacts by delegating to their integrated json composers (threading the resolved corpus args per each composer's signature), render both sections in a stable order to stdout as one markdown fragment. Fail-safe: zeroed/empty artifacts render well-formed zero tables and a zero exit.

## Context packet

### Decisions

- Render the treatment-vs-control DELTA and the arm-integrity AUDIT, which the summary-bundle renderer (TASK-0085) does not cover: TASK-0085 renders per-arm absolutes from the summary bundle, whereas the delta (the headline finding) and the audit (experiment validity) are separate integrated artifacts with no markdown surface.
- Emit markdown to STDOUT and never write `experiment-report.md`, because that file is an operator-owned concept; the renderer is presentation tooling the operator merges, not the report author.
- Ship a SEPARATE new file rather than extending `engine/ctx-experiment-render.sh`, because that file is integrated (a pre-existing file, full-suite gate and new-file-convention friction) and avoiding it also prevents any owned-file overlap with in-flight CLI work.

### Rejected alternatives

- Extending `engine/ctx-experiment-render.sh` to add the delta/audit sections — rejected: pre-existing file (full-suite gate) and possible overlap with concurrent work; a new file keeps this additive and non-conflicting.
- Re-reading runs/events to recompute the delta or audit — rejected: both artifacts already carry every value; re-deriving would duplicate metric logic and risk drift.

### Assumptions

- [validated] `singular_ctx_experiment_delta_json` emits per-metric records with `a`, `b`, `delta`, and a neutral `direction`, and `singular_ctx_experiment_armaudit_json` emits per-arm recorded/unrecorded/consistent/inconsistent counts plus inconsistent runIds — basis: engine/ctx-experiment-delta.sh (TASK-0089) and engine/ctx-experiment-armaudit.sh (TASK-0097) public entries.
- [open] Some metrics or arms may be absent on a sparse corpus; the renderer omits an empty row rather than erroring — basis: the fail-safe contract of the sibling aggregators and renderer.
