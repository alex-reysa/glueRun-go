## Objective

Advance the executable DAG node `critic-carryover` (stage `S3-plan-revision`, area `plancritic`, layer `engine_runtime`, kind `runtime`) with the integrated-only glue brick the terminal post-acceptance hook needs: the pure, read-only LOCATOR that resolves, for an accepted task, the two inputs the recheck runner `gluerun_ctx_critic_recheck_run` (TASK-0031) requires but that are NOT available at the `l1-drive.sh` acceptance site — the executable DAG node that owns the task's critiqued batch, and the path to the prior `gluerun.orchestration.plan-critique.v0` record produced for that node at planning time.

The acceptance hook in `engine/l1-drive.sh` (alongside the integrated paired-audit hook, TASK-0006) has only `run_id`, `task_id`, `run_dir`, and `worktree` in scope — it does not carry the originating `node` nor the critique-record path. The critic session is node-keyed (`<state-dir>/sessions/plan-critic/<node>.json`, TASK-0013) and the critique record is written per node at `<stage_dir>/plan-critique.json`, so the recheck can only resume the right specialist session and classify against the right prior findings once the node and record are resolved from the accepted task. This brick supplies exactly that resolution, reading ONLY already-integrated artifacts (the durable node association recorded for the task and the plan-critique record convention). It builds on integrated work only and does NOT depend on the recheck runner (`engine/ctx-critic-recheck-run.sh`, TASK-0031, `accepted` but not yet integrated).

Add a new `engine/ctx-critic-recheck-locate.sh`, auto-sourced by the existing ctx-loader glob in `lib.sh` (the `engine/ctx-*.sh` convention — this task does NOT own or edit `lib.sh`). It defines NEW functions only; NO existing engine path invokes them, so with the file present-but-uncalled the engine is byte-identical to prior behavior (mirroring TASK-0027 / TASK-0028 / TASK-0029).

Public entry points:

- `gluerun_ctx_critic_recheck_locate_node <task_id> [worktree]` — PURE and READ-ONLY. Resolve the executable DAG node that owns the accepted task's critiqued batch by reading the durable node association recorded for the task (its task-file / packet node field or the control-state task->node mapping). Print the node id when it is present and unambiguous, else empty. Appends no event, writes no state, invokes no runner, always exits 0.
- `gluerun_ctx_critic_recheck_locate_record <node> <task_id> [worktree]` — PURE and READ-ONLY. Resolve the path to the prior plan-critique.v0 record produced for `<node>` at planning time (the durable/archived critique record for the batch that included `<task_id>`, or the node stage-dir convention `<stage_dir>/plan-critique.json`). Print the path ONLY when the file exists AND parses as a `gluerun.orchestration.plan-critique.v0` record, else empty. Appends no event, writes no state, invokes no runner, always exits 0.

Both locators fail SAFE: any ambiguity — a missing/ambiguous node association, or an absent/unparseable/wrong-schema record — resolves to EMPTY output (never a crash, never a fabricated node or path), so the terminal hook safely SKIPS the recheck and records nothing rather than misfiring. A skipped recheck mutates no accept/reject outcome, preserving evidence invariance.

Advocate/skeptic line + evidence invariance: the locators decide nothing and record nothing — they are pure read-only resolvers. They change no accept/reject outcome, weaken no gate, and never make the fresh implementation auditor bypassable. The whole recheck stays default-OFF behind `GLUERUN_CRITIC_RECHECK_PCT` (TASK-0027). The terminal `l1-drive.sh` post-acceptance hook that delegates these locators into the recheck runner (TASK-0031), self-guarded on the default-OFF knob and byte-identical when OFF, is the sanctioned follow-up slice and is OUT OF SCOPE here.
