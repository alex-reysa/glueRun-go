## Objective

Advance the `routing-module` executable DAG node (layer `engine_runtime`) by delivering the one stage-5 deliverable for the node that is not yet integrated: strategy/outcome splits per role. The strategy dispatcher (TASK-0047) and its live `engine/l1-drive.sh` wire-in (TASK-0048) now emit `context.strategy_selected` events and record per-attempt worker/reviewer strategies, and `engine/ctx-metrics.sh` already reports the marginal per-role strategy counts, the reason counts, and per-task acceptance — but nothing reports the JOINT: for each role and each strategy, how the outcomes split into accepted vs rejected. That joint is what lets the routing / A-B learning loop tell whether a `resume` decision actually pays off against a `fresh` one.

`engine/ctx-route-metrics.sh` is a new read-only extractor (planner-contract rule 1, new-file convention) that composes the already-integrated attempts index and events log WITHOUT perturbing `engine/ctx-metrics.sh`'s byte-pinned output. `singular_ctx_route_metrics_json <runs-dir> <events-file>` emits deterministic, sorted-keys JSON under the additive `singular.orchestration.ctx-route-metrics.v0` schema namespace giving per-role, per-strategy outcome splits. It is present-but-uncalled — the `singular metrics` / `engine/ctx-metrics.sh` merge is a later hook and is OUT OF SCOPE here — so the engine stays byte-identical.

## Acceptance Criteria

- `engine/ctx-route-metrics.sh` defines `singular_ctx_route_metrics_json` which, given a runs dir of attempts indexes and the events file, emits deterministic sorted-keys JSON with a stable `schema` value of `singular.orchestration.ctx-route-metrics.v0` and a trailing newline, so tests can pin the exact bytes.
- The output reports per-role (worker, reviewer) strategy-by-outcome splits: for each strategy value seen across the attempts, the count of accepted vs rejected outcomes for that role (for example `roleStrategyOutcomeSplits.worker.<strategy>.accepted` and `.rejected`), using the SAME accepted definition as `engine/ctx-metrics.sh` — a per-attempt failureClass that is empty, `accepted`, or `none` counts as accepted, anything else as rejected.
- Absent strategy fields are not counted; an empty or missing runs dir yields empty splits; the JSON is byte-deterministic for a fixed input set.
- The extractor is READ-ONLY: it appends no events, writes no files, and mutates no run artifact (mirroring `engine/ctx-metrics.sh`), and it never exits non-zero on malformed or absent inputs (it degrades to empty splits).
- `tests/test-ctx-route-metrics.sh` drives fixtures whose attempts carry varied (role strategy, outcome) combinations and asserts the joint splits, that the accepted/rejected classification matches `engine/ctx-metrics.sh`, determinism, and the empty-input case; it is red before implementation and green after. `bash tests/test-engine-clean.sh` stays green (no project-specific symbols in `engine/`).
- GATE CANDIDATE (node-level, not declared here): with this extractor integrated, `routing-module` exposes per-role strategy/outcome splits (the stage-5 deliverable `ctx-metrics.sh learns strategy/outcome splits per role`) atop the already-integrated dispatcher, window/diff gates, generalized session lease, taint independence pin, and live `l1-drive.sh` wire-in.

## Context packet

Decisions:
- Deliver the last outstanding stage-5 routing deliverable — per-role strategy/outcome splits — as a NEW read-only extractor (`engine/ctx-route-metrics.sh`) rather than editing `engine/ctx-metrics.sh`: this honors the new-file convention (rule 1), keeps `ctx-metrics.sh`'s byte-pinned output intact, and avoids reaching into the metrics-extract node's file. The `singular metrics` merge is a later hook.
- Report the JOINT strategy-by-outcome per role: the marginal per-role strategy counts, reason counts, and per-task acceptance already exist in `ctx-metrics.sh`; the joint the routing / A-B loop needs does not.
- Reuse `ctx-metrics.sh`'s accepted definition (failureClass empty / `accepted` / `none`) so the two reports agree.

Rejected alternatives:
- Editing `engine/ctx-metrics.sh` to add the joint fields inline: rejected — it perturbs that file's byte-pinned output, reaches into another node's file, and cuts against the new-file convention; a new extractor composes the same integrated inputs cleanly.
- Treating `routing-module` as complete because its requiredCompletion is integrated: rejected — completion is gate authority, not the planner's; with the gate result absent this brick advances the node's remaining stage-file deliverable while the gate is pending.
