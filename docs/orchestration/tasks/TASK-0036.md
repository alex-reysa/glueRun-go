## Objective

Advance the executable DAG node `assumption-ledger` (layer `engine_runtime`, stage
`S4-context-packets`) with its host-derived status-transition brick — the
`requiredCompletion` clause "host-derived status transitions". The integrated seed
(`singular_ctx_assumptions_seed`, engine/ctx-assumptions.sh) already emits a per-run
ledger of assumptions carrying stable positional ids `A1..An`. This slice ships a new,
pure `engine/ctx-assumptions-transition.sh` with a helper
`singular_ctx_assumptions_transition <ledger-json> <findings-json>` that updates that
ledger from an attempt's auditor findings: an auditor finding that references an
assumption's id IS the host-observable evidence the assumption was violated, so the
HOST deterministically flips that entry's status to `violated`. Model-only status
assertions that do not resolve to a ledger id are segregated into a non-authoritative
`claims` array and never move an authoritative status — this is the host/model
boundary the planner contract's evidence-invariance rule requires.

The function is a pure ledger→ledger transform: it takes the findings JSON as an
argument (it does NOT read capsules or events), so it stays independent of driver
wiring. Like the seed, the file is auto-sourced by the ctx loader block yet called by
no default engine/CLI/driver path, so behavior under `SINGULAR_CTX_PACKET=0` stays
byte-identical. This slice does NOT touch driver files, does NOT inject into any
prompt, does NOT add per-attempt carry or capsule recording, and does NOT add the
flag — those are later slices for this node.

## Context packet

### Decisions

- Host-derived authority: an auditor finding that references an assumption id IS the host-observable evidence of a violation, so the host flips that entry to `violated` deterministically — the model's own status assertion is never the authority.
- Model-only assertions (asserting a status but not resolving to a ledger id) are segregated into a non-authoritative `claims` array rather than dropped or applied — preserves the reasoning residue for later audit while keeping `assumptions` host-authoritative.
- The transition is a pure ledger→ledger transform taking findings JSON as an argument, not reading capsules/events itself — keeps this brick independent of driver wiring; the l1-drive/capsule hook that supplies real findings is a later slice.

### Assumptions

- [validated] the ledger id scheme is the stable positional `A1..An` shipped by `singular_ctx_assumptions_seed`, and findings reference those ids via an `assumptionId` field — engine/ctx-assumptions.sh seed output.
- [open] per-attempt carry (like the findings ledger), prompt/auditor injection, and the capsule recording of statuses are LATER slices for `assumption-ledger`; this slice must not touch driver files, must not add `SINGULAR_CTX_PACKET`, and must not inject into any prompt — stage-4 node wire-in bullets.
- [open] `violated` is the only host-derived target status in this brick (a referencing finding = a violation); any host-promotion to `validated` is not model-authoritative and is out of scope here — requiredCompletion parenthetical.

### Rejected alternatives

- Letting a model-asserted status flip `assumptions` directly — violates evidence invariance (a tainted/model channel would gain authoritative power over ledger status); such assertions route to `claims` instead.
- Reading auditor findings from events or capsules inside this function — couples the pure transform to driver state; findings are passed as an argument so the brick stays pure and independently testable.

### Inspected symbols

- `singular_ctx_assumptions_seed` — produces the input ledger (schema const plus stable `A1..An` ids) this transform consumes; the transform never re-seeds, it only updates statuses and appends `claims`.
