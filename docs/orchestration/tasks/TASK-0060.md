## Objective

Third slice of the stage file's explicitly-OPTIONAL authored-knowledge manifest ingestion for the executable DAG node `rehydrate-path` (stage `S5-routing`, layer `engine_runtime`). The core `requiredCompletion` behavior is already integrated (TASK-0051–0057); this OPTIONAL feature is NOT part of `requiredCompletion` and does not gate the node — completion and gate promotion are operator authority and are not claimed here. TASK-0058 (`gluerun_ctx_rehydrate_authored_select`) and TASK-0059 (`gluerun_ctx_rehydrate_authored_eligible`) reduce a fixture authored-knowledge manifest to the eligible entries as JSON Lines (`id`, `source` `body`|`path`, the `body` or `path`, `class`=`authored-knowledge`, `authoritative`=`false`, `load-when`, `freshness`).

This slice adds the pure composer that turns those eligible entries into the two artifacts the eventual wire-in will merge: an injectable capped packet SECTION and the authored MANIFEST entries recording which authored ids were injected. Introduce a new pure, read-only leaf `engine/ctx-rehydrate-authored-packet.sh` composing the integrated `select` and `eligible` leaves. It DEFINES new functions only and is present-but-uncalled by every existing engine/CLI/driver path, so with it sourced the engine stays byte-identical to current behavior. Implement and test against FIXTURE manifests only; take no dependency on the singular-brain runtime. `GLUERUN_CTX_MANIFEST` (default 0) gates the later config/driver wire-in, not this pure leaf.

Behavior of `engine/ctx-rehydrate-authored-packet.sh` (node `rehydrate-path`, layer `engine_runtime`):

- `gluerun_ctx_rehydrate_authored_render <manifest-path> [trigger ...]`: composes `gluerun_ctx_rehydrate_authored_select <manifest-path>` piped through `gluerun_ctx_rehydrate_authored_eligible [trigger ...]`, then renders each eligible entry into a labeled section (e.g. `=== authored:<id> ===`) headed by an explicit authored-knowledge / not-authoritative marker, followed by the entry body (an inline `body`, or the contents of a `path`-backed entry read READ-ONLY), each section capped at `GLUERUN_CONTEXT_SECTION_MAX_CHARS` with a stable truncation marker. Deterministic, id-sorted.
- `gluerun_ctx_rehydrate_authored_manifest <manifest-path> [trigger ...]`: emits the manifest entries for exactly the injected authored ids — a deterministic JSON sources list, each `{id, sha256, class:"authored-knowledge", authoritative:false}` over the rendered body — recording which authored entries were injected, like any other rehydration source, and never as authoritative.
- Quarantine, `description_unverified`, stale-freshness, and trigger-mismatch exclusions are inherited from the integrated `select` / `eligible` leaves; the composer introduces no content that bypasses them.
- Pure, read-only, deterministic, fail-soft: an absent, empty, or malformed manifest yields an empty section and empty manifest sources; the function writes/renames/deletes nothing, appends no events, and never exits non-zero on well-formed input.

## Acceptance Criteria

- `tests/test-ctx-rehydrate-authored-packet.sh` is written first and fails (red) before `engine/ctx-rehydrate-authored-packet.sh` exists, then passes (green) after implementation; `bash tests/test-engine-clean.sh` stays green (no project-specific symbols in `engine/`).
- Render: given a fixture manifest with a body-backed eligible entry and a path-backed eligible entry (trigger matching), `gluerun_ctx_rehydrate_authored_render <path> <trigger>` emits both as labeled `authored:<id>` sections, each headed as authored-knowledge / not authoritative, with the path-backed entry's file contents read in.
- Caps: a section whose content exceeds `GLUERUN_CONTEXT_SECTION_MAX_CHARS` is truncated to at most the cap with a stable marker; a lowered cap tightens it and the default (4000) is honored when unset.
- Manifest entries: `gluerun_ctx_rehydrate_authored_manifest` emits, for exactly the injected ids, `{id, sha256, class:"authored-knowledge", authoritative:false}`; two runs over identical bytes are identical, and changing an entry's bytes changes only that entry's hash.
- Exclusion inheritance: a `description_unverified`, stale, quarantined, or trigger-mismatched entry appears in neither the rendered section nor the manifest entries.
- Never authoritative: no rendered section or manifest entry is marked authoritative; the authored-knowledge marker is present on each.
- Determinism / purity / fail-soft: identical inputs yield byte-identical outputs; an absent or malformed manifest yields empty outputs; the function writes nothing and never exits non-zero on well-formed input.
- OFF-parity: the file only defines new functions (present-but-uncalled), so the engine is byte-identical; `GLUERUN_CTX_MANIFEST` (default 0) gates the future wire-in, not this leaf.
- Gate candidate: with this composer integrated, the authored packet section and authored manifest entries are table-tested in isolation; the sole remaining OPTIONAL slice is the `gluerun.config.json` additive `contextManifest` field plus the `GLUERUN_CTX_MANIFEST` driver wire-in that merges this authored section into the injected rehydration packet (TASK-0057) and these authored ids into the recorded packet manifest (TASK-0055 / TASK-0056). This OPTIONAL feature is NOT required for the `rehydrate-path` node exit gate, whose core behavior (`test-ctx-rehydrate.sh` green plus the full suite) is already integrated.

## Context packet

Decisions:

- Render the eligible authored entries into a packet section plus manifest entries in a pure composer leaf (composing `select` | `eligible`), deferring the `gluerun.config.json` field and the driver merge, mirroring the leaf-before-wire-in discipline; this keeps the eventual wire-in a thin merge into TASK-0057's injection and TASK-0055 / TASK-0056's manifest recording. Basis: planner-contract new-file convention and folding = 1.
- Give authored entries their own render/manifest path rather than coercing them into the `<id>=<path>` spec form of `gluerun_ctx_rehydrate_packet` / `gluerun_ctx_rehydrate_manifest`: authored entries may be body-backed (inline content, no path), which the durable-artifact assembler cannot represent. Basis: TASK-0058 emits `source` = `body` | `path`.
- Mark every rendered section and manifest entry as authored-knowledge / `authoritative=false`, carrying the class through from TASK-0058, so injected authored content is never presented as current host-verified or tainted-model evidence. Basis: singular-brain integration point 3 and planner-contract rule 8 (evidence invariance).

Assumptions:

- [validated] `gluerun_ctx_rehydrate_authored_select` piped through `gluerun_ctx_rehydrate_authored_eligible` emits JSONL entries carrying `id`, `source` (`body`|`path`), the `body` or `path`, `class`=`authored-knowledge`, `authoritative`=`false`, `load-when`, and `freshness` (TASK-0058 / TASK-0059); the composer consumes exactly that.
- [validated] `GLUERUN_CONTEXT_SECTION_MAX_CHARS` is the per-section cap (`engine/lib.sh`), reused here — no new cap knob.
- [validated] The core `rehydrate-path` `requiredCompletion` is integrated (TASK-0051–0057); this OPTIONAL slice does not gate the node.
- [open] Path-backed entries are read read-only from their declared path; quarantine exclusion already occurred in the selector, so the composer reads survivors only.

Rejected alternatives:

- Reusing `gluerun_ctx_rehydrate_packet` / `gluerun_ctx_rehydrate_manifest` by coercing authored entries into `<id>=<path>` specs — rejected: body-backed entries have no path, so a dedicated authored render is needed to handle inline bodies.
- Doing the render inline in the future config/driver wire-in — rejected: that wire-in owns `gluerun.config.json` plus existing driver files (full-suite gate); the pure composer is table-testable and keeps the wire-in a merge.
- Marking authored manifest entries authoritative to unify them with durable sources — rejected: authored-knowledge is neither host-verified nor tainted-model and must never be recorded as authoritative.
