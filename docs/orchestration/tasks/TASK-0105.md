## Objective

Advance the executable DAG node `subgraph-rehydrate` (stage `S6-graph`, layer
`engine_runtime`) by WIRING the integrated subgraph toolchain into the route
spine so a treatment-arm refused-resume step actually rehydrates from the
graph-selected packet instead of the flat capsule — the stage A/B hook made
live. The pieces exist and are integrated (arm decider
`gluerun_ctx_rehydrate_subgraph_arm_mode` from TASK-0104; assembler
`gluerun_ctx_rehydrate_subgraph_assemble` from TASK-0102), but nothing selects
them: `_gluerun_ctx_route_refuse_resume` in `engine/ctx-route.sh` still composes
only the FLAT manifest (`gluerun_ctx_rehydrate_sources` ->
`gluerun_ctx_rehydrate_manifest`).

Implement two chained slices in order:

1. New `engine/ctx-route-subgraph.sh` — the flat-vs-subgraph manifest selector
   `gluerun_ctx_route_subgraph_manifest <reason> <role> <step> <meta> <key>`. It
   prints the manifest to hand to the integrated decision leaf
   `gluerun_ctx_route_rehydrate_decide`:
     - When GLUERUN_CTX_SUBGRAPH_REHYDRATE=1 AND
       `gluerun_ctx_rehydrate_subgraph_arm_mode <key> <graphDir>` returns
       subgraph, resolve the task node id by composing the integrated identity
       primitives — node = `gluerun_graph_node_id`(`gluerun_graph_identity task
       <key>`) — and print
       `gluerun_ctx_rehydrate_subgraph_assemble <graphDir> <node> manifest`
       (contradictions-first, rejected-excluded subgraph selection). graphDir
       defaults to ${GLUERUN_CTX_GRAPH_DIR:-.gluerun-state/graph}.
     - Otherwise print the FLAT manifest via the existing composition
       (`gluerun_ctx_rehydrate_sources` over run_dir = dirname(meta) ->
       `gluerun_ctx_rehydrate_manifest`), BYTE-IDENTICAL to today.
   The integrated arm decider already re-checks the knob, the treatment arm, and
   graph-corpus presence, so this selector must not duplicate those conditions.

2. Minimal `engine/ctx-route.sh` call-site hook — thread `<key>` (the taskId the
   route contract already passes for task roles) into
   `_gluerun_ctx_route_refuse_resume` at its three call sites, and replace its
   inline flat-manifest composition with a delegating call to
   `gluerun_ctx_route_subgraph_manifest`, feeding the result to
   `gluerun_ctx_route_rehydrate_decide`. The outer GLUERUN_REHYDRATE != 1 ->
   `fresh <reason>` short-circuit and the spine one-line / no-event / tainted
   contract are unchanged.

Feature-flag discipline: GLUERUN_CTX_SUBGRAPH_REHYDRATE defaults 0, so the
selector always returns the flat manifest and the route is byte-identical to
today; the subgraph branch is reachable only with the knob on, the treatment
arm, and a present non-empty graph corpus.

Evidence invariance / advocate-skeptic line: the wire-in only chooses WHICH
manifest the existing decision leaf sees. Rehydrate stays tainted per
`gluerun_ctx_route_strategy_tainted`, confers NO independence, appends no events,
writes nothing, and never exits non-zero — the spine keeps its one-line
contract.

## Acceptance Criteria

- With GLUERUN_REHYDRATE=1 and GLUERUN_CTX_SUBGRAPH_REHYDRATE=1, for a task whose
  deterministic arm is the treatment arm and a present, non-empty graph corpus, a
  refused-resume lineage step emits `rehydrate <reason>` decided over the
  SUBGRAPH manifest (`gluerun_ctx_rehydrate_subgraph_assemble` for the task node),
  i.e. the contradictions-first, rejected-excluded selection.
- For a control-arm task, or with the subgraph knob off, or with an absent/empty
  graph corpus, the same step emits the FLAT `rehydrate`/`fresh` outcome
  byte-identical to the pre-wire-in behavior.
- OFF-parity: with GLUERUN_CTX_SUBGRAPH_REHYDRATE unset/0 the refused-resume
  outcome AND the manifest bytes are identical to the current flat path; with
  GLUERUN_REHYDRATE unset/0 the step stays `fresh <reason>` unchanged.
- The task node id is resolved deterministically as
  `gluerun_graph_node_id`(`gluerun_graph_identity task <key>`) — the exact id the
  projector assigns the task node — so the subgraph assemble targets the correct
  lineage root.
- The spine keeps its one-line, no-event contract; the rehydrate strategy stays
  tainted; nothing is written.
- Gate candidate: `tests/test-ctx-rehydrate-subgraph-route.sh` is red before the
  hook and green after; `bash tests/run.sh` (full suite — this task owns the
  existing driver file `engine/ctx-route.sh`) stays green.

## Context packet

Decisions:
- Branch logic in a new `engine/ctx-route-subgraph.sh`; `engine/ctx-route.sh`
  gets only a minimal delegating call-site hook plus key threading — why:
  planner-contract rule 2 keeps driver-file hooks scarce and minimal, delegating
  into a ctx-*.sh function.
- The flat-vs-subgraph choice reuses the integrated
  `gluerun_ctx_rehydrate_subgraph_arm_mode` (which already re-checks knob + arm +
  corpus presence) rather than re-deriving those conditions — why: a single
  source of truth for the mode avoids drift.
- Resolve the task node id by composing `gluerun_graph_identity` +
  `gluerun_graph_node_id`, not a corpus scan — why: deterministic and matches the
  projector node id exactly.

Assumptions:
- [validated] the route contract passes `<key>` == taskId for task roles into
  `gluerun_ctx_route` — basis: engine/ctx-route.sh line 29 and
  engine/ctx-route-drive.sh; the hook threads key into
  `_gluerun_ctx_route_refuse_resume` (today it receives only reason/role/step/meta).
- [validated] `gluerun_ctx_rehydrate_subgraph_arm_mode` returns subgraph only
  when GLUERUN_CTX_SUBGRAPH_REHYDRATE=1, the treatment arm is selected, and the
  corpus is present — basis: engine/ctx-rehydrate-subgraph-arm.sh (TASK-0104).
- [validated] `gluerun_graph_node_id`(`gluerun_graph_identity task <taskId>`) is
  the id the projector assigns the task node — basis:
  engine/ctx-graph-project-records.sh `gluerun_graph_project_task`.
- [open] the flat manifest produced by the relocated composition is
  byte-identical to the current inline composition — basis: OFF-parity requires
  it; the worker MUST NOT alter the flat path bytes.

Rejected alternatives:
- Inlining the subgraph branch directly in `_gluerun_ctx_route_refuse_resume` —
  why-not: rule 2 keeps driver hooks minimal; the branch logic belongs in a new
  ctx-*.sh.
- Scanning nodes.jsonl to find the task node — why-not: the id is a pure
  composition of integrated primitives; a scan is slower and risks a mismatch.

Inspected symbols:
- `_gluerun_ctx_route_refuse_resume` (engine/ctx-route.sh) — role: the single
  refused-resume hook site (three call sites: session-lease, window-pressure,
  diff-volume) that currently composes the FLAT manifest; the wire-in threads
  key here and delegates manifest selection.
- `gluerun_ctx_rehydrate_subgraph_arm_mode` (engine/ctx-rehydrate-subgraph-arm.sh)
  — role: the integrated mode authority; the wire-in must not duplicate its
  knob/arm/corpus checks.
