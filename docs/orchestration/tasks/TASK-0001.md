## Objective

Advance executable DAG node `ctx-loader` (stage `S0-baseline`, layer `contract`,
kind `contract`) by adding the single guarded loader block to `engine/lib.sh` —
the ONLY `lib.sh` edit permitted in the entire context-evolution plan. The block
sources every `engine/ctx-*.sh` file exactly once, in sorted order, so every
later stage can ship context-evolution logic as new `engine/ctx-*.sh` files
without ever touching `lib.sh` again.

No `engine/ctx-*.sh` files exist yet, so this change must be byte-identical to
current runtime behavior; it only installs the structural hook. A ctx file that
fails to source must fail loudly (fail closed), never be silently skipped.

This is a `contract` node: exactly one strict-test-first slice, no folding.

## Scope

Owned files:

- `engine/lib.sh`
- `tests/test-ctx-loader.sh`

Scope notes (prose, not paths): `engine/lib.sh` receives ONE guarded loader
block near the end of the file plus a header comment documenting the
convention — all context-evolution logic lives in `engine/ctx-*.sh`, and
`lib.sh` is frozen for the rest of this plan (this node is its sole owner).
`tests/test-ctx-loader.sh` is the new strict-first test for the loader block.

Forbidden files:

- Any file outside the owned scope. Do NOT create a product `engine/ctx-*.sh`
  file in this task — the loader is proven with throwaway fixtures the test
  writes to a temp dir. No other engine, cli, schema, or driver file may change.

## Acceptance Criteria

- Strict test-first: `tests/test-ctx-loader.sh` is authored and fails (red)
  before the `lib.sh` loader block exists, then passes (green) after it is added.
- The loader block sources every present `engine/ctx-*.sh` file, in sorted order,
  exactly once, guarded so a re-source of `lib.sh` does not double-source them.
- No-files case: with zero `engine/ctx-*.sh` files, engine functions are
  unchanged and behavior is byte-identical to the pre-change engine (the test
  pins an existing engine function behaving identically with no ctx files).
- Loads case: a fixture `engine/ctx-*.sh` defining a new function makes that
  function available after `lib.sh` is sourced.
- Fails-loud case: a broken fixture `engine/ctx-*.sh` (syntax error / non-zero
  source) fails the source loudly and fails closed — sourcing `lib.sh` surfaces
  the failure and does not continue silently.
- The diff to `lib.sh` is exactly the single loader block plus its convention
  header comment — no other `lib.sh` changes.
- Gate candidate: `bash tests/run.sh` is green including the new
  `tests/test-ctx-loader.sh`, and `tests/test-engine-clean.sh` stays green (no
  project-specific symbols added to `engine/`). This mirrors node `ctx-loader`'s
  requiredCompletion and the stage-0 exit gate.
