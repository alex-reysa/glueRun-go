## Objective

Refinement slice of the stage file's explicitly-OPTIONAL authored-knowledge manifest ingestion for the executable DAG node `rehydrate-path` (stage `S5-routing`, layer `engine_runtime`). The core `requiredCompletion` behavior is fully integrated (TASK-0051–0057) and so is the authored-knowledge feature end to end (TASK-0058–0063); this slice does NOT gate the node — completion and gate promotion are operator authority and are not claimed here.

TASK-0059 (`gluerun_ctx_rehydrate_authored_eligible`) matches each authored entry's `load-when` list against the trigger tokens the caller supplies. But the two live call sites — the injection wire-in (`engine/l1-drive.sh`, TASK-0062) and the manifest-record merge (`engine/ctx-rehydrate-event.sh`, TASK-0063) — both pass only the single hardcoded literal `implement`. As a result, an authored entry whose `load-when` targets any other dimension (a role, a node/stage, or a specific task) can never become eligible: the `load-when` matcher is functionally inert for everything except `implement`.

This slice adds the pure token-set builder that closes that gap. Introduce a new pure, read-only leaf `engine/ctx-rehydrate-authored-triggers.sh` that DEFINES a new function only and is present-but-uncalled by every existing engine/CLI/driver path, so with it sourced the engine stays byte-identical to current behavior. A follow-up slice will substitute the hardcoded `implement` at the two call sites with this set (owning those existing files). Fixture-only; no singular-brain runtime dependency.

Behavior of `engine/ctx-rehydrate-authored-triggers.sh` (node `rehydrate-path`, layer `engine_runtime`) — a function such as `gluerun_ctx_rehydrate_authored_triggers <role> <step> [node] [task-id]`:

- Emits a deterministic, order-stable, de-duplicated set of `load-when` trigger tokens for the run (one per line), drawn from the run's identifying dimensions: the role (e.g. `implementer`), the step (e.g. `implement`), and, when supplied, the node (e.g. `rehydrate-path`) and the task id (e.g. `TASK-0063`).
- Backward-compatible: the literal `implement` token is included whenever the step is `implement`, so existing `implement`-scoped authored entries keep matching once the follow-up wire-in lands.
- Absent optional arguments (empty node / task id) contribute nothing — no empty tokens.
- Pure, read-only, deterministic: it names the run's dimensions only, reads no config or manifest, writes/renames/deletes nothing, appends no events, and never exits non-zero on well-formed input.

The end-to-end feature stays gated by `GLUERUN_CTX_MANIFEST` (default 0) via the config gate (TASK-0061); this leaf is inert until the follow-up wire-in feeds its output to `gluerun_ctx_rehydrate_authored_config_render` / `gluerun_ctx_rehydrate_authored_config_manifest`.

## Context packet

Decisions:

- Build the run's `load-when` trigger set in a pure leaf so TASK-0059's matcher — which today only ever receives the literal `implement` from TASK-0062 / TASK-0063 — can match on role / step / node / task dimensions; without it, authored entries whose `load-when` targets anything other than `implement` are structurally inert. Basis: `engine/l1-drive.sh:457` and TASK-0063 both pass only `implement`, while TASK-0059 matches whatever triggers it is given.
- Include the literal `implement` token whenever the step is `implement`, so existing `implement`-scoped authored entries keep matching after the follow-up wire-in (backward compatible). Basis: the TASK-0062 / TASK-0063 trigger.
- Keep it a pure token-set builder (no config or manifest reads); it only names the run's structured dimensions. The wire-in that feeds this set to the config-gated authored functions is a later slice owning the existing driver files. Basis: planner-contract new-file convention and minimal driver hooks.

Assumptions:

- [validated] `gluerun_ctx_rehydrate_authored_eligible` matches an entry's `load-when` list against the trigger arguments supplied by the caller (TASK-0059); the two live call sites currently pass only `implement` (TASK-0062 / TASK-0063).
- [validated] The core `rehydrate-path` `requiredCompletion` is integrated (TASK-0051–0057); this slice refines the OPTIONAL authored feature and does not gate the node.
- [open] The trigger token vocabulary (role / step / node / task id) — pick a documented, deterministic set; the follow-up wire-in supplies the concrete values from the `engine/l1-drive.sh` run context.

Rejected alternatives:

- Leaving the hardcoded `implement` in place — rejected: it makes TASK-0059's `load-when` matching inert for any non-`implement` trigger, so most authored entries can never load.
- Wiring the enriched triggers directly into `engine/l1-drive.sh` / `engine/ctx-rehydrate-event.sh` now — rejected: that owns existing driver files (full-suite gate); the pure token-set builder is the smaller first brick and keeps the eventual wire-in a two-line substitution.
- Deriving triggers from free-form task text — rejected: non-deterministic; use the run's structured dimensions (role / step / node / task id).
