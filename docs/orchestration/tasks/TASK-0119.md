## Objective

`singular test` (the embedded Python in `cli/singular`, `singular_test_py`) already contains
every hard property of a supervised job, battle-tested: atomic durable manifest
(tmp+`os.replace`), kernel `flock` as the liveness oracle (shared-lock probe; EPERM-safe),
attach with log drain and exit-code mirroring, `progress.jsonl`, `setsid` process-group
ownership with a 300 s recency-bounded reap, and interrupted-state reconciliation ordered
reap-before-count. But it is welded to one caller: the suite path is hardcoded to the engine's
own `tests/run.sh`, there is no `cancel`, the attach loop has no bounded wait, and nothing else
can import it. Gates duplicate a worse spawn/poll/kill by hand.

Required changes:

1. Extract the machinery into importable host-owned `engine/supervised_job.py`, preserving the
   proven semantics EXACTLY (flock probe, atomic writes, pipe start-handshake, close_fds lock
   hygiene, reap recency bound, reconcile ordering). Parameterize the supervised command
   (argv array, cwd, env allowlist, run-dir root) instead of the hardcoded suite.
2. Add the two missing verbs:
   - `cancel <job>`: reap the job's process group via the existing guarded reap path and
     reconcile the manifest to `cancelled` (new enum member alongside `interrupted`);
   - bounded `wait`: `attach --timeout-sec N` returns a distinct exit code on deadline without
     touching the job.
3. Job manifest: new `schemas/job.v0.schema.json` (`singular.orchestration.job.v0`), a
   generalization of `test-run.v0` (command argv, cwd hash, env-allowlist hash, workspace,
   pgid, status incl. `cancelled`, exitCode, timestamps, `reconciledBy`). Keep
   `schemas/test-run.v0.schema.json` untouched.
4. Re-base `cmd_test` in `cli/singular` onto the module with a parity contract: every
   assertion in `tests/test-cli-test-run.sh` passes unmodified, and `singular test`'s user
   surface (flags, output, run-dir layout, `current.json`) is byte-compatible.
5. No consumer-specific vocabulary in the module (it must pass `tests/test-engine-clean.sh`);
   phases/progress strings remain opaque.
