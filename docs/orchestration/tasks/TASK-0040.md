## Objective

Complete the executable DAG node `assumption-ledger` (layer `engine_runtime`, stage
`S4-context-packets`) with its terminal driver wire-in — the piece that makes the
`requiredCompletion` true: the per-run assumption ledger seeded from the context
packet flows into the fix and audit prompts behind `SINGULAR_CTX_PACKET` (default 0),
host-derived status transitions are applied across attempts, and behavior is
byte-identical when OFF. All pure bricks are integrated —
`singular_ctx_assumptions_seed`, `_carry`, `_transition`, the fix/audit render
(`_fix_section` / `_audit_section`), and the attempt-open envelope
`singular_ctx_assumptions_assemble`. This slice adds MINIMAL, flag-guarded call sites
to `engine/l1-drive.sh`, chained AFTER the existing paired-audit (TASK-0006) and
critic-recheck (TASK-0033) hooks so this node's l1-drive.sh ownership does not collide
with theirs. Each site delegates into the integrated functions; the driver adds no
rendering of its own.

- Attempt-open: call `singular_ctx_assumptions_assemble` on the task file and the
  per-run prior ledger (read from the run_dir sidecar `assumptions-ledger.json`, empty
  on attempt 1), then inject the envelope's `fixSection` into the implementer's
  already-rendered active/fix prompt (around the fix-prompt render site) and its
  `auditSection` into the per-attempt auditor prompt `active_audit_prompt` (around the
  re-audit render site), before each runner reads its prompt file.
- Attempt-close: after a parseable auditor verdict, fold the auditor findings (the
  injected auditSection instructs the auditor to cite assumption ids) via
  `singular_ctx_assumptions_transition` and persist the updated ledger back to the
  sidecar, so the NEXT attempt's assemble carries sticky `violated` statuses.
- Record the per-attempt ledger (assumption statuses) alongside the implementer
  capsule write, additively and non-fatally.

With `SINGULAR_CTX_PACKET` unset or `0`, none of these run and l1-drive.sh stays
byte-identical.

- ON injection: with `SINGULAR_CTX_PACKET=1` and a task whose context packet declares assumptions, the implementer's active/fix prompt gains the assembled `fixSection` (violated assumptions surfaced like open findings) and the auditor's `active_audit_prompt` gains the assembled `auditSection` (verify assumptions; flag violations as findings citing the assumption id) — injected purely by delegating to `singular_ctx_assumptions_assemble`, the driver adding only the call site.
- Host-derived transitions wired across attempts: on a stubbed retry run, an auditor finding citing an assumption id in attempt 1 flips that assumption to `violated` via `singular_ctx_assumptions_transition`, the ledger is persisted to the run_dir `assumptions-ledger.json` sidecar, and attempt 2's assembled `fixSection` shows that assumption as `violated` (sticky carry). - Fail-closed: if assemble or transition errors, the attempt proceeds without injection (non-fatal), preserving the run.
- Evidence invariance preserved: the auditor still runs on `SINGULAR_RUNNER_BIN` (cross-model independence intact); the injected auditSection is additive context and opens no path for a resumed/tainted session to satisfy an independence-required step, and no gate is weakened.

## Context packet

### Decisions

- The wire-in delegates only — assemble at attempt-open, transition at attempt-close — keeping the l1-drive.sh hook to minimal flag-guarded call sites chained after the paired-audit and critic-recheck hooks that already own sites in this file.
- The per-run ledger is persisted to a run_dir sidecar (`assumptions-ledger.json`) rather than threaded through the capsule, so attempt-open assemble reads the prior attempt's ledger without coupling to the capsule writer's internals.
- Injection APPENDS the assembled sections to the already-rendered active prompt files (the implementer fix prompt and the per-attempt `active_audit_prompt`) at the wire-in site, so no `templates/prompts/` or base-prompt file changes and OFF stays byte-identical.

### Assumptions

- [validated] the auditor findings available at attempt-close (the parsed audit record / findings ledger) are the host-observable evidence the transition consumes, and the injected auditSection is what makes the auditor cite assumption ids so `singular_ctx_assumptions_transition` can resolve them — engine/ctx-assumptions-transition.sh and engine/ctx-assumptions-prompt.sh.
- [validated] `SINGULAR_CTX_PACKET` default is `0` (OFF), and unset/empty/`0` must be a total no-op in l1-drive.sh — planner-contract feature-flag discipline and requiredCompletion.
- [open] the artifact-secret-scan of these durable ledger sidecars is a SEPARATE node (`artifact-secret-scan`), not this slice — stage-4.

### Rejected alternatives

- Editing `templates/prompts/auditor.md` or the implementer base prompt to carry the assumptions section — would change prompts even when OFF and break byte-identical; driver-site injection behind the flag keeps OFF identical.
- Recording assumption statuses by modifying `singular_capsule_write_implementer` — broadens ownership to the capsule writer; a non-fatal additive record at the call site keeps the slice to the sanctioned l1-drive.sh hook.
- Applying the transition at attempt-open — there are no current-attempt findings yet at open; transition belongs at close after the auditor verdict, feeding the next attempt's carry.

### Inspected symbols

- `singular_ctx_assumptions_assemble` / `singular_ctx_assumptions_transition` — the attempt-open envelope producer and the attempt-close host-derived fold this hook delegates to; the hook adds only flag-guarded call sites around them.
- `active_audit_prompt` (l1-drive.sh) — the per-attempt auditor prompt file the auditor actually reads; the auditSection is injected here, not into the base audit prompt, so both the per-attempt delta and the OFF byte-identical guarantee hold.
