## Objective

Extend the `graph-projector` (layer `engine_runtime`) source-record projection layer with the task, commit, and paired-audit node families, composing the integrated identity convention + emitters (`engine/ctx-graph.sh`, `engine/ctx-graph-project.sh`). New file `engine/ctx-graph-project-records.sh`, auto-sourced by the ctx-loader block in `engine/lib.sh`, defines functions ONLY (OFF-parity for `SINGULAR_CTX_GRAPH`, default 0; nothing invokes them; they write no file and emit JSONL to stdout). Implement three mutually-independent node mappers, each RED-first in `tests/test-ctx-graph-project-records.sh`:

1. Task mapper. `singular_graph_project_task <taskFilePath>` parses the task markdown first-line header `# TASK-XXXX: ...` for the taskId and emits one `task` node (evidenceClass `claim`) keyed identity('task', taskId). This mints the exact node the integrated `implements` (attempt to task) and gate-result target edges already point at, so those stop dangling. No edge.

2. Commit mapper. `singular_graph_project_commits <eventsPath>` filters `l1.committed` events (envelope {type, message, ts, data}; `data.headSha`, `data.node`, `data.runId`) and emits one `commit` node (evidenceClass `authoritative` — a git commit is a host-verified fact) keyed identity('commit', headSha). No edge.

3. Paired-audit mapper. `singular_graph_project_paired_audits <pairedAuditRecordPath>` reads a `singular.orchestration.paired-audit.v0` record (`runId`, `taskId`, `verdict`, `findingsCount`, `agreement`/`disagreement`) and emits one `audit` node (evidenceClass `claim` — the auditor is itself a model, never authoritative) keyed identity('audit', runId) with `attributes` projecting verdict/findingsCount/disagreement. No edge.

Each mapper prints schema-valid JSONL node lines to stdout (self-identifying via `kind`); the future `singular graph rebuild` entry point partitions by `kind` and feeds `singular_graph_write_corpus`. The cross-record edges (the audit verifies/contradicts edge to the accepted attempt, and `depends_on` from the task node) are deferred to a follow-up linkage task because they need endpoint alignment this slice does not pin. This task advances `graph-projector` toward its `requiredCompletion` by covering the task/commit/audit node families and closing the dangling edge targets; it does not complete the node or declare a gate pass.

## Context packet

### Decisions
- Node-only slice: task, commit, and audit nodes ship now; the integrated attempt/gate-result `implements`/verifies edges already target the task node, so minting it here closes those dangling references without any new edge.
- `commit` is the third `authoritative` family (alongside the already-mapped gate-result); `audit` is `claim` per docs/context-build-plan/graph-event-mapping.md's explicit auditor-is-a-model rule — projecting an audit as authoritative would violate evidence invariance.
- Commit identity is keyed by headSha (not runId) so duplicate commit-bearing events for the same sha collapse to one node under canonicalize.

### Deferred (slice boundary — not asserted in the test)
- The audit `verifies` (agreement) / `contradicts` (disagreement) edge to the accepted attempt: the `paired-audit.v0` record carries runId+taskId but not the accepted attempt ordinal `n`, so resolving the exact attempt node needs the attempts index — a follow-up linkage slice.
- `depends_on` edges (from the DAG / batch) out of the task node.

### Assumptions
- [validated] task files carry a `# TASK-XXXX:` first-line header giving the taskId, and identity('task', taskId) is the key the integrated attempts/gate-result mappers already target — basis: docs/orchestration/tasks/TASK-0078.md header + engine/ctx-graph-project.sh.
- [validated] `l1.committed` events carry `data.headSha` (the worker's git commit sha) — basis: real `.singular-state/events.ndjson`.
- [validated] `paired-audit.v0` records carry `runId`, `verdict`, `findingsCount`, and `agreement`/`disagreement` — basis: the record builder in engine/ctx-paired-audit.sh and a real paired-audit.json.
- [open] `python3` is available for parsing in the mappers and their test — basis: prior graph mappers and engine/ctx-metrics.sh rely on it.

### Rejected alternatives
- Emitting the audit-to-attempt verifies/contradicts edge now, targeting the task node as a stand-in for the attempt — rejected: the mapping specifies attempt-level and the record lacks `n`; a mis-targeted edge is worse than a deferred one.
- Projecting `commit` from `integration.integrated.mergeCommit` — rejected: the per-task worker commit is `l1.committed.headSha` (the attempt's own commit); merge commits belong to a later integration-lineage slice.

### Inspected symbols
- `singular_graph_project_attempts` implements-edge target (`engine/ctx-graph-project.sh`): already `node_id(identity('task', taskId))`; slice 1 mints exactly that node so the edge stops dangling — the non-obvious reason the task mapper is the highest-value node to add next.
