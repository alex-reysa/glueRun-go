An infra retry currently destroys the previous try's entire worker trace: in
`engine/l1-drive.sh` `run_worker_phase`, every try redirects with a truncating
`>"$run_dir/worker-codex.log"` (main run and the rc-86 resume-fallback rerun). Try 0's bytes

and stderr-only runner diagnostics (resume-refused, terminal-failure notices) are lost outright.
The auditor already has the correct behavior — `auditor-codex.log` is opened with `>>` and each
try is prefixed by a `--- auditor try N (attempt M) ---` separator — and `audit-verify.sh`
already established the `<name>-${attempt}-${try}` per-try naming convention. This task brings
the worker to parity and completes the attempt-archive copy set.

Required changes:

1. In `run_worker_phase`, write each try's stream to a per-try file
   `worker-attempt-<n>-try-<m>.log` (and the resume-fallback rerun to
   `worker-attempt-<n>-try-<m>-resume-fallback.log`), then append the same bytes plus a
   `--- worker try <m> (attempt <n>) ---` header to `worker-codex.log`, which becomes
   append-only for the life of the run. `worker-codex.log` stays at its current path and name:
   it is the compatibility view read by `evidence-manifest.sh`, the console adapter, and the
   ctx-route window gate, and after this change its byte count reflects cumulative session
   output instead of only the last try (fixing the systematic underestimate in the routing
   window gate).
2. Readers that need exactly one try's output (failure classification via
   `singular_planner_failure_class`) must read the per-try file, not the aggregate.
3. Extend `singular_attempt_archive` in `engine/lib.sh`: add `auditor-codex.log`, the per-try
   `worker-attempt-*-try-*.log` files, and the per-try `*runner-result.json` +

   root files are never moved or renamed.
