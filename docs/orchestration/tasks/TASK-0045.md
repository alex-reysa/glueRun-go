## Objective

Advance the `routing-module` executable DAG node (layer `engine_runtime`) by shipping the two role-available resume gates its `requiredCompletion` names — window-pressure and diff-volume — as two independent leaf predicates in new `engine/ctx-*.sh` files. These are the fail-closed tripwires the later `engine/ctx-route.sh` strategy dispatcher will consult before it ever returns `resume`. Building them first (leaf-before-orchestrator, mirroring how the plan-revision loop was assembled: deciders and assemblers first, the composed orchestrator last) lets the router compose both gates once without re-touching either file.

Both gates are pure decision functions defined in new auto-sourced files. No existing engine path invokes them, so the engine stays byte-identical (OFF-parity by construction, as in `engine/ctx-planner-resume.sh`); the `SINGULAR_CTX_ROUTING` wire-in and the `engine/ctx-route.sh` spine that wraps `singular_session_resume_decide` / `singular_planner_resume_decide` are later slices of this node and are OUT OF SCOPE here.

Slice 1 — window-pressure gate (`engine/ctx-route-window.sh`): `singular_ctx_route_window_gate <role> <session-transcript-path>` estimates session tokens from the provider session transcript via a documented deterministic estimate and compares the estimate/window ratio against `SINGULAR_SESSION_WINDOW_MAX_PCT` (window size from the documented additive knob `SINGULAR_SESSION_WINDOW_TOKENS`). Over threshold → refuse; missing/unreadable/indeterminate → refuse (fail closed).

Slice 2 — diff-volume gate (`engine/ctx-route-diff.sh`): `singular_ctx_route_diff_gate <role> <worktree> <head-sha-at-create> <lineage-head>` measures churn in the role's relevant files between `headShaAtCreate` and the current lineage head (git numstat, role-relevant paths supplied as the gate's scoping input) and refuses when churn exceeds the documented additive threshold knob `SINGULAR_SESSION_DIFF_MAX_LINES`; empty/absent shas or any git error → refuse (fail closed). Wall-clock age alone under-measures staleness — this is the churn axis.

Each gate prints EXACTLY one line — `pass` or `refuse <reason-code>` (`window-pressure` / `diff-volume`) — and never exits non-zero. Gates are monotonic-refuse: they can only push a decision toward `fresh`, never turn a fresh-required decision into a resumable one. This is a gate, not a numeric score, and it preserves evidence invariance and the advocate/skeptic line — no gate here creates a path by which a tainted (resumed) session could satisfy an independence-required step.

## Acceptance Criteria

- `engine/ctx-route-window.sh` defines `singular_ctx_route_window_gate` and, given a fixture provider transcript whose deterministic token estimate exceeds `SINGULAR_SESSION_WINDOW_MAX_PCT` of `SINGULAR_SESSION_WINDOW_TOKENS`, prints exactly `refuse window-pressure`; an estimate at/under the threshold prints exactly `pass`; a missing or unreadable transcript prints exactly `refuse window-pressure` (fail closed). Never exits non-zero.
- `SINGULAR_SESSION_WINDOW_MAX_PCT` and `SINGULAR_SESSION_WINDOW_TOKENS` are additive documented knobs with defaults; the token estimate is deterministic and reproducible over a fixed fixture.
- `engine/ctx-route-diff.sh` defines `singular_ctx_route_diff_gate` and, over a fixture git worktree, prints exactly `refuse diff-volume` when churn between `headShaAtCreate` and the lineage head in the role's relevant files exceeds `SINGULAR_SESSION_DIFF_MAX_LINES`, exactly `pass` when churn is at/under threshold, and exactly `refuse diff-volume` when either sha is empty/absent or git cannot compute the diff (fail closed). Never exits non-zero.
- `SINGULAR_SESSION_DIFF_MAX_LINES` is an additive documented knob with a default; both gates take `<role>` so the later `engine/ctx-route.sh` can consult them per role.
- Each gate's only outputs are `pass` or a `refuse <reason-code>`; there is no input under which a gate converts a would-be-`fresh` decision into a `resume` (monotonic-refuse output alphabet, pinned behaviorally with the fail-closed fixtures).
- `bash tests/test-ctx-route-window.sh` and `bash tests/test-ctx-route-diff.sh` are red before implementation and green after; `bash tests/test-engine-clean.sh` stays green (no project-specific symbols in `engine/`).
- GATE CANDIDATE (node-level, not declared here): composed with the later strategy dispatcher, `routing-module` refuses resume under window pressure and under diff volume with enumerated reasons — two of the node's `requiredCompletion` predicates.

## Context packet

Decisions:
- Ship the two gates as the first `routing-module` brick, leaf-before-orchestrator — matches the plan-revision-loop assembly (TASK-0019..0023: deciders/assemblers first, composed orchestrator last) and lets `engine/ctx-route.sh` compose the wrapped decide functions plus both gates in one later slice without re-touching gate files.
- Gates emit `pass` / `refuse <reason>` and are monotonic-refuse only, so they can never weaken a fresh-required decision — keeps the advocate/skeptic line and evidence invariance intact and stays a gate, never a numeric score.
- Fail-closed direction is REFUSE (prefer fresh) on every ambiguity, mirroring `singular_planner_resume_decide`.

Rejected alternatives:
- Router-spine-first (`engine/ctx-route.sh` wrapping the decide functions before the gates exist): rejected — it would ship a router that ignores gates and be re-edited when the gates land, adding churn to the node's central file; the DAG names both gates as required predicates, so build them as reusable leaves first.
- Folding a gate together with the router into this task: rejected — keeps this task to two mutually-independent leaf slices with no file overlap and no later re-touch.

Assumptions:
- [open] provider session transcripts are locatable from the integrated session-meta (provider/sessionId) and a fixture transcript is sufficient to exercise the estimate — basis: session-meta shape landed in Stage 1; the gate must not couple to any live provider runtime.
- [validated] new `engine/ctx-*.sh` files are auto-sourced by the ctx-loader block and define-only files stay OFF-parity because no existing path calls them — basis: `engine/ctx-planner-resume.sh` header and the integrated ctx-loader node.
- [open] `git diff --numstat <base> <head> -- <role-paths>` is the churn measure and role-relevant path scoping is the gate's caller-supplied input, not a hard-coded set — basis: the stage-5 diff-volume text.
