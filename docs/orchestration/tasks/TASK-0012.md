## Objective

Deliver the contract layer of executable DAG node `plan-critique-contract` (stage `S2-plan-critique`, area `plancritic`, layer `contract`, kind `contract`): the additive `schemas/plan-critique.v0.schema.json` schema and the `templates/prompts/plan-critic.md` skeptic prompt adapted from the orphaned `templates/prompts/reviewer.md`, plus a strict-test-first fixture validator. Per the stage file section for node `plan-critique-contract`, the schema `$id` is `gluerun.orchestration.plan-critique.v0`, with `additionalProperties: false` and required top-level fields: `schema` (const `gluerun.orchestration.plan-critique.v0`); `node` (string, minLength 1 — the DAG node the batch targets); `runId` (string, minLength 1); `batchTaskIds` (array of task-id strings, each pattern `^TASK-[0-9]{4,}$`); `verdict` (enum `approve | revise | park`); `findings` (array of objects, each `additionalProperties: false` with `id` — the stable finding id, pattern `^f-[0-9a-f]{12}$`, reusing the normalized-hash identity produced by `gluerun_finding_id` in `engine/lib.sh`; `severity` — enum `blocking | should-fix | note`; `claim` — string, minLength 1; `evidence` — the evidence pointer string, minLength 1; and an OPTIONAL `suggestedChange` — string); `assumptionsChallenged` (array of strings); and `rationale` (string, minLength 1). No additional top-level fields are permitted, per the additive-schemas rule, and validation fails closed.

`templates/prompts/plan-critic.md` is adapted from `reviewer.md` into a plan-batch SKEPTIC with read-only repo access. It challenges the batch's slicing, dependency claims, owned-file scoping, acceptance-criteria testability, duplicate/overlap risk against existing tasks, and hidden coupling between batch tasks, and it must hunt the batch's UNSTATED assumptions (advocate/skeptic line: the critic is the skeptic, fresh and read-only by design; the un-bypassable implementation auditor is unaffected). Its final message must be exactly one JSON object valid against `schemas/plan-critique.v0.schema.json` and nothing else. In this slice the prompt is present-but-unreferenced by any engine, CLI, or driver path.
