## Objective

Extend the `graph-projector` (layer `engine_runtime`) mapping-table coverage toward the full `context-graph.v0` node taxonomy with the two cleanly-grounded remaining S4 context families — `assumption` and `capsule`. The node's headline `requiredCompletion` behaviors (rebuild/sync/query behind `GLUERUN_CTX_GRAPH`; idempotent + deterministic; rebuild equals sync; deletable + rebuildable loss-free; test-ctx-graph.sh green) are already integrated and guarded (TASK-0090); this task fills node-type coverage so the projected graph is a faithful durable-semantic layer, following the established land-then-wire pattern. New file `engine/ctx-graph-project-context.sh`, auto-sourced by the ctx-loader block in `engine/lib.sh`, defines functions ONLY (OFF-parity for `GLUERUN_CTX_GRAPH`, default 0; nothing invokes them; they write no file and emit JSONL to stdout — present-but-uncalled is byte-identical, the same pattern every integrated mapper used before wiring). Implement two mutually-independent node mappers, each RED-first in `tests/test-ctx-graph-project-context.sh`:

1. Assumption mapper. `gluerun_graph_project_assumptions <taskFilePath>` parses the task markdown `## Context packet` `### Assumptions` block (grammar `[open|validated|violated] <claim> — <basis>`) and emits one `assumption` node (evidenceClass `claim`) per entry, keyed identity('assumption', taskId, entryKey) with `attributes.status` in {open, validated, violated}. A task with no Context packet or no Assumptions entries emits nothing (empty, not an error).

2. Capsule mapper. `gluerun_graph_project_capsules <capsuleRecordPath>` reads a per-run implementer/reviewer capsule record (`implementer-capsule.json` / `reviewer-capsule.json`) and emits one `capsule` node (evidenceClass `claim`) keyed identity('capsule', runId, role), with provenance (source path + content hash) and `attributes.role`.

Both families are model-authored, so every node is `claim` — none may be `authoritative`. Wiring these mappers into the `gluerun_graph_rebuild` walk and extending the composed guard (`tests/test-ctx-graph.sh`) to assert them in the rebuilt corpus, plus the `derived_from` edges from assumption/capsule to their task/attempt and the fuzzier `goal`/`plan-batch` families, are follow-up tasks. This task advances `graph-projector` by covering two more mapping-table node types; it does not touch the already-met requiredCompletion and does not declare the node complete.

## Context packet

### Decisions
- The headline requiredCompletion behaviors are already integrated and guarded by TASK-0090; this task extends the projector's node-type coverage (assumption + capsule are two of the four remaining families) so the graph is a faithful durable-semantic layer, without touching the met requiredCompletion.
- Mappers land new-file / OFF-parity first (present-but-uncalled is byte-identical — the established pattern every mapper used before wiring); adding them to the `gluerun_graph_rebuild` walk and extending the composed guard is a clean follow-up.
- Assumption source is the durable, authored task-markdown `## Context packet` `### Assumptions` block (S4 packet grammar); capsule source is the per-run implementer/reviewer capsule JSON already tracked by artifact-secret-scan and rehydrate-sources.

### Assumptions
- [validated] `implementer-capsule.json` / `reviewer-capsule.json` are durable per-run records — basis: `engine/ctx-artifact-scan.sh` and `engine/ctx-rehydrate-sources.sh` reference them.
- [validated] the Context-packet Assumptions grammar is `[open|validated|violated] <claim> — <basis>` and ledger entries carry id/status/claim/basis — basis: the planner contract and the integrated `engine/ctx-packet.sh` / `engine/ctx-assumptions.sh`.

### Rejected alternatives

- Mapping `goal` / `plan-batch` now — rejected: there is no `goal.md` and no discoverable session-meta schema or fixture, so those sources are fuzzy; assumption and capsule are the cleanly-grounded remaining families.
