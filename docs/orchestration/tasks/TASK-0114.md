## Objective

Terminal handoff in `engine/l1-drive.sh` is an in-process EXIT trap (`l1_on_exit`): if the
driver dies before a durable terminal transition, the trap writes
`L1 driver exited before a durable terminal handoff` — and under SIGKILL the trap never runs
at all, leaving `run-status.json` frozen in an active phase that the health digest counts as a
live run forever. The codebase already contains the correct pattern for one outcome: the
`accept-pending` recovery record plus `l1_try_auto_accept_existing` re-accepts a completed
packet without re-running anything. This task generalizes that precedent to every terminal
outcome.

Required changes:

1. Stage the handoff: immediately after the attempt loop resolves a terminal outcome (accept,
   escalate-parked, escalate-infra, waiver, budget exhaustion) and BEFORE the lease/task/status
   transitions, atomically write `terminal-pending.json` into the run dir: outcome, decider
   action/authority, attempt number, verdict/packet refs, and a monotonic timestamp. Remove it
   only after the final durable transition completes (the existing status/lease/event writes).
2. Reconciliation: teach the dispatch reaper path (`engine/reconcile.sh` /
   `singular_reap_dispatches` in `engine/lib.sh`) that a dead tree with a `terminal-pending.json`
   reconciles the lease and run-status TO THE RECORDED OUTCOME instead of forcing `failed` —
   the same self-heal shape as `accept-pending`, for all outcomes.
3. The EXIT trap keeps its current role for the no-marker case; its message and recovery record
   are unchanged.
4. Do not weaken any transition: a `terminal-pending.json` may only ever move state toward its
   recorded outcome, never resurrect an already-terminal run, and never bypass packet/audit
   validation (the marker references artifacts; it validates nothing itself).
