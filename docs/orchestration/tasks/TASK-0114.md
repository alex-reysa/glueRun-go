## Objective

Terminal handoff in `engine/l1-drive.sh` is an in-process EXIT trap (`l1_on_exit`): if the
driver dies before a durable terminal transition, the trap writes
`L1 driver exited before a durable terminal handoff` — and under SIGKILL the trap never runs
at all, leaving `run-status.json` frozen in an active phase that the health digest counts as a
live run forever. The codebase already contains the correct pattern for one outcome: the
`accept-pending` recovery record plus `l1_try_auto_accept_existing` re-accepts a completed
packet without re-running anything. This task generalizes that precedent to every terminal
outcome.

Required changes:

1. Stage the handoff: immediately after the attempt loop resolves a non-accept terminal outcome
   (escalate-parked, escalate-infra, budget exhaustion) and BEFORE the lease/task/status
   transitions, atomically write `terminal-pending.json` into the run dir: outcome, decider
   action/authority, attempt number, verdict/packet refs, and a monotonic timestamp. Acceptance,
   including waiver/`accept-waiver`, is deliberately later: write an `accept-finalizing`
   marker only after TASK-0113's packet-only
   secret preflight, atomic accepted stamp, and exact root/manifest verification succeed, but
   before accepted task/lease/inbox publication. That marker binds the accepted packet and final
   manifest path, size, and SHA-256 plus the intended inbox target. Remove either marker only
   after the final durable transition completes (the existing status/lease/event writes).
2. Reconciliation: teach the dispatch reaper path (`engine/reconcile.sh` /
   `singular_reap_dispatches` in `engine/lib.sh`) that a dead tree with a `terminal-pending.json`
   reconciles the lease and run-status TO THE RECORDED OUTCOME instead of forcing `failed` —
   the same self-heal shape as `accept-pending`, for all outcomes. An `accept-finalizing` marker
   is not authority by itself: re-run the packet-only secret preflight and validate the bound
   accepted root/manifest tuple before publishing a byte-identical inbox copy or accepted
   controls. Missing, tampered, secret-bearing, or mismatched evidence blocks with no inbox and
   imports zero packets; it never falls through to generic recorded-outcome acceptance.
3. The EXIT trap keeps its current role for the no-marker case; its message and recovery record
   are unchanged.
4. Do not weaken any transition: a `terminal-pending.json` may only ever move state toward its
   recorded outcome, never resurrect an already-terminal run, and never bypass packet/audit
   validation (the marker references artifacts; it validates nothing itself).
5. Close FR-047 with a frozen cleanup-only mode: `singular drive TASK-ID --reset-only` is
   permitted only while STOP exists and the exact task and lease are terminal
   blocked/failed/superseded/cancelled. Under the Git-operation lock it must prove the recorded
   process tree dead, resolve the exact task worktree and worker branch, and remove only those
   two retained objects. It must create no run ID, lease, prompt, status transition, provider
   invocation, or dispatch record. Refuse running/accepted/ambiguous control state, a live or
   unverifiable process tree, a mismatched branch/worktree, or absent STOP. Normal reset/drive
   behavior remains unchanged and dispatch occurs only in a later separately authorized step.

  - kill the driver (SIGKILL) between terminal resolution and the final transitions (use a

    run-status stays active-or-bare-failed.
  - with STOP present and a dead blocked task retaining its exact worktree/worker branch, the
    current reset path exits before cleanup; capture that behavior before implementing
    `--reset-only`.
- GREEN:
  - the same kill followed by one reconcile cycle lands the lease AND run-status on the
    recorded outcome, with an event recording `reconciledBy`;
  - a SIGKILLed driver with NO marker still reconciles to `failed` exactly as today;
  - a live driver is never touched (marker present, tree alive: reconcile skips);
  - valid `accept-pending` auto-heal behavior is preserved semantically, but it reuses the rel-05
    secret/binding transaction: accepted root/manifest/inbox are byte-identical and publish once;
    secret-bearing, missing, tampered, or mismatched recovery evidence blocks and imports zero;
  - a killed `accept-finalizing` handoff, both native and waiver paths, with valid bound
    root/manifest evidence completes the TASK-0113 publication transaction exactly once,
    producing byte-identical accepted root/manifest/inbox and accepted task/lease;
  - missing, tampered, secret-bearing, or mismatched accepted packet/manifest evidence never
    produces accepted controls or inbox bytes, dry and actuated reconcile import zero packets,
    and the task/lease block with stage- and SHA-bound failure evidence;
  - `drive TASK-ID --reset-only` under STOP removes exactly the verified dead task worktree and
    worker branch, leaves every other worktree/ref/control file byte-identical, and creates no
    run, lease mutation, prompt, provider invocation, dispatch, or task-status change;
  - the reset-only mode fails closed for absent STOP, live/unverifiable processes,
    running/accepted/ambiguous state, wrong branch identity, or any target outside the exact
    task worktree/worker branch.
- `bash tests/test-recover.sh` passes unchanged.
