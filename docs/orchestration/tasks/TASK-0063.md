## Objective

Sixth and final slice of the stage file's explicitly-OPTIONAL authored-knowledge manifest ingestion for the executable DAG node `rehydrate-path` (stage `S5-routing`, layer `engine_runtime`). The core `requiredCompletion` behavior is already integrated (TASK-0051–0057); this OPTIONAL feature is NOT part of `requiredCompletion` and does not gate the node — completion and gate promotion are operator authority and are not claimed here. TASK-0062 injects the eligible authored-knowledge section into the rehydration prompt on `rehydrate` runs behind `GLUERUN_CTX_MANIFEST` (via `gluerun_ctx_rehydrate_authored_config_render implement`). This slice records its counterpart in the strategy-event manifest, completing the optional-slice contract "the packet manifest records which entries were injected, like any other rehydration source."

Extend `gluerun_ctx_rehydrate_event_data` in `engine/ctx-rehydrate-event.sh` (the payload assembler that builds the recorded packet manifest) so that, in addition to the durable-artifact manifest, it merges the config-gated authored manifest entries — `gluerun_ctx_rehydrate_authored_config_manifest implement` — into the event's nested `manifest`, using the SAME `implement` trigger TASK-0062 passes at injection so the recorded authored entries match the injected authored section (consistency invariant). The config gate (TASK-0061) internally checks `GLUERUN_CTX_MANIFEST` (default 0) and the optional `gluerun.config.json` `contextManifest` field, so with either OFF it returns empty and nothing is merged.

Detail, node `rehydrate-path`, layer `engine_runtime`: `gluerun_ctx_rehydrate_event_data` currently builds `manifest` via `gluerun_ctx_rehydrate_manifest` over `gluerun_ctx_rehydrate_sources "$run_dir"` (`{schema, sources:[{id,sha256}…]}`) and embeds it as the nested `manifest` object. Add the authored entries (each carrying `id` + `sha256` + `class`=`authored-knowledge` + `authoritative`=`false`), recorded distinguishably from the durable host-verified sources and never as authoritative.

- Gate candidate: with this merge integrated, the authored-knowledge optional feature is complete — eligible entries are injected into the rehydration packet (TASK-0062) AND recorded in the strategy-event manifest, both behind `GLUERUN_CTX_MANIFEST` (default 0). ## Context packet

Decisions:

- Merge the authored manifest entries into the strategy event's nested `manifest` inside `gluerun_ctx_rehydrate_event_data` (TASK-0055's payload assembler) — the single site that builds the recorded packet manifest — completing the optional-slice contract "packet manifest records which entries were injected, like any other rehydration source." Basis: singular-brain integration point 3; TASK-0055 owns the event manifest.
- Use trigger `implement`, identical to TASK-0062's injection call, so the recorded authored entries match the injected authored section (consistency invariant); if TASK-0062's trigger vocabulary generalizes later, both sites must stay aligned. Basis: `engine/l1-drive.sh:457` `gluerun_ctx_rehydrate_authored_config_render implement`.
- Record authored entries with `authoritative`=`false` / the authored-knowledge class (carried from TASK-0060), distinguishable from durable `{id,sha256}` sources, so authored knowledge is never recorded as authoritative host-verified evidence. Basis: planner-contract rule 8 (evidence invariance).

Assumptions:

- [validated] `gluerun_ctx_rehydrate_event_data` builds the nested `manifest` via `gluerun_ctx_rehydrate_manifest` over `gluerun_ctx_rehydrate_sources "$run_dir"` (`engine/ctx-rehydrate-event.sh`).
- [validated] `gluerun_ctx_rehydrate_authored_config_manifest [triggers ...]` emits the authored manifest entries iff `GLUERUN_CTX_MANIFEST=1` and `contextManifest` is configured, else empty (TASK-0061 over TASK-0060).
- [validated] TASK-0062 injects with trigger `implement` (`engine/l1-drive.sh`); this slice records with the same trigger for injection/recording consistency.
- [open] The merge shape (authored entries into `manifest.sources` with class markers, or a parallel `manifest.authored` array) — pick a deterministic additive shape; either satisfies "recorded like any other source" so long as authored entries carry `id` + `sha256` + authored-knowledge / non-authoritative markers.

Rejected alternatives:

- Recording authored entries in a separate event type — rejected: the optional-slice contract records them in the packet manifest of the same `context.strategy_selected` event, like any other rehydration source.
- Using a different trigger than TASK-0062's injection — rejected: it would desync recorded versus injected authored entries; both must use `implement`.
- Recording the authored bodies (not just ids + hashes) — rejected: the manifest records ids + hashes only (evidence invariance; no artifact or authored content in the event stream), matching the durable manifest.
