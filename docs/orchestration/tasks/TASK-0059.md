## Objective

Second slice of the stage file's explicitly-OPTIONAL authored-knowledge manifest ingestion for the executable DAG node `rehydrate-path` (stage `S5-routing`, layer `engine_runtime`). The core `requiredCompletion` behavior is already integrated (TASK-0051–0057); this OPTIONAL feature is NOT part of `requiredCompletion` and does not gate the node — completion and gate promotion are operator authority and are not claimed here. TASK-0058 shipped the pure entry selector `gluerun_ctx_rehydrate_authored_select`, which emits surviving authored-knowledge entries as JSON Lines — each record carrying `id`, `source` (`body`|`path`), `class`=`authored-knowledge`, `authoritative`=`false`, `load-when` (list), and `freshness` (string), id-sorted — but does NOT yet filter on `load-when` or `freshness`.

This slice adds that filter. Introduce a new pure, read-only leaf `engine/ctx-rehydrate-authored-eligible.sh` that consumes the selector's JSONL and a current trigger context and emits only the entries eligible to inject now. It DEFINES a new function only and is present-but-uncalled by every existing engine/CLI/driver path, so with it sourced the engine stays byte-identical to current behavior. Implement and test against FIXTURE records only; take no dependency on the singular-brain runtime. `GLUERUN_CTX_MANIFEST` (default 0) gates the later packet wire-in, not this pure leaf.

Behavior of `engine/ctx-rehydrate-authored-eligible.sh` (node `rehydrate-path`, layer `engine_runtime`) — a function such as `gluerun_ctx_rehydrate_authored_eligible <trigger> [<trigger> ...]` reading the selector JSONL on stdin:

- `load-when` matching: an entry is eligible iff its `load-when` list is empty (the documented unconditional-baseline default) or contains at least one of the supplied `<trigger>` values; ineligible entries are dropped.
- freshness gate: an entry whose `freshness` is a documented stale/expired state is NEVER emitted as current — it is skipped, or emitted only with an explicit stale marker — mirroring TASK-0058's `description_unverified` rule, so non-current authored knowledge can never be presented as current or authoritative.
- Class markers pass through unchanged: emitted entries retain `class`=`authored-knowledge` and `authoritative`=`false`; the filter never elevates an entry to authoritative.
- Emits the eligible subset as JSONL, order-stable (the same id sort), deterministically.
- Pure, read-only, fail-soft: malformed JSONL lines are skipped, empty input yields empty output, it writes/renames/deletes nothing, appends no events, and never exits non-zero on well-formed input.

## Context packet

Decisions:

- Consume TASK-0058's selector JSONL (`id` / `source` / `class` / `authoritative` / `load-when` / `freshness`) and apply `load-when` + freshness eligibility in a separate pure leaf, mirroring the leaf-before-wire-in discipline; this keeps the eventual config-field / packet wire-in a minimal `select | eligible` compose. Basis: TASK-0058 carries `load-when` / `freshness` but does not filter on them.
- Enforce the stale-freshness never-as-current rule here, mirroring TASK-0058's `description_unverified` rule: authored knowledge that is not current must never be presented as current or authoritative. Basis: singular-brain integration point 3 and planner-contract rule 8 (evidence invariance).
- Treat an empty or absent `load-when` as unconditional baseline eligibility (a documented, tested default) so curated baseline entries load regardless of trigger; ground the rule in the `KNOWLEDGE.json` contract if it dictates otherwise.

Assumptions:

- [validated] `gluerun_ctx_rehydrate_authored_select` emits JSONL records with fields `id`, `source` (`body`|`path`), `class`=`authored-knowledge`, `authoritative`=`false`, `load-when` (list), and `freshness` (string), id-sorted (`engine/ctx-rehydrate-authored.sh`).
- [open] The exact `freshness` enum (which values mean stale/expired versus current) is defined by the `KNOWLEDGE.json` contract; the filter documents and tests its stale set and treats stale as never-current.
- [open] The empty-`load-when` default (unconditional versus never) — the filter documents a deterministic rule and pins it in the test; ground it in the contract.
- [validated] The core `rehydrate-path` `requiredCompletion` is integrated (TASK-0051–0057); this OPTIONAL slice does not gate the node.

Rejected alternatives:

- Folding `load-when` / freshness filtering into TASK-0058's selector — rejected: it is already integrated; a separate filter keeps each brick tight, and the selector's carried metadata is the seam.
- Applying eligibility inline in the future packet wire-in — rejected: that wire-in owns `gluerun.config.json` plus packet composition (a larger surface); a pure filter is table-testable and keeps the wire-in a compose.
- Emitting stale entries as current — rejected: the contract forbids presenting non-current authored knowledge as current or authoritative.
