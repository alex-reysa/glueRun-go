## Objective

Deliver the `graph-projector` (layer `engine_runtime`) `sync` entry point — the incremental append that satisfies the `requiredCompletion` property `rebuild equals sync on fixtures`. It composes the integrated rebuild machinery: the projection mappers, the `kind`-partition helper, and the loss-free canonical writer (`engine/ctx-graph-rebuild.sh`, `engine/ctx-graph-corpus.sh`). New file `engine/ctx-graph-sync.sh`, auto-sourced by the ctx-loader block in `engine/lib.sh`, defines functions ONLY (OFF-parity for `SINGULAR_CTX_GRAPH`, default 0; nothing invokes it; the eventual `cli/singular graph` call site is a later task). Implement two chained slices in order, each RED-first in `tests/test-ctx-graph-sync.sh`:

1. Event-log cursor. `singular_graph_sync_cursor_read <graphDir>` and `singular_graph_sync_cursor_write <graphDir> <n>` persist and read the count of `events.ndjson` lines already projected, stored under `<graphDir>` (e.g. `<graphDir>/.sync-cursor`). A missing cursor reads as `0`. Pure and deterministic.

2. Sync entry. `singular_graph_sync <stateDir> [graphDir]` reads the existing corpus (if any) and the cursor, projects the `events.ndjson` lines BEYOND the cursor via the event mappers (`singular_graph_project_plan_versions`, `singular_graph_project_decisions`, `singular_graph_project_commits`), reprojects the bounded record-based sources (attempts, gate-results, tasks, paired-audits, critiques — idempotent, so duplicates collapse), merges all lines with the existing corpus, partitions via `singular_graph_partition`, and writes the canonical corpus via `singular_graph_write_corpus`; then advances the cursor to the current `events.ndjson` line count. `graphDir` defaults to `${SINGULAR_CTX_GRAPH_DIR:-.singular-state/graph}`. Consumes slice 1 + the integrated rebuild machinery.

Because `singular_graph_write_corpus` re-canonicalizes (dedup by id + sort by id), the union of the existing corpus and the newly-projected delta converges to the same canonical corpus a full rebuild produces over the augmented source set — so `sync` equals `rebuild` regardless of how the source set was chunked. The cursor makes the append-only event log incremental; bounded record sources are safely re-walked. `singular graph query` and the `cli/singular graph` driver hook are subsequent `graph-projector` tasks. This task advances `graph-projector` toward its `requiredCompletion` by delivering the rebuild-equivalent `sync`; it proposes the rebuild-equals-sync half of the exit gate as a candidate but does not complete the node.

## Context packet

### Decisions
- Sync guarantees rebuild-equivalence by MERGING the existing corpus with the newly-projected delta and delegating to `singular_graph_write_corpus`, whose dedup-by-id + sort-by-id makes the result independent of how sources were chunked — the same canonicalization point rebuild uses.
- The cursor is scoped to the append-only `events.ndjson` (the unbounded source the stage file names for `sync`); bounded record sources (attempts, gates, tasks, paired-audits, critiques) are re-walked each sync because reprojection is idempotent — this keeps the from-scratch sync identical to a full rebuild without a per-record processed-set.
- The cursor lives under `<graphDir>` so deleting the graph clears the cursor too, keeping the delete-and-rebuild path loss-free and consistent.

### Assumptions
- [validated] `singular_graph_rebuild`, `singular_graph_partition`, the nine projection mappers, and `singular_graph_write_corpus` (which clears then canonicalizes `nodes.jsonl`/`edges.jsonl`) are integrated — basis: TASK-0074/0075/0076/0078/0080/0082 integrated.
- [validated] `events.ndjson` is append-only and lives at `<stateDir>/events.ndjson`; the event mappers read it whole — basis: the rebuild walk in `engine/ctx-graph-rebuild.sh` + real `.singular-state/events.ndjson`.
- [open] `python3` is available for line counting / JSON handling in the cursor and sync and their test — basis: prior graph code relies on it.

### Rejected alternatives
- Implementing sync as a pure event-tail append that never re-reads records — rejected: a from-scratch sync must equal a full rebuild (which projects record sources too), so the first sync has to seed those; re-walking bounded records each sync is simpler and idempotent under canonicalize.
- Having sync bypass `singular_graph_write_corpus` and append raw lines to `nodes.jsonl`/`edges.jsonl` — rejected: that would skip canonicalization and break both determinism and rebuild-equals-sync; all writing must flow through the one canonical writer.

### Inspected symbols
- `singular_graph_write_corpus` (`engine/ctx-graph-corpus.sh`): it `rm -f`s the prior `nodes.jsonl`/`edges.jsonl` then writes canonicalized streams — the reason sync must READ the existing corpus and pass it back through the writer rather than appending in place.
