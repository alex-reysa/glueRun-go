## Objective

Extend the `graph-projector` (layer `engine_runtime`) source-record projection layer with the plan-lifecycle families, composing the integrated identity convention + emitters (`engine/ctx-graph.sh`, `engine/ctx-graph-project.sh`) and, in a later `singular graph rebuild` entry point, the corpus writer (`engine/ctx-graph-corpus.sh`). New file `engine/ctx-graph-project-plans.sh`, auto-sourced by the ctx-loader block in `engine/lib.sh`, defines functions ONLY (OFF-parity for `SINGULAR_CTX_GRAPH`, default 0; nothing invokes them; they write no file and emit a mixed node+edge JSONL stream to stdout). Implement three mutually-independent mappers, each RED-first in `tests/test-ctx-graph-project-plans.sh`:

1. Plan-version mapper. `singular_graph_project_plan_versions <eventsPath>` filters `plan.revised` events (envelope {type, message, ts, data}; `data.node`, `data.runId`, `data.revisesRunId`) and emits one `plan-version` node (evidenceClass `claim`) per event keyed by identity('plan-version', node, runId); when `data.revisesRunId` is non-empty it also emits one `revises` edge and one `supersedes` edge from the new version to the prior version node id (identity('plan-version', node, revisesRunId)); when it is empty/absent, no revises/supersedes edge.

2. Decision mapper. `singular_graph_project_decisions <eventsPath>` filters `context.strategy_selected`, `decision.recorded`, and `context.resume_failed` events and emits one `decision` node (evidenceClass `claim`) each, keyed collision-free by (type, data.node, data.runId, ts). No edges.

3. Critique/finding mapper. `singular_graph_project_critique <planCritiqueRecordPath>` reads a `singular.orchestration.plan-critique.v0` record (`node`, `runId`, `findings[]` rows with `id`/`severity`) and emits one `critique` node (evidenceClass `claim`) plus one `finding` node (evidenceClass `claim`) per findings[] entry, keyed identity('finding', node, runId, findingId) with `attributes.severity` projected.

Each mapper prints schema-valid JSONL lines to stdout (each self-identifies via `kind`); the future rebuild entry partitions by `kind` and feeds `singular_graph_write_corpus`. All four projected node types here are model-authored, so every node is `claim` — none may be `authoritative`. The full source walk, the `query` read API, and the `cli/singular graph` driver hook are subsequent `graph-projector` tasks. This task advances `graph-projector` toward its `requiredCompletion` by covering the plan-lifecycle node/edge families; it does not complete the node or declare a gate pass.

## Context packet

### Decisions
- All four families here (plan-version, decision, critique, finding) are model-authored, so every node is `claim`; `authoritative` stays reserved for the host-verified families already mapped (commit, gate-result).
- Plan-version identity is keyed by (node, runId) so its `revises`/`supersedes` edge targets the prior version via (node, revisesRunId) — self-consistent within this one mapper, needing no cross-mapper coordination.
- Mappers keep the stdout mixed node+edge stream and file-free convention established by the integrated `engine/ctx-graph-project.sh` mappers, so the future rebuild entry partitions by `kind` before calling `singular_graph_write_corpus`.

### Deferred (slice boundary — not asserted in the test)
- The `critiques` edge (critique to plan-version) is deferred: its target is the plan-batch (planner session-meta) or the initially staged plan-version, neither minted until those mappers land; the critique and finding NODES ship now.
- `ctx.critic_recheck` decisions and their `contradicts` edge, and the per-finding `accepts_observation`/`rejects_observation` disposition edges, are separate follow-up slices.

### Assumptions
- [validated] the event envelope is {type, message, ts, data} with type-specific fields under `data` (e.g. `data.revisesRunId` on `plan.revised`) — basis: real `.singular-state/events.ndjson` and the `plan.revised` emitter in `engine/ctx-plan-revise-dispositions.sh`.
- [validated] `plan-critique.v0` records carry `node`, `runId`, and `findings[]` rows with `id`/`severity` — basis: `schemas/plan-critique.v0.schema.json`.
- [validated] `singular_graph_identity` is type-agnostic (joins the type token with its key tokens) and works for any node type — basis: `engine/ctx-graph-project.sh` (TASK-0076).
- [open] `python3` is available for JSON parsing in the mappers and their test — basis: prior graph mappers and `engine/ctx-metrics.sh` rely on it.

### Rejected alternatives
- Emitting the `critiques` edge now, targeting the critic record's own `runId` — rejected: a critique targets the staged plan it reviewed, not the critic session's runId, and that target node is not yet minted; a wrong edge is worse than a deferred one.
- Splitting the three families into separate tasks — rejected: three small mutually-independent same-node mappers must fold into one task per the folding rule to avoid per-task overhead (fresh worker, audit, integrate, gate).

### Inspected symbols
- `singular_graph_project_attempts` / `singular_graph_project_gate_results` (`engine/ctx-graph-project.sh`): the shipped precedent for a single-source mapper that emits a mixed node+edge stdout stream through the emitters — the shape these three mappers mirror.
