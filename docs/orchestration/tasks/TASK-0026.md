- `gluerun_plan_recritic_run <node> <run_id> <stage_dir> <revises_run_id> [worktree]` performs ONE read-only critic re-critique pass over the staged candidate set that MAY resume the persisted plan-critic session: it consults the integrated `gluerun_plan_recritic_resume_decide` over the canonical per-node plan-critic session-meta and records the outcome via `gluerun_plan_recritic_record_strategy` (role plan-critic, carrying revisesRunId).
- fresh path: a `fresh <reason>` decision (including the knob-off `fresh disabled`) runs the FRESH critic pass by delegating to the integrated `gluerun_ctx_plan_critic_run`, so with `GLUERUN_PLAN_RECRITIC_RESUME` off the outcome is byte-identical to today's fresh re-critique (no `--resume-session`, same record, same event).
- resume path: a `resume <sid>` decision runs the read-only critic on the DEFAULT runner WITH `--resume-session <sid>`; on a runner rc-86 (resume refused) it records the fresh fallback and re-runs FRESH with the same prompt. The resume path persists the critique through the SHARED lib.sh helpers (`gluerun_extract_json`, `gluerun_finding_id` id normalization, `gluerun_session_meta_finalize`) into the same `plan-critique.json` record and appends the same single `plan.critiqued` event (verdict + finding count) as the fresh path, yielding an identical plan-critique.v0 contract.
