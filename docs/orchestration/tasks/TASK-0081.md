## Objective

Advance the `experiment-run` executable DAG node (layer `evaluation`) by shipping the LAST remaining stage-7 SECONDARY raw metrics not yet aggregated per arm: attempts-to-accept and findings-per-attempt. TASK-0077 (`engine/ctx-experiment-report.sh`) delivered the primary escape-rate, per-arm cost, and bias measurements; TASK-0079 (`engine/ctx-experiment-strategy.sh`) delivered resume/rehydrate hit rates and the gate-refusal reason mix. This task completes the secondary set and does NOT duplicate either. Running the paired-audited A/B experiment, authoring `experiment-report.md`, and recording per-knob default decisions in `docs/orchestration/decisions.md` remain OPERATOR authority (kind: evaluation) and are OUT OF SCOPE; this task neither declares nor gates node completion.

All logic lands in one NEW `engine/ctx-experiment-attempts.sh`, auto-sourced by the ctx-loader block and defining new functions only. No existing engine path invokes them, so the engine is byte-identical with the file present (OFF-parity intrinsic, mirroring the `engine/ctx-metrics.sh` and sibling `engine/ctx-experiment-*.sh` idiom). It does NOT edit `engine/ctx-metrics.sh`, `engine/ctx-experiment-report.sh`, `engine/ctx-experiment-strategy.sh`, or any other pre-existing file. Every function reads only the runs directory attempts indexes (`runs/<runId>/attempts/index.json`, whose entries carry a per-attempt ordinal, `failureClass`, and a `findings` array) plus the events log `events.ndjson` for `ctx.arm_assigned` (carrying `taskId`, `arm` in A|B) to group by arm. It reuses the `ctx-metrics.sh` acceptance convention verbatim — an attempt is accepted when its `failureClass` is one of empty / `accepted` / `none` — so attempts-to-accept agrees with the primary metrics. It creates, moves, or mutates nothing — no run artifact, index, event, lease, or task file.

Implement three chained slices in order, all inside `engine/ctx-experiment-attempts.sh`:

1. Per-arm attempts-to-accept aggregator: over the attempts indexes joined to their arm via `taskId` (A = control / M0 knob-state, B = treatment), take for each accepted task the ordinal of its FIRST accepted attempt; per arm emit acceptedTasks (count), attemptsToAcceptSum, and attemptsToAcceptMean. Missing/empty inputs or an arm with no accepted tasks yield a well-formed zeroed result (fail-safe), never an error.

2. Per-arm findings-per-attempt aggregator: over the same indexes joined to arm, per arm emit attempts (count of attempt entries), findingsTotal (sum over attempts of the per-attempt `findings` array length, an absent/empty `findings` counted as 0), and findingsPerAttemptMean = findingsTotal / attempts. An arm with no attempts yields a zeroed result, never a divide error.

3. Composed secondary-metrics artifact: emit ONE deterministic JSON object on stdout (keys sorted, stable for a given input set) conforming to a NEW additive schema `singular.orchestration.ctx-experiment-attempts.v0`, merging both per-arm rollups. This object is the raw metrics artifact the operator's `experiment-report.md` references alongside the TASK-0077 and TASK-0079 artifacts.

## Context packet

### Decisions

- Ship a SEPARATE new `engine/ctx-experiment-attempts.sh` + new additive schema rather than extending `engine/ctx-metrics.sh`, because ctx-metrics.sh is a pre-existing file (full-suite gate, new-file-convention friction) and, while it computes per-task `attemptsToAccept`, it exposes neither per-arm rollups nor findings-per-attempt; a new reader keeps this additive, OFF-parity intrinsic, and scoped-gate eligible.
- Reuse the ctx-metrics acceptance convention (`failureClass` in empty / `accepted` / `none`) verbatim so attempts-to-accept agrees with the primary metrics rather than introducing a second, divergent definition.

### Rejected alternatives

- Consuming a precomputed ctx-metrics JSON for attempts and reading the index only for findings — rejected: two input contracts and a version-skew seam; reading the attempts index once is simpler and self-consistent.
- Counting findings from `ctx.paired_audit` / audit events instead of the per-attempt index `findings` — rejected: paired-audit findings are post-acceptance sampled (one record per sampled accepted task), not per implementation attempt; the report metric is findings-per-attempt.

### Assumptions

- [validated] Attempts index entries carry a per-attempt ordinal, `failureClass`, and a `findings` array; `ctx.arm_assigned` carries `taskId` and `arm` — basis: engine/ctx-metrics.sh (which derives attemptsTotal/attemptsToAccept over the same index), the attempts-index writer fields, and engine/ctx-ab.sh.
- [open] Some attempt entries may omit `findings`; the aggregator treats absent/empty as 0-length rather than erroring — basis: the fail-safe contract of the sibling ctx-experiment aggregators.
