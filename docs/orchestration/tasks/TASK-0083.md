## Objective

Advance the `experiment-run` executable DAG node (layer `evaluation`) with the capstone record-merge: a single composed raw-metrics bundle that unifies the three integrated per-family aggregators into the one referenceable artifact the operator's `experiment-report.md` points at (the exit gate requires the report merged with raw metrics artifacts referenced). The per-family aggregators already exist and are integrated: TASK-0077 `engine/ctx-experiment-report.sh` (per-arm escape-rate, cost, bias), TASK-0079 `engine/ctx-experiment-strategy.sh` (resume/rehydrate hit rates + gate-refusal reason mix), and TASK-0081 `engine/ctx-experiment-attempts.sh` (per-arm attempts-to-accept + findings-per-attempt). This task merges them; it does NOT re-derive any metric and does NOT duplicate them. Running the paired-audited A/B experiment across both arms, authoring `experiment-report.md`, and recording per-knob default decisions in `docs/orchestration/decisions.md` remain OPERATOR authority (kind: evaluation) and are OUT OF SCOPE; this task neither declares nor gates node completion.

All logic lands in one NEW `engine/ctx-experiment-summary.sh`, auto-sourced by the ctx-loader block and defining a new function only. No existing engine path invokes it, so the engine is byte-identical with the file present (OFF-parity intrinsic, mirroring the sibling `engine/ctx-experiment-*.sh` idiom). It does NOT edit the three sibling aggregators, `engine/ctx-metrics.sh`, or any other pre-existing file. It DELEGATES to the integrated composers `singular_ctx_experiment_report_json`, `singular_ctx_experiment_strategy_json`, and `singular_ctx_experiment_attempts_json`, nesting their outputs verbatim; it computes no metric of its own. It reads only the runs directory (attempts indexes), the events log `events.ndjson`, and an optional precomputed `ctx-metrics` JSON, routing each input to the correct sub-composer per that function's EXISTING signature (the three composers take different parameter lists). It creates, moves, or mutates nothing — no run artifact, index, event, lease, or task file.

Implement the following, chained, inside `engine/ctx-experiment-summary.sh`:

1. Input-routing + delegation: define `singular_ctx_experiment_summary_json` that resolves the runs directory, events log, and optional metrics file, then invokes each of the three integrated `*_json` composers with exactly the inputs its own signature expects, capturing each composer's JSON output.

2. Merge + emit: assemble ONE deterministic JSON object (keys sorted, stable for a given input set) carrying a `schema` field and the three sub-artifacts nested verbatim under stable keys (report, strategy, attempts) — loss-preserving, so no nested value is dropped or reshaped. Fail-safe: when an input is missing or empty, the corresponding sub-object is present and zeroed (as its own composer emits) rather than absent or an error, and the overall exit is zero.

## Context packet

### Decisions

- The summary DELEGATES to the three integrated `*_json` composers and nests their outputs verbatim rather than recomputing any metric, so each measurement keeps exactly one definition site (single-source) and the umbrella cannot drift from the per-family artifacts.
- Nest the sub-artifacts verbatim (loss-preserving) rather than flattening, so the operator report can reference either the whole bundle or an individual family without a second schema per nested shape.

### Rejected alternatives

- Adding a `singular experiment-report` CLI subcommand — rejected here: it would own `cli/singular` (a pre-existing driver file, forcing the full-suite gate) and CLI-doc coverage belongs to the `polish-release` node, not `experiment-run`; the operator can invoke the composer directly.
- Extending `engine/ctx-experiment-report.sh` to fold in strategy + attempts — rejected: it is a pre-existing file (full-suite gate, new-file-convention friction) and its artifact is one metric family, not the umbrella bundle.

### Assumptions

- [validated] The composers `singular_ctx_experiment_report_json`, `singular_ctx_experiment_strategy_json`, and `singular_ctx_experiment_attempts_json` exist and each emit a deterministic sorted-key JSON artifact conforming to its own additive schema — basis: the public entry points of engine/ctx-experiment-report.sh, engine/ctx-experiment-strategy.sh, engine/ctx-experiment-attempts.sh.
- [open] The three composers take different input signatures (events; events + metrics; runs + events); the summary must route each input to the correct sub-composer per its existing signature rather than assuming a uniform arg list — basis: their differing parameter lists.
