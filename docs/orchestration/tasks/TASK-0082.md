## Objective

Assemble the `graph-projector` (layer `engine_runtime`) `rebuild` entry point — the composition keystone of `requiredCompletion` — by walking the durable S0-S5 sources, invoking every integrated projection mapper, and delegating canonical writing to the integrated loss-free corpus writer. This turns the mapper library into an actual `gluerun graph rebuild`. New file `engine/ctx-graph-rebuild.sh`, auto-sourced by the ctx-loader block in `engine/lib.sh`, defines functions ONLY (OFF-parity for `GLUERUN_CTX_GRAPH`, default 0; nothing invokes it; the eventual `cli/gluerun graph` call site is a later task). Implement two chained slices in order, each RED-first in `tests/test-ctx-graph-rebuild.sh`:

1. Kind-partition helper. `gluerun_graph_partition <nodesOut> <edgesOut>` reads a mixed node+edge JSONL stream on stdin and routes every `kind` `node` line to `<nodesOut>` and every `kind` `edge` line to `<edgesOut>`, losslessly and deterministically. This bridges the mappers' mixed stdout streams to the separate node/edge inputs that `gluerun_graph_write_corpus` expects.

2. Rebuild entry point. `gluerun_graph_rebuild <stateDir> [graphDir]` walks the durable sources under `<stateDir>` in sorted order and invokes each integrated mapper over its source set — `runs/*/attempts/index.json` via `gluerun_graph_project_attempts`; `docs/orchestration/gates/*.gate-result.json` via `gluerun_graph_project_gate_results`; `events.ndjson` via `gluerun_graph_project_plan_versions`, `gluerun_graph_project_decisions`, and `gluerun_graph_project_commits`; the plan-critique records via `gluerun_graph_project_critique`; the task markdown files via `gluerun_graph_project_task`; and `runs/*/paired-audit.json` via `gluerun_graph_project_paired_audits` — collects every emitted line, partitions it with slice 1, and calls `gluerun_graph_write_corpus <graphDir>` to write the canonical `nodes.jsonl` + `edges.jsonl`. `graphDir` defaults to `${GLUERUN_CTX_GRAPH_DIR:-.gluerun-state/graph}`. Consumes slice 1 + the integrated mappers + writer.

Determinism comes for free from the canonicalizer inside `gluerun_graph_write_corpus` (dedup by id + sort by id), so the final corpus is independent of walk/emission order provided the walk reads a complete, stable set of source files. The still-unmapped node families (goal, plan-batch, assumption, capsule) and the cross-record edges (depends_on, derived_from, critiques, accepts_observation/rejects_observation, contradicts) are added to this walk by follow-up mapper+wire tasks; `gluerun graph sync`, `gluerun graph query`, and the `cli/gluerun graph` driver hook are subsequent `graph-projector` tasks. This task advances `graph-projector` toward its `requiredCompletion` by delivering the deterministic, loss-free `rebuild`; it proposes the rebuild half of the exit gate as a candidate but does not complete the node.

## Context packet

### Decisions
- The spine COMPOSES the integrated mappers rather than re-implementing projection: it only enumerates sources, partitions the mixed stream by `kind`, and delegates all filesystem writing + canonicalization to the single integrated `gluerun_graph_write_corpus`. One canonicalization point keeps rebuild deterministic and sets up rebuild-equals-sync.
- Because the writer dedups by id and sorts by id, the final corpus is order-independent; the walk only needs to read a COMPLETE, stable set of source files (sorted globs), not emit in any particular order.
