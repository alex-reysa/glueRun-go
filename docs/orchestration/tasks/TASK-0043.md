## Objective

Complete the executable DAG node `artifact-secret-scan` (layer `engine_runtime`)
by making the already-integrated, currently-uncalled containment helpers live in
the drive loop. TASK-0041 shipped `--artifacts` detection
(`gluerun_ctx_artifact_scan`), and TASK-0042 shipped
`gluerun_ctx_artifact_quarantine` (rename `.quarantined` + one
`ctx.artifact_secret` event, non-blocking) and `gluerun_ctx_artifact_exclude`
(drop quarantined paths); none has a live caller yet.

Add a small, additive call-site hook in `engine/l1-drive.sh`, behind a new
default-OFF knob `GLUERUN_CTX_ARTIFACT_SCAN` (default 0):

- At the post-acceptance artifact-finalize region — beside the existing
  `gluerun_ctx_paired_audit_record` / critic-recheck hooks, and placed BEFORE
  the post-acceptance paired-audit fresh-audit prompt is assembled from durable
  artifacts — invoke `gluerun_ctx_artifact_quarantine "$run_dir"`. This renames
  any artifact that matches a secret pattern to `<path>.quarantined`, records the
  `ctx.artifact_secret` event, and leaves the run's accept/reject outcome
  unchanged. The call is non-fatal: on any error it logs an event and never
  aborts the drive (same pattern as the capsule-write-failed and paired-audit
  hooks).
- Where the drive enumerates durable artifacts to feed a rendered prompt, apply
  `gluerun_ctx_artifact_exclude` so a quarantined artifact is never included
  (belt-and-suspenders beyond the rename, which already removes the artifact
  from its canonical path).

When the knob is unset or `0`, `engine/l1-drive.sh` is byte-identical to current
behavior: no scan, no rename, no event. This is the finalize-site wire-in the
stage file requires for `artifact-secret-scan`; it does not flip the knob on by
default.

## Acceptance Criteria

- `tests/test-ctx-artifact-scan-hook.sh` is red before implementation and green
  after (strict_test_first).
- OFF (`GLUERUN_CTX_ARTIFACT_SCAN` unset or `0`): `engine/l1-drive.sh` behavior
  is byte-identical — no artifact scan runs, no artifact is renamed, and no
  `ctx.artifact_secret` event is emitted.
- ON: after a run whose durable artifact (a capsule, session-meta, context
  packet, critique record, or paired-audit record) contains a seeded fake
  secret, the finalize hook quarantines it — the artifact is renamed to
  `<path>.quarantined` and exactly one `ctx.artifact_secret` event referencing
  it is recorded — and the run's accept/reject outcome is unchanged.
- ON: a rendered prompt assembled from durable artifacts after the finalize hook
  (e.g. the post-acceptance paired-audit fresh-audit prompt) does not contain
  the seeded secret; the quarantined artifact is excluded.
- The hook is non-fatal and evidence-preserving: a quarantine error logs an
  event and never aborts the drive or changes the task outcome; the quarantined
  content is retained under its `.quarantined` name, not deleted.
- Advocate/skeptic line and evidence invariance preserved: quarantine is
  host-mechanical (rename + event) and creates no path by which a
  resumed/rehydrated session satisfies an independence-pinned step or a gate is
  weakened.
- `bash tests/run.sh` passes (full suite), including `test-ctx-artifact-scan.sh`,
  `test-ctx-artifact-quarantine.sh`, `test-ctx-artifact-exclude.sh`, and
  `test-engine-clean.sh`.
- Gate candidate (proposed, not a completion declaration): with this wire-in the
  `artifact-secret-scan` requiredCompletion is satisfied end-to-end —
  `--artifacts` detection covers all artifact classes, hits quarantine the
  artifact and exclude it from prompt assembly without changing task outcomes,
  and the artifact-scan test suite is green.

## Context packet

Decisions:
- Single wire-in slice in `engine/l1-drive.sh`: the only remaining
  requiredCompletion behavior is making the integrated quarantine/exclusion
  helpers live at the finalize and assembly sites, which all touch the same
  driver file — so this is one slice, not a two-slice fold.
- Place the quarantine hook BEFORE the post-acceptance paired-audit fresh-audit
  prompt assembly (which reads durable artifacts). Why: gives a concrete in-node
  demonstration of the exit gate — a seeded secret in a capsule is quarantined
  and cannot reach that rendered prompt.
- Reuse the existing post-acceptance hook region beside
  `gluerun_ctx_paired_audit_record` and the additive non-fatal `|| true` +
  event-on-failure pattern already established there.

Assumptions:
- [validated] `gluerun_ctx_artifact_quarantine` and `gluerun_ctx_artifact_exclude`
  are integrated and have no live caller — basis: engine/ctx-artifact-quarantine.sh,
  engine/ctx-artifact-exclude.sh, and no references in l1-drive.sh/reconcile.sh/cli.
- [open] the hook is behind default-OFF `GLUERUN_CTX_ARTIFACT_SCAN` and OFF is
  byte-identical — basis: planner-contract rule 3 (feature-flag discipline);
  default flips are a separate later task.
- [open] quarantine runs after the accept/reject outcome is finalized and is
  non-fatal, so it can never change the task outcome — basis: stage file
  "without changing task outcomes"; mirrors the paired-audit hook placement.
- [open] the hook must not weaken independence: quarantine only renames and
  records; it must not create a path where a resumed/rehydrated session
  satisfies an independence-pinned step — basis: planner-contract rule 8.

Rejected alternatives:
- Hook quarantine into `secret-scan.sh` — why not: that file is the CLI surface
  already extended in TASK-0041; the artifact-finalize events happen in the
  drive loop, so the call-site hook belongs in `l1-drive.sh`.
- Flip `GLUERUN_CTX_ARTIFACT_SCAN` on by default in this task — why not:
  feature-flag discipline; default flips are separate tasks after the stage
  exit gate.
- Add an enumeration-based exclusion pass to every artifact read site — why not:
  quarantine renames the offending artifact out of its canonical path, so
  canonical-path readers already miss it; apply `gluerun_ctx_artifact_exclude`
  only where the drive enumerates durable artifacts to build a prompt.

Inspected symbols:
- `gluerun_ctx_paired_audit_record` — the existing post-acceptance hook the new
  quarantine hook sits beside; role: fixes placement so quarantine runs before
  the paired-audit prompt is assembled, letting that prompt exclude quarantined
  artifacts.
- `gluerun_append_event` — the recorder for the non-fatal failure event,
  matching the capsule-write-failed pattern already in the finalize region.
