## Objective

Advance the `routing-module` node (layer `engine_runtime`, stage S5-routing) toward the requiredCompletion clause "`engine/ctx-route.sh` returns one of continue/resume/fork/fresh/rehydrate with reason". Today the composed spine (`engine/ctx-route.sh`) frames every wrapped-decider `resume` verdict as the bare `resume` strategy, so the stage's distinct `continue` strategy — "same session, same lineage, next phase" (planner revision; implementer retry-resume), as opposed to `resume` = "a persisted specialist re-engaged" (critic recheck, reviewer re-audit) — is never realized.

Ship the missing LEAF: a new pure predicate `engine/ctx-route-strategy.sh` that classifies a would-be resume into `continue` vs `resume` from `<role>` and `<step>`, exactly as the window/diff/lease/taint leaves were shipped before the TASK-0047 spine composed them. This slice ships the predicate present-but-uncalled; the `ctx-route.sh` relabel wire-in that consumes it is a SEPARATE later slice and is OUT OF SCOPE here.

## Acceptance Criteria

- `engine/ctx-route-strategy.sh` is auto-sourced by the existing ctx-loader block in `lib.sh` (the `engine/ctx-*.sh` convention) and defines a NEW pure predicate function only. No existing engine path invokes it; with the file present the engine is byte-identical to prior behavior and `bash tests/test-engine-clean.sh` stays green (no project-specific symbols). Do NOT edit `engine/ctx-route.sh` or any driver hook.
- The predicate takes `<role> <step>` and prints EXACTLY one line: one token from `{continue, resume}`. It appends no events, writes no files, and never exits non-zero on any input (leaf discipline mirroring `engine/ctx-route-taint.sh` and `engine/ctx-route-window.sh`).
- Primary-lineage continuation classifies as `continue`: the actor re-engaging its OWN lineage's next phase — the planner revising its node's plan, and the implementer/worker retry-resuming its own task.
- Specialist re-engagement classifies as `resume`: a persisted specialist re-invoked over accepted work — critic recheck and reviewer re-audit (and any skeptic/advocate re-invoked as an auditor).
- Fail-closed default: an unrecognized or empty role/step classifies as `resume`, never `continue`. Because `continue` is untainted and `resume` is tainted (`singular_ctx_route_strategy_tainted continue` prints 0, `... resume` prints 1), defaulting an unknown case to `continue` could let a tainted session appear independence-eligible; failing closed to the tainted label upholds planner-contract rule 8 (the advocate/skeptic line and evidence invariance).
- Taint consistency is pinned behaviorally (never by an absence/present-but-uncalled grep, planner-contract rule 9): for every fixture input, feeding the predicate's output into `singular_ctx_route_strategy_tainted` yields 0 for `continue` and 1 for `resume`.
- Strict-test-first: `tests/test-ctx-route-strategy.sh` fails (RED) before the engine file exists and passes (GREEN) after, enumerating each classified strategy together with its reason (role/step basis); the gate command `bash tests/test-ctx-route-strategy.sh && bash tests/test-engine-clean.sh` passes.
- Gate candidate (proposed, NOT a completion declaration): once this leaf and its later `ctx-route.sh` relabel wire-in land, the spine emits all realized routing strategies — `continue`, `resume`, `fresh` — each reason-coded and enumerated by `tests/test-ctx-route.sh`, satisfying the requiredCompletion "returns one of continue/resume/fork/fresh/rehydrate with reason" clause for `routing-module`.
