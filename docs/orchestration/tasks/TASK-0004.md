## Objective

Advance the executable DAG node `ab-harness` (layer `harness`, stage `S0-baseline`) toward its required completion: deterministic per-task A/B arm assignment behind the default-OFF `GLUERUN_CTX_AB` knob, recorded as `ctx.arm_assigned` events, with zero events when the knob is OFF.

Add a new self-contained `engine/ctx-ab.sh` that defines assignment functions only. It is auto-sourced by the already-integrated `ctx-loader` block in `lib.sh` (do NOT edit `lib.sh`); no existing engine path invokes it, so present-but-uncalled the engine is byte-identical to current behavior. Assignment maps a task id to an arm in `{A,B}` via a stable content hash (e.g. a SHA-256 / cksum of the task id reduced modulo 2), NOT `$RANDOM` or any process/host-specific source, so the mapping is machine-independent and identical across repeated invocations and machines. When `GLUERUN_CTX_AB=1`, the assignment is recorded by appending one `ctx.arm_assigned` event (via the existing `gluerun_append_event` helper) whose data carries at least the task id and the assigned arm; when `GLUERUN_CTX_AB` is unset or `0`, the function emits NO event and performs no other side effect on the events log. Arms carry no downstream behavioral difference in this stage — assignment and its event are the only effects (later stages key their knobs off the arm). This node owns no driver-file hook and no schema change; the event uses the existing events log.

Write `tests/test-ctx-ab.sh` first (red before implementation, green after): it sources the engine, drives the assignment function directly, and asserts (a) OFF (`GLUERUN_CTX_AB` unset and `=0`) → zero `ctx.arm_assigned` events appended to an isolated events log; (b) determinism — the same task id always yields the same arm across repeated calls and across separate `bash` processes, and both arms are drawn from `{A,B}`; (c) distribution sanity over a fixture id set — both arm A and arm B occur and no id maps to two different arms; (d) with `GLUERUN_CTX_AB=1`, each assignment appends exactly one `ctx.arm_assigned` event whose data includes the task id and its arm. Point the events log at an isolated temp file (`GLUERUN_EVENTS_FILE`) so the suite never mutates real run state. `tests/run.sh` auto-discovers `tests/test-*.sh`, so no runner edit is needed.

Because this is the smallest single ready slice for `ab-harness` and the max task count is 1, this batch emits exactly one task.

## Acceptance Criteria

- `GLUERUN_CTX_AB` unset or `0`: invoking the assignment function appends ZERO `ctx.arm_assigned` events and makes no other change to the events log (default-OFF, byte-identical behavior).
- `GLUERUN_CTX_AB=1`: the assignment function maps every task id to exactly one arm in `{A,B}` and appends exactly one `ctx.arm_assigned` event per assignment, via `gluerun_append_event`, with event data including the task id and the assigned arm.
- Determinism: the same task id always resolves to the same arm across repeated calls and across separate processes; the mapping is machine-independent (derived from a stable content hash of the task id, not `$RANDOM` or any host/process-specific source).
- Distribution sanity: over the fixture id set, both arms A and B occur and no id ever maps to two different arms.
- No behavior differs between arms in this stage; `engine/ctx-ab.sh` defines new functions only and is not invoked by any existing engine path (present-but-uncalled → engine byte-identical), and does not edit `lib.sh` or any driver file.
- `tests/test-ctx-ab.sh` exists, was red before implementation and green after, and covers OFF→no-events, determinism, distribution sanity, and event shape using an isolated `GLUERUN_EVENTS_FILE`.
- Gate command `bash tests/run.sh` is green, including `test-ctx-ab.sh` and `test-engine-clean.sh`.
- Gate candidate (advisory, not a completion declaration): with these behaviors verified, `ab-harness` meets its `requiredCompletion` — deterministic per-task arm assignment behind `GLUERUN_CTX_AB` (default 0) recorded as `ctx.arm_assigned` events, OFF emits nothing, `test-ctx-ab.sh` green.
