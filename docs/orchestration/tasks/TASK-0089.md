## Objective

Advance the `experiment-run` executable DAG node (layer `evaluation`) by computing the treatment-vs-control CONTRAST that the per-arm aggregators do not: arm B (treatment) minus arm A (control / M0 knob-state) for each headline metric. The full per-arm measurement suite is integrated — TASK-0077 `engine/ctx-experiment-report.sh` (escape-rate/cost/bias), TASK-0079 `engine/ctx-experiment-strategy.sh` (resume/rehydrate hit rates + refusal mix), TASK-0081 `engine/ctx-experiment-attempts.sh` (attempts-to-accept + findings-per-attempt), TASK-0083 `engine/ctx-experiment-summary.sh` (umbrella bundle), TASK-0085 `engine/ctx-experiment-render.sh` (markdown tables), and TASK-0087 `engine/ctx-experiment-pipeline.sh` (end-to-end guard) — but every one reports ABSOLUTE per-arm values. The requiredCompletion clause `per-knob default decisions` turns on the A-vs-B delta (does the treatment lower escape rate, at what cost/attempts delta, with what bias?), and no brick computes it. This task ships that delta as decision-support tooling; it does NOT decide which knobs flip, map metrics to specific knobs, author `docs/context-build-plan/experiment-report.md`, or record per-knob default decisions in `docs/orchestration/decisions.md` — all OPERATOR authority (kind: evaluation). It neither declares nor gates node completion.

All logic lands in one NEW `engine/ctx-experiment-delta.sh`, auto-sourced by the ctx-loader block and defining new functions only. No existing engine path invokes them, so the engine is byte-identical with the file present (OFF-parity intrinsic, mirroring the sibling `engine/ctx-experiment-*.sh` idiom). It does NOT edit the six sibling `ctx-experiment-*.sh` files, `engine/ctx-metrics.sh`, or any other pre-existing file. It reads only the summary bundle (obtained by delegating to `gluerun_ctx_experiment_summary_json`, or from a supplied bundle source) and computes DIFFERENCES of the already-computed per-arm values — it re-derives no base metric and creates, moves, or mutates nothing.

Implement three chained slices in order, all inside `engine/ctx-experiment-delta.sh`:

1. Pure delta helper: given the two arm sub-objects and a metric value path, produce a stable record {a, b, delta} where delta = b minus a, plus a NEUTRAL direction label in {lower, higher, equal} describing B relative to A. Deterministic; a missing arm value is treated as zero.

2. Headline metric-set consumer: apply the helper across the headline metrics read from the summary bundle — escape rate, cost (tokens and wall-clock per accepted task), attempts-to-accept mean, findings-per-attempt mean, bias directional-disagreement rate, resume hit rate, and rehydrate hit rate.

3. Composed public entry `gluerun_ctx_experiment_delta_json [runs_dir] [events_file] [metrics_file]`: obtain the summary bundle (explicit corpus args threaded through `gluerun_ctx_experiment_summary_json`, or a supplied bundle source), assemble the per-metric treatment-effect deltas into ONE deterministic sorted-key JSON object conforming to a NEW additive schema `gluerun.orchestration.ctx-experiment-delta.v0`. Fail-safe: missing or empty inputs yield well-formed zeroed deltas and a zero exit, never an error or partial output.

## Context packet

### Decisions

- Compute B-minus-A deltas of the already-computed per-arm summary values rather than re-deriving base metrics, so each metric keeps one upstream definition site and the contrast cannot drift from the per-arm artifacts.
- Emit only numeric deltas plus a neutral direction (lower/higher/equal), never a better/worse or flip judgment and never a per-knob mapping, so the decision authority (which knobs flip default-ON) stays with the operator and `engine/` stays project-agnostic (test-engine-clean).

### Rejected alternatives

- Mapping metrics to specific knobs and recommending flips — rejected: that is the operator's per-knob default decision (requiredCompletion names it operator-driven) and would put project-specific knob names in `engine/`, breaking engine cleanliness.
- Folding the delta into the summary bundle or renderer — rejected: those are integrated pre-existing files (full-suite gate, new-file-convention friction) and the contrast is a separately-referenceable artifact.

### Assumptions

- [validated] The summary bundle carries per-arm A/B values for escapeRate, cost (tokens and wall-clock), bias directionalDisagreementRate, attemptsToAcceptMean, findingsPerAttemptMean, resumeHitRate, and rehydrateHitRate — basis: engine/ctx-experiment-summary.sh and the ctx-experiment-summary.v0 schema keys.
- [open] Some metrics may be present for only one arm on a sparse corpus; the delta treats a missing arm value as zero and still emits a well-formed entry rather than erroring — basis: the fail-safe contract of the sibling aggregators.
