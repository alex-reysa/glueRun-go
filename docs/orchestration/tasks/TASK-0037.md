## Objective

Advance the executable DAG node `assumption-ledger` (layer `engine_runtime`, stage
`S4-context-packets`) toward its `requiredCompletion` headline — the ledger "flows
into fix and audit prompts". The seed (`gluerun_ctx_assumptions_seed`) and the
host-derived transition (`gluerun_ctx_assumptions_transition`) are integrated, so the
ledger already carries stable `A1..An` ids and host-set `violated` statuses. This
slice ships the pure render brick that turns that ledger into prompt text: a new
`engine/ctx-assumptions-prompt.sh` with two pure helpers.
`gluerun_ctx_assumptions_fix_section <ledger-json>` renders the implementer/fix-prompt
section, calling out `violated` assumptions like open findings (with the rest for
context). `gluerun_ctx_assumptions_audit_section <ledger-json>` renders the
auditor-prompt section instructing the auditor to verify the assumptions were not
silently violated and to flag any violation as a finding that cites the assumption's
id — closing the loop with the host-derived transition, which resolves such a finding
by its id and flips the entry to `violated`.

Both helpers are pure string→string transforms over the ledger argument: they read no
files, consult no flag, and emit no events. Like the seed and transition files, this
file is auto-sourced by the ctx loader block yet called by no default
engine/CLI/driver path, so behavior under `GLUERUN_CTX_PACKET=0` stays byte-identical.
This slice does NOT touch driver files, does NOT inject into any real prompt, does NOT
add per-attempt carry or capsule recording, and does NOT add or consult the flag —
those are later slices for this node.

## Context packet

### Decisions

- Two render helpers in one file, one per prompt sink (fix, audit), because both walk the same ledger with the same violated-as-open-finding convention — splitting them would duplicate the walk and formatting and produce two bricks the single wire-in hook must both await.
- The auditor section explicitly directs findings to cite the assumption id — this is what lets the host-derived transition resolve a finding to a ledger entry and flip it to `violated`; without the id citation the loop cannot close host-side.
- A zero-assumptions ledger renders the empty string (not a header with an empty list) so the later flag-gated injection is a true no-op and prompts stay byte-identical when a task has no assumptions.

### Assumptions

- [validated] the ledger shape is exactly what `gluerun_ctx_assumptions_seed` and `gluerun_ctx_assumptions_transition` emit — the schema const plus an `assumptions` array of `{id,status,claim,basis}` with stable `A1..An` ids and host-set `violated` statuses — engine/ctx-assumptions.sh and engine/ctx-assumptions-transition.sh.
- [open] the flag-gated injection into the real implementer/auditor prompts, the per-attempt carry (like the findings ledger), and the capsule recording of statuses are LATER slices for `assumption-ledger`; this slice must not touch driver files, must not consult or add `GLUERUN_CTX_PACKET`, and must not inject into any prompt — stage-4 node wire-in bullets.

### Rejected alternatives

- Consulting `GLUERUN_CTX_PACKET` inside the render helper — the flag gate belongs at the wire-in site so the render stays a pure, independently testable transform; a helper that reads the flag would smear the gate across two slices.
- Rendering violated assumptions as ordinary context lines rather than open-finding-like call-outs — loses the stage requirement that violated assumptions are surfaced to the implementer like open findings.

### Inspected symbols

- `gluerun_ctx_assumptions_transition` — the host-derived transition that consumes auditor findings citing an assumption id; the audit section this slice renders is what elicits those id-citing findings, so the two must agree on the id form (`A1`, `A2`, …).
