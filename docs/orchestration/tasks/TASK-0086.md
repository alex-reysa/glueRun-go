## Objective

Deliver the `graph-projector` (layer `engine_runtime`) `query` read API — the third and final `requiredCompletion` verb alongside the integrated `rebuild` (TASK-0082) and `sync` (TASK-0084). It is a read-only, deterministic reader over the materialized corpus `<graphDir>/nodes.jsonl` + `<graphDir>/edges.jsonl` (canonical: dedup + sorted by id). New file `engine/ctx-graph-query.sh`, auto-sourced by the ctx-loader block in `engine/lib.sh`, defines functions ONLY (OFF-parity for `GLUERUN_CTX_GRAPH`, default 0; nothing invokes them; the eventual `cli/gluerun graph` call site is a later task). Implement three mutually-independent read modes, each RED-first in `tests/test-ctx-graph-query.sh`:

1. Neighbors. `gluerun_graph_query_neighbors <graphDir> <nodeId>` returns, deterministically, every edge incident to `<nodeId>` (as `from` or `to`) and the adjacent node ids. An unknown node id yields a well-formed empty result, not an error.

2. Lineage walk. `gluerun_graph_query_lineage <graphDir> <startNodeId>` returns the provenance lineage reachable from the start node by following the provenance-edge taxonomy (task -> attempt -> plan-version -> critiques -> findings -> dispositions), in deterministic order, with a visited-set guard so cycles terminate.

3. Open-contradictions. `gluerun_graph_query_open_contradictions <graphDir>` returns exactly the `contradicts` / `invalidates` edges that have NO superseding resolution — i.e. no `supersedes` edge resolving the contradicted/invalidated node — deterministically ordered.

Each function reads only the two corpus files, writes nothing, and emits byte-identical output for a given corpus. The lineage walk is defined over the GENERAL edge taxonomy rather than the currently-emitted subset, so its test builds a self-contained fixture corpus containing the lineage edges instead of asserting which edges today's mappers emit (planner-contract rule 9). The `cli/gluerun graph` driver hook and the remaining node/edge coverage are subsequent `graph-projector` tasks. This task advances `graph-projector` toward its `requiredCompletion` by delivering `query`; with `rebuild`, `sync`, and `query` now all present, deterministic, and loss-free, it proposes the query third of the exit gate as a candidate but does not complete the node.

## Context packet

### Decisions
- Query is corpus-driven and read-only: it parses `<graphDir>/nodes.jsonl` + `edges.jsonl` (the output of rebuild/sync) and never re-projects, so it composes with both entry points and inherits their determinism.
- The lineage walk follows the general provenance-edge taxonomy (implements, revises, critiques, derived_from, accepts_observation, rejects_observation, ...) with a visited-set cycle guard; its test uses a self-contained fixture corpus containing those edges rather than asserting the current mappers' partial edge coverage — avoiding a slice-boundary temporal assertion (rule 9).
- open-contradictions filters `contradicts`/`invalidates` edges to those with no resolving `supersedes` edge, per the stage-file definition.

### Assumptions
- [validated] rebuild/sync write the corpus as `<graphDir>/nodes.jsonl` + `<graphDir>/edges.jsonl`, canonical (dedup + sorted by id) — basis: TASK-0075/0082/0084 integrated.
- [validated] the edge taxonomy includes `contradicts`/`invalidates`/`supersedes` for the contradiction query and `implements`/`critiques`/`revises`/`derived_from` for lineage — basis: schemas/context-graph.v0.schema.json.
- [open] `python3` is available for JSON parsing and the graph walks in the query and its test — basis: prior graph code relies on it.

### Rejected alternatives
- Having query re-run projection/rebuild internally — rejected: query is a read API over the already-materialized corpus; re-projecting would couple it to source layout and forfeit the determinism the corpus already guarantees.
- Asserting in the lineage test that critiques/derived_from edges are absent under today's partial coverage — rejected: that is a temporal negative assertion (rule 9); the test instead builds a fixture corpus with those edges present so it survives later mapper slices landing.
