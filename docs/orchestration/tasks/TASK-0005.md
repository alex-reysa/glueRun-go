## Objective

Advance the executable DAG node `paired-audit` (layer `engine_runtime`, stage `S0-baseline`) toward its required completion: a sampled post-acceptance FRESH audit behind the default-OFF `GLUERUN_PAIRED_AUDIT_PCT` knob that records a verdict and findings without changing any task outcome.

Add a new self-contained `engine/ctx-paired-audit.sh` that defines the paired-audit functions only. It is auto-sourced by the already-integrated `ctx-loader` block in `lib.sh` (do NOT edit `lib.sh`); no existing engine path invokes it yet, so present-but-uncalled the engine is byte-identical to current behavior. The `l1-drive.sh` post-acceptance call site is the FIRST `l1-drive.sh` hook this node owns and is the follow-up slice of this node — it is out of scope here.

Provide two things. First, a deterministic sampling gate keyed on a stable content hash of the run/task id reduced modulo 100 (never `$RANDOM` or any host/process-specific source), so the sampled decision honors `GLUERUN_PAIRED_AUDIT_PCT`: `0` (unset or `0`) never samples; `100` always samples; a mid value samples a deterministic, reproducible subset — machine-independent and identical across repeated calls and separate processes. Second, a recorder entry point that, only when sampled, runs exactly ONE additional auditor pass over the just-accepted result — always a FRESH session (no `--resume`/session reuse), the base auditor prompt (`$GLUERUN_ORCH_DIR/prompts/auditor.md`), read-only — via the configured runner (`GLUERUN_RUNNER`, stubbable in tests). It captures the paired verdict and findings and records them as one `ctx.paired_audit` event (via `gluerun_append_event`) plus a `paired-audit.json` in the run dir. Disagreement — paired verdict != `accepted` OR non-empty paired findings — is flagged in both the event data and the record; agreement is recorded otherwise.

The recorder MUST run strictly after acceptance and only record: it must not create, move, or mutate the packet, the primary audit record, the lease, the task file, or the inbox placement, and the paired verdict must never feed back into the accept/reject decision. When the knob is OFF (unset or `0`), it performs no fresh audit, appends no event, and writes no `paired-audit.json` — the acceptance flow is byte-identical. This slice owns no schema change and no driver-file hook; the event uses the existing events log and the record is a plain JSON file in the run dir.

Write `tests/test-ctx-paired-audit.sh` first (red before implementation, green after). It sources the engine, points `GLUERUN_EVENTS_FILE` at an isolated temp file, uses a temp run dir, drives the recorder directly with a stub `GLUERUN_RUNNER`, and asserts: (a) OFF (`GLUERUN_PAIRED_AUDIT_PCT` unset and `=0`) yields no `ctx.paired_audit` event, no `paired-audit.json`, and an otherwise untouched events log and run dir; (b) `PCT=100` with a stub runner returning an accepted, findings-empty verdict records exactly one `ctx.paired_audit` event and one `paired-audit.json` flagged as agreement, with no write to any packet/lease/inbox/primary-audit path; (c) `PCT=100` with a stub runner returning a disagreeing verdict (verdict != accepted or non-empty findings) flags disagreement in both the event and the record; (d) sampling determinism — the decision is reproducible for the same id across repeated calls and separate `bash` processes, `PCT=0` never samples any id in a fixture set and `PCT=100` always does; (e) freshness — the stub records that it was invoked fresh (no resume/session reuse) and read-only. `tests/run.sh` auto-discovers `tests/test-*.sh`, so no runner edit is needed.

Because this is the smallest single ready slice for `paired-audit` and the max task count is 1, this batch emits exactly one task.

- `GLUERUN_PAIRED_AUDIT_PCT` unset or `0`: invoking the recorder runs no fresh audit, appends ZERO `ctx.paired_audit` events, writes no `paired-audit.json`, and makes no other change — the post-acceptance flow is byte-identical (default-OFF).
- `GLUERUN_PAIRED_AUDIT_PCT=100`: for a sampled accepted task the recorder runs exactly one FRESH, read-only auditor pass via `GLUERUN_RUNNER` using the base auditor prompt, and records its verdict and findings as exactly one `ctx.paired_audit` event (via `gluerun_append_event`) plus one `paired-audit.json` in the run dir.
- Sampling honors the knob deterministically: `0` never samples; `100` always samples; a mid value samples a reproducible subset. The decision derives from a stable content hash of the run/task id (machine-independent; never `$RANDOM` or host/process-specific input) and is identical across repeated calls and separate processes.
- Disagreement — paired verdict != `accepted` OR non-empty paired findings — is flagged in both the `ctx.paired_audit` event data and the `paired-audit.json` record; agreement is recorded otherwise.
- Evidence invariance / no outcome change: the recorder runs strictly after acceptance and only records; it does not create, move, or modify the packet, the primary audit record, the lease, the task file, or the inbox placement, and the paired verdict never feeds back into the accept/reject decision.
- `engine/ctx-paired-audit.sh` defines new functions only, is auto-sourced by the integrated `ctx-loader` block, is not invoked by any existing engine path (present-but-uncalled → engine byte-identical), and does not edit `lib.sh` or any driver file.
- `tests/test-ctx-paired-audit.sh` exists, was red before implementation and green after, and covers OFF→no-record, PCT=100 agreement recording, disagreement recording, sampling determinism/knob honoring, and fresh+read-only invocation, using an isolated `GLUERUN_EVENTS_FILE`, a temp run dir, and a stub `GLUERUN_RUNNER`.
- Gate command `bash tests/run.sh` is green, including `test-ctx-paired-audit.sh` and `test-engine-clean.sh`.

The remaining `l1-drive.sh` post-acceptance call-site wiring is the follow-up slice of this node.
