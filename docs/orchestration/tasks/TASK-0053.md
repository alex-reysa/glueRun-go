## Objective

Third strict-test-first slice of the executable DAG node `rehydrate-path` (stage `S5-routing`, layer `engine_runtime`). TASK-0051 shipped the pure packet assembler `engine/ctx-rehydrate.sh` (`gluerun_ctx_rehydrate_packet` / `gluerun_ctx_rehydrate_manifest`, consuming class-tagged `<id>=<path>` specs); TASK-0052 shipped the pure rehydrate-vs-fresh decision leaf `engine/ctx-route-rehydrate.sh` (`gluerun_ctx_route_rehydrate_decide`, whose 4th argument is the packet **manifest**). Nothing yet resolves the durable-artifact `<id>=<path>` specs those consume from a lineage step, so neither the manifest nor the packet can be built by the routing spine.

This slice adds that missing prerequisite: a new pure, read-only leaf `engine/ctx-rehydrate-sources.sh` that enumerates the class-tagged durable rehydration sources present under a run directory. It DEFINES a new function only and is present-but-uncalled by every existing engine/CLI/driver path, so with it sourced the engine stays byte-identical to current behavior. The `engine/ctx-route.sh` / `engine/ctx-route-drive.sh` spine wire-in (composing resolver → `gluerun_ctx_rehydrate_manifest` → `gluerun_ctx_route_rehydrate_decide`, emitting `rehydrate` on a refused-resume lineage step and stamping the manifest into the strategy event) and the `l1-drive.sh` packet-injection hook are SEPARATE later slices and are OUT OF SCOPE here.

The canonical durable-artifact root is `run_dir = dirname(meta)` — the same root `engine/ctx-route-drive.sh` derives and `gluerun_ctx_artifact_scan_paths` scans. But that scan set returns bare, untagged paths and includes raw provider session logs (`session-*.json`) that must NOT be injected as durable context. The assembler instead requires a curated, class-tagged subset, so this leaf is distinct.

Behavior of `engine/ctx-rehydrate-sources.sh` (node `rehydrate-path`, layer `engine_runtime`) — a function such as `gluerun_ctx_rehydrate_sources <run_dir> [extra-id=path ...]`:

- Prints, one per line, `<id>=<path>` specs for each durable rehydration source that EXISTS under `<run_dir>`, tagged with the assembler's source-class id, in a fixed documented order, deterministically (independent of filesystem enumeration).
- Class → `run_dir` file mapping (single-sourced here): `task-packet`→`packet.json`, `implementer-capsule`→`implementer-capsule.json`, `reviewer-capsule`→`reviewer-capsule.json`, `findings-ledger`→`findings-status.json`, `critique-record`→`plan-critique.json` (plus `assumptions-ledger` and `decision-record` — see Context packet).
- Existing-files-only: a class is emitted only when its mapped file exists (`-f`), mirroring `gluerun_ctx_artifact_scan_paths`; a missing artifact contributes nothing.
- Caller-supplied `extra-id=path` specs (e.g. repo-level decision records that live outside `run_dir`) are appended verbatim after the `run_dir`-resolved specs.
- The ids MUST exactly match the assembler's source-class ids so the resolver's stdout composes directly as arguments to `gluerun_ctx_rehydrate_packet` / `gluerun_ctx_rehydrate_manifest`.
- Quarantine exclusion is NOT performed here: the assembler/manifest already compose `gluerun_ctx_artifact_exclude`, so a single quarantine authority is preserved; the resolver only enumerates candidates.
- Pure and read-only: it inspects paths but never writes, renames, or deletes; appends no events; and never exits non-zero on well-formed input (an absent/empty `run_dir` yields no specs, non-fatal). It confers no independence — the `rehydrate` strategy remains tainted per `gluerun_ctx_route_strategy_tainted`.

## Acceptance Criteria

- `tests/test-ctx-rehydrate-sources.sh` is written first and fails (red) before `engine/ctx-rehydrate-sources.sh` exists, then passes (green) after implementation; `bash tests/test-engine-clean.sh` stays green (no project-specific symbols in `engine/`).
- Enumeration + omission: given a fixture `run_dir` containing `packet.json`, `implementer-capsule.json`, and `findings-status.json` but NOT `reviewer-capsule.json`, the function emits exactly `task-packet=<run_dir>/packet.json`, `implementer-capsule=<run_dir>/implementer-capsule.json`, and `findings-ledger=<run_dir>/findings-status.json` — one per line, class-tagged, in the fixed order — and omits the absent `reviewer-capsule` class.
- Determinism: two runs over the same fixture yield byte-identical output; the order is fixed and independent of on-disk enumeration order.
- Composition: passing the resolver's output as arguments to `gluerun_ctx_rehydrate_manifest` produces a manifest whose `sources` ids are exactly the resolved, non-quarantined classes; a quarantined artifact under `run_dir` is still enumerated by the resolver yet excluded from the manifest by the assembler (quarantine authority stays in the assembler) — assert the manifest omits it.
- Extra specs: `gluerun_ctx_rehydrate_sources <run_dir> decision-record=<path>` appends the caller-supplied `decision-record=<path>` spec after the `run_dir`-resolved specs.
- Purity / evidence invariance: the function writes/renames/deletes no files, appends no events, and never exits non-zero on well-formed input; an absent or empty `run_dir` yields no specs and is non-fatal; the leaf grants no independence (the `rehydrate` strategy stays tainted per `gluerun_ctx_route_strategy_tainted`).
- Gate candidate: with this resolver integrated, the manifest/packet source set is single-sourced and table-tested; the remaining `rehydrate-path` slices are the `engine/ctx-route.sh` / `engine/ctx-route-drive.sh` spine wire-in (compose resolver → manifest → decision, emit `rehydrate`, record the manifest in the strategy event; owns existing files, full-suite gate) and the `l1-drive.sh` packet-injection hook — after which the node exit gate (`test-ctx-rehydrate.sh` green plus suite) can be proposed.

## Context packet

Decisions:

- Ship a dedicated class-tagged source resolver as the next leaf rather than reusing `gluerun_ctx_artifact_scan_paths`: the scan set returns bare, untagged paths and includes raw provider session logs (`session-*.json`) that are NOT durable rehydration sources, whereas the assembler/manifest require class-tagged `<id>=<path>` specs from a curated subset. Basis: `engine/ctx-rehydrate.sh` RANK ids versus the contents of `gluerun_ctx_artifact_scan_paths`.
- Leaf-before-spine: build the resolver (new file, scoped gate) before the `engine/ctx-route.sh` / `engine/ctx-route-drive.sh` wire-in (existing files, full-suite gate), so the eventual wire-in is a thin compose of resolver → `gluerun_ctx_rehydrate_manifest` → `gluerun_ctx_route_rehydrate_decide`, mirroring routing-module's leaf → spine → driver sequence.
- Quarantine exclusion stays in the assembler (which composes `gluerun_ctx_artifact_exclude`), not the resolver; the resolver only enumerates candidates, keeping a single quarantine authority. Basis: the TASK-0051 assembler already filters.
- Root the resolver at `run_dir = dirname(meta)` — the canonical durable-artifact root `engine/ctx-route-drive.sh` already derives and the secret-scan enumerates over — so the later spine can hand it the `run_dir` it already holds.

Assumptions:

- [validated] The durable `run_dir` artifacts and their filenames are `packet.json` (task-packet), `implementer-capsule.json`, `reviewer-capsule.json`, `findings-status.json` (findings-ledger, `engine/lib.sh`), and `plan-critique.json` (critique-record) — per `gluerun_ctx_artifact_scan_paths` and the lib.sh findings ledger.
- [open] The durable `assumptions-ledger` file under `run_dir` — the implementer must ground it in what `engine/ctx-assumptions*.sh` actually persists (the ledger is computed as `carry(prior, seed)`; confirm whether and where it is written durably) and map it to the `assumptions-ledger` id; if it is not durably persisted, omit that class rather than invent a path.
- [open] `decision-record` sources live outside `run_dir` (repo-level decision records), so the resolver accepts them as caller-supplied `extra-id=path` specs rather than rooting them in `run_dir`.
- [validated] The assembler's source-class ids and fixed order are `task-packet`, `implementer-capsule`, `reviewer-capsule`, `findings-ledger`, `assumptions-ledger`, `critique-record`, `decision-record` (`engine/ctx-rehydrate.sh` RANK) — the resolver's ids MUST match these exactly so its output composes into `gluerun_ctx_rehydrate_packet` / `gluerun_ctx_rehydrate_manifest`.

Rejected alternatives:

- Reusing `gluerun_ctx_artifact_scan_paths` directly in the spine — rejected: its paths are untagged and include `session-*.json` raw provider logs that must never be injected as durable context.
- Filtering quarantine inside the resolver — rejected: duplicates the assembler's `gluerun_ctx_artifact_exclude` authority; keep one quarantine gate.
- Folding the resolver into the `engine/ctx-route.sh` spine wire-in — rejected: that owns existing files (full-suite gate) and couples enumeration to strategy-event recording; the resolver is independently table-testable as a pure new-file leaf.
