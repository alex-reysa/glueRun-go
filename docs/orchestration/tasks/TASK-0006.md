## Objective

Advance the executable DAG node `paired-audit` (layer `engine_runtime`, stage `S0-baseline`) toward its required completion by wiring the already-integrated recorder into the driver: add the FIRST `l1-drive.sh` post-acceptance hook this node owns so a sampled fresh audit is actually recorded after a task is accepted, still without changing any outcome.

The recorder functions (`gluerun_ctx_paired_audit_record` and its sampling gate) already exist in the integrated `engine/ctx-paired-audit.sh`, but no engine path calls them, so paired audits never run in practice. This slice adds exactly one minimal call site in `engine/l1-drive.sh` that delegates into `gluerun_ctx_paired_audit_record "$run_id" "$task_id" "$run_dir" "$worktree"`, placed STRICTLY AFTER acceptance is fully finalized — after the packet status is set to `accepted`, the lease and task statuses are set to `accepted`, `record-decision.sh --decision accept` has run, the inbox packet has been written to `$GLUERUN_INBOX_DIR/$run_id.json`, and the `l1.task_accepted` event has been appended (i.e. immediately after that event, at the end of the accept block). The hook is the minimum lines that delegate into the `ctx-*.sh` function; it needs no conditional of its own because the recorder self-guards on the default-OFF `GLUERUN_PAIRED_AUDIT_PCT` knob (unset or `0` → no fresh audit, no event, no file → the acceptance flow is byte-identical). The paired verdict is observability only and MUST NEVER feed back into the accept/reject decision, reorder or gate acceptance, or change the process exit status; a recorder or runner failure leaves the accepted outcome untouched. The hook runs only on the accepted path — not on needs-fix/blocked/parked terminal paths. No schema change, no `lib.sh` edit, and no change to `engine/ctx-paired-audit.sh`.

Write `tests/test-l1-drive-paired-audit-hook.sh` first (red before the hook, green after). Drive a task through the `l1-drive.sh` acceptance path in a hermetic temp `GLUERUN_ROOT` with an isolated `GLUERUN_EVENTS_FILE`, a stub `GLUERUN_RUNNER` that yields an accepted verdict, and (as needed) stubbed provisioning, and assert: (a) default-OFF (`GLUERUN_PAIRED_AUDIT_PCT` unset and `=0`) the accepted path produces the same acceptance artifacts and events and NO `ctx.paired_audit` event and NO `paired-audit.json` — byte-identical to pre-hook behavior; (b) `PCT=100` on an accepted task produces exactly one `ctx.paired_audit` event and one `paired-audit.json` in the run dir while the acceptance outcome — packet status `accepted`, lease/task status `accepted`, the accept decision, the inbox packet at `$GLUERUN_INBOX_DIR/$run_id.json`, and the `l1.task_accepted` event — is unchanged and the `ctx.paired_audit` event is ordered strictly after `l1.task_accepted`; (c) the paired result never changes the accept/reject decision or exit status, and a failing paired runner still yields the same accepted outcome; (d) a non-accepted (needs-fix/parked) run invokes no paired audit. `tests/run.sh` auto-discovers `tests/test-*.sh`, so no runner edit is needed.

Because this is the single smallest ready follow-up slice of `paired-audit` and the max task count is 1, this batch emits exactly one task.

## Acceptance Criteria

- `GLUERUN_PAIRED_AUDIT_PCT` unset or `0` (default-OFF): the `l1-drive.sh` accepted path is byte-identical to pre-hook behavior — no `ctx.paired_audit` event, no `paired-audit.json`, and the same acceptance artifacts and events in the same order.
- `GLUERUN_PAIRED_AUDIT_PCT=100`: an accepted task produces exactly one `ctx.paired_audit` event and one `paired-audit.json` in the run dir, while the acceptance outcome is unchanged — packet status `accepted`, lease and task status `accepted`, the recorded accept decision, the inbox packet at `$GLUERUN_INBOX_DIR/$run_id.json`, and the `l1.task_accepted` event are all identical to a `PCT=0` run.
- The hook fires STRICTLY AFTER acceptance is finalized (packet status set to `accepted`, lease/task statuses set, `record-decision.sh --decision accept` run, inbox packet written, `l1.task_accepted` appended); the `ctx.paired_audit` event is ordered after `l1.task_accepted`.
- Evidence invariance / no outcome change: the paired verdict never feeds back into the accept/reject decision, never reorders/gates/blocks acceptance, and never changes the process exit status; a recorder or runner failure leaves the accepted outcome and exit status untouched. The hook does not create, move, or mutate the packet, the primary audit record, the lease, the task file, or the inbox placement.
- The hook runs only on the accepted path: a non-accepted (needs-fix/blocked/parked) outcome invokes no paired audit and writes no paired record.
- The change is a single minimal call site in `engine/l1-drive.sh` delegating into `gluerun_ctx_paired_audit_record` from the integrated `engine/ctx-paired-audit.sh`; it introduces no schema, does not edit `lib.sh`, and does not modify `engine/ctx-paired-audit.sh`. `tests/test-engine-clean.sh` stays green (no project-specific symbols in `engine/`).
- `tests/test-l1-drive-paired-audit-hook.sh` exists, was red before the hook (accepted path produced no paired record) and green after, and covers default-OFF byte-identical acceptance, `PCT=100` paired recording with unchanged acceptance and post-`l1.task_accepted` ordering, decision/exit invariance under a failing paired runner, and no-invocation on a non-accepted path — using a hermetic `GLUERUN_ROOT`, an isolated `GLUERUN_EVENTS_FILE`, and a stub `GLUERUN_RUNNER`.
- Gate command `bash tests/run.sh` is green, including `test-l1-drive-paired-audit-hook.sh`, `test-ctx-paired-audit.sh`, and `test-engine-clean.sh`.
- Gate candidate (advisory, not a completion declaration): with the recorder now invoked strictly post-acceptance behind `GLUERUN_PAIRED_AUDIT_PCT` (default 0) and the acceptance outcome verified unchanged, `paired-audit` reaches its required completion — sampled post-acceptance fresh audit that records verdict/findings without changing any outcome, suite green. The disagreement-rate reporting in `ctx-metrics.sh` is a later node's concern, not this slice.
