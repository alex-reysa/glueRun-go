## Objective

Advance executable DAG node `planner-session-meta` (stage `S1-planner-persistence`, layer `engine_runtime`, kind runtime) by landing its sanctioned driver-hook slice: the first `engine/generate-tasks.sh` call-site hook that makes an actual planner run persist finalized per-node session-meta. TASK-0007 already integrated the library brick `engine/ctx-planner-session.sh` (pure per-node path helper `gluerun_ctx_planner_session_path` plus the guarded `gluerun_ctx_planner_session_finalize`), but those functions are defined-only and no engine path invokes them, so `planner-session-meta`'s requiredCompletion — "Planner runs persist finalized session-meta per node under .gluerun-state/sessions/planner/ behind GLUERUN_PLANNER_SESSION (default 0); planner-failed never finalizes" — is not yet satisfied.

This slice wires exactly two minimal, default-OFF delegations into `engine/generate-tasks.sh` (the node owns the first generate-tasks.sh hook per the DAG node description and the stage-1 file): (1) when `GLUERUN_PLANNER_SESSION=1`, pass `--session-meta <canonical planner path>` to the runner invocation (the runner already accepts `--session-meta`, exactly as the worker path in `l1-drive.sh` does), where the path is `gluerun_ctx_planner_session_path <planned-node>`; and (2) on a successful accepted batch (staged or generated, single or multi), before the process exits 0, call `gluerun_ctx_planner_session_finalize` with rc 0, the planned node, the run id, the runner basename, the planner prompt sha, the target-branch head resolved at planning time as the lineage anchor, and the attempt. Every planner-failed exit (runner non-zero, empty output, or batch validation failure) must leave finalize uninvoked / rc non-zero so NO resumable meta is written (evidence invariance — a rejected planner lineage is not extended blindly; Stage 3 revision is the deliberate exception, out of scope). The resume/gate side (`gluerun_planner_resume_decide`, node lineage, session leases, rc-86 fallback) is the downstream `planner-resume-gates` node and is OUT OF SCOPE here.

Feature-flag discipline: with `GLUERUN_PLANNER_SESSION` unset or `0` the runner is invoked with NO `--session-meta` argument and no meta file is written, so the driver stays byte-identical to current behavior. The hook adds only minimal delegating call lines — no new logic — and does not modify `engine/ctx-planner-session.sh`, `engine/lib.sh`, or any schema.

## Acceptance Criteria

- With `GLUERUN_PLANNER_SESSION=1`, a planner run for node `planner-session-meta` (layer `engine_runtime`) that produces a valid accepted task batch causes `engine/generate-tasks.sh` to (a) invoke the runner with `--session-meta "$(gluerun_ctx_planner_session_path <planned-node>)"` and (b) on that success write a finalized `gluerun.orchestration.session-meta.v0` meta at `.gluerun-state/sessions/planner/<planned-node>.json` (under the runtime state dir, never `docs/`) via `gluerun_ctx_planner_session_finalize`, with `role: "planner"`, `node` equal to the planned node, and `headShaAtCreate` equal to the target-branch head at planning time.
- Every planner-failed exit (runner non-zero rc, empty runner output, or task-batch validation failure) writes NO finalized meta at the canonical path (evidence invariance — a rejected planner lineage is not extended).
- `GLUERUN_PLANNER_SESSION` defaults to 0: when unset or `0` the runner is invoked WITHOUT `--session-meta` and no meta file is written, byte-identical to prior behavior, independent of run outcome.
- The change is limited to minimal call-site delegations into the already-integrated `gluerun_ctx_planner_session_path` / `gluerun_ctx_planner_session_finalize`; `engine/ctx-planner-session.sh`, `engine/lib.sh`, and all schemas are unmodified, and `tests/test-ctx-planner-session.sh` stays green.
- New `tests/test-generate-tasks-planner-session-hook.sh` drives `engine/generate-tasks.sh` with a stub runner in an isolated `GLUERUN_ROOT`/`GLUERUN_STATE_DIR` (never the real repo or its state dir) and asserts: (a) knob ON + successful stub batch → a valid finalized meta at `.gluerun-state/sessions/planner/<node>.json` with correct `role`/`node`/`headShaAtCreate`, and the stub runner recorded receiving `--session-meta <that path>`; (b) knob ON + planner-failed stub (non-zero rc) → no finalized meta; (c) knob OFF → no meta written and the stub runner recorded NO `--session-meta`. The test fails before the hook is added (red) and passes after (green).
- `tests/test-engine-clean.sh` stays green (no project-specific symbols in `engine/`) and the gate command `bash tests/run.sh` passes.
- Gate candidate: with this hook landed and both `tests/test-ctx-planner-session.sh` and `tests/test-generate-tasks-planner-session-hook.sh` green under the suite, node `planner-session-meta` (layer `engine_runtime`) meets its requiredCompletion — planner runs persist finalized per-node session-meta under `.gluerun-state/sessions/planner/` behind `GLUERUN_PLANNER_SESSION` (default 0) and planner-failed never finalizes; propose this as the node's gate candidate. Completion is authoritative only via the gate result, not this task.
