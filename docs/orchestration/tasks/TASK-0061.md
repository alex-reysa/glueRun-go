## Objective

Fourth slice of the stage file's explicitly-OPTIONAL authored-knowledge manifest ingestion for the executable DAG node `rehydrate-path` (stage `S5-routing`, layer `engine_runtime`). The core `requiredCompletion` behavior is already integrated (TASK-0051–0057); this OPTIONAL feature is NOT part of `requiredCompletion` and does not gate the node — completion and gate promotion are operator authority and are not claimed here. TASK-0058 / TASK-0059 / TASK-0060 built `select` → `eligible` → `render` / `manifest` over a manifest PATH (`singular_ctx_rehydrate_authored_render` / `singular_ctx_rehydrate_authored_manifest`).

This slice adds the pure config-gated entry point that turns the `SINGULAR_CTX_MANIFEST` knob and the optional `singular.config.json` `contextManifest` field into a single decision, so the final driver wire-in becomes two one-line delegations rather than duplicating the gate across two scarce driver files. Introduce a new pure, read-only leaf `engine/ctx-rehydrate-authored-config.sh` that DEFINES new functions only and is present-but-uncalled by every existing engine/CLI/driver path, so with it sourced the engine stays byte-identical to current behavior. Implement and test against FIXTURE manifests and a fixture config only; take no dependency on the singular-brain runtime.

Behavior of `engine/ctx-rehydrate-authored-config.sh` (node `rehydrate-path`, layer `engine_runtime`):

- `singular_ctx_rehydrate_authored_config_render [trigger ...]`: emits the authored packet section only when `SINGULAR_CTX_MANIFEST=1` AND `singular.config.json` declares a readable `contextManifest` path — by resolving that path and delegating to `singular_ctx_rehydrate_authored_render <resolved-path> [trigger ...]`; otherwise it emits nothing.
- `singular_ctx_rehydrate_authored_config_manifest [trigger ...]`: the same gate, delegating to `singular_ctx_rehydrate_authored_manifest` for the authored manifest entries; otherwise nothing.
- `contextManifest` is an OPTIONAL ADDITIVE field read via `singular_json_field` over `SINGULAR_JSON_CONFIG_FILE` (`engine/lib.sh`); there is no config schema file, so no schema change is needed and the field's absence is the OFF default.
- Pure, read-only, deterministic, fail-soft: any unmet precondition (flag off, field absent, path missing or unreadable, malformed manifest) yields empty output; the function writes/renames/deletes nothing, appends no events, and never exits non-zero on well-formed input.

`SINGULAR_CTX_MANIFEST` (default 0) gates this feature; with it unset the entry point emits nothing.

This OPTIONAL feature is NOT required for the `rehydrate-path` node exit gate, whose core behavior (`test-ctx-rehydrate.sh` green plus the full suite) is already integrated.

## Context packet

Decisions:

- Centralize the `SINGULAR_CTX_MANIFEST` gate plus `contextManifest` config resolution in one pure leaf so the two driver merge points (packet injection TASK-0057, manifest recording TASK-0055 / TASK-0056) become one-line delegations rather than duplicating the gate across two scarce driver files. Basis: planner-contract rule 2 (minimal driver hooks) and DRY.
- Read `contextManifest` via `singular_json_field` over `SINGULAR_JSON_CONFIG_FILE` (`engine/lib.sh`); it is an OPTIONAL ADDITIVE field with no config schema file, so no schema change is needed and its absence is the OFF default. Basis: no `schemas/` config file; the `singular_json_field` precedent.
- Keep the leaf a delegation over TASK-0060's `render` / `manifest` (do not re-render): the composer already applies caps, class markers, and the quarantine / `description_unverified` / stale / trigger exclusions. Basis: TASK-0060 integrated.

Assumptions:

- [validated] `SINGULAR_JSON_CONFIG_FILE` points at `singular.config.json` and `singular_json_field <file> <key>` reads a top-level field (`engine/lib.sh`).
- [validated] `singular_ctx_rehydrate_authored_render` / `singular_ctx_rehydrate_authored_manifest <manifest-path> [triggers ...]` are the integrated composer entry points (TASK-0060).
- [open] `contextManifest` is a repo-relative path resolved against `SINGULAR_ROOT` (or repo root); an unreadable or absent resolved path yields empty output (feature off).
- [validated] The core `rehydrate-path` `requiredCompletion` is integrated (TASK-0051–0057); this OPTIONAL slice does not gate the node.

Rejected alternatives:

- Inlining the flag-plus-config gate at each driver merge point — rejected: it duplicates the gate in `engine/l1-drive.sh` and `engine/ctx-rehydrate-event.sh` (scarce driver files) and violates DRY; a single config-gate leaf keeps both hooks minimal.
- Adding a `singular.config.json` schema file for `contextManifest` — rejected: there is no config schema file; the field is optional and additive and read directly, so its absence is a clean OFF default.
- Re-implementing `render` / `manifest` in the config gate — rejected: TASK-0060 already renders with caps, class markers, and exclusions; the gate only resolves the path and delegates.
