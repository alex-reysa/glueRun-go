## Objective

Close a durable-artifact coverage gap in the executable DAG node `artifact-secret-scan` (layer `engine_runtime`). The integrated enumerator `singular_ctx_artifact_scan_paths` in `engine/ctx-artifact-scan.sh` covers the paired-audit class as BOTH `paired-audit.json` and its raw model transcript `paired-audit-raw.json`, but covers the critique class only as `plan-critique.json` / `critique.json` — it never enumerates the raw critic transcript `plan-critique-raw.json` that the plan-critic driver writes beside `plan-critique.json`. That raw file is the highest-risk secret-bearing critique artifact (verbatim model output) and is a durable context record named in this node requiredCompletion (`critique ... records`), so a secret seeded there today escapes `secret-scan.sh --artifacts`, and therefore escapes quarantine and prompt-assembly exclusion.

Extend the existing enumerator — the single source of the covered artifact-class list this node owns — so the critique class is scanned as a matched pair, `plan-critique.json` AND `plan-critique-raw.json`, mirroring the paired-audit pairing. Because quarantine (`singular_ctx_artifact_quarantine`) and the finalize hook already compose over this enumerator, closing the enumerator gap automatically extends detection, quarantine, and exclusion to the raw critique record with no change to any hook or driver.

This is detection-coverage completion only: it adds no new secret patterns (the shared `singular_secret_scan_patterns` is reused unchanged), flips no knob, and adds no new default flow. With `SINGULAR_CTX_ARTIFACT_SCAN` unset or `0`, `engine/l1-drive.sh` remains byte-identical. The scan stays read-only; only the already-integrated, default-OFF containment path acts on the newly-covered file.

## Context packet

Decisions:
- Fix in the existing enumerator `singular_ctx_artifact_scan_paths`, not a new `engine/ctx-*.sh`. Why: it is the single source of the covered artifact-class list that detection, quarantine and the finalize hook all compose over; a second file deciding which artifacts to scan would split that source of truth and silently drift coverage. This completes an owned coverage list rather than adding new logic.
- Cover the critique class as a matched pair (`plan-critique.json` + `plan-critique-raw.json`), mirroring the already-covered paired-audit pair (`paired-audit.json` + `paired-audit-raw.json`). Why: the `-raw` transcript is the verbatim model output — the likeliest place a secret lands — and the asymmetry (paired-audit covers its raw sibling, critique does not) is the concrete gap.

Assumptions:
- [validated] the enumerator matches critique only via `-name plan-critique.json -o -name critique.json` and omits `plan-critique-raw.json` — basis: engine/ctx-artifact-scan.sh.
- [validated] the plan-critic driver writes `plan-critique-raw.json` beside `plan-critique.json` in the same run staging directory, reachable by the enumerator recursive `find` over the run dir — basis: the raw record is written to the same stage dir as `plan-critique.json`.
- [open] quarantine and the finalize hook need NO edit: both compose over `singular_ctx_artifact_scan_paths`, so extending it propagates coverage automatically — basis: engine/ctx-artifact-quarantine.sh and the l1-drive.sh finalize hook enumerate via that function.
- [open] detection stays read-only and the OFF path stays byte-identical — basis: planner-contract feature-flag discipline; the containment path is default-OFF under SINGULAR_CTX_ARTIFACT_SCAN.

Rejected alternatives:
- Add a new `engine/ctx-*.sh` for critique-raw coverage — why not: it fragments the single enumerator source of truth and would need re-wiring into quarantine and the finalize hook; the correct site is the enumerator this node already owns.
- Also fold in the per-run assumption ledger (`assumptions-ledger.json`, `assumptions-attempt-ledger.json`) — why not: the ledger is not among the classes named in this node requiredCompletion (capsules, session meta, packets, critique, paired-audit); it is a distinct durable artifact owned by the assumption-ledger node and, if it warrants scanning, belongs in its own bounded slice. Kept out to keep this slice tight and in-scope.
- Broaden the match to a wildcard such as `*critique*.json` — why not: it would also sweep unrelated files (e.g. schema fixtures) and drift coverage unpredictably; enumerate the exact record names instead.

Inspected symbols:
- `singular_ctx_artifact_scan_paths` — the enumerator whose critique branch omits the raw sibling; role: the single coverage-list source that detection, quarantine and the finalize hook all depend on, so the fix must land here to propagate to all three.
