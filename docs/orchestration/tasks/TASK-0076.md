## Objective

Ship the first source-record projection mappers that turn integrated durable S0 records into projected `context-graph.v0` JSONL lines — the `graph-projector` (layer `engine_runtime`) rebuild's inner layer. They compose the integrated primitives (`engine/ctx-graph.sh` emitters `singular_graph_emit_node`/`_edge`) and will feed the integrated corpus writer (`engine/ctx-graph-corpus.sh`) from a later `singular graph rebuild` entry point. New file `engine/ctx-graph-project.sh`, auto-sourced by the ctx-loader block in `engine/lib.sh`, defines functions ONLY (OFF-parity for `SINGULAR_CTX_GRAPH`, default 0; nothing invokes them; they write no file and emit JSONL to stdout). Implement three chained slices in order, each RED-first in `tests/test-ctx-graph-project.sh`:

1. Identity convention. `singular_graph_identity <type> <key...>` builds the canonical source-record identity STRING per node type (e.g. `task` from taskId, `attempt` from runId+n, `gate-result` from the gate record identity) so that `singular_graph_node_id` mints consistent ids across every mapper and cross-family edges connect. Pure and deterministic. This is the keystone every present and future mapper reuses.

2. Attempts mapper. `singular_graph_project_attempts <attemptsIndexPath>` reads an `attempts/index.json` (schema `singular.orchestration.attempts-index.v0`; `runId`, `taskId`, `attempts[]` rows keyed by `n`) and emits one `attempt` node (evidenceClass `claim`) per attempt row plus one `implements` edge from each attempt to its `task` node id (identity via slice 1). Consumes slice 1 + the integrated emitters.

3. Gate-result mapper. `singular_graph_project_gate_results <gateRecordPath>` reads a `singular.orchestration.gate-result.v0` record and emits one `gate-result` node (evidenceClass `authoritative`, for every `status` — the source is host-verified) plus, on `status` `passed`, a `verifies` edge and, on `status` `failed`, an `invalidates` edge from the gate-result node to the decided target's node id (identity via slice 1). Consumes slice 1 + the emitters.

Each mapper prints a mixed node+edge JSONL stream to stdout (one schema-valid line each; every line self-identifies via `kind`); the future `singular graph rebuild` entry point partitions by `kind` and hands the node/edge streams to `singular_graph_write_corpus`. The full source walk, the `query` read API, and the `cli/singular graph` driver hook are subsequent `graph-projector` tasks and are out of this slice's scope. This task advances `graph-projector` toward its `requiredCompletion` by pinning the cross-family identity convention and the first two host-source mappers; it does not complete the node or declare a gate pass.

## Acceptance Criteria

- `tests/test-ctx-graph-project.sh` is green and is the strict-test-first regression: it fails before `engine/ctx-graph-project.sh` exists (RED) and passes after (GREEN).
- Determinism: `singular_graph_identity` returns byte-identical strings for identical inputs and distinct strings for distinct source records; ids minted via `singular_graph_node_id(identity)` are stable across repeated projection and AGREE across the attempts and gate-result mappers — an `implements` edge's `to` equals `singular_graph_node_id(singular_graph_identity('task', taskId))`.
- Attempts: every attempt row yields exactly one `attempt` node (evidenceClass `claim`) plus one `implements` edge (attempt to task); every emitted line validates against `schemas/context-graph.v0.schema.json`.
- Gate-result: every record yields one `gate-result` node with evidenceClass `authoritative` for every `status`; a `passed` record additionally emits a `verifies` edge and a `failed` record an `invalidates` edge to the decided target's node id; `proposed`/`blocked` emit the node with no verify/invalidate edge; every emitted line validates against the schema.
- Evidence invariance (fail-closed): no model-authored input path mints an `authoritative` node; the `gate-result` node is `authoritative` solely because its source is a host-verified record, and the `attempt` node is `claim`.
- Idempotence: re-running either mapper over the same source emits byte-identical lines, so feeding the output through `singular_graph_canonicalize` collapses to the same canonical set.
- OFF-parity: `engine/ctx-graph-project.sh` only DEFINES functions; sourcing it under the ctx-loader block invokes nothing, writes no file, and leaves engine behavior byte-identical when `SINGULAR_CTX_GRAPH` is unset or `0`.
- `bash tests/test-engine-clean.sh` stays green: no project-specific symbols in `engine/`.

## Context packet

### Decisions
- The identity convention is pinned ONCE here (slice 1) so every present and future mapper mints node ids from the same source-identity strings — the precondition for cross-family edges (`implements`, `verifies`, `invalidates`) to connect in the assembled corpus. `singular_graph_node_id` already hashes an arbitrary identity string (TASK-0074); what was missing is the per-type identity STRING convention.
- Mappers emit a mixed node+edge JSONL stream to stdout (each line self-identifies via `kind`); the later rebuild entry partitions by `kind` before calling `singular_graph_write_corpus`, keeping each mapper a single pure, file-free function.
- `gate-result` is `authoritative` for every status because the source is a host-decided record; `passed` maps to `verifies`, `failed` to `invalidates`, and `proposed`/`blocked` emit the node with no verify/invalidate edge (routing state, not an attempt outcome) — faithful to docs/context-build-plan/graph-event-mapping.md.

### Assumptions
- [validated] `engine/ctx-graph.sh` emitters and `engine/ctx-graph-corpus.sh` canonicalize/write are integrated — basis: TASK-0074 and TASK-0075 integrated.
- [validated] `attempts/index.json` carries `runId`, `taskId`, and `attempts[]` rows keyed by `n`; `singular.orchestration.gate-result.v0` records carry `status` in {passed, failed, blocked, proposed} plus `node`/target identity — basis: the `engine/ctx-metrics.sh` reader and `schemas/gate-result.v0.schema.json`.
- [open] `python3` is available for JSON parsing in the mappers and their test — basis: `engine/ctx-metrics.sh` and the shipped graph tests rely on it.

### Rejected alternatives
- Bundling all node-type mappers into one task — rejected: far exceeds the smallest-brick bound; the remaining source families (plan-version, critique/finding, decision, assumption, capsule, commit) land as subsequent folded mapper tasks reusing this identity convention.
- Emitting nodes and edges on separate file descriptors to match `singular_graph_write_corpus`'s two inputs — rejected: couples each mapper to the writer's plumbing; a single stdout stream partitioned by `kind` keeps mappers independently testable.
