## Objective

Record the sprint contract for the reliability program (DAG nodes `rel-*`) as a single
authoritative document, `docs/orchestration/areas/reliability-contract.md`, so every later task
and its auditor can cite one fixed statement of scope and invariants instead of re-deriving them.

The contract must contain, verbatim or tightened, the following sections from
`claudedocs/reliability-sprint-01-plan.md`:

1. The eight safety invariants (checkpoint-never-acceptance, advocate/skeptic separation,
   exact job identity, evidence binding unchanged, checkpoint scope fail-closed,
   evidence-remedies-never-implement, no auto-redispatch of known ambiguous external effects,
   recovery-never-kills-live-work).
2. The audited baseline failure modes this program fixes, each with its code anchor:
   - worker log truncation per infra try (`engine/l1-drive.sh`, the `>"$run_dir/worker-codex.log"`
     redirect in `run_worker_phase`);
   - stale `last-message.json` across tries (same function, `--output-last-message` path is
     never cleared between tries, unlike the auditor's `rm -f` of its record);
   - `revalidate-evidence` sharing the `retry` branch (the terminal `case "$action"` block);
   - overloaded `audit-infra` (13 emitter sites; the source-integrity site is a correctness
     event, not infrastructure);
   - frozen deadlines (`deadline=$((SECONDS + budget))` computed once in every runner and in
     `gate-check.sh`);
   - EXIT-trap-only terminal handoff (`l1_on_exit`), SIGKILL leaving a stale `active` record;
   - L1 planning-lease reclaim with no liveness probe (`singular_l1_reclaim_stale`);
   - ctx routing reading `audit-codex.log` while the driver writes `auditor-codex.log`.
3. The explicit deferrals (checkpoint grades beyond `snapshot`, effect ledger, writable
   run-control, cross-run resume, budget heuristics) so no worker widens scope.
