# TASK-0042: artifact-secret-scan — quarantine on hit + prompt-assembly exclusion of quarantined artifacts

Test policy: `strict_test_first`

Dispatch mode: canonical
Depends on: []

## Objective

Advance the executable DAG node `artifact-secret-scan` (layer `engine_runtime`)
from detect-only to detect-and-contain, by folding two mutually-independent,
strict-test-first slices that build on the already-integrated `--artifacts`
detection (`gluerun_ctx_artifact_scan_paths` and the shared
`gluerun_secret_scan_patterns`).

Slice A — quarantine on hit (`engine/ctx-artifact-quarantine.sh`): a new
`gluerun_ctx_artifact_quarantine <run_dir>` that enumerates the durable context
artifacts by reusing the integrated enumerator and shared secret patterns, and
for every artifact that matches a secret pattern it (1) renames the artifact to
`<path>.quarantined`, (2) appends one `ctx.artifact_secret` event recording the
artifact path and matched pattern label, and (3) returns success (exit 0). It
never blocks or changes the task outcome, and it leaves clean artifacts
byte-for-byte untouched. The rename preserves the content under the
`.quarantined` name (never deletes it) so forensic evidence is retained.

Slice B — exclusion filter (`engine/ctx-artifact-exclude.sh`): a new
`gluerun_ctx_artifact_exclude` that, given a set of candidate artifact paths,
drops every quarantined entry — any path ending in `.quarantined`, and any
original path whose `.quarantined` sibling exists — and emits only the surviving
safe paths, order-stable, so a quarantined artifact can never reach a rendered
prompt or rehydration packet. It is pure and read-only.

Both slices are additive helpers not yet invoked by any default flow. The
finalize-site hook that fires quarantine where artifacts are finalized, and the
assembly wire-in that applies the exclusion filter (each behind a documented
`GLUERUN_*` knob), are separate later slices of `artifact-secret-scan` and are
OUT OF SCOPE here. The two slices are mutually independent: they own disjoint
new files and share only the stage-file-fixed `.quarantined` suffix convention
and the `ctx.artifact_secret` event type — neither calls the other.

## Acceptance Criteria

- `tests/test-ctx-artifact-quarantine.sh` and `tests/test-ctx-artifact-exclude.sh`
  are each red before implementation and green after (strict_test_first).
- Quarantine: given a run-state directory with a seeded fake secret planted in
  any covered artifact class (capsule, session-meta, context packet, critique
  record, paired-audit record), `gluerun_ctx_artifact_quarantine` renames that
  artifact to `<path>.quarantined`, appends exactly one `ctx.artifact_secret`
  event referencing the artifact path and matched pattern label, and returns
  exit 0.
- Quarantine leaves clean artifacts untouched (not renamed, no event) and
  returns exit 0; a run directory with no artifacts is a no-op success.
- Quarantine is non-blocking and evidence-preserving: it never exits non-zero on
  a hit and never deletes the secret content — the offending artifact survives
  under its `.quarantined` name, just renamed out of the active path.
- Exclusion: `gluerun_ctx_artifact_exclude` over a candidate list drops every
  `.quarantined` path and every original path shadowed by a `.quarantined`
  sibling, preserves all other paths order-stable, and passes an
  all-clean list through unchanged.
- Both slices honor the exact `.quarantined` suffix convention fixed by the
  stage file, and quarantine reuses the same commit-grade secret patterns as
  detection (no separate or weaker pattern set).
- Additive / default-OFF: no existing default flow invokes either helper; the
  finalize hook and the assembly wire-in, with their `GLUERUN_*` knob, land in
  later slices of `artifact-secret-scan`.
- Advocate/skeptic line and evidence invariance preserved: containment is
  host-mechanical (rename + event), changes no task outcome, and weakens no
  gate.
- Gate command passes:
  `bash tests/test-ctx-artifact-quarantine.sh && bash tests/test-ctx-artifact-exclude.sh && bash tests/test-engine-clean.sh`
  (both slice tests green plus engine cleanliness); the full `bash tests/run.sh`
  still runs structurally at integrate and node-gate promotion.

## Context packet

Decisions:
- Fold quarantine + exclusion-filter into one task: both build only on the
  integrated `--artifacts` detection and the stage-file `.quarantined`
  convention, own disjoint new files, and neither calls the other — so they are
  mutually-independent same-node slices and the folding rule (max 2/task)
  requires bundling them now.
- Quarantine re-enumerates via the integrated `gluerun_ctx_artifact_scan_paths`
  and re-checks with the shared `gluerun_secret_scan_patterns` to decide
  per-file, rather than editing TASK-0041's detection function. Why: keeps
  ownership to new files only and keeps detection read-only.
- Exclusion is a pure path filter (no I/O beyond stat-ing for a `.quarantined`
  sibling), shipped ahead of its assembly wire-in. Why: matches the codebase's
  helper-then-wire-in granularity and keeps the slice independent of assembly
  sites.

Assumptions:
- [validated] the integrated detection exposes `gluerun_ctx_artifact_scan_paths`
  and a shared `gluerun_secret_scan_patterns` function — basis:
  engine/ctx-artifact-scan.sh.
- [open] quarantine must be non-blocking: it returns exit 0 even when it
  quarantines, so no calling flow aborts — basis: stage file "never blocks the
  task outcome"; the later finalize hook relies on this.
- [open] quarantine renames and preserves content under `.quarantined`, never
  deletes — basis: evidence invariance plus stage file "rename `.quarantined`";
  forensics need the retained content.
- [open] both slices honor the exact `.quarantined` suffix and the
  `ctx.artifact_secret` event type — basis: stage file; divergence would
  silently break the later exclusion wire-in and the graph/rehydration
  consumers.

Rejected alternatives:
- Emit only the quarantine slice — why not: the exclusion filter is also ready
  and independent, so the folding rule requires bundling both.
- Wire quarantine into the finalize sites in this task — why not: that hook
  touches existing driver files, depends on this quarantine helper, and is a
  separate later slice; folding it would break mutual independence and pull
  `bash tests/run.sh`-scope files into scope.
- Move quarantined files into a `quarantine/` subdirectory — why not: the stage
  file fixes the `.quarantined` rename convention that the exclusion filter
  keys on.

Inspected symbols:
- `gluerun_append_event` — the event recorder quarantine must use to append the
  `ctx.artifact_secret` record; role: fixes the event API so the later
  rehydration/graph slices can consume the quarantine record.
- `gluerun_ctx_artifact_scan_paths` — the integrated artifact enumerator that
  quarantine composes over; role: the single source of the covered artifact-class
  list, so quarantine coverage stays in lockstep with detection.
