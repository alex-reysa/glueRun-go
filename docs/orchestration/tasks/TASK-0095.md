## Objective

Advance the `experiment-run` executable DAG node (layer `evaluation`) by durably RECORDING the per-run knob-state provenance that TASK-0093 can only emit. TASK-0093 shipped the pure read-only emitter `gluerun_ctx_experiment_armstate_json` (the observed continuity knob-state: `control = M0 knob-state` when the knobs are unset, treatment when they are set) but is present-but-uncalled, so no run persists its knob-state and the report's per-arm attribution is not auditable on disk. That emitter's context packet explicitly deferred the driver wire-in as a separable slice. This task adds it — the same emitter-then-l1-drive-hook second step that paired-audit (TASK-0006), critic-recheck (TASK-0033), and artifact-scan finalize (TASK-0043) all use. It is a small call-site hook that DELEGATES to the integrated emitter, default-OFF behind a documented knob, byte-identical when unset. It does NOT run the paired-audited A/B experiment, author `docs/context-build-plan/experiment-report.md`, or record per-knob default decisions in `docs/orchestration/decisions.md` — all OPERATOR authority (kind: evaluation). It neither declares nor gates node completion.

Implement the following single hook, in the `engine/l1-drive.sh` finalize region beside the sibling per-run provenance blocks (the `GLUERUN_CTX_ARTIFACT_SCAN` durable-artifacts block, the paired-audit recorder, and the critic-recheck block), plus its test:

1. Guarded recording hook: when `GLUERUN_CTX_ARMSTATE` is set and not 0, write the output of `gluerun_ctx_experiment_armstate_json` (for the run's environment) to a durable `arm-knob-state.json` under the run directory, non-fatal (`|| true`), mirroring the `GLUERUN_CTX_ARTIFACT_SCAN` block that writes `durable-artifacts.manifest`. The hook inlines no knob-state logic; it only forwards to the integrated emitter.

## Context packet

### Decisions

- Record the snapshot as a durable `arm-knob-state.json` provenance file under the run directory, mirroring the `GLUERUN_CTX_ARTIFACT_SCAN` finalize block's `durable-artifacts.manifest`, rather than appending an event — keeping the event stream unchanged while giving each arm run an auditable on-disk knob-state.
- Gate behind a dedicated default-OFF `GLUERUN_CTX_ARMSTATE` knob so provenance recording is opt-in during experiment runs and the engine is byte-identical when the knob is unset (feature-flag discipline).

### Rejected alternatives

- Appending a new `ctx.experiment_armstate` event — rejected here: it adds per-run event-stream weight and a new event type without a consumer; the run-directory provenance file matches the artifact-scan precedent and is what the report references.
- Folding the recording side effect into the TASK-0093 emitter — rejected: that emitter is a pure read-only stdout function (present-but-uncalled OFF-parity); the durable side effect belongs at the sanctioned `l1-drive.sh` finalize hook, per driver-hook ownership.
