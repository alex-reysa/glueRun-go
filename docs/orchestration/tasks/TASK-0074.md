## Objective

Ship the deterministic pure-projection primitives that every later `graph-projector` (layer `engine_runtime`) capability — `gluerun graph rebuild/sync/query` behind `GLUERUN_CTX_GRAPH` (default 0) — will compose. New file `engine/ctx-graph.sh`, auto-sourced by the ctx-loader block in `engine/lib.sh`, defines functions ONLY; no engine path invokes them, so the engine is byte-identical with the file present (OFF-parity). Implement the three chained slices below in order, each with its RED test in `tests/test-ctx-graph.sh` before code:

1. Deterministic identity primitives. `gluerun_graph_content_hash` maps a source record's canonical content to a `sha256:<64-hex>` digest; `gluerun_graph_node_id` maps a source-record identity string to a stable `n-<12-hex>` id; `gluerun_graph_edge_id` maps the identity triple `(fromId, edgeType, toId)` to a stable `e-<12-hex>` id. Pure and deterministic: identical input yields byte-identical output; distinct source identities yield distinct ids.

2. Node emitter. `gluerun_graph_emit_node` consumes a node `type`, a source identity, a `sourcePath`, and the source content (plus optional `label`/`attributes`) and prints ONE `nodes.jsonl` line valid against `schemas/context-graph.v0.schema.json`: `id` from slice 1, `provenance` `{sourcePath, contentHash}`, and a fail-closed `evidenceClass` — `authoritative` ONLY for the host-verified types (`commit`, `gate-result`), `claim` for every other type (including `audit`, per the mapping table's auditor-is-a-model rule). Consumes slice 1.

3. Edge emitter. `gluerun_graph_emit_edge` consumes an `edgeType`, a `from` node id, a `to` node id, a `sourcePath`, and source content (plus optional `attributes`) and prints ONE `edges.jsonl` line valid against the same schema, with `id` = `gluerun_graph_edge_id(from, edgeType, to)`, directed `from`->`to`, and `provenance`. Consumes slice 1.

The emitters print single JSONL lines to stdout and perform NO filesystem writes. Full-corpus assembly (`nodes.jsonl`/`edges.jsonl`), the rebuild/sync cursor loop, the `query` read API, and the `cli/gluerun graph` hook (chained behind `metrics-extract`) are subsequent `graph-projector` tasks and are out of this slice's scope. This task advances `graph-projector` toward its `requiredCompletion` by delivering the deterministic, idempotent projection atom; it does not complete the node or declare a gate pass.

## Acceptance Criteria

- `tests/test-ctx-graph.sh` is green and is the strict-test-first regression: it fails before `engine/ctx-graph.sh` exists (RED) and passes after (GREEN).
- Determinism: `gluerun_graph_content_hash`, `gluerun_graph_node_id`, and `gluerun_graph_edge_id` return byte-identical output for identical input across repeated calls, and distinct output for distinct source identities. Ids match `^n-[0-9a-f]{12}$` / `^e-[0-9a-f]{12}$`; the content hash matches `^sha256:[0-9a-f]{64}$`.
- Every line produced by `gluerun_graph_emit_node` / `gluerun_graph_emit_edge` validates against the shipped `schemas/context-graph.v0.schema.json` (closed object; required `schema`/`kind`/`id`/`type`/`evidenceClass`/`provenance` present for nodes, `schema`/`kind`/`id`/`type`/`from`/`to`/`provenance` for edges), and the emitted edge's `id` equals `gluerun_graph_edge_id(from, type, to)`.
- Evidence invariance (fail-closed): a `commit` or `gate-result` node is `authoritative`; every other node type — including `audit` — is `claim`. No input path mints `authoritative` for a model-authored type.
- OFF-parity: `engine/ctx-graph.sh` only DEFINES functions; sourcing it under the ctx-loader block invokes nothing, writes no file, and leaves engine behavior byte-identical when `GLUERUN_CTX_GRAPH` is unset or `0`. The emitters create no files — pinned behaviorally (e.g. assert no artifacts appear after a call), not by any absence/temporal grep.
- `bash tests/test-engine-clean.sh` stays green: no project-specific symbols in `engine/`.

## Context packet

### Decisions
- Emitters print single JSONL lines to stdout (mirroring `engine/ctx-metrics.sh`'s stdout-only, read-only contract) rather than writing `nodes.jsonl`/`edges.jsonl`; file assembly + cursor belong to the rebuild/sync slice, keeping this atom pure and byte-pinnable.
- Stable ids hash source-record IDENTITY, not full content: node id from the source identity string, edge id from `(from,type,to)`. Content hash is separate `provenance`. This matches the schema's id/provenance split so a later rebuild is byte-identical.

### Assumptions
- [validated] `schemas/context-graph.v0.schema.json` and `docs/context-build-plan/graph-event-mapping.md` are integrated and are the authority for node/edge types and the evidenceClass rule — basis: graph-contract tasks TASK-0071/0072/0073 integrated.
- [open] `python3` is available for hashing, JSON emission, and schema validation in the test — basis: `engine/ctx-metrics.sh` and `tests/test-context-graph-schema.sh` both rely on it.

### Rejected alternatives
- Folding the full-corpus rebuild loop into this task — rejected: rebuild over the event log (ordering, dedup, two-file assembly, loss-free delete/rebuild) is a meatier slice that COMPOSES these primitives; bundling it here would exceed the smallest-brick bound and mix a full-suite risk surface with a pure leaf.

### Inspected symbols
- ctx-loader block (`engine/lib.sh`): sources every `engine/ctx-*.sh` once in sorted order and is a no-op with none present — the mechanism that makes a define-only new file OFF-parity without any `lib.sh` edit.
