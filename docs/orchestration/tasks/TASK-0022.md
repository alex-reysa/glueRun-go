## Objective

Fourth brick of the executable DAG node `plan-revision-loop` (stage `S3-plan-revision`, area `plancritic`, layer `engine_runtime`, kind `runtime`). The bound decider `singular_plan_revise_decide` (TASK-0019), the structured-findings revision prompt assembler `singular_plan_revise_prompt` (TASK-0020), and the per-finding disposition classifier + `plan.revised` events `singular_plan_revise_dispositions` (TASK-0021) are integrated. This brick implements the still-untouched core requiredCompletion spine "revise verdict resumes the node planner with structured findings ... fresh fallback recorded": the engine-side revision-round strategy that decides whether the revise round RESUMES the persisted planner node session or runs FRESH, and records both the chosen strategy and the resume-refused (rc-86) fresh fallback.

It reuses the integrated fail-closed planner-role decider `singular_planner_resume_decide` (TASK-0009) so a revision round resumes ONLY the same persisted node session those ordered gates already trust, and it mirrors the strategy-event convention that the integrated generate-tasks.sh planner-resume consult hook (TASK-0011) established: a `context.strategy_selected` event on resume/fresh and a `context.resume_failed` event on the rc-86 fresh fallback. New file `engine/ctx-plan-revise-resume.sh` is auto-sourced by the ctx-loader block in lib.sh and defines NEW functions only; NO existing engine path invokes them, so with the file present-but-uncalled the engine is byte-identical to prior behavior (mirroring engine/ctx-plan-revise.sh). It never owns engine/lib.sh and adds NO driver-file hook and invokes NO runner. The single SINGULAR_PLAN_CRITIQUE-gated generate-tasks.sh / l1-plan-node.sh driver hook that wires the bounded revise -> (resume|fresh) -> re-critique -> approve -> import loop over a stub runner, and the test-ctx-plan-revision.sh full-walk, are the sanctioned final follow-up slice of this node and are OUT OF SCOPE here.
