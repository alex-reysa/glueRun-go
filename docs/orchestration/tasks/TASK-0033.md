## Objective

Wire the terminal driver hook for the executable DAG node `critic-carryover` (stage `S3-plan-revision`, area `plancritic`, layer `engine_runtime`, kind `runtime`): a minimal post-acceptance call site in `engine/l1-drive.sh` that fires the read-only critic recheck after a task is accepted. It is the direct sibling of the integrated paired-audit hook (TASK-0006) and the last wiring the node needs — the sampling gate (TASK-0027), classifier/recorder (TASK-0028), resume authority + skeptic role gate (TASK-0029), the recheck runner (TASK-0031), and the locator (TASK-0032) are all integrated; this hook makes the recheck actually fire post-acceptance so the node's requiredCompletion is exercised end-to-end.

The hook sits strictly AFTER acceptance is finalized (immediately beside the integrated `gluerun_ctx_paired_audit_record` call site) and is a minimal delegation per the planner contract's driver-hook rule: resolve the node via `gluerun_ctx_critic_recheck_locate_node "$task_id" "$worktree"` (TASK-0032); when non-empty, resolve the prior plan-critique record via `gluerun_ctx_critic_recheck_locate_record "$node" "$task_id" "$worktree"` (TASK-0032); when BOTH are non-empty, invoke `gluerun_ctx_critic_recheck_run "$node" "$run_id" "$task_id" "$run_dir" "$record" "$worktree"` guarded by `|| true`. The variables `task_id`, `run_id`, `run_dir`, and `worktree` are already in scope at the acceptance site. The hook adds no recheck logic of its own.

The recheck verdict/dispositions NEVER feed back into the accept decision or the exit status; a locator or runner failure is non-fatal (guarded). Because the runner self-guards on the default-OFF `GLUERUN_CRITIC_RECHECK_PCT` sampling gate (returning a byte-identical no-op when not sampled) and the locators are pure/read-only, the accepted flow's observable state — events, files, decisions, inbox placement, exit status — is byte-identical when the knob is OFF.

Wiring TASK-0030's accepted-diff/prior-findings context assembler (`engine/ctx-critic-recheck-context.sh`, currently accepted) into the runner's prompt is an optional follow-up enhancement, NOT required for this node's requiredCompletion, and is OUT OF SCOPE here.

Advocate/skeptic line + evidence invariance: the hook drives only the read-only recheck; it never blocks or changes any accept/reject outcome, never weakens a gate, and never makes the fresh implementation auditor bypassable. The skeptic role gate (resume only a plan-critic-role session, never a planner/implementer one) is enforced inside the integrated runner/decider; this hook adds no bypass.
