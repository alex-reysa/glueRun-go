## Objective

Sixth strict-test-first slice of the executable DAG node `rehydrate-path` (stage `S5-routing`, layer `engine_runtime`). The spine now emits `rehydrate <reason>` on refused-resume lineage steps, and TASK-0055 shipped the pure, present-but-uncalled strategy-event payload assembler `singular_ctx_rehydrate_event_data <role> <task-id> <run-id> <attempt> <reason> <run_dir>` (embedding the packet manifest of ids + hashes). Nothing calls it yet, so the requiredCompletion clause "manifest recorded in strategy events" is not met: the `engine/l1-drive.sh` `context.strategy_selected` emission at the implementer decision site still branches only on `resume` versus an `else` that hardcodes `"strategy":"fresh"`, so a `rehydrate` decision is mislabeled as fresh and carries no manifest.

This slice wires the integrated assembler into that site. At the implementer routing-decision emission in `engine/l1-drive.sh`, add an explicit branch for `worker_strategy == "rehydrate"` that appends the `context.strategy_selected` event using `singular_ctx_rehydrate_event_data implementer "$task_id" "$run_id" "$n" "$worker_strategy_reason" "$run_dir"` as the event data — recording `strategy=rehydrate`, its refusal reason, and the nested packet manifest. The `resume` and `fresh` (`else`) branches are unchanged and byte-identical. The reviewer / `final-audit` decision site is independence-pinned (`fresh tainted`), so `rehydrate` is structurally unreachable there and that site is left untouched. The remaining `l1-drive.sh` packet-injection hook (rendering the assembled packet into the fresh-run prompt) is the final `rehydrate-path` slice and is OUT OF SCOPE here.

Behavior is gated by the same knobs as the spine (`SINGULAR_CTX_ROUTING`, `SINGULAR_REHYDRATE`, default 0): with `SINGULAR_REHYDRATE` unset the spine never yields `rehydrate`, so the new branch never fires and every emitted `context.strategy_selected` event is byte-identical to current behavior. This is a minimal call-site hook delegating into the integrated `ctx-*.sh` assembler (node `rehydrate-path`, layer `engine_runtime`); no rehydration logic is inlined into the driver.

## Acceptance Criteria

- `tests/test-ctx-rehydrate-event-drive.sh` is written first and fails (red) before the wire-in (a `rehydrate` decision is recorded as `strategy=fresh` with no manifest), then passes (green) after; `bash tests/run.sh` (full suite) is green.
- Recording: with `SINGULAR_CTX_ROUTING=1` and `SINGULAR_REHYDRATE=1`, when the implementer routing decision is `rehydrate <reason>` (a would-be resume refused by a gate on the non-pinned `implement` step, with `run_dir` holding at least one durable artifact), the emitted `context.strategy_selected` event has `data.strategy == "rehydrate"`, `data.reason == "<reason>"`, `data.role == "implementer"`, and a nested `data.manifest` whose `sources` equal `singular_ctx_rehydrate_manifest` applied to `singular_ctx_rehydrate_sources <run_dir>` for that run.
- OFF-parity: with `SINGULAR_REHYDRATE` unset (and =0) the same path records the existing `strategy=fresh` (or `resume`) event byte-identical to before this wire-in — the existing driver and routing tests stay green under the full suite.
- Resume unchanged: a `resume` decision still records its resume event verbatim.
- Independence untouched: the reviewer / `final-audit` `context.strategy_selected` recording is unchanged, since `rehydrate` cannot occur there (the independence pin forces `fresh tainted`).
- Minimal delegation: the hook adds only a small branch delegating into the integrated `singular_ctx_rehydrate_event_data` plus `singular_append_event`; no resolver/manifest/packet logic is inlined into `engine/l1-drive.sh`.
- Evidence invariance: the recorded event carries the manifest (ids + hashes) only, not the packet body; `rehydrate` remains tainted per `singular_ctx_route_strategy_tainted`, so no rehydrated session becomes eligible for an independence-required step.
- Gate candidate: with this wire-in integrated, the packet manifest is recorded in strategy events on `rehydrate` selections; the sole remaining `rehydrate-path` slice is the `engine/l1-drive.sh` packet-injection hook that renders the assembled packet into the fresh-run prompt, after which `test-ctx-rehydrate.sh` green plus the full suite can be proposed as the node exit gate.

## Context packet

Decisions:

- Wire the just-landed pure payload assembler (`singular_ctx_rehydrate_event_data`, TASK-0055) into the existing `context.strategy_selected` site rather than inline the resolver/manifest composition, keeping the scarce `l1-drive.sh` hook a minimal delegation (planner-contract rule 2). Adding an explicit `rehydrate` branch also corrects the current mislabel where the `fresh` `else`-branch would stamp `strategy=fresh` on a rehydrate.
- Scope the wire-in to the implementer (`implement`) decision site: it is the only `context.strategy_selected` site where the spine can emit `rehydrate`; the reviewer site is `final-audit`, independence-pinned to `fresh tainted`, so `rehydrate` is structurally unreachable there. Basis: `engine/ctx-route-taint.sh` and the reviewer-site comment in `engine/l1-drive.sh`.
- Record the manifest but NOT the packet body in the event: the body is prompt-injected by the next slice; events keep ids + hashes only, so no durable artifact content (or scanned-out secret) enters the event stream.

Assumptions:

- [validated] At the implementer `context.strategy_selected` site, `task_id`, `run_id`, the attempt local `n`, `worker_strategy` / `worker_strategy_reason`, and `run_dir` are in scope, and `run_dir` (`engine/l1-drive.sh:110`) is the durable-artifact root the resolver expects — `dirname(session_meta_implementer)` equals `run_dir` (`session_meta_implementer=$run_dir/session-implementer.json`).
- [validated] `singular_ctx_rehydrate_event_data` prints a JSON object with `strategy` / `reason` / `role` / `attempt` plus a nested `manifest`, suitable as the `singular_append_event` data argument (TASK-0055).
- [validated] With `SINGULAR_REHYDRATE` default 0 the spine never emits `rehydrate`, so the new branch is inert and events remain byte-identical (OFF-parity).
- [open] Prior `l1-drive.sh` driver wire-ins are exercised by a `tests/test-ctx-*-drive.sh` harness (e.g. `test-ctx-assumptions-drive.sh`, `test-ctx-route-drive.sh`); this slice adds `tests/test-ctx-rehydrate-event-drive.sh` following that pattern.

Rejected alternatives:

- Folding the packet-injection into this slice — rejected: injection modifies prompt assembly, a distinct and riskier call site; keep it a separate gated slice (folding = 1 mandates one smallest slice regardless).
- Adding a `rehydrate` branch at the reviewer site as well — rejected: `final-audit` is independence-pinned, so `rehydrate` cannot occur there; the branch would be dead code.
- Inlining `singular_ctx_rehydrate_sources` / `singular_ctx_rehydrate_manifest` at the event site — rejected: it duplicates TASK-0055's tested payload assembler inside the hard-to-test driver file.
