## Objective

Advance executable DAG node `planner-resume-gates` (stage `S1-planner-persistence`, area `session`, layer `engine_runtime`) by landing the binding SHA-alignment slice its stage file calls for after the TASK-0008 review. The integrated planner finalize wrapper `gluerun_ctx_planner_session_finalize` in `engine/ctx-planner-session.sh` currently stores whatever `prompt_sha` its `generate-tasks.sh` call sites pass, and those call sites pass `gluerun_prompt_sha "$prompt_file"` — the sha of the RENDERED per-frontier planner prompt (`$run_dir/planner-prompt.md`). The integrated decider `gluerun_planner_resume_decide` in `engine/ctx-planner-resume.sh` keys gate 8 on the sha of the planner TEMPLATE `docs/orchestration/prompts/l1-planner.md` (never the rendered prompt, which varies per frontier by design). As integrated these two sides can never agree, so a finalized planner meta permanently yields `fresh prompt-template-changed` and planner resume is silently neutered.

This slice aligns BOTH sides on the TEMPLATE sha by normalizing inside the finalize wrapper (re-owning `engine/ctx-planner-session.sh`, so driver-file hooks in `generate-tasks.sh` stay untouched): the finalized meta's `promptSha256` must be the sha256 of the planner TEMPLATE file, resolved with the SAME canonical path convention the decider keys on (honor `GLUERUN_PLANNER_TEMPLATE`; default `docs/orchestration/prompts/l1-planner.md` under `GLUERUN_ROOT`; reuse `gluerun_planner_resume_template_path` / `gluerun_sha256_file`), regardless of the rendered-prompt sha the call site passes. This is the sanctioned follow-up to the decider core and does NOT touch the `generate-tasks.sh` consult hook, the rc-86 in-run fresh fallback, or the `context.strategy_selected` planner events, which remain out of scope and unowned here.

Feature-flag discipline is preserved: the finalize wrapper stays a no-op when `GLUERUN_PLANNER_SESSION` is unset or `0` (default OFF), so `bash tests/run.sh` is byte-identical to current behavior with the knob off. The `gluerun.orchestration.session-meta.v0` shape is reused as-is (no new fields; only the value stored in the existing `promptSha256` field changes). Evidence invariance holds: an unreadable/absent template resolves fail-closed to an empty/absent stored sha so a later decide returns `fresh prompt-template-changed` and never `resume`.

## Acceptance Criteria

Behavior-level and checked by the new `tests/test-ctx-planner-sha-align.sh` (strict_test_first: the new test is red before implementation, green after; `bash tests/run.sh` and `tests/test-engine-clean.sh` stay green). All criteria concern node `planner-resume-gates`, layer `engine_runtime`.

- With `GLUERUN_PLANNER_SESSION=1` and `rc=0`, `gluerun_ctx_planner_session_finalize` writes a finalized planner meta whose `promptSha256` equals sha256 of the planner TEMPLATE `docs/orchestration/prompts/l1-planner.md` (honoring `GLUERUN_PLANNER_TEMPLATE`), NOT the sha of the rendered prompt passed by the call site — so a fixture whose rendered-prompt sha differs from the template sha still finalizes with the template sha.
- Finalize→decide round-trips to `resume`: after finalizing under the knob, calling `gluerun_planner_resume_decide` with every other gate satisfied (role `planner`, matching node, ancestor head, matching runner, unexpired, matching cwd, no held lease) yields `resume <sessionId>`.
- Two-frontier proof: two finalize runs for the same node using two DIFFERENT rendered prompts but the SAME template both produce metas that each decide `resume` — the per-frontier rendering variation never forces a `fresh prompt-template-changed`.
- Fail-closed template resolution: when the template file is unreadable/absent at finalize time, the stored `promptSha256` is empty/absent (never a stale or rendered sha), so a later `gluerun_planner_resume_decide` returns `fresh prompt-template-changed` and never `resume` (evidence invariance — alignment never weakens gate 8 into a spurious resume).
- Feature-flag discipline: with `GLUERUN_PLANNER_SESSION` unset or `0` the finalize wrapper writes no file and is byte-identical to current behavior; with a non-numeric or non-zero `rc` no resumable meta is finalized. `bash tests/run.sh` remains byte-identical when the knob is OFF.
- Additive-schema discipline: the `gluerun.orchestration.session-meta.v0` shape is reused unchanged (only the value in the existing `promptSha256` field is normalized; no new required fields; the optional `node` field is still set).
- Engine cleanliness: `tests/test-engine-clean.sh` stays green (no project-specific symbols introduced into `engine/`); the finalize wrapper still never fails its caller and writes only under the runtime state dir, never under `docs/`.
