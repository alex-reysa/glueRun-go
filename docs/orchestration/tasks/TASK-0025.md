## Objective

Next deliverable of the executable DAG node `plan-revision-loop` (stage `S3-plan-revision`, area `plancritic`, layer `engine_runtime`, kind `runtime`). The planner-resume spine is integrated (TASK-0019..TASK-0024), but one stage-file deliverable of this node is still unimplemented: "Revised candidates re-enter the critic (same critic session where its gates allow — its prior concerns are the checklist)." The integrated loop engine/ctx-plan-revise-loop.sh (TASK-0023) re-critiques every round by running the plan-critic FRESH (engine/ctx-plan-critic.sh always runs fresh, no session reuse), so the same-critic-session carry-over on re-critique does not yet exist. This is distinct from the separate post-acceptance `critic-carryover` node (GLUERUN_CRITIC_RECHECK_PCT), which rechecks an accepted diff.

The plan-critic driver already FINALIZES a canonical per-node critic session-meta with role `plan-critic` at `<state-dir>/sessions/plan-critic/<node>.json` (TASK-0013, explicitly earmarked usable by Stage 3 carry-over). This brick adds the fail-closed authority that decides whether a re-critique may RESUME that persisted critic session (where its gates allow) or must run fresh, plus the recorder that makes the carry-over observable — mirroring how the integrated planner-role decider gluerun_planner_resume_decide (TASK-0009) landed before its consult hook. New file `engine/ctx-plan-recritic-resume.sh` is auto-sourced by the ctx-loader block in lib.sh and defines NEW functions only; NO existing engine path invokes them, so present-but-uncalled the engine is byte-identical to prior behavior (mirroring engine/ctx-plan-revise-resume.sh). It adds NO driver-file hook and never owns engine/lib.sh. Consulting this decider inside the re-critique step of the integrated loop (behind the new knob) is the sanctioned follow-up slice and is OUT OF SCOPE here.

## Acceptance Criteria

- `gluerun_plan_recritic_resume_decide <critic_session_meta> <node> <runner_basename> <worktree> <lineage_head>` prints EXACTLY one line, `resume <sessionId>` or `fresh <reason>`, and never exits non-zero. It applies ordered fail-closed gates where the FIRST failing gate names the reason and resumes the persisted plan-critic session ONLY when every gate passes; any ambiguity resolves to `fresh <reason>`, NEVER to resume.
- Gate 1 default-OFF: `GLUERUN_PLAN_RECRITIC_RESUME` unset or not equal to 1 -> `fresh disabled`, so with the knob off the re-critique stays FRESH exactly as today (byte-identical), independent of GLUERUN_PLAN_CRITIQUE. This is a new documented knob (default 0); no default flip here.
- Skeptic role gate (advocate/skeptic line): the session-meta role must be exactly `plan-critic`; any other role (planner, implementer, reviewer, and so on) -> `fresh role-mismatch`. Combined with the integrated planner decider's own role==planner gate, a plan-critic session is NEVER resumable as planner/implementer and vice versa — a re-critique may only re-enter a skeptic session.
- The remaining ordered gates mirror the integrated planner-resume decider and fail closed, each resolving to `fresh <reason>`: missing/unparseable meta -> no-session; empty provider or sessionId -> no-session-id; node mismatch -> node-mismatch; headShaAtCreate not an ancestor of the lineage head, or either empty/indeterminate -> head-rewritten; runner basename changed -> runner-changed; critic prompt-template sha changed or unreadable -> prompt-template-changed; age greater than GLUERUN_SESSION_MAX_AGE_SEC or missing createdAt -> expired; worktree moved -> worktree-moved; a live critic session-lease held -> leased.

Records only: no lease change, no runner, no outcome mutation.
