## Objective

Advance the executable DAG node `critique-import-gate` (stage `S2-plan-critique`, area `plancritic`, layer `engine_runtime`, kind runtime) toward its required completion — L0 import honors critique verdicts behind `GLUERUN_PLAN_CRITIQUE` (default 0 = observe-only), ON enforces approve/revise/park and fails closed on missing record — by adding a new, present-but-uncalled `engine/ctx-critique-import-fanout.sh`: a critique-aware L1 import fanout orchestrator that composes the already-integrated pieces so the import path can honor the plan critic verdict.

The enforcement decision and disposition are already integrated: `gluerun_ctx_critique_import_decide` (TASK-0015, the pure read-only DECISION — OFF always imports; ON maps `approve` to import and `revise` / `park` / missing / invalid to a reject carrying the stable reason token `plan-critique`) and `gluerun_ctx_critique_import_gate` (TASK-0016, the DISPOSITION — on the ON-reject path it records exactly one `origin.l1_import_rejected` event with reason `plan-critique` and sets the node lease to failed via `gluerun_l1_lease_set_status`, otherwise zero side effects). What is missing is the seam that actually applies the disposition to the import: the shared L1 importer `gluerun_l1_import_staged` and the fanout that calls it live in `engine/lib.sh`, which this node may not own, and they couple per-node staging and import so a minimal `reconcile.sh` call-site cannot interpose the gate between them. This brick supplies the drop-in vehicle that resolves that seam WITHOUT modifying `engine/lib.sh`, by orchestrating stage then gate then import-only-approved out of the existing integrated functions.

The public entry point mirrors the shape of `gluerun_l1_fanout` (same two arguments, same `l1_planner_failures=` / `l1_import_rejections=` summary lines the caller parses) so it is a drop-in the follow-up hook can select. For a run it selects the L1 frontier (reusing `gluerun_select_l1_frontier`), stages candidates per node by invoking the same planner driver into the same `l1-staging/<node>` dirs (so the staged candidate sets are identical to plain fanout), then for each successfully-staged node assembles the read-only critic context (reusing `gluerun_ctx_plan_critic_context`) and runs the integrated critic driver `gluerun_ctx_plan_critic_run` on the default runner to persist `plan-critique.json`, applies `gluerun_ctx_critique_import_gate`, and PARTITIONS nodes by disposition: `import`-disposition nodes are handed to the integrated `gluerun_l1_import_staged` (reused verbatim — its promotion logic is never duplicated), while `reject`-disposition nodes are dropped (the gate has already recorded the `origin.l1_import_rejected` reason `plan-critique` and failed the lease). Because the integrated gate returns `import` for every node when `GLUERUN_PLAN_CRITIQUE` is observe-only (0), the imported node set then equals plain fanout while critique records and `plan.critiqued` events are still produced — the import path is equivalent to today in observe-only mode, and only ON (`=1`) actually withholds `revise` / `park` / fail-closed batches.

The file defines NEW functions only and is invoked by NO existing engine path — `engine/reconcile.sh` still calls `gluerun_l1_fanout` — so with it present-but-uncalled the engine is byte-identical to prior behavior (mirroring `engine/ctx-critique-import.sh`, `engine/ctx-critique-import-gate.sh`, and `engine/ctx-plan-critic.sh`). It never owns `engine/lib.sh` and adds no driver-file hook: the small `reconcile.sh` call-site that swaps this orchestrator in behind the knob, and the update to the frozen present-but-uncalled assertion in `tests/test-ctx-critique-import.sh`, are the FINAL wiring slice for this same `critique-import-gate` node and are out of scope here. Advocate/skeptic line and evidence invariance hold: the critic runs read-only, fresh, on the default runner, enforcement is layered over it, and no path weakens, resumes into, or bypasses the un-bypassable implementation auditor; the ON-reject path only ever withholds import, never fabricating an approval.
