## Objective

Advance the `experiment-run` executable DAG node (layer `evaluation`) with the presentation capstone of the raw-metrics measurement suite: a deterministic, strictly read-only renderer that formats the integrated summary bundle into the markdown metrics tables the operator drops into `experiment-report.md` (the exit gate requires the report merged with raw metrics artifacts referenced). All raw-metrics JSON aggregators are integrated: TASK-0077 `engine/ctx-experiment-report.sh` (per-arm escape-rate, cost, bias), TASK-0079 `engine/ctx-experiment-strategy.sh` (resume/rehydrate hit rates + gate-refusal reason mix), TASK-0081 `engine/ctx-experiment-attempts.sh` (attempts-to-accept + findings-per-attempt), and TASK-0083 `engine/ctx-experiment-summary.sh` which merges them via `singular_ctx_experiment_summary_json` into one bundle conforming to `singular.orchestration.ctx-experiment-summary.v0`. This brick RENDERS that bundle; it computes no metric of its own and does not duplicate any aggregator. It emits markdown to STDOUT ONLY: it never writes `docs/context-build-plan/experiment-report.md` (an operator-owned concept), never runs the A/B experiment, and never records per-knob default decisions in `docs/orchestration/decisions.md` — all OPERATOR authority (kind: evaluation). It neither declares nor gates node completion.

All logic lands in one NEW `engine/ctx-experiment-render.sh`, auto-sourced by the ctx-loader block and defining new functions only. No existing engine path invokes them, so the engine is byte-identical with the file present (OFF-parity intrinsic, mirroring the sibling `engine/ctx-experiment-*.sh` idiom). It does NOT edit the four sibling `ctx-experiment-*.sh` files, `engine/ctx-metrics.sh`, or any other pre-existing file. It consumes a summary-bundle JSON source (a file path, or `-` for stdin); when no source is supplied it obtains the bundle by delegating to `singular_ctx_experiment_summary_json` with the standard env defaults. It formats the bundle's already-computed values verbatim (no recomputation, no reclassification) and reads or writes nothing else.

Implement three chained slices in order, all inside `engine/ctx-experiment-render.sh`:

1. Per-arm PRIMARY table renderer: from the bundle, render a deterministic markdown table comparing arm A (control / M0 knob-state) and arm B (treatment) across escape rate, cost (tokens + wall-clock per accepted task), attempts-to-accept (mean), and findings-per-attempt (mean).

2. BIAS + STRATEGY table renderer: render the bias table (flagged findings, directional disagreements, directional-disagreement rate) and the resume/rehydrate hit-rate + gate-refusal reason-mix table (by arm, and by role where the bundle carries it).

3. Composed public entry `singular_ctx_experiment_render_md [summary_source]`: obtain the bundle (from the file/stdin arg, else by delegating to `singular_ctx_experiment_summary_json`), render all sections in a stable order to stdout as one markdown fragment. Fail-safe: a zeroed/empty bundle renders well-formed tables with zero values and a zero exit, never an error or partial output.

## Context packet

### Decisions

- Emit markdown to STDOUT and never write `experiment-report.md`, because that file is an operator-owned concept; the renderer is presentation tooling (JSON bundle to tables) the operator merges, not the report author.
- Format the integrated summary bundle verbatim (no recomputation), so every rendered value has a single upstream definition site and the tables cannot drift from the JSON artifacts.
- No new schema: the output is markdown and the input already conforms to `singular.orchestration.ctx-experiment-summary.v0`; a golden-markdown test pins the bytes.

### Rejected alternatives

- Writing `experiment-report.md` directly — rejected: operator-owned file/concept; the planner contract keeps eval doc authorship operator-driven.
- Re-reading runs/events to render — rejected: the summary bundle already carries every value; re-deriving would duplicate metric logic and risk drift.
- A `singular experiment-report` CLI subcommand — rejected here: it would own `cli/singular` (a pre-existing driver file, forcing the full-suite gate) and CLI coverage belongs to the `polish-release` node, not `experiment-run`.

### Assumptions

- [validated] `singular_ctx_experiment_summary_json` emits a bundle conforming to `singular.orchestration.ctx-experiment-summary.v0` with nested `report` (escapeRate/cost/bias by arm), `strategy` (hitRates/refusalMix by arm and role), and `attempts` (attemptsToAccept/findingsPerAttempt by arm) — basis: engine/ctx-experiment-summary.sh public entry and the summary schema keys.
- [open] Role-level strategy splits (implementer/reviewer/planner) may be absent for some arms; the renderer omits an empty role row rather than erroring — basis: the fail-safe contract of the sibling aggregators.
