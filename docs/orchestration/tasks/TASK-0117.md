## Objective

Task-lease recovery is liveness-aware: `engine/recover.sh` runs
`singular_dispatch_tree_alive` (five probes: pid+start-time, descendants, pgid, run-id
cmdline, run-dir mtime window) and skips live trees before any wall-clock rule. L1 planning
leases have none of that: `singular_l1_reclaim_stale` (via `singular_l1_list_stale` in
`engine/lib.sh`) compares only `updatedAt` against `SINGULAR_L1_STALE_MINUTES` (default 60)
and marks each hit `failed` — a healthy long-running planner is reclaimed under its own feet.
This was the one path where the audited "recovery can't tell live from abandoned" claim was
fully true.

Required changes:

1. Record enough identity at L1 lease creation/refresh to probe liveness: pid, pid start-time,
   and pgid of the planning process (mirror the dispatch-record fields; extend the L1 lease
   record additively — readers must accept old records without these fields).
2. In the reclaim path, before the wall-clock comparison: if identity fields are present,
   probe with the same primitives task recovery uses (`singular_pid_alive` with start-time
   match; pgid membership as fallback). A live planner is skipped with a logged
   `recover: skipped <lease> (planner still alive)` line. Absent identity fields (old
   records) fall through to today's wall-clock behavior unchanged.
3. Keep a hard cap: at `SINGULAR_L1_STALE_HARD_MINUTES` (new, default 240, mirroring the task
   path's bounded conservatism) the wall-clock rule wins even over a live probe, and the
   reclaim log says so explicitly.
