## Objective

Extend the `graph-projector` (layer `engine_runtime`) mapping-table coverage with the `plan-batch` node family — the 12th of the 13 node types, and the last one with a durable source. The headline requiredCompletion behaviors (rebuild/sync/query behind `GLUERUN_CTX_GRAPH`, idempotent + deterministic, rebuild equals sync, loss-free, test-ctx-graph.sh green) are already integrated and guarded (TASK-0090); this fills a remaining node type so the projected graph is a fuller durable-semantic layer. It lands solo because the only other uncovered node family, `goal`, has no durable record (no `docs/orchestration/goal.md`, no DAG objective field), and the remaining cross-record edges (`critiques`, `accepts_observation`/`rejects_observation`, `contradicts`) carry identity-alignment risk — none is a clean ready slice to fold. New file `engine/ctx-graph-project-planbatch.sh`, auto-sourced by the ctx-loader block, defines functions ONLY (OFF-parity for `GLUERUN_CTX_GRAPH`, default 0; present-but-uncalled is byte-identical — the established land-then-wire pattern; wiring into rebuild/sync is a follow-up):

- `gluerun_graph_project_plan_batch <sessionMetaRecordPath>` reads a durable S1 planner session-meta record (the `planner-session-meta/planner.out` line carrying `node=`, `stage=`, `area=`, and `staged:TASK-*` entries) and emits one `plan-batch` node (evidenceClass `claim`) keyed identity('plan-batch', node, runId), with `attributes` projecting stage/area and the staged-task count. It is TOLERANT: a missing field is skipped and a malformed or empty record yields no node and a zero exit (fail-safe), never a crash.

The `derived_from` edge from `plan-batch` to `goal` is deferred: `goal` has no durable source to mint, so plan-batch ships node-only until a goal record is introduced. This task advances `graph-projector` by covering the plan-batch node type; it does not touch the already-met requiredCompletion and does not declare the node complete.

## Context packet

### Decisions
- Plan-batch lands solo and node-only: `goal` has no durable record to mint (so its `derived_from` edge is deferred), and the remaining cross-record edges are identity-alignment-risky — plan-batch is the single clean ready slice.
- The mapper is tolerant of the free-form `planner.out` text (key=value plus `staged:` lines) because that record is a log, not a schema-backed JSON; defensive parsing avoids brittle failures on format drift.
- Landed new-file / OFF-parity first (the pattern every mapper used before wiring); adding it to the rebuild/sync walks and the composed guard is a clean follow-up.

### Assumptions
- [validated] a durable planner session-meta record exists at `runs/<runId>/l1-staging/<node>/planner-session-meta/planner.out` carrying `node=`, `stage=`, `area=`, and `staged:TASK-*` — basis: the real `.gluerun-state` tree.
- [validated] `gluerun_graph_identity` and the emitters are type-agnostic and integrated — basis: TASK-0074 / TASK-0076.
- [violated] a durable `goal` record (`docs/orchestration/goal.md` or a DAG objective field) exists — basis: neither is present in the repo, so `goal` and the `plan-batch` -> `goal` `derived_from` edge cannot be minted yet.
- [open] `python3` is available for parsing in the mapper and its test — basis: prior graph code relies on it.

### Rejected alternatives
- Mapping `goal` now to anchor the `derived_from` edge — rejected: there is no durable goal record, so any goal node would be fabricated, violating the pure-projection rule.
- Emitting `accepts_observation`/`rejects_observation` or `critiques` edges this turn — rejected: their finding/plan-version endpoints are keyed by the critique's node+runId while the referencing events carry a different runId, so the join is not reliably alignable without deeper tracing; a mis-joined edge is worse than a deferred one.
