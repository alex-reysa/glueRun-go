## Objective

Advance the executable DAG node `subgraph-rehydrate` (stage `S6-graph`, layer
`engine_runtime`) with the next chained brick after the accepted selection
reader (TASK-0099): a NEW pure, read-only, deterministic resolver in
`engine/ctx-rehydrate-subgraph-sources.sh` defining
`gluerun_ctx_rehydrate_subgraph_sources`. It maps the SELECTED subgraph — a
stream of canonical `schemas/context-graph.v0.schema.json` node records read
from stdin (or a file arg) — onto class-tagged `<source-class-id>=<path>`
rehydration source specs, the bridge from graph nodes to the integrated
rehydration assembler.

Behavior: for each selected node whose `type` maps to a durable rehydration
source class, emit one `<source-class-id>=<provenance.sourcePath>` spec; nodes
whose type has no durable rehydration source class (e.g. goal, plan-batch,
gate-result, audit, commit) emit nothing. The emitted source-class ids MUST
match the integrated assembler vocabulary EXACTLY (task-packet,
implementer-capsule, reviewer-capsule, findings-ledger, assumptions-ledger,
critique-record, decision-record — the RANK in `engine/ctx-rehydrate.sh`, same
vocabulary as the run-dir resolver `gluerun_ctx_rehydrate_sources` in
`engine/ctx-rehydrate-sources.sh`) so the resolver stdout composes directly as
arguments to `gluerun_ctx_rehydrate_packet` / `gluerun_ctx_rehydrate_manifest`
with caps and manifest UNCHANGED.

Order: PRESERVE the input record order (the selection order emitted by the
selector) — do NOT re-sort by source-class rank — so the selector
contradictions-first ordering survives intact into a later order-preserving
subgraph packet renderer slice.

Data-contract coupling: this slice consumes selected node records as INPUT and
does NOT call the TASK-0099 selection reader. That reader is accepted but not
yet integrated into `agent/integration` (its `gluerun_ctx_rehydrate_subgraph_*`
symbols are absent on the branch this worker forks from), so the two pieces
compose later purely through the canonical node-record JSONL contract, each
fixture-tested on its own.

Feature-flag discipline: the file DEFINES a new function only and no existing
engine/CLI/driver path invokes it, so with it sourced the engine is
byte-identical to prior behavior (OFF-parity).

Evidence invariance / advocate-skeptic line: the resolver is a pure read — it
never writes, never mutates taint, confers NO independence on a
resumed/rehydrated session, and records nothing as `authoritative`. It only maps
selected records to source specs.

## Acceptance Criteria

- Over a hand-authored fixture stream of canonical context-graph.v0 node records
  representing a selected subgraph (task, a surviving finding, an open
  assumption, a critique, a decision, a capsule), the resolver emits exactly one
  `<source-class-id>=<provenance.sourcePath>` spec per node whose type maps to a
  durable rehydration source class, using the integrated assembler source-class
  vocabulary.
- A selected node whose type has NO durable rehydration source class (e.g. goal,
  plan-batch, gate-result, audit, commit) emits NO spec.
- Output preserves the input record order (selection order) and is NOT re-sorted
  by source-class rank, so a contradictions-first selection stays
  contradictions-first through the resolver.
- Emitted ids match the integrated assembler source-class ids exactly, so piping
  the resolver stdout as arguments to `gluerun_ctx_rehydrate_packet` /
  `gluerun_ctx_rehydrate_manifest` composes without any unknown-id fallback, and
  section caps (`GLUERUN_CONTEXT_SECTION_MAX_CHARS`) and the manifest schema
  `gluerun.orchestration.ctx-rehydrate-manifest.v0` are unchanged.
- Deterministic: identical input node records yield byte-identical specs across
  repeated runs.
- Fail-safe: empty input (no node records) yields no specs and exits zero;
  well-formed input never exits non-zero.
- OFF-parity: with the new file sourced but uncalled, the engine is
  byte-identical to prior behavior.
- Gate candidate: `tests/test-ctx-rehydrate-subgraph-sources.sh` is red before
  implementation and green after; `tests/test-engine-clean.sh` stays green (no
  project-specific symbols in `engine/`).

## Context packet

Decisions:
- New file `engine/ctx-rehydrate-subgraph-sources.sh`, not an edit to
  `engine/ctx-rehydrate-sources.sh` — why: the run-dir resolver maps a
  filesystem run directory to source classes, whereas this maps GRAPH NODE
  RECORDS (different input domain); the new-file convention keeps a scoped gate
  and avoids the full-suite gate that editing the existing resolver would force.
- Consume selected node records as a DATA CONTRACT (stdin/file), do not call the
  TASK-0099 selector — why: TASK-0099 is accepted but NOT integrated into
  `agent/integration`, so its runtime symbols are unavailable to a worker
  forking the branch; a runtime call would red the gate. Composition happens
  later over canonical node-record JSONL.
- Preserve input (selection) order; do NOT re-sort by the assembler RANK — why:
  the flat assembler re-sorts sections by a fixed source-class RANK independent
  of argument order, which would destroy the selector contradictions-first
  ordering; the subgraph path needs an order-preserving renderer in a later
  slice, so order must not be collapsed here.
- Reuse the assembler exact source-class id vocabulary — why: keep caps and
  manifest UNCHANGED and let the specs compose as
  `gluerun_ctx_rehydrate_packet`/`_manifest` arguments without unknown-id
  fallback.

Assumptions:
- [validated] a context-graph.v0 node record carries `provenance.sourcePath`
  (durable source path) plus a `type` from the fixed node taxonomy — basis: the
  node and provenance defs in `schemas/context-graph.v0.schema.json`.
- [validated] the integrated assembler orders sections by a FIXED source-class
  RANK independent of argument order — basis: RANK in
  `engine/ctx-rehydrate.sh`; hence order preservation must be enforced by a later
  renderer, not by feeding the flat assembler.
- [open] the node-type to source-class table maps task->task-packet,
  finding->findings-ledger, assumption->assumptions-ledger,
  critique->critique-record, decision->decision-record, and
  capsule->implementer-capsule/reviewer-capsule (capsule role taken from the
  node attributes/label); node types without a durable rehydration source class
  stay intentionally unmapped — basis: the source-class vocabulary in
  `engine/ctx-rehydrate-sources.sh`; the worker MUST NOT invent source-class ids
  outside the assembler vocabulary.

Rejected alternatives:
- Feeding selected node records straight into the flat assembler as artifacts —
  why-not: the assembler reads durable ARTIFACT bytes at `provenance.sourcePath`,
  not node JSON; the node-to-(class,path) bridge is exactly this resolver job.
- Re-sorting emitted specs by source-class RANK for direct flat-assembler reuse
  — why-not: destroys the contradictions-first selection order (see decisions).

Inspected symbols:
- `gluerun_ctx_rehydrate_sources` (`engine/ctx-rehydrate-sources.sh`) — role: the
  run-dir analogue whose source-class id vocabulary this resolver must match
  exactly; NOT a duplicate (different input domain: run directory vs selected
  graph nodes).
- RANK (`engine/ctx-rehydrate.sh`) — role: the fixed section ordering the flat
  assembler imposes; the reason this resolver must preserve selection order for a
  later subgraph renderer instead of relying on the flat assembler.
