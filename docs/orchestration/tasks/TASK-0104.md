## Objective

Advance the executable DAG node `subgraph-rehydrate` (stage `S6-graph`, layer
`engine_runtime`) with its stage A/B hook — arms can now compare flat-capsule
rehydration versus subgraph rehydration — as a pure, new-file decision leaf in
`engine/ctx-rehydrate-subgraph-arm.sh`. The subgraph toolchain is fully
integrated (selector `singular_ctx_rehydrate_subgraph_select`, resolver
`singular_ctx_rehydrate_subgraph_sources`, and the order-preserving assembler
`singular_ctx_rehydrate_subgraph_assemble`), but nothing yet CHOOSES it per arm;
the flat path is still the only rehydration mode any call site selects.

Add a deterministic mode decider:
`singular_ctx_rehydrate_subgraph_arm_mode <task_id> [graphDir]` prints exactly
`subgraph` or `flat`. It selects `subgraph` only when ALL fail-closed conditions
hold, else `flat`:
  (1) the dedicated feature knob SINGULAR_CTX_SUBGRAPH_REHYDRATE=1 (default 0);
  (2) the task deterministic arm — via the integrated `singular_ctx_ab_arm_for`
      (engine/ctx-ab.sh) — is the designated treatment arm (control arm stays
      flat), so a given id yields the same mode across processes and machines;
  (3) the graph corpus at graphDir (default
      ${SINGULAR_CTX_GRAPH_DIR:-.singular-state/graph}) exists and is non-empty,
      so `singular_ctx_rehydrate_subgraph_assemble` could actually render a
      packet.
Any failing precondition yields `flat`. This is the single point that lets a
later ctx-route.sh selection wire-in and l1-drive.sh subgraph-packet injection
swap the flat assembler for the subgraph assembler on the treatment arm; those
wire-ins touch existing driver files (full-suite gate, scarce hooks) and are
SEPARATE later tasks, out of scope here.

Feature-flag discipline: the file DEFINES a new function only and no existing
engine/CLI/driver path invokes it, and the knob defaults OFF, so with it sourced
the engine is byte-identical to prior behavior and the decider returns `flat`
for every id (OFF-parity: today flat is the only mode).

Evidence invariance / advocate-skeptic line: the decider is a pure read — it
chooses a rendering mode only. It appends no events, writes/renames/deletes
nothing, confers NO independence, and does not alter taint; the `rehydrate`
strategy stays tainted per singular_ctx_route_strategy_tainted regardless of which
mode is chosen.

## Acceptance Criteria

- Default OFF: with SINGULAR_CTX_SUBGRAPH_REHYDRATE unset or 0, the decider prints
  `flat` for every task id regardless of arm or corpus (OFF-parity with today
  flat-only rehydration).
- With the knob = 1 and a present, non-empty graph corpus at graphDir, the
  decider prints `subgraph` for task ids whose deterministic arm (via
  `singular_ctx_ab_arm_for`) is the designated treatment arm and `flat` for the
  other arm; the same id yields the same mode across repeated calls, separate
  processes, and different machines (deterministic, machine-independent).
- Fail-closed to flat: with the knob = 1 but the graph corpus missing or empty,
  the decider prints `flat` for every task id (no subgraph packet could be
  produced).
- Pure and non-fatal: the decider prints only the mode token, appends no events,
  writes/renames/deletes nothing, and exits zero on well-formed input.
- Evidence invariance: the mode choice never marks a session independent and
  never changes the tainted status of the rehydrate strategy.
- OFF-parity: with the new file sourced but the decider uncalled (and the knob at
  its default), the engine is byte-identical to prior behavior.
- Gate candidate: `tests/test-ctx-rehydrate-subgraph-arm.sh` is red before
  implementation and green after; `tests/test-engine-clean.sh` stays green (no
  project-specific symbols in `engine/`).

## Context packet

Decisions:
- A new dedicated knob SINGULAR_CTX_SUBGRAPH_REHYDRATE (default 0), separate from
  SINGULAR_CTX_GRAPH — why: feature-flag discipline requires each behavior change
  default-OFF behind its own documented knob; building the graph
  (SINGULAR_CTX_GRAPH) and choosing subgraph rehydration are distinct behaviors,
  and reusing the graph knob would silently flip rehydration mode the moment a
  corpus exists.
- A pure decider leaf in a new file; the ctx-route.sh selection wire-in and the
  l1-drive.sh subgraph-packet injection are SEPARATE later tasks — why: those
  touch existing driver files (full-suite gate, scarce hooks), so the
  chained-slice rule requires them to land alone.
- Fail-closed to flat when the knob is off, the treatment arm is not selected, or
  the graph corpus is absent/empty — why: preserve current behavior and never
  select a mode that cannot render a packet.

Assumptions:
- [validated] `singular_ctx_ab_arm_for <task_id>` deterministically maps an id to
  arm A|B, machine-independently, with no side effects — basis: engine/ctx-ab.sh.
- [validated] `singular_ctx_rehydrate_subgraph_assemble` needs a present,
  non-empty graph corpus (nodes.jsonl/edges.jsonl) to render a packet, and the
  selector is fail-safe empty on a missing corpus — basis:
  engine/ctx-rehydrate-subgraph-packet.sh and engine/ctx-rehydrate-subgraph.sh.
- [open] the treatment (subgraph) arm is B and the control (flat) arm is A —
  basis: the stage A/B hook compares flat vs subgraph; the exact arm-to-mode
  binding must be deterministic and documented, and either arm value must yield
  `flat` when any precondition fails.

Rejected alternatives:
- Reusing SINGULAR_CTX_GRAPH as the subgraph-rehydration gate — why-not: it gates
  graph PROJECTION, not the rehydration-mode choice; conflating them would flip
  rehydration behavior as soon as the graph is built.
- Wiring the mode choice directly into ctx-route.sh in this task — why-not:
  existing driver file (full-suite gate, scarce-hook ownership); that wire-in is
  a separate task.

Inspected symbols:
- `singular_ctx_ab_arm_for` (engine/ctx-ab.sh) — role: the deterministic,
  event-free arm source this decider keys the treatment/control split off; NOT
  `singular_ctx_ab_assign`, whose event append would break the decider purity.
- the flat rehydrate wire-in in engine/ctx-route.sh (SINGULAR_REHYDRATE;
  `singular_ctx_rehydrate_sources` -> `singular_ctx_rehydrate_manifest`) — role: the
  existing flat path a later wire-in will let the treatment arm swap for the
  subgraph assembler; shown so this decider output vocabulary (flat|subgraph)
  matches what that future wire-in branches on.
