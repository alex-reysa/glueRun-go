## Objective

Every provider runner and the gate freeze their timeout at spawn:
`deadline=$((SECONDS + budget))` computed once above the poll loop (`engine/codex-run.sh`,
`engine/claude-run.sh`, `engine/cursor-run.sh`, `engine/grok-run.sh`, `engine/gemini-run.sh`,
`engine/opencode-run.sh`, `engine/gate-check.sh`), with no reload path anywhere. Field
consequence (audited, reproduced from real run state): an operator raising the budget mid-run
has zero effect on the running try — three consecutive kills each fired at the exact stale
budget, every raise landing after the kill it was meant to prevent.

The first dogfood implementation proved that a plain JSON file cannot also satisfy the authored
host-authority boundary. Provider and gate children run as the same UID as the host; hiding paths,
scrubbing environment variables, chmod/ACL/chflags, or a deprecated platform sandbox cannot stop
an arbitrary child from deriving `.singular-state/runs`, replacing the file, and self-extending.
The control must therefore be writable but not *authorable* by the supervised identity: only a
run-bound asymmetric signature from an external operator authority makes a record honor-able.

Required changes:

1. New sourced helper `engine/run-control.sh` verifies an optional signed
   `<control_dir>/run-control.json`. The v1 record contains exactly `schema`, `runId`,
   monotonically increasing `generation`, `deadlineExtendSec`, `cancel`, `reason`, `updatedAt`,
   `signerKeyId`, and `signature`. Verify an Ed25519 signature over a documented,
   domain-separated canonical payload containing every field except `signature`. The expected
   run ID, signer key ID, and public-key bytes are pinned in parent memory before the child
   spawns and are never re-read from a child-writable path. The
   production private signing key must never enter the repository, worktree, state root, child
   environment, argv, or supervised UID's runtime filesystem. Operators supply a pre-signed
   record; writer/key provisioning remains outside this task. Tests may create an ephemeral
   fixture key only in parent-process memory or an anonymous pipe before the adversarial child
   exists; its private bytes must be erased before spawn and must never appear in a filesystem
   path, environment, or argument. Resolve and pin every verification dependency before child
   spawn. A verifier is trusted only when it is pinned before spawn through a root-owned,
   non-group/other-writable canonical regular executable chain, or is an equivalently immutable
   in-process verifier whose exact code is already resident and is never executed through a
   mutable path. Byte-hashing a tool and later reopening its pathname is not sufficient. A PATH
   lookup, a sandbox-relative `-w` result, a user-owned Homebrew/venv binary, or a replaceable
   symlink is not a trust boundary. If no trusted verifier exists, signed control fails closed
   while no-control behavior remains unchanged.
2. New additive schema `schemas/run-control.v1.schema.json` with
   `schema: "singular.orchestration.run-control.v1"`, RFC3339 `updatedAt`, non-negative integer
   generation/extension, boolean cancel, bounded strings (including an empty `reason`), base64
   signature, and `additionalProperties: false`. Add the byte-identical consumer mirror
   `schemas/orchestration/run-control.v1.schema.json`; the runtime hard protocol ceiling and both
   schemas must declare the same maximum extension. The configured per-invocation cap may be
   lower; any configured value above the hard protocol ceiling is clamped down to it. Snapshot at
   most 16 KiB from a non-symlink regular file
   without blocking or following a replaced path; symlink or any non-regular file (including
   FIFO/device/socket/directory), unreadable, changed-during-
   snapshot, unsigned, malformed, schema-invalid, modified, wrong-run, wrong-key, replayed/non-
   increasing within the current bounded invocation, negative, or oversized records are absent.
3. In each of the six runner poll loops and the two gate poll loops (`gate-check.sh` and the
   duplicated loop in `audit-verify.sh`): once per iteration (the loops already wake at
   0.1-2 s), first terminate an already-expired effective deadline, then consult the helper;
   within each bounded poll-loop invocation, accept only increasing
   generations, retain monotonic
   `max(deadlineExtendSec)`, make cancellation sticky, and apply
   `effective_deadline = spawn_deadline + extend` within
   `SINGULAR_RUN_CONTROL_MAX_EXTEND_SEC` (default 4 hours). On cancel, use the existing
   `singular_kill_tree` path and exit semantics. Emit exactly one event per newly honored
   generation per bounded invocation, never per poll. Cross-process high-water persistence is
   outside this task; a replay remains an externally signed authorization bound to the same run.
4. Preserve byte-identical no-control behavior. Use a separate host-selected `control_dir`; it is
   not a secrecy or ACL boundary, and the child may know and overwrite it. Do not
   relocate the legacy capture/output `run_dir`, remove child-visible environment variables, or
   add files when no valid control exists. A child may overwrite control bytes, but without the
   external private key it cannot author an honored extension. The unbounded-timeout path
   (`timeout 0`) stays unchanged.

## Acceptance Criteria

- New focused test `tests/test-run-control.sh` is authored and run RED against the unmodified
  amended target before any production edit: with a short budget and a stub child that outlives
  it, an externally pre-signed, correct-run extension written before expiry is ignored by the
  baseline and the kill still fires. The RED must fail on the same behavioral assertion that
  turns GREEN after implementation—not on a missing helper, structural precondition, or TODO
  marker. GREEN: the exact fixture survives and the honored generation appears exactly once in
  the events log.
- Generate a test-only private key only in parent-process memory or an anonymous pipe before the
  child exists, derive the public key and pre-sign every required record, then erase the private
  bytes before spawning the supervised child. Prove no private key bytes/path are ever written,
  exported, passed in argv, or child-visible. Give an adversarial child the exact real
  control path and an attacker key; its create, replace, tamper, wrong-run/key, and replay/lower-
  generation attempts never extend the original deadline.
- Extension applied after the original deadline already fired changes nothing (no
  resurrection); the loop checks the effective deadline before polling while preserving a
  record observed before expiry.
- `cancel: true` terminates the child within one poll interval plus kill grace, via the existing
  kill path, with the loop's existing exit semantics.
- Malformed/unsigned/modified/wrong-run/wrong-key/replayed-or-lower/oversized/negative records are
  ignored (fail closed); per-invocation generation, monotonic extension, sticky cancel, one-event
  accounting, and the extension cap are pinned. A correctly signed record with `reason: ""` is
  honored once and its event preserves `reason` as the empty string. Symlink, any non-regular
  file (including FIFO/device/socket/directory), and change-during-snapshot substitutions neither
  block the parent nor become valid records.
- The authoritative and consumer v1 schema files are byte-identical, parse as JSON, declare the
  runtime hard protocol ceiling, and pass `tests/test-schema-sync.sh`; the configured
  per-invocation cap may be lower, while any above-ceiling value is clamped down.
- Before spawn, verification pins a root-owned, non-group/other-writable canonical regular
  executable chain or an equivalently immutable already-resident in-process verifier that never
  executes through a mutable path. A same-UID child replacing PATH entries, a user-owned verifier
  target, or any symlink/parent component cannot cause any control to be honored; valid records
  are intentionally inert when no trusted verifier exists, without changing the no-control path.
- At least one provider runner test and the gate-check test both prove the re-read; the
  remaining runners share the same sourced helper call (grep-asserted in the test).
- With no valid control present, all six changed providers and both gate loops retain byte-
  identical child environment, output, exit status, and capture/state files compared against a
  frozen unmodified-target baseline (behavioral golden, not grep-only or candidate-vs-candidate
  evidence).
- Timeout-zero behavior is unchanged even when a valid signed extension or cancel record exists:
  the unbounded Codex path never becomes finite, never honors cancel, and emits no control event.
