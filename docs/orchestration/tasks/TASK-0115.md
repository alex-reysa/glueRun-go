## Objective

Every provider runner and the gate freeze their timeout at spawn:
`deadline=$((SECONDS + budget))` computed once above the poll loop (`engine/codex-run.sh`,
`engine/claude-run.sh`, `engine/cursor-run.sh`, `engine/grok-run.sh`, `engine/gemini-run.sh`,
`engine/opencode-run.sh`, `engine/gate-check.sh`), with no reload path anywhere. Field
consequence (audited, reproduced from real run state): an operator raising the budget mid-run
has zero effect on the running try — three consecutive kills each fired at the exact stale
budget, every raise landing after the kill it was meant to prevent.

Required changes:

1. New sourced helper `engine/run-control.sh` exposing one function,
   `singular_run_control_read RUN_DIR`, which reads an optional
   `<run_dir>/run-control.json` and prints `deadlineExtendSec=<int> cancel=<0|1>`
   (defaults `0 0`). Fail closed: unreadable, unparsable, schema-invalid, negative, or
   non-integer content is treated as absent; the file is READ-ONLY control — the engine never
   writes it, and worker/gate processes must not be able to author their own extension
   (document that the file lives in the run dir owned by the host, is honored only up to
   `SINGULAR_RUN_CONTROL_MAX_EXTEND_SEC`, default 4 hours, and every honored change emits an
   event).
2. New additive schema `schemas/run-control.v0.schema.json`:
   `{schema: "singular.orchestration.run-control.v0", deadlineExtendSec: int >= 0,
   cancel: bool, reason: string, updatedAt: timestamp}`, additionalProperties false.
3. In each of the six runner poll loops and the two gate poll loops (`gate-check.sh` and the
   duplicated loop in `audit-verify.sh`): once per iteration (the loops already wake at
   0.1-2 s), consult the helper; apply `effective_deadline = spawn_deadline + extend` (bounded);
   on `cancel=1`, kill via the existing `singular_kill_tree` path and return the loop's
   existing timeout/cancel exit code. Emit one event per CHANGE of honored values, not per poll.
4. No writer, no operator CLI verb in this task — an operator creates the file by hand or via
   later tooling. The unbounded-timeout path (`timeout 0`) is out of scope and unchanged.

## Acceptance Criteria

- New focused test `tests/test-run-control.sh` (RED first): with a short budget and a stub
  child that outlives it, writing `run-control.json` with a sufficient `deadlineExtendSec`
  BEFORE expiry currently changes nothing (kill still fires); after the change the child
  survives to completion, and the honored extension appears exactly once in the events log.
- Extension applied after the original deadline already fired changes nothing (no
  resurrection).
- `cancel: 1` terminates the child within one poll interval plus kill grace, via the existing
  kill path, with the loop's existing exit semantics.
- Malformed/oversized/negative control files are ignored (fail closed) and the run behaves
  exactly as today; the cap `SINGULAR_RUN_CONTROL_MAX_EXTEND_SEC` is enforced.
- At least one provider runner test and the gate-check test both prove the re-read; the
  remaining runners share the same sourced helper call (grep-asserted in the test).
- With no `run-control.json` present, behavior is byte-identical to today (golden assertion).
