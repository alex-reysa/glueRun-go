## Objective

First foundational brick of the executable DAG node `plan-revision-loop` (stage `S3-plan-revision`, area `plancritic`, layer `engine_runtime`, kind `runtime`). Add a pure, deterministic decider that maps a plan-critic verdict plus the number of revision rounds already spent to the next loop action, bounded by `SINGULAR_PLAN_REVISE_MAX` (default 1). This directly implements the requiredCompletion predicate "bounded by SINGULAR_PLAN_REVISE_MAX (default 1) ... exhausted budget with a still-non-approve verdict park", giving the later planner-re-invocation slice one fail-closed authority for whether to revise, park, or import.

New file `engine/ctx-plan-revise.sh` is auto-sourced by the ctx-loader block in lib.sh and defines NEW functions only; NO existing engine path invokes them, so with the file present-but-uncalled the engine is byte-identical to current behavior (mirroring engine/ctx-planner-resume.sh and engine/ctx-critique-import.sh). The SINGULAR_PLAN_CRITIQUE-gated planner re-invocation resuming the persisted node session via singular_planner_resume_decide, the rc-86 fresh-fallback record, the per-finding accepted-observation / rejected-observation disposition events (plan.revised with revisesRunId), and the generate-tasks.sh / l1-plan-node.sh driver hooks are the sanctioned follow-up slices of this node and are OUT OF SCOPE here.

## Acceptance Criteria

- `singular_plan_revise_decide <verdict> <revisions_done>` prints EXACTLY one line and never exits non-zero:
  - `verdict=approve` -> `import` (terminal accept; the loop stops and the batch proceeds to import).
  - `verdict=revise` with `revisions_done` less than the effective max -> `revise <next_round>` where `<next_round>` = `revisions_done + 1`.
  - `verdict=revise` with `revisions_done` at or above the effective max -> `park revise-budget-exhausted`: a still-non-approve verdict with no budget left parks and NEVER emits another `revise`.
  - `verdict=park` (or any explicit non-approve, non-revise terminal verdict) -> `park <verdict>`.
- Bound: the effective max reads `SINGULAR_PLAN_REVISE_MAX`, defaulting to `1` when unset or empty; an override such as `SINGULAR_PLAN_REVISE_MAX=2` is honored so a second round is allowed and the third parks. A pure helper (e.g. `singular_plan_revise_max`) centralizes the default.
- Fail-closed (evidence invariance): an empty or unknown verdict, a non-integer or negative `revisions_done`, or a non-integer / negative `SINGULAR_PLAN_REVISE_MAX` each resolve to `park <reason>`; the function NEVER resolves ambiguity to `revise`, so no unbounded revision path can exist.
- The file defines new functions only and is invoked by no existing engine path: `tests/test-engine-clean.sh` stays green and an unused run is byte-identical to current behavior (no events, no state writes, no runner invocation).
- Strict-test-first: `tests/test-ctx-plan-revise.sh` is authored red first (asserting the above before implementation) and green after, running against isolated state (no real run state mutated); the full suite `bash tests/run.sh` is green. Cases covered: approve->import, revise-within-budget->revise with correct next_round, revise-at-budget->park, default max=1, `SINGULAR_PLAN_REVISE_MAX` override, and each fail-closed input.
- Gate candidate: with this slice integrated, `plan-revision-loop` has a tested, fail-closed bound authority; the node gate remains BLOCKED pending the planner-re-invocation, resume vs fresh-fallback, disposition-event, and driver-hook follow-up slices and their test-ctx-plan-revision.sh full-walk coverage.
