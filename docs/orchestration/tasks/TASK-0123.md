## Objective

The engine has zero mid-attempt byte preservation: the only durable capture is the
end-of-attempt commit after gate + secret scan, so a timed-out multi-hour worker try loses
every uncommitted byte (audited field cost: an operator hand-mirroring files out of a worktree
between kills). This task ships the MINIMAL audited scope — `snapshot` grade only: preserve
bytes at controlled termination, verifiable, never restorable automatically, and constitutionally
incapable of being mistaken for validation or acceptance. `validated`/`candidate` grades,
automatic restore, and GC are explicitly deferred pending a second consumer's field evidence.

Required changes:

1. New `engine/checkpoint.sh` with three verbs (host-owned, callable via `cli/singular`
   subcommand `checkpoint`):
   - `create --worktree W --task T --run R --attempt N --try M --reason controlled-timeout`:
     using a TEMPORARY index file (never the worktree's own index) and a private ref
     `refs/singular/checkpoints/<task>/<run>/<seq>`, commit ONLY task-owned paths. Owned/
     forbidden path sets come from the task record exactly as `scope-check.sh` consumes them;
     `secret-scan.sh`'s working-tree mode must pass over the candidate path set or the
     checkpoint is refused (fail closed — record the refusal, capture nothing). Unowned dirty
     paths are recorded by name in the manifest without capturing bytes. The worker branch,
     HEAD, and index are untouched.
   - `verify <ref|seq>`: recompute and compare the manifest's tree/commit/diff hashes;
     tampering fails closed.
   - `list/show`: read-only inspection.
2. Manifest: `schemas/checkpoint.v0.schema.json`
   (`singular.orchestration.checkpoint.v0`): task/run/attempt/try/role, worktree HEAD,
   checkpoint commit + tree hash, owned-file set, diff hash, reason, grade fixed to
   `"snapshot"` (single-member enum THIS release — the field exists so later grades are
   additive), createdAt. No validation/gate fields at all in v0 — their absence is the
   design: a snapshot cannot claim validation.
3. One engine capture point: in the worker-timeout kill path, after `singular_kill_tree`
   returns and before the try is classified, invoke `create` best-effort (never blocks the
   retry, never alters classification; failure to capture is logged and the run proceeds
   exactly as today). Coherence guard: fingerprint the owned paths before and after the
   commit; mismatch (still-running writer mutating files) discards the checkpoint as
   incoherent rather than recording a torn state.
4. Containment: a checkpoint ref must never satisfy packet, audit, gate-result, integration,
   or promotion logic. `integrate.sh` and the promotion path must not see these refs
   (private-ref namespace outside `refs/heads`); add an explicit negative assertion.

## Acceptance Criteria

- RED first: a stub worker writes owned bytes and is timeout-killed; nothing preserves them.
- GREEN: the same fixture yields a checkpoint whose tree restores byte-identically into a
  scratch worktree BY HAND (`git worktree add` + `git checkout <ref> -- .` in the test — no
  engine restore verb exists); `verify` passes; a tampered commit/manifest fails `verify`.
- Forbidden-path, secret-bearing, and unowned dirty files never enter the checkpoint; unowned
  dirty paths are named in the manifest; a secret-scan hit refuses the whole capture.
- The worker branch head, index, and reflog are unchanged by capture (asserted by hash).
- A checkpoint ref does not appear to `integrate.sh`'s branch enumeration or the promotion
  path (negative assertion).
- Capture failure (e.g., scratch dir unwritable) leaves classification and retry behavior
  byte-identical to today.
