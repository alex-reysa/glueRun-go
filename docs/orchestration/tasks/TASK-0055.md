## Objective

Fifth strict-test-first slice of the executable DAG node `rehydrate-path` (stage `S5-routing`, layer `engine_runtime`). The three pure leaves and the spine wire-in are integrated, so `engine/ctx-route.sh` now emits `rehydrate <reason>` on refused-resume lineage steps behind `SINGULAR_REHYDRATE=1`. The requiredCompletion still demands that the packet **manifest** (which artifacts, which hashes) be recorded in the strategy event — and today the `engine/l1-drive.sh` `context.strategy_selected` sites branch only on `resume` versus an `else` that hardcodes `"strategy":"fresh"`, so a `rehydrate` decision is mislabeled and its manifest is never recorded.

This slice adds the pure, testable payload that the later `l1-drive.sh` wire-in will record. Introduce a new pure, read-only leaf `engine/ctx-rehydrate-event.sh` (auto-sourced by the ctx-loader `engine/ctx-*.sh` glob) that DEFINES a new function only and is present-but-uncalled by every existing engine/CLI/driver path, so with it sourced the engine stays byte-identical to current behavior. The wire-in that records this payload at the `context.strategy_selected` site, and the separate `l1-drive.sh` hook that injects the assembled packet into the fresh-run prompt, are LATER slices and are OUT OF SCOPE here.

Behavior of `engine/ctx-rehydrate-event.sh` (node `rehydrate-path`, layer `engine_runtime`) — a function such as `singular_ctx_rehydrate_event_data <role> <task-id> <run-id> <attempt> <reason> <run_dir> [extra-id=path ...]`:

- Prints a single compact JSON object suitable as the third (`data`) argument to `singular_append_event "context.strategy_selected"`, extending the existing resume/fresh payload shape additively: `{"taskId":…,"runId":…,"role":…,"attempt":<n>,"strategy":"rehydrate","reason":"<reason>","manifest":<manifest-json>}` — `attempt` numeric, the rest strings, and `manifest` a nested JSON object (not a stringified blob).
- `manifest` is the deterministic output of `singular_ctx_rehydrate_manifest` over `singular_ctx_rehydrate_sources <run_dir> [extra…]` — i.e. `{"schema":"singular.orchestration.ctx-rehydrate-manifest.v0","sources":[{"id","sha256"}…]}` — recording exactly which surviving durable artifacts, at which content hashes, the run rehydrates from.
- Quarantine-aware transitively: quarantined artifacts are excluded from `manifest.sources` because the assembler already composes `singular_ctx_artifact_exclude`.
- Deterministic: identical `run_dir` bytes yield byte-identical event data.
- Robust to an empty source set: when no durable artifact survives, `manifest.sources` is `[]` and the object is still well-formed valid JSON.
- Pure and read-only: it reads artifact bytes and hashes them but never writes, renames, or deletes anything, and appends NO events itself (it PRODUCES the data string; the later wire-in calls `singular_append_event`). It confers no independence — `rehydrate` remains tainted per `singular_ctx_route_strategy_tainted`.

The event records the MANIFEST (ids + hashes), never the packet body, so durable artifact content is not duplicated into the event stream.

## Acceptance Criteria

- `tests/test-ctx-rehydrate-event.sh` is written first and fails (red) before `engine/ctx-rehydrate-event.sh` exists, then passes (green) after implementation; `bash tests/test-engine-clean.sh` stays green (no project-specific symbols in `engine/`).
- Payload shape: given a fixture `run_dir` holding at least one durable artifact, `singular_ctx_rehydrate_event_data implementer T-1 R-1 2 window-pressure <run_dir>` prints valid JSON with `strategy` = `rehydrate`, `reason` = `window-pressure`, `role` = `implementer`, `attempt` = `2` (numeric, unquoted), and a nested `manifest` object.
- Manifest fidelity: the embedded `manifest.sources` (ids and sha256) exactly equal `singular_ctx_rehydrate_manifest` applied to `singular_ctx_rehydrate_sources <run_dir>` for the same fixture.
- Determinism: two runs over the same fixture yield byte-identical output.
- Quarantine exclusion: a quarantined artifact under `run_dir` is absent from the embedded `manifest.sources`.
- Empty-source robustness: with a `run_dir` holding no durable artifacts, the output is well-formed JSON with `manifest.sources` = `[]` and `strategy` = `rehydrate`.
- JSON embedding: the printed string parses as a single JSON object (so `singular_append_event`'s `json.loads` stores `manifest` as a structured object, not a `{"raw":…}` fallback).
- Purity / evidence invariance: the function writes/renames/deletes no files, appends no events, and never exits non-zero on well-formed input; the packet body is NOT included (only the manifest of ids + hashes); `rehydrate` remains tainted per `singular_ctx_route_strategy_tainted`.
- Gate candidate: with this leaf integrated, the manifest-in-strategy-event payload is deterministic and table-tested; the remaining `rehydrate-path` slices are the `engine/l1-drive.sh` `context.strategy_selected` wire-in (record this payload when the routed strategy is `rehydrate`) and the `engine/l1-drive.sh` packet-injection hook (render the packet into the fresh-run prompt), after which `test-ctx-rehydrate.sh` green plus the full suite can be proposed as the node exit gate.

## Context packet

Decisions:

- Assemble the rehydrate strategy-event payload (with its embedded manifest) in a pure leaf, then wire `engine/l1-drive.sh` to it, mirroring the leaf-before-driver-hook discipline every prior `l1-drive` hook follows (TASK-0040 / TASK-0043 / TASK-0033 each delegate into a pure `ctx-*.sh`). This keeps the scarce `context.strategy_selected` site a minimal one-line `singular_append_event` delegation and makes the requiredCompletion-critical manifest-in-event content table-testable. Basis: planner-contract rule 2 (minimal driver hooks).
- Embed the manifest as a nested JSON object, not a stringified blob, so downstream metrics/consumers read structured sources; `singular_append_event` parses its data argument with `json.loads`, so a valid nested object is stored structurally. Basis: `engine/lib.sh` `singular_append_event`.
- Keep the leaf role-parameterized even though the reviewer / `final-audit` `context.strategy_selected` site can NEVER see `rehydrate` (the independence pin forces `fresh tainted`); the reachable producer is the implementer (`implement`) site. Basis: `engine/ctx-route-taint.sh` pin and the `engine/l1-drive.sh` reviewer-site comment.

Assumptions:

- [validated] The strategy-event type is `context.strategy_selected`, and the existing resume/fresh payloads carry `taskId` / `runId` / `role` / `attempt` / `strategy` / `reason` (`engine/l1-drive.sh` ~445/688); the rehydrate payload extends that shape additively with a `manifest` object.
- [validated] `singular_ctx_rehydrate_sources <run_dir>` piped into `singular_ctx_rehydrate_manifest` yields `{"schema":…,"sources":[{"id","sha256"}…]}` excluding quarantined artifacts (TASK-0053 / TASK-0051).
- [validated] `singular_append_event`'s third argument is JSON-parsed (`engine/lib.sh`), so an embedded manifest object is stored structurally rather than as a `{"raw":…}` fallback.
- [open] `run_dir` is in scope at the `l1-drive.sh` implementer `context.strategy_selected` site (it already references `$run_dir/last-message.json`); the later wire-in passes it, so this leaf only needs the path argument.

Rejected alternatives:

- Inlining the manifest composition directly at the `l1-drive.sh` `context.strategy_selected` site — rejected: it puts non-trivial resolver/manifest composition and JSON embedding inside the scarce, hard-to-test driver file; the pure leaf is table-testable and keeps the hook a one-liner.
- Recording only the source ids and dropping the hashes — rejected: the stage file requires "which artifacts, which hashes"; the per-source `sha256` is the evidence-invariance anchor.
- Emitting the packet body into the event — rejected: the event records the MANIFEST (ids + hashes); the packet body is injected into the prompt by the separate `l1-drive.sh` injection slice, and storing artifact content in events would duplicate durable content and risk re-introducing scanned-out secrets into the event stream.
