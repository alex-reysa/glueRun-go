## Objective

The core requiredCompletion behavior of the executable DAG node `rehydrate-path` (stage `S5-routing`, layer `engine_runtime`) is integrated: TASK-0051–0057 delivered deterministic capped quarantine-aware rehydration packets from durable artifacts, injected on refused-resume lineage steps behind `SINGULAR_REHYDRATE` (default 0), with the packet manifest recorded in strategy events. This slice begins the stage file's explicitly-OPTIONAL additive deliverable — authored-knowledge manifest ingestion (singular-brain integration point 3) — behind `SINGULAR_CTX_MANIFEST` (default 0) with an optional `contextManifest` path in `singular.config.json`. It is NOT part of `requiredCompletion` and does not gate the node; node completion and gate promotion are operator authority and are not claimed here.

Introduce a new pure, read-only leaf `engine/ctx-rehydrate-authored.sh` that parses a FIXTURE authored-knowledge manifest JSON and selects the injectable entries, enforcing the AUTHORED-KNOWLEDGE class rules — without yet wiring into `singular.config.json` or the packet assembler (those are later slices). It DEFINES new functions only and is present-but-uncalled by every existing engine/CLI/driver path, so with it sourced the engine stays byte-identical to current behavior. Implement and test against FIXTURE manifests only; take no dependency on the singular-brain runtime — the JSON contract is the interface.

Behavior of `engine/ctx-rehydrate-authored.sh` (node `rehydrate-path`, layer `engine_runtime`) — a function such as `singular_ctx_rehydrate_authored_select <manifest-json-path>`:

- Reads the machine-readable manifest whose entries carry an `id`, a body or path, `load-when` triggers, a freshness state, and an optional `description_unverified` flag.
- Entries flagged `description_unverified` are NEVER emitted as current: they are skipped, or emitted only with an explicit unverified marker, so they can never be treated as current or authoritative.
- Quarantined path-backed entries are excluded by composing the integrated `singular_ctx_artifact_exclude`.
- Surviving entries are emitted deterministically with their ids, tagged as AUTHORED-KNOWLEDGE class — human-curated content, distinct from durable host-verified artifacts AND from model-authored (tainted) records. The emission form is suitable for a later slice to ingest into the rehydration packet and to record injected entry ids in the packet manifest like any other source, and is NEVER marked authoritative.
- Pure, read-only, deterministic: it reads the manifest (and hashes/paths) but writes, renames, and deletes nothing; appends no events; and never exits non-zero on well-formed input. A malformed or absent manifest yields no entries (fail-soft).

`SINGULAR_CTX_MANIFEST` (default 0) gates the later wire-in, not this pure leaf.

- OFF-parity: the file only defines new functions (present-but-uncalled), so the engine is byte-identical to current behavior; `SINGULAR_CTX_MANIFEST` (default 0) gates the future wire-in, not this leaf.

## Context packet

Decisions:

- Name the file and functions `ctx-rehydrate-authored` / `singular_ctx_rehydrate_authored_*` to avoid colliding with the integrated `singular_ctx_rehydrate_manifest` (the packet-manifest emitter, TASK-0051): the authored-knowledge manifest (an INPUT of human-curated entries) is a distinct concept from the packet manifest (the OUTPUT record of injected sources). Basis: TASK-0051 owns `singular_ctx_rehydrate_manifest`.
- Ship the parse-and-select rules as a pure leaf first (present-but-uncalled), deferring the `singular.config.json` field and the `SINGULAR_CTX_MANIFEST` packet wire-in, mirroring the whole rehydrate-path leaf-before-wire-in sequence. Basis: planner-contract new-file convention and folding = 1.
- Enforce the authored-knowledge safety rules inside the selector itself (`description_unverified` never-as-current; quarantine exclusion; never authoritative), since those are the class's defining invariants and must hold before any ingestion. Basis: singular-brain integration point 3 and planner-contract rule 8 (evidence invariance) — authored-knowledge is neither host-verified nor tainted-model and must never be recorded as authoritative.

Assumptions:

- [validated] The core `requiredCompletion` behavior of `rehydrate-path` is integrated (TASK-0051–0057); this OPTIONAL slice extends the stage file's additive deliverable and does not gate the node.
- [open] The authored-knowledge manifest JSON schema (entry fields `id`, body/path, `load-when`, freshness, `description_unverified`) is defined by the singular-brain `KNOWLEDGE.json` contract; implement and test against FIXTURE manifests only, with no singular-brain runtime dependency.
- [validated] `singular_ctx_artifact_exclude` is available to exclude quarantined path-backed entries (`engine/ctx-artifact-exclude.sh`).
- [open] `load-when` trigger matching and freshness-based eligibility may be a later slice; this leaf carries those fields as metadata and focuses on the class safety rules plus deterministic selection.

Rejected alternatives:

- Extending `engine/ctx-rehydrate.sh` directly to ingest the authored manifest — rejected: the new-file convention wants a separate `ctx-*.sh`; keep the durable-artifact assembler and the authored-knowledge ingestion in distinct files.
- Wiring `singular.config.json` `contextManifest` plus `SINGULAR_CTX_MANIFEST` in this slice — rejected: config-field parsing plus packet composition touches more surface; the pure selector is the smallest first brick (scoped gate).
- Injecting `description_unverified` entries as current content — rejected: the contract forbids it; they must be skipped or carry an explicit unverified marker, never presented as current or authoritative.
