## Objective

Advance executable DAG node `metrics-extract` (stage `S0-baseline`, layer `harness`, kind `harness`) by shipping its first, smallest strict-test-first slice: a new read-only `engine/ctx-metrics.sh` extractor that reads `runs/*/attempts/index.json` and the events log (`events.ndjson`) and emits documented per-task and aggregate metrics as stable JSON.

This extractor is the prerequisite brick the node's sanctioned `cli/singular metrics` subcommand will later delegate into. Because that CLI hook must call this extractor, the hook slice depends on this slice and is not mutually independent with it; with fold/max = 1 this batch emits only the earliest ready slice — the extractor — and defers the `cli/singular` hook to a later task on this same node.

The extractor is strictly read-only and additive: it defines new functions in a new `engine/ctx-*.sh` file (auto-sourced by the guarded ctx-loader block already integrated into `lib.sh`). No existing engine path invokes it, so with the file present-but-uncalled the engine is byte-identical to current behavior — its OFF/byte-identical guarantee, consistent with the read-only, no-outcome-change constraint of stage `S0-baseline`.

## Scope

## Acceptance Criteria

- Strict test-first: `tests/test-ctx-metrics.sh` is authored and fails (red) before `engine/ctx-metrics.sh` exists, then passes (green) after the extractor is implemented.
- Read-only: given a runs directory and an events file, the extractor computes metrics without creating, modifying, or deleting any run artifact, index, or event; the test asserts the fixture inputs are byte-unchanged after a run.
- Per-task JSON: for each run under the fixture `runs/<runId>/attempts/index.json`, the extractor emits documented, stable fields covering at least attempts-to-accept, failure-class counts, audit-verdict counts, `workerStrategy`/`reviewerStrategy` mix, and decider-authority mix, derived from `singular.orchestration.attempts-index.v0` attempts entries.
- Aggregate JSON: the extractor emits a documented aggregate object across all fixture runs (totals and distributions for the same dimensions), plus `context.strategy_selected` reason counts read from the fixture events log.
- Machine-stable output: field names and shape are documented in an `engine/ctx-metrics.sh` header comment and are deterministic for a given fixture set (stable key ordering), so downstream consumers and tests can pin them.
- Empty/missing inputs fail safe: an empty or absent runs dir and/or events file yields a well-formed metrics object with zeroed counts, not an error or crash.
- Additive/byte-identical: `engine/ctx-metrics.sh` only adds new functions in a new `engine/ctx-*.sh` file; no existing engine path calls it, so behavior with the file present-but-uncalled is byte-identical to the current engine.
- No schema churn in this slice: the output shape is documented in-header only; this task adds or modifies no file under `schemas/` (a formal `singular.orchestration.*.v0` metrics schema, if wanted, is a later additive slice).
- Gate candidate: `bash tests/run.sh` is green including the new `tests/test-ctx-metrics.sh`, and `tests/test-engine-clean.sh` stays green (no project-specific symbols added to `engine/`). This advances node `metrics-extract` but does NOT by itself complete it — the node's full exit gate additionally requires the `cli/singular metrics --json` hook, a separate downstream slice; this task proposes only a gate candidate and declares neither the node nor the area complete.
