## Objective

Fourth strict-test-first slice of the executable DAG node `rehydrate-path` (stage `S5-routing`, layer `engine_runtime`). The three pure leaves are integrated: the packet assembler `engine/ctx-rehydrate.sh` (`singular_ctx_rehydrate_packet` / `singular_ctx_rehydrate_manifest`), the rehydrate-vs-fresh decision `engine/ctx-route-rehydrate.sh` (`singular_ctx_route_rehydrate_decide`), and the durable-artifact source resolver `engine/ctx-rehydrate-sources.sh` (`singular_ctx_rehydrate_sources`). None is wired into the live routing path yet, so the spine still emits bare `fresh` on every refused resume. This slice performs the routing integration: it wires the composition into the `engine/ctx-route.sh` spine so that, on a refused-resume lineage-continuation step and behind `SINGULAR_REHYDRATE=1`, the spine emits `rehydrate <reason>` instead of bare `fresh <reason>`.

The spine `singular_ctx_route` runs the independence pin FIRST (final-audit / paired-audit → `fresh tainted`, before the gates), then, for a would-be `resume`, applies three fail-closed resume gates that today emit `fresh session-lease`, `fresh window-pressure`, or `fresh diff-volume`. Those three refusal sites — and only those — are the refused-resume lineage steps to upgrade. Replace each with an emission mediated by the decision leaf: derive `run_dir` = `dirname(meta)` (the same durable-artifact root `engine/ctx-route-drive.sh` and the secret-scan use), compose `singular_ctx_rehydrate_sources <run_dir>` → `singular_ctx_rehydrate_manifest` → `singular_ctx_route_rehydrate_decide <reason> <role> <step> <manifest>`, and print its one-line verdict. Guard the resolver/manifest composition behind `SINGULAR_REHYDRATE=1` so the OFF path spawns no extra work and stays byte-identical to the current `fresh <reason>` line.

Scope boundaries, node `rehydrate-path`, layer `engine_runtime`:

- Only the three resume-gate refusals are upgraded. The baseline-fresh pass-through (a wrapped-decider `fresh` with no resumable session — not a refused resume) and the resume-stands line are UNCHANGED.
- The spine keeps its contract: it prints EXACTLY one line and appends NO events. The `context.strategy_selected` strategy event is emitted at the driver (`engine/l1-drive.sh`), so recording the packet manifest into that event is a SEPARATE later slice and is OUT OF SCOPE here, as is the `l1-drive.sh` packet-injection hook that renders the assembled packet into the fresh run's prompt.
- The decision leaf already enforces OFF-parity, the independence guard, and the empty-packet guard internally; the spine only supplies `(reason, role, step, manifest)`.

## Context packet

Decisions:

- Wire the upgrade into the spine `singular_ctx_route`, not the `engine/ctx-route-drive.sh` adapter: the spine owns the strategy alphabet and already produces the three `fresh <gate-reason>` refusal lines (`engine/ctx-route.sh` ~113/117/121), while the adapter only assembles routing context and delegates. Basis: the spine header reserves `rehydrate` in the alphabet.
- Upgrade ONLY the three resume-gate refusals (session-lease, window-pressure, diff-volume), not the baseline-fresh pass-through: those are the refused-resume lineage steps the stage file names; a wrapped-decider baseline `fresh` had no resumable session, so there is no lineage to rehydrate. Basis: stage-5-routing.md — "when resume is refused for a lineage-continuation step."
- Keep the spine's one-line / no-events contract: the manifest-into-strategy-event recording belongs at the driver's `context.strategy_selected` sites (`engine/l1-drive.sh` ~445/688) and is a separate later slice; re-deriving the manifest there is cheap and deterministic. Basis: the spine emits no events today.
- Guard the resolver/manifest composition behind `SINGULAR_REHYDRATE=1` so the OFF path spawns no python and stays byte-identical; `run_dir` = `dirname(meta)`, matching `engine/ctx-route-drive.sh` and the secret-scan root.

Assumptions:

- [validated] The three refused-resume reasons are `session-lease`, `window-pressure`, `diff-volume`, and the independence pin returns before them (`engine/ctx-route.sh`), so final-audit / paired-audit never reach the upgrade.
- [validated] `singular_ctx_route_rehydrate_decide` handles OFF-parity, the independence guard, and the empty-packet guard internally (`engine/ctx-route-rehydrate.sh`); the spine supplies only `(reason, role, step, manifest)`.
- [validated] `singular_ctx_rehydrate_sources <run_dir>` piped into `singular_ctx_rehydrate_manifest` yields the manifest the decision consumes (TASK-0053 / TASK-0051); an absent `run_dir` yields no specs, hence an empty manifest, hence a fail-soft `fresh`.
- [open] `meta` (the spine's 3rd argument) is non-empty at the live call sites (`engine/ctx-route-drive.sh` passes it); when empty, `run_dir` degrades and the upgrade fails soft to `fresh` — acceptable.

Rejected alternatives:

- Recording the packet manifest into the strategy event in this slice — rejected: the event is emitted at the driver (`engine/l1-drive.sh` `context.strategy_selected`), a different file; combining would own two existing files and exceed a tight single slice. It is the next slice.
- Injecting the assembled packet into the prompt here — rejected: prompt assembly is the `l1-drive.sh` hook's job (a separate later slice); this slice only makes the strategy decision emit `rehydrate`.
- Upgrading the baseline-fresh pass-through too — rejected: that is not a refused resume; upgrading it would rehydrate steps with no resumable lineage, outside the stage-file scope.
