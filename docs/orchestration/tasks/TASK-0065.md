## Objective

Follow-up wire-in completing the TASK-0064 trigger-set mini-track for the stage file's explicitly-OPTIONAL authored-knowledge manifest ingestion of the executable DAG node `rehydrate-path` (stage `S5-routing`, layer `engine_runtime`). The core `requiredCompletion` behavior is fully integrated (TASK-0051–0057); this slice does NOT gate the node — completion and gate promotion are operator authority and are not claimed here.

TASK-0064 shipped the pure builder `gluerun_ctx_rehydrate_authored_triggers <role> <step> [node] [task]` (emits the run's deterministic, de-duplicated `load-when` trigger tokens), but it is present-but-uncalled: the two live consumers still pass the hardcoded literal `implement` — the injection at `engine/l1-drive.sh:457` (`gluerun_ctx_rehydrate_authored_config_render implement`, TASK-0062) and the manifest-record at `engine/ctx-rehydrate-event.sh:79` (`gluerun_ctx_rehydrate_authored_config_manifest implement`, TASK-0063). Because only `implement` is ever supplied, TASK-0059's `load-when` matcher is inert for any authored entry scoped to a role or task rather than that literal step.

This slice substitutes the hardcoded `implement` at BOTH sites with the enriched set from `gluerun_ctx_rehydrate_authored_triggers implementer implement "$task_id"`, passed expanded to the config-gated function. The two sites MUST pass the identical trigger set so the injected authored section (TASK-0062) and the recorded manifest entries (TASK-0063) keep describing the SAME entries — the injected⇔recorded consistency invariant TASK-0063 established — so they are wired together in one slice.

Backward compatibility and OFF-parity: the enriched set is a strict superset of `{implement}` (it still contains `implement`), so every entry that matched before still matches. With `GLUERUN_CTX_MANIFEST` unset (default) the config gate returns empty regardless of triggers, so nothing is injected or recorded — byte-identical; with `GLUERUN_REHYDRATE` unset no rehydrate run occurs at all. This is a minimal call-site substitution delegating into `gluerun_ctx_rehydrate_authored_triggers`; no authored logic is inlined (node `rehydrate-path`, layer `engine_runtime`).

- `tests/test-ctx-rehydrate-authored-triggers-wirein.sh` is written first and fails (red) before the substitution (an authored entry whose `load-when` is `["implementer"]` or `[<task-id>]` but not `["implement"]` is neither injected nor recorded), then passes (green) after; `bash tests/run.sh` (full suite) is green.
- Enriched matching: with `GLUERUN_CTX_ROUTING=1`, `GLUERUN_REHYDRATE=1`, `GLUERUN_CTX_MANIFEST=1`, a `rehydrate` run, and a fixture `contextManifest` entry whose `load-when` matches the run role (`implementer`) or task id but not the literal `implement`, that entry is BOTH injected into `$active_prompt` (TASK-0062 path) AND recorded in the strategy-event manifest (TASK-0063 path).
- Injected⇔recorded consistency: for the same `rehydrate` run, the authored entries injected into the packet equal the authored entries recorded in the event manifest, because both sites pass the identical trigger set `gluerun_ctx_rehydrate_authored_triggers implementer implement "$task_id"`.
- Backward compatibility: entries with `load-when` `["implement"]` still inject and record exactly as before (the enriched set contains `implement`).
- OFF-parity (manifest flag): with `GLUERUN_CTX_MANIFEST` unset, no authored content is injected or recorded, and both `$active_prompt` and the event manifest are byte-identical to the durable-only behavior.
- OFF-parity (rehydrate flag): with `GLUERUN_REHYDRATE` unset, no `rehydrate` run occurs and behavior is byte-identical.
- Minimal delegation: each site computes the trigger set via `gluerun_ctx_rehydrate_authored_triggers` and passes it expanded to the config-gated function; no selection or render logic is inlined into either driver file.
- Gate candidate: with this wire-in integrated, authored `load-when` matching is functional across role / step / task dimensions (not only `implement`), completing the TASK-0064 mini-track and eliminating its dead-code status. This refines the OPTIONAL authored-knowledge feature; the core `requiredCompletion` (TASK-0051–0057) is already integrated and this slice does not gate the node.

## Context packet

Decisions:

- Substitute the hardcoded `implement` at BOTH the injection (TASK-0062, `engine/l1-drive.sh:457`) and manifest-record (TASK-0063, `engine/ctx-rehydrate-event.sh:79`) sites in one slice, because both must pass the identical trigger set to preserve the injected⇔recorded consistency invariant TASK-0063 established; wiring only one site would desync them. Basis: TASK-0063 records exactly what TASK-0062 injects.
- Pass `(implementer, implement, task_id)` — the dimensions available at both sites (`gluerun_ctx_rehydrate_event_data` has role and task id; the injection path is the implementer `implement` step) — so the enriched sets are identical and a strict superset of `{implement}` (backward compatible). Node-scoped `load-when` can follow if the node dimension is later threaded to both sites. Basis: TASK-0064 builder signature and site-available context.
- Keep each site a minimal call-site change delegating into `gluerun_ctx_rehydrate_authored_triggers` plus the config-gated function; no authored logic inlined. Basis: planner-contract rule 2 (minimal driver hooks).

Assumptions:

- [validated] `gluerun_ctx_rehydrate_authored_triggers <role> <step> [node] [task]` emits a deterministic, de-duplicated token set including `implement` when the step is `implement` (TASK-0064).
- [validated] `gluerun_ctx_rehydrate_authored_config_render` / `gluerun_ctx_rehydrate_authored_config_manifest` are variadic over trigger args and gate internally on `GLUERUN_CTX_MANIFEST` + `contextManifest` (TASK-0061); passing the expanded set works.
- [validated] TASK-0062 injects at `engine/l1-drive.sh:457` and TASK-0063 records at `engine/ctx-rehydrate-event.sh:79`, both currently with the literal `implement`.
- [open] `task_id` is in scope at both sites (the `engine/l1-drive.sh` run function and `gluerun_ctx_rehydrate_event_data`'s `<task-id>` parameter); role and step are fixed to `implementer` / `implement` for the rehydrate implementer path.

Rejected alternatives:

- Wiring only the injection site (or only the manifest site) — rejected: it desyncs injected versus recorded authored entries, breaking TASK-0063's consistency invariant; both must use identical triggers.
- Threading a node/stage trigger now — rejected: the node dimension is not readily in scope at the event site; keep the enriched set to dimensions available at both (role / step / task) and defer node-scoped `load-when`.
- Leaving `gluerun_ctx_rehydrate_authored_triggers` present-but-uncalled — rejected: it would remain dead code; this wire-in is its intended consumer.
