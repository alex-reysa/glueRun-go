## Objective

Advance the `experiment-run` executable DAG node (layer `evaluation`) by making the recorded arm knob-state VERIFIABLE across the corpus. TASK-0095's `l1-drive.sh` hook now durably writes per-run knob-state provenance to `arm-knob-state.json` under each run directory (conforming to `gluerun.orchestration.ctx-experiment-armstate.v0`, carrying an `activeCount` and a per-knob `active` flag), but NOTHING reads it — the provenance is write-only. requiredCompletion defines the arms by their knob-state (`control = M0 knob-state`, `treatment = critique+revision+packets+routing`), and the escape-rate/cost/bias comparison is only valid if each arm actually ran with the expected knob-state; a contaminated control run (continuity knobs active) or a treatment run that ran as M0 silently invalidates the experiment. This task ships the consumer that audits that integrity across the runs corpus. It uses the GENERIC arm boundary only (control expects `activeCount` 0; treatment expects `activeCount` greater than 0) — it does NOT prescribe the operator's exact treatment knob-set. It does NOT run the paired-audited A/B experiment, author `docs/context-build-plan/experiment-report.md`, or record per-knob default decisions in `docs/orchestration/decisions.md` — all OPERATOR authority (kind: evaluation). It neither declares nor gates node completion.

All logic lands in one NEW `engine/ctx-experiment-armaudit.sh`, auto-sourced by the ctx-loader block and defining new functions only. No existing engine path invokes them, so the engine is byte-identical with the file present (OFF-parity intrinsic, mirroring the sibling `engine/ctx-experiment-*.sh` idiom). It does NOT edit `engine/l1-drive.sh`, the emitter `engine/ctx-experiment-armstate.sh`, or any other pre-existing file. It reads only the runs directory (each run's `arm-knob-state.json` provenance and its attempts index for the taskId) plus the events log `events.ndjson` for `ctx.arm_assigned` (taskId to arm), and creates, moves, or mutates nothing.

Implement three chained slices in order, all inside `engine/ctx-experiment-armaudit.sh`:

1. Per-run knob-state reader: for each run directory, read its `arm-knob-state.json` (the `ctx-experiment-armstate.v0` artifact), extract `activeCount` and the set of active knob names; a run without the file is classified `unrecorded` (fail-safe, not an error).

2. Arm-join + per-run classification: resolve each run's taskId (from its attempts index) and arm (from `ctx.arm_assigned`), then classify — a control-arm (A) run is `consistent` iff `activeCount` is 0 (M0), else `contaminated` with the active knobs listed; a treatment-arm (B) run is `consistent` iff `activeCount` is greater than 0, else flagged `misconfigured-as-M0`.

3. Composed audit artifact: emit ONE deterministic sorted-key JSON object conforming to a NEW additive schema `gluerun.orchestration.ctx-experiment-armaudit.v0`, carrying per arm the runsRecorded, runsUnrecorded, consistent, and inconsistent counts plus the inconsistent runIds with their offending knob-state. Fail-safe: missing or empty inputs yield a well-formed zeroed audit and a zero exit.

## Context packet

### Decisions

- Consume the `arm-knob-state.json` provenance TASK-0095 records but nothing yet reads, closing the produce-to-consume loop so the recorded knob-state becomes a verifiable arm-integrity signal rather than write-only evidence.
- Use the generic arm boundary (control expects `activeCount` 0; treatment expects `activeCount` greater than 0) rather than a specific treatment knob-set, because the exact treatment configuration is operator run-config; this keeps the audit faithful to requiredCompletion's `control = M0 knob-state` language and `engine/` project-agnostic.

### Rejected alternatives

- Prescribing the exact treatment knob-set and flagging any deviation — rejected: the specific arm configuration is operator judgment; hardcoding it risks drift and engine-cleanliness violations.
- Folding the audit into the summary bundle — rejected: the summary is an integrated pre-existing file (full-suite gate, new-file-convention friction) and arm integrity is a separately-referenceable validity artifact.
