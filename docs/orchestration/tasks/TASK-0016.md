## Objective

Advance the executable DAG node `critique-import-gate` (stage `S2-plan-critique`, area `plancritic`, layer `engine_runtime`, kind runtime) toward its required completion — L0 import honors critique verdicts behind `GLUERUN_PLAN_CRITIQUE` (default 0 = observe-only), ON enforces approve/revise/park and fails closed on missing record — by adding a new, present-but-uncalled `engine/ctx-critique-import-gate.sh` that turns the integrated gate DECISION into the reject DISPOSITION the L0 importer will apply.

TASK-0015 integrated the pure decider `gluerun_ctx_critique_import_decide <stage_dir>` (and `gluerun_ctx_critique_import_enabled`): OFF is always `import`; ON maps `approve` to import and `revise` / `park` / missing / invalid to a `reject` carrying the stable reason token `plan-critique`. The decider is pure — it appends no events and mutates nothing. This brick supplies the other half the stage file requires for a rejected staged batch: findings-and-disposition recorded via an `origin.l1_import_rejected` event with reason `plan-critique`, and the node lease handled as planning-failed so the frontier can be re-planned.

The composed entry point consults the integrated decider for a node's staged candidate dir and acts on the disposition, gated on `GLUERUN_PLAN_CRITIQUE` (default 0):

- OFF (unset or `0`): observe-only — return the `import` disposition with ZERO side effects: no event appended, no lease change, staged candidate files untouched, so an OFF flow is byte-identical to today (the recorded verdict is not enforced).
- ON (`=1`): consult the decider over the node's stage dir. An `approve` record returns `import` with no side effects and the staged set left intact for the importer. A `reject` disposition (`revise`, `park`, a missing / unreadable / schema-invalid record, or a verdict outside `approve|revise|park`) records the disposition — exactly one `origin.l1_import_rejected` event with reason `plan-critique` carrying the node, runId, and observed classifier — and sets the node lease status to failed (planning-failed) via the integrated `gluerun_l1_lease_set_status`, then returns the `reject` disposition. Missing record with the knob ON fails CLOSED to reject; it never fabricates an approval.

The file defines NEW functions only and is invoked by NO existing engine path, so with it present-but-uncalled the engine is byte-identical to prior behavior (mirroring `engine/ctx-critique-import.sh`, `engine/ctx-plan-critic.sh`, and `engine/ctx-paired-audit.sh`). It never owns `engine/lib.sh` and adds no driver-file hook: the actual skip-of-import — the small `reconcile.sh` / L0 import call-site hook that invokes this disposition and keeps rejected candidates out of the tasks dir — is the FINAL wiring slice for this same `critique-import-gate` node and is out of scope here. This brick does not itself promote, delete, or quarantine candidate files, and invokes no runner; on the ON-reject path its only side effects are the single disposition event and the lease status. Advocate/skeptic line and evidence invariance hold: enforcement is layered over the read-only, default-runner skeptic critique and never weakens, resumes into, or bypasses the un-bypassable implementation auditor.
