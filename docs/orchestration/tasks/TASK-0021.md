## Objective

Third brick of the executable DAG node `plan-revision-loop` (stage `S3-plan-revision`, area `plancritic`, layer `engine_runtime`, kind `runtime`). The bound authority `singular_plan_revise_decide` (TASK-0019) and the structured-findings revision prompt assembler `singular_plan_revise_prompt` (TASK-0020) are integrated. This brick implements the still-untouched requiredCompletion predicate "per-finding accepted/rejected-observation dispositions evented": after a revision round produces a revised batch, classify each critique finding as `accepted-observation`, `rejected-observation`, or (for a silent drop) `accepted-but-unaddressed`, and record those dispositions as provenance events. ## Acceptance Criteria

- `singular_plan_revise_classify <critique_record> <revised_batch>` is PURE and READ-ONLY: it reads every `f-[0-9a-f]{12}` finding id from the `singular.orchestration.plan-critique.v0` record at `<critique_record>` and the revised task batch at `<revised_batch>` (task-batch.v0 content / its rendered notes); it prints one tab-separated `<finding-id>` then `<disposition>` line per finding in id-sorted order; it appends no events, mutates nothing, and always exits 0 (bad input yields the conservative classification below, never a crash).
- Per-finding disposition, mirroring the stage file: `rejected-observation` when the revised batch EXPLICITLY marks that finding id as rejected (the planner stated the rejection referencing the id); `accepted-observation` when the id is otherwise referenced / addressed in the revised batch; `accepted-but-unaddressed` when the id appears nowhere (a silent drop, recorded rather than dropped).
- Fail-closed, no fabrication (evidence invariance): any id whose disposition cannot be positively established — including under a missing / unparseable critique record or revised batch — defaults to `accepted-but-unaddressed`; the classifier NEVER fabricates a `rejected-observation` or a clean `accepted-observation` on ambiguity, so no unaddressed finding is silently credited as handled.
- `singular_plan_revise_record_dispositions <node> <revises_run_id> <critique_record> <revised_batch>` records ONLY: it emits provenance through `singular_append_event` under event type `plan.revised`, carrying `node`, `revisesRunId` (= `<revises_run_id>`), and the full per-finding id->disposition set; it changes no outcome, promotes / quarantines no candidate, invokes no runner, and touches no lease. Events land only in the pinned `SINGULAR_EVENTS_FILE`.
- Determinism: for a fixed (critique record, revised batch) the classifier output and the recorded disposition payload are byte-stable (id-sorted; no nondeterministic ordering or timestamps beyond the event envelope's own `ts`).
- The file defines new functions only and is invoked by no existing engine path: `tests/test-engine-clean.sh` stays green and an unused run is byte-identical to current behavior (no events, no state writes).
- Strict-test-first: `tests/test-ctx-plan-revise-dispositions.sh` is authored red first (asserting the above before implementation) and green after, fully hermetic (pins `SINGULAR_EVENTS_FILE` and all inputs to tmp so real run state is untouched); the full suite `bash tests/run.sh` is green. Cases covered: an addressed id -> accepted-observation; an explicitly-rejected id -> rejected-observation; a never-mentioned id -> accepted-but-unaddressed; missing / unparseable critique record and revised batch -> every finding defaults to accepted-but-unaddressed without crashing; `record_dispositions` emits the `plan.revised` event(s) carrying node + revisesRunId + per-id dispositions and mutates nothing else; two runs byte-identical.
- Gate candidate: with this slice integrated, the node's per-finding accepted-observation / rejected-observation / accepted-but-unaddressed dispositions are classified and evented; the `plan-revision-loop` node gate remains BLOCKED pending the resume-vs-fresh planner re-invocation with the rc-86 fresh-fallback record and the generate-tasks.sh / l1-plan-node.sh driver-hook slices, all under SINGULAR_PLAN_CRITIQUE, with test-ctx-plan-revision.sh full-walk coverage.
