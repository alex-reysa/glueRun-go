## Objective

In `engine/l1-drive.sh`, the disposable-rerun branch that detects
`sourceIntegrity.status == violation` — the independently rerun gate attempted to mutate
committed source — currently sets `attempt_failure="audit-infra"`. That is a deterministic
correctness/containment event, not an environment fault, yet it inherits `audit-infra`'s
unconditional `escalate-infra` park ("the work is fine, the environment is not" — exactly
wrong here) and disappears inside every infra-vs-product metric.

Required changes:

1. Introduce the failure class `integrity-violation` at that emitter site. Keep the existing
   `audit.source_integrity_violation` event and written verdict text unchanged.
2. Route it in `singular_decider_fast_action` (`engine/lib.sh`): `integrity-violation` maps to
   `escalate-parked` regardless of remaining budget — a human must judge this work; it must
   never be relabeled by the model decider, never retried automatically, and never parked as
   infrastructure. Update the in-function comment table accordingly.
3. Add the class to the `decider-verdict.v0` interoperability surface only if the existing
   in-test enum assertion in `tests/test-decider-fastpath.sh` requires it — the action emitted
   is `escalate-parked`, which is already a schema enum member; `failureClass` is free-form by
   schema, so no schema change is expected. Do not widen any schema in this task.
