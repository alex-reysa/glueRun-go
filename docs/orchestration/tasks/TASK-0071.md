## Objective

Advance executable DAG node `graph-contract` (stage `S6-graph`, layer `contract`, single-slice) toward its `requiredCompletion` by authoring the append-only JSONL provenance-graph contract and the written event-to-graph mapping table. This is the PURE-PROJECTION contract ONLY: no projector, no CLI, no engine wiring (those belong to the downstream `graph-projector` node).

One cohesive contract slice, in implementation order:

1. `schemas/context-graph.v0.schema.json` — the additive, fail-closed JSON Schema for one line of the append-only JSONL corpus under `.gluerun-state/graph/` (`nodes.jsonl` + `edges.jsonl`). It defines a node record and an edge record (e.g. via local `$defs.node` / `$defs.edge`) with: the full node-type taxonomy (`goal, plan-batch, plan-version, critique, finding, assumption, task, attempt, commit, gate-result, audit, decision, capsule`); the full edge-type taxonomy (`depends_on, derived_from, revises, critiques, accepts_observation, rejects_observation, implements, verifies, contradicts, invalidates, supersedes`); `evidenceClass` on every node as an enum of exactly `authoritative | claim`; `provenance` on every node (source record path + content hash) as required fields; closed objects (`additionalProperties: false`); and an `$id`/const in the `gluerun.orchestration.*.v0` family, mirroring `schemas/plan-critique.v0.schema.json`.
2. A hand-authored fixture corpus (`tests/fixtures/context-graph/nodes.jsonl` + `edges.jsonl`) of representative lines the schema validates, alongside malformed lines the test proves it rejects. Hand-authored because no projector emits graph records yet.
3. `docs/context-build-plan/graph-event-mapping.md` — the written mapping table: for every S0-S5 durable record/event type, the node and/or edge type(s) it projects to, and whether the resulting node is `authoritative` (host-verified: gate results, commits, scope/secret scans) or `claim` (every model-authored statement). Must cover all S0-S5 record types.
4. `tests/test-context-graph-schema.sh` — strict-test-first guard: RED (missing-schema fail) before the schema exists, GREEN after. It carries a tiny schema-driven validator that reads the ACTUAL schema file (mirroring `tests/test-plan-critique-schema.sh`), validates the fixtures line-by-line, rejects each malformed class, asserts the node/edge enums contain the full taxonomy, asserts `evidenceClass` is exactly `authoritative|claim`, and asserts the mapping doc names every S0-S5 record type.

Objective names the executable DAG node `graph-contract` and layer `contract` as required.

- `bash tests/test-context-graph-schema.sh && bash tests/test-engine-clean.sh` passes; the schema test fails closed when `schemas/context-graph.v0.schema.json` is absent (strict-test-first RED precondition).
- `schemas/context-graph.v0.schema.json` validates every line of the `tests/fixtures/context-graph/nodes.jsonl` and `edges.jsonl` fixtures, and rejects at least: an unknown node `type`, an unknown edge `type`, a node missing `provenance`, an `evidenceClass` value outside `authoritative|claim`, and an unknown top-level property (closed object).
- The schema enumerates the complete node-type taxonomy (`goal, plan-batch, plan-version, critique, finding, assumption, task, attempt, commit, gate-result, audit, decision, capsule`) and the complete edge-type taxonomy (`depends_on, derived_from, revises, critiques, accepts_observation, rejects_observation, implements, verifies, contradicts, invalidates, supersedes`); the test asserts each taxonomy member is accepted and a non-member `type` is rejected.

- `docs/context-build-plan/graph-event-mapping.md` maps every S0-S5 durable record/event type to its projected node/edge type(s) and marks a node `authoritative` only for host-verified records (gate-result, commit, scope/secret scan) and `claim` for every model-authored record (plan-batch/plan-version, critique, finding, assumption, audit-claim); the test asserts the doc names each S0-S5 record type listed in the context packet.

## Context packet

Decisions:

- File path is exactly `schemas/context-graph.v0.schema.json` (schemas/ root), per `docs/orchestration/areas/graph/state.md` and the stage-6 deliverable list; the `$id`/const uses the `gluerun.orchestration.*.v0` namespace (planner-contract rule 4), mirroring `schemas/plan-critique.v0.schema.json`, which sits at schemas/ root with `$id gluerun.orchestration.plan-critique.v0`.
- One schema file describes both record kinds via local `$defs.node` and `$defs.edge`; validate each `nodes.jsonl` line against `$defs.node` and each `edges.jsonl` line against `$defs.edge`. Extend the tiny embedded validator (from `test-plan-critique-schema.sh`) with local-`$ref`/`$defs` resolution if the top level uses `oneOf`, or validate lines directly against the extracted `$def` sub-object — the environment ships no jsonschema module.
- `evidenceClass` is a plain enum in the schema; the authoritative-reserved-for-host-verified INVARIANT is a projection-time rule, so it is captured and made checkable in the mapping table rather than asserted structurally by the schema.

Assumptions:

- `[validated] the graph is a pure projection — stage-6-graph.md: models never write graph records`. This node ships contract + fixtures + mapping ONLY: no `engine/ctx-graph.sh`, no `cli/gluerun graph` hook, no wiring; those belong to the downstream `graph-projector` node.
- `[open] S0-S5 record/record-type coverage set — must cover at least the durable records/events observed in the repo`: task file (`docs/orchestration/tasks/TASK-*.md`), attempt record, commit, gate-result (`schemas/gate-result.v0`), audit verdict (`schemas/audit-verdict.v0`), decision record (`decision.recorded`), plan batch (`task-batch.v0`), plan-critique record (`plan-critique.v0` / `plan.critiqued`), plan revision (`plan.revised`, `plan.revise_parked`), assumption ledger, arm assignment (`ctx.arm_assigned`), paired audit (`ctx.paired_audit`), critic recheck (`ctx.critic_recheck`), strategy selection (`context.strategy_selected`), resume-failed (`context.resume_failed`), artifact secret scan (`ctx.artifact_secret`). The worker MUST confirm the full set against `docs/context-build-plan/stage-0..5-*.md` plus the event vocabulary and must not silently drop a type.
- `[validated] no temporal negative assertion — planner-contract rule 9`. The test MUST NOT assert the schema is present-but-unwired (an unwired grep breaks the moment `graph-projector` legitimately loads the schema). Pin behavior positively (fixtures validate, malformed rejected, taxonomy and coverage complete). This deliberately diverges from the older `wired=...
