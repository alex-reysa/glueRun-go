## Objective

Begin the executable DAG node `critic-carryover` (stage `S3-plan-revision`, area `plancritic`, layer `engine_runtime`, kind `runtime`) with its smallest strict-test-first brick: the deterministic post-acceptance sampling gate behind the default-OFF `GLUERUN_CRITIC_RECHECK_PCT` knob. The stage-3 node text names this knob explicitly as the sibling of the integrated paired-audit sampling knob (`engine/ctx-paired-audit.sh`, TASK-0005), so this brick establishes that sibling gate as the pure, side-effect-free entry point the later recheck recorder will consult before deciding whether an accepted task is sampled for a critic recheck.

Add a new `engine/ctx-critic-recheck.sh` auto-sourced by the ctx-loader block in `lib.sh` (the `engine/ctx-*.sh` convention). It defines NEW functions only; NO existing engine path invokes them, so with the file present-but-uncalled the engine is byte-identical to prior behavior. It adds no driver-file hook, invokes no runner, and writes no state. It never owns `engine/lib.sh`.

Public entry points (mirroring the integrated paired-audit sampling primitive):

- `gluerun_ctx_critic_recheck_bucket <id>` — pure: print the id's sampling bucket in 0..99 from a stable content hash (SHA-256 where available, else shasum, else cksum CRC), reduced modulo 100. Never `$RANDOM` or any process/host-specific source.
- `gluerun_ctx_critic_recheck_should_sample <id>` — pure: exit 0 iff the id is sampled under `GLUERUN_CRITIC_RECHECK_PCT`, else exit 1. Default 0 (unset or `"0"`) never samples; 100 always samples; a mid value P samples the reproducible subset whose bucket < P; a non-numeric/garbage value is treated as 0 (fail-safe OFF).

Advocate/skeptic line + evidence invariance: this brick decides sampling only — it never blocks or changes any accept/reject outcome, never weakens a gate, and never makes the fresh implementation auditor bypassable. The read-only critic session resume over the accepted diff, the skeptic role gate (this session may never be resumed as planner/implementer), the per-finding `addressed | survives | obsolete` disposition recorder + `ctx.critic_recheck` events, and the `l1-drive.sh` post-acceptance hook are the sanctioned follow-up slices of `critic-carryover` and are OUT OF SCOPE here.
