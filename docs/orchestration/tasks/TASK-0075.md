## Objective

Ship the deterministic corpus assembler that turns the stream of projected JSONL lines (emitted by the integrated `engine/ctx-graph.sh` primitives `gluerun_graph_emit_node`/`gluerun_graph_emit_edge`) into the on-disk append-only corpus `<graphdir>/nodes.jsonl` + `<graphdir>/edges.jsonl` — the determinism/idempotence keystone that the later `graph-projector` (layer `engine_runtime`) capabilities `gluerun graph rebuild`/`sync` both funnel through, so equal source sets yield a byte-identical graph. New file `engine/ctx-graph-corpus.sh`, auto-sourced by the ctx-loader block in `engine/lib.sh`, defines functions ONLY; no engine path invokes them, so the engine is byte-identical with the file present (OFF-parity for `GLUERUN_CTX_GRAPH`, default 0; the flag gates the future `cli/gluerun graph` call site, a separate task). Implement the two chained slices below in order, each with its RED test in `tests/test-ctx-graph-corpus.sh` before code:

1. Canonicalizer. `gluerun_graph_canonicalize` reads projected JSONL lines on stdin and prints them deduplicated by `id` (identical projection lines for the same id collapse to one) and sorted by `id` ascending. Pure stdin->stdout and permutation-independent: any input ordering of the same line set yields byte-identical output. This is what makes the projector deterministic and idempotent.

2. Loss-free corpus writer. `gluerun_graph_write_corpus <graphdir> <nodesInput> <edgesInput>` runs each input stream through slice 1 and writes `<graphdir>/nodes.jsonl` and `<graphdir>/edges.jsonl`, first clearing any prior graph files in `<graphdir>` so no stale line survives a rebuild (deletable + rebuildable loss-free). `<graphdir>` defaults to `${GLUERUN_CTX_GRAPH_DIR:-.gluerun-state/graph}` when not supplied. Idempotent: writing twice over the same inputs, or deleting `<graphdir>` and writing again, reproduces a byte-identical corpus. Consumes slice 1.

The rebuild/sync source walk (mapping each S0-S5 source record to emitter calls), the `query` read API, and the `cli/gluerun graph` driver hook are the subsequent `graph-projector` tasks and are out of this slice's scope. This task advances `graph-projector` toward its `requiredCompletion` by delivering the canonical, idempotent, loss-free assembly atom; it does not complete the node or declare a gate pass.

## Acceptance Criteria

- `tests/test-ctx-graph-corpus.sh` is green and is the strict-test-first regression: it fails before `engine/ctx-graph-corpus.sh` exists (RED) and passes after (GREEN).
- Determinism / idempotence: `gluerun_graph_canonicalize` emits byte-identical output for any input permutation of the same line set, collapses duplicate-`id` lines to a single line, and sorts by `id` ascending.
- Loss-free rebuild: after `gluerun_graph_write_corpus` writes a corpus, deleting `<graphdir>` and re-running over the same emitted inputs reproduces byte-identical `nodes.jsonl` and `edges.jsonl`; a second write over the same inputs is byte-identical to the first (idempotent); and stale lines from a prior corpus never survive a rewrite.
- Round-trips the real primitives: lines produced by `gluerun_graph_emit_node` / `gluerun_graph_emit_edge` fed through the writer still validate against `schemas/context-graph.v0.schema.json`, and every written line is preserved verbatim except for dedup and ordering.
- OFF-parity: `engine/ctx-graph-corpus.sh` only DEFINES functions; sourcing it under the ctx-loader block invokes nothing and leaves engine behavior byte-identical when `GLUERUN_CTX_GRAPH` is unset or `0`. The writer touches only the explicitly-provided `<graphdir>` and no other path.
- `bash tests/test-engine-clean.sh` stays green: no project-specific symbols in `engine/`.

## Context packet

### Decisions
- The canonicalizer keys on `id` (not full-line content): identical projection guarantees identical content per id, so dedup-by-id + sort-by-id makes rebuild and sync produce byte-identical corpora from the same source set — the mechanism behind the `requiredCompletion` rebuild-equals-sync property.
- The writer clears `<graphdir>` before writing rather than appending, so a delete-and-rebuild is loss-free and no stale line from a prior projection survives; append-only is the on-disk record shape, not the rebuild strategy.
- New sibling file `engine/ctx-graph-corpus.sh` (not an edit to the integrated `engine/ctx-graph.sh`) keeps the gate scoped and mirrors the established `engine/ctx-rehydrate*.sh` multi-file-per-node pattern.

### Assumptions
- [validated] `engine/ctx-graph.sh` emitters (`gluerun_graph_emit_node`/`_edge`) are integrated and each print one schema-valid JSONL line — basis: TASK-0074 integrated.
- [open] `python3` is available for JSON `id` parsing and a stable sort in both the function and its test — basis: `engine/ctx-metrics.sh` and `tests/test-context-graph-schema.sh` both rely on it.

### Rejected alternatives
- Folding the S0-S5 source walk (the rebuild entry point) into this task — rejected: mapping every event/record family to emitter calls is a larger slice that COMPOSES this assembler; bundling it would exceed the smallest-brick bound.
- Owning/editing the integrated `engine/ctx-graph.sh` to add the writer there — rejected: re-owning an existing file forces the full-suite gate and needlessly widens the blast radius for a purely additive sink.
