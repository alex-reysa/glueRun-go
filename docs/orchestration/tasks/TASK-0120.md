## Objective

`evidenceBindingSha256` — the tamper-evident composite over
`{headSha, commandSha256, rawExitCode, logSha256, outcome, baselineSha256}` — is hand-computed
in three separate places today: `engine/gate_report.py`, `engine/gate-report.py`, and the
inline recomputation in `engine/dag.sh`'s validator. The supervised-job work (rel-11/rel-13)
needs a fourth identity hash (pre-execution job identity). Four hand-rolled canonicalizations
of overlapping field sets is guaranteed drift; the audit flags this as the top structural risk
of the sprint. Centralize FIRST, so rel-13 consumes a canonicalizer instead of adding impl #4.

Required changes:

1. New module `engine/identity.py`:
   - `canonical_json(obj)` — sorted keys, no whitespace variance, UTF-8, explicit rejection of
     floats/NaN (byte-stable across process restarts and Python versions);
   - `identity_sha256(obj)` — sha256 of the canonical bytes;
   - `evidence_binding(fields)` — the EXISTING binding, byte-for-byte compatible with today's
     output for today's inputs (this is the hard constraint: every historical
     `gate-report.json` must still verify);
   - `job_identity(fields)` — pre-execution identity over
     `{taskId, runId, role, engineContractVersion, argv (array, not a shell string),
     envAllowlist (sorted name=value), workspace, headSha, inputHashes}` — the strict
     input-superset of evidence binding minus its output fields. Output fields
     (exitCode, logSha256, outcome) MUST be rejected if passed to `job_identity`.
2. Adopt it in all three existing recomputation sites so each imports/invokes the shared
   implementation (for `engine/dag.sh`, via its embedded Python importing `engine/identity.py`
   the same way it already imports `human_gate`).
3. Cross-implementation drift test: one fixture file of inputs -> expected hashes, asserted
   against ALL call sites, so any future divergence fails in one place.
