## Objective

Advance the executable DAG node `plan-critic-driver` (stage `S2-plan-critique`, layer `engine_runtime`, kind runtime) toward its required completion — "critiques STAGED CANDIDATES read-only on the default runner" — by adding a new, present-but-uncalled `engine/ctx-plan-critic-context.sh` that assembles the read-only staged-candidate critic context the skeptic must actually receive.

The already-integrated driver `engine/ctx-plan-critic.sh` (TASK-0013) wires the fresh, read-only default-runner call, critique persistence, the `plan.critiqued` / `ctx.plan_critique_infra` events, and the per-node critic session meta — but it invokes the runner with ONLY the base `plan-critic` prompt (`--prompt-file`). It derives `batchTaskIds` from the staged filenames yet never composes the candidate CONTENT, so the critic is flown blind and cannot genuinely critique the staged set. This brick closes that gap by building the composed critic input from exactly what the driver already stages: the rendered candidate task files in the node-local stage dir (`*.candidate.md`), the existing-task summary the planner itself was shown, and the node's own stage file under `docs/context-build-plan/`.

The file defines NEW functions only and is invoked by NO existing engine path, so with it present-but-uncalled the engine is byte-identical to prior behavior (mirroring `engine/ctx-plan-critic.sh` and `engine/ctx-paired-audit.sh`). Wiring the assembled context into the driver's runner invocation, and the `reconcile.sh` / L0 import enforcement, belong to later slices and to the `critique-import-gate` node and are out of scope here. The assembler is pure and read-only: it reads the staged inputs and writes ONLY its single composed output file — it appends no events, spawns no runner, and mutates nothing else — preserving the advocate/skeptic line and evidence invariance (the critic stays read-only, fresh-by-default, on the default runner, and never weakens, resumes into, or bypasses the un-bypassable implementation auditor).

Public entry points are `gluerun_ctx_plan_critic_*`-scoped and free of project-specific symbols (so `tests/test-engine-clean.sh` stays green): a pure resolver that, given a `<node>`, prints the node's stage file path under `docs/context-build-plan/` (or empty when none matches), and a pure assembler that, given `<node> <stage_dir> <out_file>` (with the existing-task summary staged for the node), composes the read-only critic context into `<out_file>`.
