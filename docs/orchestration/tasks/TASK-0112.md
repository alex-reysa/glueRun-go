## Objective

`revalidate-evidence` is a first-class member of the `decider-verdict.v0` action enum, but in
`engine/l1-drive.sh`'s terminal `case "$action"` block it shares one branch with
`retry|rerun-tests|rebuild-context|amend-scope`: it bumps the product lease retry counter
(`singular_lease_bump_retry`), renders a fix prompt telling the implementer to "Address it",
and re-enters the attempt loop, which unconditionally runs `prepare_worker_prompt` +
`run_worker_phase`. The verdict promises an evidence remedy the engine does not implement —
a full implementer re-run for what is by definition not a product defect. The in-file comment
near the no-changes handling already records a field failure caused by exactly this gap.

Required changes:

1. Give `revalidate-evidence` its own case branch implementing an evidence-only remedy against
   the SAME accepted candidate tree (no worker, no new commits):
   - re-run the evidence-manifest build/refresh for the run;
   - re-run gate-report head-binding if the manifest step requires it;
   - re-run the audit phase (`run_audit_phase`) against the refreshed evidence.
2. Budget: introduce `SINGULAR_EVIDENCE_REMEDY_MAX` (default 1) as a separate counter. The
   remedy never calls `singular_lease_bump_retry`. On exhaustion or repeated failure the task
   parks `escalate-parked` with the original evidence intact.
3. The remedy path must be inert to worker state: no call into `prepare_worker_prompt`,
   `run_worker_phase`, or fix-prompt rendering; the worker session meta is untouched so
   attempt-level session affinity is unaffected.
4. Auditor independence is preserved: the re-audit follows the existing audit-phase rules
   (fresh-or-affinity per current policy); nothing about this task may resume an advocate
   session into a skeptic role.
