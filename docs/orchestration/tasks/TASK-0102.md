## Objective

Advance the executable DAG node `subgraph-rehydrate` (stage `S6-graph`, layer
`engine_runtime`) with the next chained brick after the integrated selection
reader (TASK-0099, `singular_ctx_rehydrate_subgraph_select`) and the integrated
node-record source-spec resolver (TASK-0101,
`singular_ctx_rehydrate_subgraph_sources`): the ORDER-PRESERVING subgraph
rehydration packet + manifest renderer and its composed graph entry point, in a
NEW file `engine/ctx-rehydrate-subgraph-packet.sh`. This is the piece the
resolver comment explicitly anticipates (the order-preserving subgraph packet
renderer) and it is what makes rehydration packets ASSEMBLED BY subgraph
selection — the node requiredCompletion.

Implement two chained slices in order, in one cohesive file (mirroring how the
flat assembler `engine/ctx-rehydrate.sh` carries both packet and manifest
modes):

1. Order-preserving renderer over resolver specs. Read the resolver output —
   `<source-class-id>=<path>` specs, one per line on stdin — and emit either the
   rehydration packet or the manifest, PRESERVING the input spec order (the
   selector contradictions-first ordering) instead of re-sorting by the flat
   assembler RANK:
     - `singular_ctx_rehydrate_subgraph_packet` — one labeled
       `=== <source-class-id> ===` section per surviving spec IN INPUT ORDER,
       each artifact body read read-only and capped to
       SINGULAR_CONTEXT_SECTION_MAX_CHARS (default 4000) with the same truncation
       marker convention as the flat assembler (caps UNCHANGED).
     - `singular_ctx_rehydrate_subgraph_manifest` — a manifest conforming to the
       EXISTING schema singular.orchestration.ctx-rehydrate-manifest.v0 (included
       source ids + sha256 of each artifact), sources listed in the same
       selection order (manifest schema UNCHANGED; this task owns no schema
       file).
   Quarantine-aware: each candidate is filtered through the integrated
   singular_ctx_artifact_exclude, so a quarantined source (a .quarantined path or
   one with a .quarantined sibling) never reaches the packet or the manifest —
   the single quarantine authority is preserved. A declared-but-missing artifact
   contributes nothing (non-fatal).

2. Composed graph entry point.
   `singular_ctx_rehydrate_subgraph_assemble <graphDir> <taskNodeId> <packet|manifest>`
   pipes the integrated read path end-to-end: select the subgraph
   (`singular_ctx_rehydrate_subgraph_select`) -> resolve source specs
   (`singular_ctx_rehydrate_subgraph_sources`) -> render (slice 1), so a
   contradictions-first, capped packet or its matching manifest is produced
   directly from a graph dir + task node id — the deterministic subgraph-selected
   rehydration packet.

Per-node sections, not per-class dedup: because a subgraph can select several
nodes of one class (e.g. multiple surviving findings), multiple sections may
carry the same class label — one durable source per selected node, in selection
order; this is intended.

Feature-flag discipline: the file DEFINES new functions only and no existing
engine/CLI/driver path invokes them, so with it sourced the engine is
byte-identical to prior behavior (OFF-parity). Choosing subgraph vs flat
rehydration per A/B arm and the l1-drive.sh injection wire-in are SEPARATE later
slices (driver hooks, full-suite gate) and are out of scope here.

Evidence invariance / advocate-skeptic line: rendering is a pure read — it reads
and hashes artifact bytes but never writes, renames, or deletes; appends no
events; mutates no taint; confers NO independence (the rehydrate strategy stays
tainted per singular_ctx_route_strategy_tainted); and records nothing as
authoritative.

## Acceptance Criteria

- Given a fixed sequence of resolver `<source-class-id>=<path>` specs (a
  contradiction-flagged node first, then the rest), the packet renderer emits
  one `=== <source-class-id> ===` section per spec IN THE GIVEN ORDER (the
  contradiction section first), NOT re-sorted by the flat assembler RANK.
- Each section body is capped to SINGULAR_CONTEXT_SECTION_MAX_CHARS with the flat
  assembler truncation-marker convention; setting the knob smaller shrinks the
  section deterministically (caps unchanged).
- The manifest renderer emits an object conforming to
  singular.orchestration.ctx-rehydrate-manifest.v0 with each included source id +
  its sha256; identical artifact bytes yield a byte-identical manifest (manifest
  schema unchanged).
- A quarantined source (a .quarantined path or a source with a .quarantined
  sibling) never appears in the packet or the manifest; a declared-but-missing
  artifact contributes nothing; neither is fatal.
- `singular_ctx_rehydrate_subgraph_assemble` over a hand-authored fixture corpus
  (nodes.jsonl + edges.jsonl per schemas/context-graph.v0.schema.json, with a
  deep task -> plan-version -> critique -> finding lineage, a rejected
  observation, and an open contradiction) plus fixture artifacts at the node
  provenance.sourcePath values produces a packet whose sections are
  contradictions-first and exclude the rejected observation, and a manifest
  listing exactly the included sources — end-to-end deterministic (byte-identical
  across runs).
- Determinism and fail-safe: identical inputs yield byte-identical packet and
  manifest; an empty selection (no durable-class nodes, or missing/empty corpus)
  yields a well-formed empty result and a zero exit.
- OFF-parity: with the new file sourced but uncalled, the engine is
  byte-identical to prior behavior.
- Gate candidate: `tests/test-ctx-rehydrate-subgraph-packet.sh` is red before
  implementation and green after; `tests/test-engine-clean.sh` stays green (no
  project-specific symbols in `engine/`).

## Context packet

Decisions:
- A new order-preserving renderer rather than reusing
  `singular_ctx_rehydrate_packet` — why: the flat assembler re-sorts sections by a
  fixed source-class RANK independent of argument order, which would DESTROY the
  selector contradictions-first ordering; the subgraph packet must render in
  selection order, so the ordering logic differs even though caps, truncation
  marker, quarantine authority, and manifest schema are reused UNCHANGED.
- Bundle the spec renderer and the composed graph entry point in one file/task —
  why: chained micro-slices in the same node (a helper renderer, then its
  select->sources->render consumer) belong in one task; both are small and the
  entry point is a thin composition over already-integrated readers.
- Reuse SINGULAR_CONTEXT_SECTION_MAX_CHARS and
  singular.orchestration.ctx-rehydrate-manifest.v0 verbatim and own no schema file
  — why: caps and manifests UNCHANGED is a node requirement, and schema changes
  are additive-only and out of scope here.

Assumptions:
- [validated] `singular_ctx_rehydrate_subgraph_select` emits selected node records
  contradictions-first and `singular_ctx_rehydrate_subgraph_sources` maps them to
  `<class>=<sourcePath>` specs preserving that order — basis:
  engine/ctx-rehydrate-subgraph.sh and engine/ctx-rehydrate-subgraph-sources.sh.
- [validated] the flat assembler re-sorts by RANK and caps at
  SINGULAR_CONTEXT_SECTION_MAX_CHARS with a fixed truncation marker, and its
  manifest uses singular.orchestration.ctx-rehydrate-manifest.v0 with a
  sources:[{id,sha256}] shape — basis: engine/ctx-rehydrate.sh.
- [validated] `singular_ctx_artifact_exclude` is the single quarantine authority
  the flat packet/manifest already compose — basis: engine/ctx-rehydrate.sh
  composes it; reuse it, do NOT re-implement quarantine.

Rejected alternatives:
- Feeding the resolver specs straight into `singular_ctx_rehydrate_packet` —
  why-not: its RANK re-sort collapses contradictions-first order, the whole point
  of the subgraph path.
- Deduping multiple same-class sections into one — why-not: each selected node is
  a distinct durable source; per-node sections in selection order are intended.

Inspected symbols:
- `singular_ctx_rehydrate_subgraph_sources`
  (engine/ctx-rehydrate-subgraph-sources.sh) — role: produces the ORDERED
  `<class>=<sourcePath>` specs this renderer consumes; its order-preservation is
  the contract this brick must not break.
- RANK (engine/ctx-rehydrate.sh) — role: the fixed re-sort this renderer must NOT
  apply, the reason a separate order-preserving renderer exists.
