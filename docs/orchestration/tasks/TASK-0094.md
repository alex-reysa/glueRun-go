## Objective

Make the integrated `assumption` and `capsule` projection mappers (TASK-0092) LIVE in the `graph-projector` (layer `engine_runtime`) corpus by wiring them into both entry-point walks and extending the composed guard. Because `engine/ctx-graph-sync.sh` duplicates rebuild's record-source enumeration (its own `find` loops, not a call to `gluerun_graph_rebuild`), the two mappers must be added to both walks identically or the sync-equals-rebuild invariant breaks. Three coordinated edits, in order:

1. Rebuild walk (`engine/ctx-graph-rebuild.sh`): call `gluerun_graph_project_assumptions` on each `docs/orchestration/tasks/TASK-*.md` (alongside the existing task-node walk) and add a new `runs/*/implementer-capsule.json` + `runs/*/reviewer-capsule.json` walk feeding `gluerun_graph_project_capsules`, in the same sorted-find style as the existing source walks.

2. Sync record re-walk (`engine/ctx-graph-sync.sh`): mirror the identical two additions in sync's bounded record re-walk so its enumeration stays byte-for-byte the same source set as rebuild (its own comment already pins it as the same walks as gluerun_graph_rebuild).

3. Composed guard (`tests/test-ctx-graph.sh`): extend the fixture state tree with a task file carrying a `## Context packet` `### Assumptions` block and an implementer/reviewer capsule record, and assert that the rebuilt corpus now contains `assumption` and `capsule` nodes (evidenceClass `claim`) and that `gluerun_graph_sync` still yields a corpus byte-identical to `gluerun_graph_rebuild` with those families present.

The additions are walk-only inside already-flag-gated library functions, so OFF-parity is unaffected (rebuild/sync are invoked only via the `GLUERUN_CTX_GRAPH`-gated `gluerun graph` cli). This task advances `graph-projector` by making two more mapping-table node families live in rebuild/sync under the existing determinism and sync-equals-rebuild guarantees; it does not declare the node complete.

## Context packet

### Decisions
- `engine/ctx-graph-sync.sh` duplicates rebuild's record-source enumeration (it does not call `gluerun_graph_rebuild`), so the two new mappers must be added to BOTH walks identically to keep sync equal to rebuild; the guard asserts the equivalence with the new families present.
- The assumption mapper attaches to the existing task-file walk (same source as the task mapper); the capsule mapper gets a new `runs/*/implementer-capsule.json` + `reviewer-capsule.json` walk mirroring the integrated paired-audit walk.

### Assumptions
- [validated] `gluerun_graph_project_assumptions <taskFilePath>` and `gluerun_graph_project_capsules <capsuleRecordPath>` are integrated and emit claim nodes to stdout — basis: engine/ctx-graph-project-context.sh (TASK-0092).
- [validated] sync re-walks the bounded record sources with its own `find` loops mirroring rebuild rather than calling it — basis: the record re-walk in engine/ctx-graph-sync.sh.
- [validated] capsule records live at `runs/<runId>/implementer-capsule.json` / `reviewer-capsule.json` — basis: engine/ctx-artifact-scan.sh and engine/ctx-rehydrate-sources.sh.
- [open] `python3` is available for the guard fixture and JSON checks — basis: prior graph tests rely on it.

### Rejected alternatives
- Wiring only rebuild and not sync — rejected: sync duplicates the record walk, so omitting it would put assumption/capsule nodes in the rebuild corpus but not the sync corpus, breaking the sync-equals-rebuild invariant the guard enforces.
- Refactoring sync to call rebuild's walk to DRY the enumeration — rejected: out of scope and riskier (it would disturb sync's cursor/merge structure); the minimal faithful edit mirrors the two walks.

### Inspected symbols
- the sync record re-walk (`engine/ctx-graph-sync.sh`): its own `find` loops over runs/gates/tasks/paired-audits are why both entry points must change in lockstep, not just rebuild.
