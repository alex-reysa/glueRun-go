## Objective

Complete the node-dimension mini-track of the explicitly-OPTIONAL authored-knowledge manifest ingestion for the executable DAG node `rehydrate-path` (stage `S5-routing`, layer `engine_runtime`): TASK-0064 shipped the trigger-set builder with a `[node]` slot, TASK-0065 wired the role/step/task dimensions into both live sites, TASK-0066 shipped the pure run-node resolver — and THIS slice threads that resolver into the `[node]` slot at both sites, the deferred follow-up TASK-0066 named.

TASK-0066 shipped the pure, read-only resolver `gluerun_ctx_rehydrate_authored_node <task_id> [worktree]` (returns the single distinct executable DAG node owning `<task_id>` from the durable control-state task->node association, or empty fail-safe on absence/ambiguity), but it is present-but-uncalled. The two live consumers of `gluerun_ctx_rehydrate_authored_triggers` — the injection at `engine/l1-drive.sh:469` (feeding `gluerun_ctx_rehydrate_authored_config_render`, TASK-0062) and the manifest-record at `engine/ctx-rehydrate-event.sh:89` (feeding `gluerun_ctx_rehydrate_authored_config_manifest`, TASK-0063) — still pass only `implementer implement "$task_id"`, omitting the builder's position-3 `[node]` slot. Consequently any authored entry whose `load-when` targets the run's node (e.g. `["rehydrate-path"]`) can never become eligible, and both TASK-0066's resolver and the builder's `[node]` parameter remain dead.

This slice substitutes, at BOTH sites, a node-resolution step: resolve `node="$(gluerun_ctx_rehydrate_authored_node "$task_id")"` and pass it into the builder's position-3 slot — `gluerun_ctx_rehydrate_authored_triggers implementer implement "$node" "$task_id"`. Both sites already have `task_id` in scope (`engine/l1-drive.sh` uses `$task_id`; `gluerun_ctx_rehydrate_event_data` has a `task_id` parameter, line 47), so each resolves the node from its own `task_id` and NO signature change to `gluerun_ctx_rehydrate_event_data` is required. Because both sites call the SAME pure deterministic resolver with the SAME `task_id`, they derive the IDENTICAL node token and therefore the identical trigger set, preserving the injected<->recorded consistency invariant TASK-0063/0065 established (wiring only one site would desync them, so both change together in one slice).

Backward compatibility and OFF-parity: an empty resolver result (the fail-safe on absent or ambiguous node) contributes nothing because `gluerun_ctx_rehydrate_authored_triggers` skips empty dimensions, so the set stays exactly `{implementer, implement, task_id}` — byte-identical to pre-TASK-0066 behavior; and node is added at position 3 with task remaining at position 4, so the enriched set is a strict superset of the prior one and every previously-matching entry still matches. With `GLUERUN_CTX_MANIFEST` unset (default) the config gate returns empty regardless of triggers, so nothing is injected or recorded; with `GLUERUN_REHYDRATE` unset no rehydrate run occurs at all. This is a minimal call-site substitution delegating into `gluerun_ctx_rehydrate_authored_node` plus the existing builder and config-gated functions; no resolve/select/render logic is inlined (node `rehydrate-path`, layer `engine_runtime`). It refines the OPTIONAL authored-knowledge feature; the core `requiredCompletion` (TASK-0051-0057) is already integrated and this slice does not gate the node — completion and gate promotion are operator authority and are not claimed here.

- Node-dimension matching: with `GLUERUN_CTX_ROUTING=1`, `GLUERUN_REHYDRATE=1`, `GLUERUN_CTX_MANIFEST=1`, a `rehydrate` run, a fixture control-state event log associating the task with exactly one node N, and a fixture `contextManifest` entry whose `load-when` matches N (but not the role, step, or task id), that entry is BOTH injected into `$active_prompt` (TASK-0062 path) AND recorded in the strategy-event manifest (TASK-0063 path).
- Injected<->recorded consistency: for the same `rehydrate` run, the authored entries injected into the packet equal the authored entries recorded in the event manifest, because both sites resolve the node via `gluerun_ctx_rehydrate_authored_node "$task_id"` and pass the identical trigger set `implementer implement "$node" "$task_id"`.
- Backward compatibility: entries scoped to `implement` / `implementer` / the task id still inject and record exactly as before (node is inserted at builder position 3, task stays at position 4; the enriched set is a superset of the prior set).

- OFF-parity (rehydrate flag): with `GLUERUN_REHYDRATE` unset, no `rehydrate` run occurs and behavior is byte-identical.
- Minimal delegation: each site resolves the node via `gluerun_ctx_rehydrate_authored_node` and passes it expanded to `gluerun_ctx_rehydrate_authored_triggers`; no resolve/select/render logic is inlined into either driver file, and `gluerun_ctx_rehydrate_event_data`'s parameter signature is unchanged (it resolves the node from its own `task_id` parameter).
- Gate candidate: with this wire-in integrated, authored `load-when` matching is functional across role / step / node / task dimensions, completing the TASK-0064 -> TASK-0065 -> TASK-0066 node-dimension mini-track and eliminating TASK-0066's present-but-uncalled dead-code status. This refines the OPTIONAL authored-knowledge feature; the core `requiredCompletion` (TASK-0051-0057) is already integrated and this slice does not gate the node.

## Context packet

Decisions:

- Substitute at BOTH the injection site (`engine/l1-drive.sh:469`) and the manifest-record site (`engine/ctx-rehydrate-event.sh:89`) in one slice, because both must pass the identical trigger set to preserve the injected<->recorded consistency invariant TASK-0063/0065 established; wiring only one desyncs the injected and recorded authored entries. Basis: TASK-0063 records exactly what TASK-0062 injects.
- Resolve the node from `task_id` in-place at each site via `gluerun_ctx_rehydrate_authored_node "$task_id"` rather than adding a `node` parameter to `gluerun_ctx_rehydrate_event_data` and threading it from the l1-drive caller — `task_id` is already in scope at both sites and the resolver is pure and deterministic, so both derive the IDENTICAL node token with a smaller diff and no caller/signature change. Basis: event builder has a `task_id` param (line 47); l1-drive uses `$task_id` (line 469).
- Pass node at builder position 3 and task at position 4 (`implementer implement "$node" "$task_id"`), keeping the enriched set a strict superset of `{implementer, implement, task}` so prior matches persist and the empty-node case degrades to the exact pre-TASK-0066 set. Basis: TASK-0064 builder signature `<role> <step> [node] [task]` and its empty-dimension skip.

Assumptions:

- [validated] `gluerun_ctx_rehydrate_authored_node <task_id> [worktree]` prints the single distinct node owning the task or nothing (fail-safe) on absence/ambiguity, rc 0 — basis: TASK-0066 header contract.
- [validated] `gluerun_ctx_rehydrate_authored_triggers` skips empty dimensions, so an empty node argument contributes no token and the set stays backward compatible — basis: TASK-0064 builder loop over `role step node task`.
- [validated] Both call sites currently pass `implementer implement "$task_id"` and have `task_id` in scope — basis: `engine/l1-drive.sh:469`, `engine/ctx-rehydrate-event.sh:47,89`.
- [open] The durable task->node association is present in the event log at the point the rehydrate strategy event is recorded, so the resolver can find node N for a live run; if it is not yet recorded the resolver returns empty and node-scoped entries simply do not match (fail-safe) — the test must exercise both a populated-association fixture and an absent/ambiguous fixture rather than assuming population.

Rejected alternatives:

- Adding a `node` parameter to `gluerun_ctx_rehydrate_event_data` and threading it from the l1-drive caller — rejected: unnecessary signature churn; the builder already has `task_id` in scope and the resolver is pure, so resolving in-function yields the identical token with a smaller diff and no caller change.
- Wiring only the injection site or only the manifest site — rejected: it desyncs injected versus recorded authored entries, breaking the TASK-0063/0065 consistency invariant; both must resolve and pass the identical node-enriched trigger set.
- Passing the node token at position 4 (the task slot) or reordering the dimensions — rejected: the builder contract is `<role> <step> [node] [task]`; node must be position 3 so the task stays addressable and the de-duplicated token order remains stable and deterministic.
