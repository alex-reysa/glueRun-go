## Objective

`$run_dir/audit-codex.log`. Nothing in the repo writes that file: the driver writes
`auditor-codex.log` (see the `auditor_log` assignment in `engine/l1-drive.sh`), and both
`evidence-manifest.sh` and the console adapter know the real name. This is a latent artifact-
contract defect for admissible non-independence reviewer routing and future callers.

production `final-audit` and `paired-audit` steps are intentionally independence-pinned to
`fresh tainted` before the window gate, as required by the advocate/skeptic invariant; the pin
must survive every subordinate/permissive routing knob. The master-off path remains the exact
legacy behavior. The original task and DAG incorrectly attributed the enabled-routing behavior
to this filename.

2. Regression-proof it structurally, not just by string: the test derives the expected name
   from what the driver writes (single source of truth), so a future rename breaks the test
   rather than silently re-introducing the fail-closed refusal.
3. Audit the same file for any other role/path mismatches against the driver's actual artifact
   names (implementer path `worker-codex.log` is correct today; keep an assertion anyway).
4. Preserve and assert the enabled-routing independence pin: with `SINGULAR_CTX_ROUTING=1`,
   `final-audit` and `paired-audit` remain `fresh tainted` under every subordinate/permissive
   routing knob and never use transcript-window resume. With the master flag `0`, preserve the
