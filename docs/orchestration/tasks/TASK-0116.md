## Objective

`engine/ctx-route-drive.sh` maps the reviewer role's transcript to
`$run_dir/audit-codex.log`. Nothing in the repo writes that file: the driver writes
`auditor-codex.log` (see the `auditor_log` assignment in `engine/l1-drive.sh`), and both
`evidence-manifest.sh` and the console adapter know the real name. The window gate fails
closed on a missing transcript (`engine/ctx-route-window.sh` — "empty path or
non-readable-regular-file"), so with `SINGULAR_CTX_ROUTING=1` — which is exactly what this
repo's own `singular.config.json` sets — the reviewer window gate always refuses and reviewer
session resume is permanently disabled. The defect is invisible at the default
`SINGULAR_CTX_ROUTING=0`, which is why it survived.

Required changes:

1. Fix the reviewer transcript path in `engine/ctx-route-drive.sh` to `auditor-codex.log`.
2. Regression-proof it structurally, not just by string: the test derives the expected name
   from what the driver writes (single source of truth), so a future rename breaks the test
   rather than silently re-introducing the fail-closed refusal.
3. Audit the same file for any other role/path mismatches against the driver's actual artifact
   names (implementer path `worker-codex.log` is correct today; keep an assertion anyway).

## Acceptance Criteria

- RED first: with `SINGULAR_CTX_ROUTING=1` and a run dir containing a real
  `auditor-codex.log`, the reviewer route decision today refuses on window-pressure
  (missing-transcript fail-closed); assert that.
- GREEN: the same fixture yields a window-gate PASS-or-substantive decision (whatever the
  existing decision vocabulary produces when the transcript is readable), and the implementer
  path still resolves `worker-codex.log`.
- No behavior change with `SINGULAR_CTX_ROUTING=0`.
