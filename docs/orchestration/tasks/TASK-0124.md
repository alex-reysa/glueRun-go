## Objective

Worker and auditor infra retries are hard-gated fresh: `worker_try -eq 0` / `audit_try -eq 0`
are the only paths that admit `--resume-session` in `engine/l1-drive.sh`. For a timeout at
hour three, the retry replays the whole session from nothing. Session affinity across ATTEMPTS
already exists with ten ordered identity gates (`singular_session_resume_decide` in
`engine/lib.sh`: role, run, runner, prompt sha, age, head lineage, worktree, ...) plus a tested
rc-86 refusal fallback in the runners. This task extends that EXISTING, tested mechanism to
one more axis — tries within an attempt — for infrastructure-class failures only. TASK-0110
added the regression test that pins today's try>0-fresh behavior; this task renegotiates that
contract explicitly, not silently.

Required changes:

1. Replace the `worker_try -eq 0` / `audit_try -eq 0` guards with a host decision:
   resume on try>0 is considered ONLY when the prior try's failure class is in the resumable
   set {`timeout`, transient transport/provider-exit per the runner-result provider
   `failureClass` vocabulary} — never for `empty-output`, never for any product or packet
   class, and gated `SINGULAR_INFRA_TRY_RESUME` (default 0 this release; flip is a release
   decision, not a code decision).
2. The resume candidate must pass the FULL existing ten-gate
   `singular_session_resume_decide` (same role, same run, same runner, same prompt sha, same
   head lineage, same worktree, unexpired) — the try axis adds a requirement, it relaxes
   nothing. A resumed advocate session must remain structurally unable to reach a skeptic
   role (per-role meta files already enforce this; keep the existing test green).
3. Separate counter: resumed tries increment a new `runtimeResumeCount` in the try loop
   (env cap `SINGULAR_RUNTIME_RESUME_MAX`, default 1), never the product lease retryCount,
   and never change the infra try counter semantics. A refused/failed resume falls back to
   today's fresh path within the same try via the existing rc-86 handling and does not burn
   the try.
4. Update the TASK-0110 regression test deliberately: with the flag OFF (default), try>0
   still omits `--resume-session` (today's behavior is the shipped default); with the flag ON
   and a resumable class, try>0 carries it; with the flag ON and a non-resumable class, it
   does not.
