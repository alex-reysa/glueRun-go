## Objective

Advance the `experiment-run` executable DAG node (layer `evaluation`) by shipping the deterministic, strictly read-only tooling that computes the remaining routing-derived SECONDARY raw metrics the operator's `experiment-report.md` references at merge: resume/rehydrate hit rates and their gate-refusal reason mix. TASK-0077 (`engine/ctx-experiment-report.sh`) already delivered the primary escape-rate, per-arm cost, and bias measurements; this task is the complementary strategy-metrics brick and does NOT duplicate it. Running the paired-audited A/B experiment, authoring `experiment-report.md`, and recording per-knob default decisions in `docs/orchestration/decisions.md` remain OPERATOR authority (kind: evaluation) and are OUT OF SCOPE; this task neither declares nor gates node completion.

All logic lands in one NEW `engine/ctx-experiment-strategy.sh`, auto-sourced by the ctx-loader block and defining new functions only. No existing engine path invokes them, so the engine is byte-identical with the file present (OFF-parity intrinsic, mirroring the `engine/ctx-metrics.sh` and `engine/ctx-experiment-report.sh` idiom). It does NOT edit `engine/ctx-experiment-report.sh` or any other pre-existing file. Every function reads only an events log (`events.ndjson`) whose relevant records are `context.strategy_selected` (carrying `taskId`, `role` in implementer|reviewer|planner, `attempt`, `strategy` in resume|rehydrate|fresh, and `reason` — the routing gate outcome / refusal reason), `context.resume_failed` (resume was chosen but failed and fell back to fresh), and `ctx.arm_assigned` (carrying `taskId`, `arm` in A|B) for per-arm grouping. It creates, moves, or mutates nothing — no run artifact, index, event, lease, or task file.

Implement three chained slices in order, all inside `engine/ctx-experiment-strategy.sh`:

1. Hit-rate aggregator: over `context.strategy_selected` events, compute the resume hit rate and the rehydrate hit rate (each = selections of that strategy / total strategy selections), sliceable by arm (joined to `ctx.arm_assigned` via `taskId`; A = control / M0 knob-state, B = treatment) and by `role`. The denominator is routing decisions, not accepted tasks. Missing/empty inputs yield a well-formed zeroed result (fail-safe), never an error.

2. Gate-refusal reason-mix aggregator: tally the `reason` values carried on non-resume (`fresh` and `rehydrate`) selections — the routing gate reasons that declined resume (e.g. window-pressure, diff-volume, lease, taint) — as a stable, sorted reason-to-count map, plus a distinct `context.resume_failed` count (resume chosen then mechanically failed). A missing/empty `reason` buckets under a stable `unspecified` key, never dropped.

3. Composed secondary-metrics artifact: emit ONE deterministic JSON object on stdout (keys sorted, stable for a given input set) conforming to a NEW additive schema `gluerun.orchestration.ctx-experiment-strategy.v0`, merging the per-arm and per-role hit rates with the gate-refusal reason mix. This object is the raw metrics artifact the operator's `experiment-report.md` references alongside the TASK-0077 report artifact.

## Context packet

### Decisions

- Ship the routing-derived secondary metrics as a SEPARATE new `engine/ctx-experiment-strategy.sh` + new additive schema rather than extending `engine/ctx-experiment-report.sh`, because that file is now integrated (a pre-existing file); a new file keeps this additive, OFF-parity intrinsic, and scoped-gate eligible, and the operator report references multiple raw-metrics artifacts by design.
- Compute hit-rate denominators over strategy-selection events (per routing decision), not per accepted task, because resume/rehydrate are decided per attempt and per role — the report's secondary metric is a decision-level rate.

### Rejected alternatives

- Editing `engine/ctx-experiment-report.sh` to merge the strategy metrics into its artifact — rejected: it is a pre-existing file (full-suite gate, new-file-convention friction) and the artifacts are legitimately separable.
- Deriving refusal reasons from routing internals (`engine/ctx-route*.sh`) instead of the emitted `reason` field — rejected: the events log is the durable, replayable measurement source; re-deriving would couple the reporter to routing implementation.

### Assumptions

- [validated] `context.strategy_selected` carries `taskId`, `role`, `attempt`, `strategy` in resume|rehydrate|fresh, and `reason`; `context.resume_failed` marks a resume that fell back to fresh; `ctx.arm_assigned` carries `taskId` and `arm` — basis: engine/l1-drive.sh strategy_selected emit sites, engine/ctx-rehydrate-event.sh, engine/generate-tasks.sh, engine/ctx-ab.sh.
- [open] Some `reason` values (e.g. `fresh decide-error`) are non-refusal fallbacks; the aggregator tallies them verbatim in the mix rather than filtering, leaving interpretation to the operator report — basis: fail-safe, no lossy filtering.
