## Objective

Advance the executable DAG node `plan-critic-driver` (stage `S2-plan-critique`, layer `engine_runtime`, kind runtime) toward its required completion by adding a new, present-but-uncalled `engine/ctx-plan-critic.sh` that runs the plan critic (the skeptic) over a STAGED candidate set and records its critique. This is the runtime brick that builds on the already-integrated `plan-critique.v0` contract (`schemas/plan-critique.v0.schema.json` + `templates/prompts/plan-critic.md`) and the integrated planner session-meta helpers.

The critic invokes the DEFAULT runner — preserving the cross-provider independence property, so even module-routed planners get a default-runner critic — in a fresh session (no `--resume`/session reuse), read-only, over the node-local stage dir (rendered candidate task files), the existing-task summary, and the node's stage file from `docs/context-build-plan/`. Robust JSON extraction uses `gluerun_extract_json`. Unparseable critic output after `GLUERUN_AUDIT_INFRA_MAX`-style bounded retries fails OPEN: it is treated as an `approve` verdict with a `ctx.plan_critique_infra` event, because the critic is an added safety layer and its infrastructure failing must never deadlock planning — the un-bypassable implementation auditor remains the safety floor. Persisted critiques validate against `gluerun.orchestration.plan-critique.v0`, with finding ids reusing the `gluerun_finding_id` normalized-hash identity.

The file defines NEW functions only and is invoked by NO existing engine path, so with it present-but-uncalled the engine is byte-identical to prior behavior (mirroring `engine/ctx-paired-audit.sh`). The `reconcile.sh` / L0 import enforcement hook belongs to the follow-up node `critique-import-gate` and is out of scope here. Behavior stays default-safe and additive per the planner contract.
