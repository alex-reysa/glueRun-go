## Objective

Advance executable DAG node `planner-session-meta` (stage `S1-planner-persistence`, layer `engine_runtime`, kind runtime) by landing its foundational library brick: a new `engine/ctx-planner-session.sh` that (1) computes the canonical per-node planner session-meta path `.gluerun-state/sessions/planner/<node>.json` under the runtime state dir (NOT `docs/` — session ids are runtime state, not repo truth), and (2) provides a feature-flagged finalize wrapper that persists a finalized planner session-meta reusing the existing `gluerun.orchestration.session-meta.v0` shape with `role: "planner"` and a new optional `node` field.

The file is auto-sourced by the existing ctx-loader block in `lib.sh` via the `engine/ctx-*.sh` convention and defines new functions ONLY — no existing engine path invokes them — so with the file present-but-uncalled the engine is byte-identical to prior behavior (mirroring `engine/ctx-paired-audit.sh`). The finalize wrapper delegates into the already-integrated `gluerun_session_meta_finalize`, adding the planner `role` and `node` field; it is guarded default-OFF by `GLUERUN_PLANNER_SESSION` (default 0). A failed/invalid planner run must NEVER finalize a resumable meta — a session that produced rejected output is not a lineage we extend (evidence invariance; Stage 3 revision is the deliberate exception, out of scope here).

The scarce `generate-tasks.sh` / `l1-plan-node.sh` call-site hook that passes `--session-meta` to the runner and calls this wrapper on a successful batch is the follow-up slice of this node and is deliberately OUT OF SCOPE for this task.

## Acceptance Criteria

- With `engine/ctx-planner-session.sh` present, `bash tests/run.sh` (including `tests/test-engine-clean.sh`) stays green; the file defines functions only and no existing engine code path invokes them, so engine behavior is byte-identical to before this task.
- A pure path helper returns the canonical per-node planner session-meta path `.gluerun-state/sessions/planner/<node>.json` under the runtime state dir (never under `docs/`), for the DAG node `planner-session-meta`.
- A guarded finalize function, when `GLUERUN_PLANNER_SESSION=1` and the planner run exited successfully (rc 0), writes/updates a finalized meta at the canonical path reusing the `gluerun.orchestration.session-meta.v0` shape via `gluerun_session_meta_finalize`, with `role: "planner"` and a new optional additive `node` field equal to the target node; the lineage anchor `headShaAtCreate` is the target-branch head at planning time.
- When the planner run failed/invalid (non-zero rc), the finalize function writes NO finalized resumable meta at the canonical path (evidence invariance — a rejected planner lineage is not extended blindly).
- `GLUERUN_PLANNER_SESSION` defaults to 0: when unset/OFF the finalize function is a no-op (no file written, byte-identical), independent of rc.
- The new optional `node` field is additive only and does not alter the meta shape when absent; no existing schema or `engine/lib.sh` is modified.
- `tests/test-ctx-planner-session.sh` drives these behaviors with a stub runner/meta and asserts: (a) success + knob ON → a valid finalized meta at the canonical path with correct `role`/`node` fields; (b) planner-failed → no finalized meta; (c) knob OFF → no-op / byte-identical. The test fails before implementation (red) and passes after (green); the gate command `bash tests/run.sh` passes.
- Gate candidate: with `tests/test-ctx-planner-session.sh` green and the suite passing, this slice satisfies the library portion of `planner-session-meta`'s requiredCompletion; the `generate-tasks.sh` / `l1-plan-node.sh` `--session-meta` hook that invokes this wrapper on a successful batch is the node's follow-up slice.

## Notes

Advocate/skeptic & evidence invariance: this task only WRITES planner-role session-meta and never introduces a path where a resumed/rehydrated (tainted) session satisfies an independence-required step; a failed planner run finalizes nothing, so no rejected lineage becomes resumable. The resume/gate side (`gluerun_planner_resume_decide`, node lineage, session leases, rc-86 fresh fallback) belongs to the downstream `planner-resume-gates` node and is out of scope. Feature-flag discipline: all new behavior is default-OFF behind `GLUERUN_PLANNER_SESSION`; a default flip is a separate task only after the stage exit gate.
