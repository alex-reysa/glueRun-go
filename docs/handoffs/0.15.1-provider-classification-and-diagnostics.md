# Handoff — glueRun-go 0.15.1 / 0.16.0

Six findings from a live 26-node localization program running against 0.14.1 on
2026-07-25, each confirmed by reading the engine source rather than taken from
the operator's report. None are addressed by 0.15.0.

This document is self-contained: it carries the evidence, the traps, and the
working agreements needed to do the work without re-deriving any of it.

## 1. A transient 529 costs 30 idle minutes  — *0.15.1, highest value*

`engine/lib.sh`, anchor `elif status in (503, 529):` — the provider-error
classifier gets this right:

```python
elif status in (503, 529):
    kind, canonical_code, retryable = "overloaded", "provider_overloaded", True
```

Then, anchor `failure_class = "quota" if provider_error["kind"] in`, it discards
that:

```python
failure_class = "quota" if provider_error["kind"] in {
    "usage-limit", "overloaded", "entitlement"
} else "provider-exit"
```

`quota` selects `GLUERUN_PLANNER_QUOTA_BACKOFF_SECONDS` (default **1800**)
rather than `GLUERUN_PLANNER_BACKOFF_SECONDS` (default 900). So a server-side
capacity blip that clears in seconds idles the whole graph for half an hour. In
the field run it was the dominant failure mode — two occurrences on one node
inside fifteen minutes, and at six concurrent agents on Opus it will be routine.

### The trap — do not "just move overloaded to provider-exit"

`engine/autonomate.sh`, anchor `must not trip the circuit breaker`:

> ONLY the "quota" class is special-cased — every other failure class falls
> through to the normal cycle below and still counts toward the breaker.

Bucketing `overloaded` as quota was buying something real: transient provider
errors do not increment `GLUERUN_MAX_CONSEC_FAILS`. Demote it to `provider-exit`
and five 529s in a row halt the loop entirely — strictly worse than the bug.

**The fix needs a third class**: short backoff *and* no breaker increment.
Something like `provider-overloaded`, with its own
`GLUERUN_PLANNER_OVERLOAD_BACKOFF_SECONDS` (suggest 120–180), routed through the
same no-breaker path `quota` uses in `autonomate.sh`. The operator's local
mitigation was `GLUERUN_PLANNER_QUOTA_BACKOFF_SECONDS=180`, which works but also
shortens genuine usage-limit waits — that is a workaround, not the fix.

Check every consumer of `failureClass == "quota"` before adding the class:
`autonomate.sh` (the nap + `quota_wait_budget` escalation to STOP),
`gluerun_planner_failure_class`, the console/health projections, and
`gluerun_runner_quota_evidence_json`.

## 2. `evidenceClass: deterministic-proof` is unreachable  — *0.15.1*

The engine cannot satisfy its own strict validator.

- `engine/gate-check.sh`: `run_dir="$GLUERUN_STATE_DIR/runs/$run_id"`,
  `log="$run_dir/gate-check.log"`, then `--log-ref "$log"` — **absolute**.
- `engine/gate_report.py`: `"logRef": args.log_ref` — written verbatim.
- `engine/dag.sh`, `validate_strict_gate_report`, anchor
  `report_log = regular_repo_file(` → `safe_repo_artifact`, anchor
  `must be a safe repository-relative path` — rejects any absolute path.

So no gate report the engine produces can ever back a `deterministic-proof`
gate-result. The operator found this by writing a promoter, correctly refused to
rewrite the engine's report to work around it ("that would mean editing
evidence"), and fell back to the weaker supported class.

**Fix direction:** make `gate-check.sh` emit `logRef` (and any sibling refs)
repo-relative when the log lives inside the repo, keeping the absolute path in a
separate field if callers need it. Then verify the strict path end to end —
`safe_repo_artifact` also refuses symlink traversal and non-regular files, and
`.gluerun-state/` is gitignored (it does *not* require the file be tracked, but
confirm that rather than assume).

Pin it with a test that takes a report `gate-check.sh` actually produced and
runs `dag.sh` strict validation over it. A test that hand-writes the report
proves nothing — that is exactly how this stayed invisible.

## 3. A DAG validation error presents as "no work to do"  — *0.15.1*

`engine/lib.sh`, two sites:

```bash
frontier="$(... dag.sh next-areas 2>/dev/null || true)"; [[ -n "$frontier" ]] || frontier="{}"
frontier_json="$(... dag.sh next-areas 2>/dev/null)" || return 0
```

`dag.sh` produces a precise diagnostic — *"gate-result.v1 for loc-00-contract
evidence[0] ref must be a safe repository-relative path: /private/tmp/…"* — and
both call sites send it to `/dev/null` and report an empty frontier.

The operator lost 34 minutes to a loop that said `frontier=0` while three nodes
were ready and the real problem was one malformed gate file. The information
already exists; the engine throws it away.

**Fix direction:** capture stderr, log it, and emit a distinct event
(`dag.evaluation_failed`) so an empty frontier caused by an invalid DAG is
never indistinguishable from an empty frontier caused by no ready work. A
doctor check that runs `dag.sh next-areas` and surfaces the failure belongs here
too. Do **not** make it fatal — the loop should keep running other work — but it
must not be silent.

## 4. A fresh consumer DAG cannot promote anything  — *0.16.0*

Two individually defensible defaults that combine into a dead graph:

- `engine/dag.sh`, anchor `authority={node.get('authority', 'operator')}` —
  nodes default to **operator** authority, i.e. manual promotion.
- `gluerun-ext/promote-gate.sh`, anchor `unsupported gate promotion node:` —
  the shipped promoter only promotes nodes in its own built-in registry and
  rejects everything else.

So a consumer who writes their own DAG gets: no node the default promoter
recognises, and every node requiring manual promotion anyway. The graph stalls
after layer 0 and the only symptom is `promotion: no promotable frontier gates`
every iteration. This blocked all 26 nodes and cost the operator a full day
before they wrote their own promoter.

**Fix direction:** a doctor check — *"N nodes have no registered promoter and
default to operator authority; this graph cannot advance unattended"* — with the
two remedies named (`authority: agent-review-allowed`, or a `promoter` config
key). Consider whether the built-in registry should be a hard rejection at all,
or whether an unregistered node should simply be reported as operator-only.

## 5. Parallel L1 planners are invisible to health and the console  — *0.16.0*

`engine/ops.sh`, anchor `runs.glob("*/run-status.json")` — direct children only.
Fanout planner sessions live under `runs/<origin>/l1-staging/<node>/`, so with
two planners running the operator saw `phases: 1` against `leases l1=2`, and
learned to distrust the phase counter.

This is the **same root cause** already recorded as deferred in the 0.14.0 notes
(`discover_sessions` scans only direct children of `runs/`). It now has field
evidence of misleading an operator mid-incident, which is why it is listed here
rather than left deferred.

## 6. Planning and integration are serialized through the origin lock  — *design, not a patch*

`reconcile.sh` acquires the origin lock and holds it for the entire cycle
including L1 planning; integration runs only at the start of a cycle. An
acceptance landing two seconds after that step waits for the whole planning
round — **13+ minutes observed**.

This is the structural cap on what raising concurrency buys, and the operator
identified it correctly. It is a design change, not a fix — do not attempt it
alongside 1–3. Worth its own scoped pass with a clear invariant for what the
lock actually protects.

## Not engine bugs (but they point somewhere)

The operator's promoter hit four contract violations in a row, each hiding the
next, each costing a loop restart: absolute paths in `evidence[].ref` and
`gateReportRef`; task-set evidence hashed by their convention instead of
`task_set_sha256`; `gate-report.taskId` constrained to `^TASK-[0-9]{4,}$` while
they passed a node name; and finding 2 above.

Each rejection surfaced one violation. A **`gluerun gate validate <file>`** verb
that reports *all* violations at once would have collapsed a multi-hour loop into
one command. Worth considering for 0.16.0.

## Working agreements carried from the 0.15.0 session

These cost real time to learn. Do not rediscover them.

### Testing discipline

- **Every fix lands with a test verified to fail against the unfixed code** —
  revert the fix, watch it go red, restore. Not "watch it pass". In 0.15.0 this
  caught **four vacuous tests and two real defects** that would otherwise have
  shipped:
  - an assertion on `"read-only guard journal"` also matched the PASS message
    `"no read-only guard journals are pending"`, so it passed with the warning
    deleted;
  - `ix_differs` was unreachable from a clean-at-capture file, so the
    index-restore path had no coverage at all.
- When a mutation **doesn't** go red, that is a finding, not a nuisance. Both
  real defects in 0.15.0 surfaced exactly that way.
- **Never `git checkout -- <file>` inside a mutation-testing script.** It
  silently destroys uncommitted work. Back up to the scratchpad with `cp` and
  restore from there. This nearly cost the entire gate-timeout implementation.
- **Verify by exit code, not by piping to `tail`.** A piped run discards the
  status and PASS lines scroll past while the script exits 1.

### Harness constraints

- **Background commands are killed at ~15 minutes.** The full `tests/run.sh` is
  ~50 minutes and cannot complete in one. `setsid nohup` does **not** survive
  either — it was tried and produced no output file at all.
- Run the suite in **index-strided slices**. The runner below replicates
  `tests/run.sh` semantics exactly (the `GLUERUN_*` env scrub and `</dev/null`
  per test) over a subset; six slices of ~30 tests each finish comfortably.

```bash
#!/usr/bin/env bash
set -uo pipefail
ROOT="$1"; SLICE="$2"; SLICES="$3"
TESTS_DIR="$ROOT/tests"
while IFS= read -r _v; do unset "$_v"; done < <(compgen -v | grep '^GLUERUN_' || true)
unset _v
EXT_DIR="$(cd "$ROOT/gluerun-ext/tests" 2>/dev/null && pwd || true)"
all=()
for t in "$TESTS_DIR"/test-*.sh ${EXT_DIR:+"$EXT_DIR"/test-*.sh}; do
  [[ -e "$t" ]] && all+=("$t")
done
pass=0; fail=0; failed=""
for i in "${!all[@]}"; do
  (( i % SLICES == SLICE )) || continue
  t="${all[$i]}"; name="$(basename "$t")"
  if out="$(bash "$t" </dev/null 2>&1)"; then
    printf "PASS  %s\n" "$name"; pass=$((pass + 1))
  else
    printf "FAIL  %s\n" "$name"
    printf '%s\n' "$out" | tail -4 | sed 's/^/      /'
    fail=$((fail + 1)); failed="$failed $name"
  fi
done
echo "SLICE $SLICE/$SLICES: $pass passed, $fail failed"
[[ -n "$failed" ]] && echo "SLICE_FAILED:$failed"
exit $(( fail > 0 ))
```

- **Never edit the tree while a suite is running.** It invalidates the run and
  produces phantom failures. Freeze, run, then edit.
- **Timing-sensitive tests flake under CPU contention.** `test-claude-run.sh`
  c10 has a 10s budget and hit 32s while an unrelated orchestration ran in
  `/private/tmp`. Check `ps -A | grep autonomate` before believing a timing
  failure — re-run it isolated before treating it as a regression.

### Engine invariants that are easy to violate

- **`GLUERUN_ENGINE_DIR` is an overridable knob, not the install path.** Tests
  shim it to a directory of selected `ctx-*.sh` symlinks to control which bricks
  load. Resolving an engine *executable* through it breaks under that shim. Use
  **`GLUERUN_LIB_DIR`** (added in 0.15.0, not overridable).
- **`.gluerun-state/autonomate.pid` must stay a bare single line.** `ops.sh`,
  `doctor` and the console all `cat` it. Process identity lives beside it in
  `autonomate.pid.identity`.
- **`kill -0` alone is not a liveness check for a long-lived pidfile** — a
  recycled pid reads as "already running" forever. Compare `ps lstart` too.
- **Widening infrastructure classification is dangerous in the optimistic
  direction.** `audit-infra` → `escalate-infra` parks *unconditionally* without
  consulting the retry budget, so a false positive kills a task a retry would
  have fixed. This is why `engine/infra-patterns.tsv` has a scope column and why
  ENOENT / ECONNREFUSED / EACCES stay `heuristic` (v0-only).
- **Test fixtures must gitignore `.gluerun-state/`.** The read-only guard writes
  its journal, quarantine and result there; without the ignore, porcelain
  comparisons report the guard's own bookkeeping as a failure.

### Release checklist

1. Bump `VERSION`, `.gluerun-version`, and `engineVersion` in both
   `gluerun.config.json` and `templates/gluerun.config.json`.
   `SCHEMA_VERSION` stays `v2`. `tests/test-release-packaging.sh` now reads
   `VERSION` rather than pinning a literal, so it will not go stale.
2. CHANGELOG entry.
3. Freeze the tree, then: bash suite (sliced), `python3 -m unittest discover` in
   `plugin/scripts`, `tests/field-report-canary.sh`,
   `gluerun doctor --json`, `engine/secret-scan.sh --worktree "$PWD" --range <prev>..HEAD`.
4. Doctor will refuse once `.gluerun-version` names an uninstalled version —
   run it with `GLUERUN_ENGINE_HOME="$PWD"` until after `install.sh`.
5. Commit, merge to `main` (fast-forward from `agent/integration`), push both,
   `bash install.sh`, then re-run doctor against the installed engine.
